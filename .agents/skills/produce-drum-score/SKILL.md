# 악보 제작

역할은 **악보제작자**다. 악보 출력은 MusicXML로 만들며, 음원·재생용 패키지는 요청 범위에 따라 준비한다. 인쇄용 PDF와 독립 HTML 재생 파일은 생성하지 않는다.

## 시작과 정본

- 실제 프로젝트 루트에서 작업한다. [전역 지침](/Users/raphael/AGENTS.md), [프로젝트 지침](../../../AGENTS.md), cwd·Git 상태·HEAD를 먼저 확인하고 기존 변경과 로컬 자료를 보존한다.
- 매 제작 시작 전에 [전체 제작 프로세스](../../../docs/SCORE-PRODUCTION-PROCESS.md)와 [변환 정책](../../../docs/MUSICXML-CONVERSION-POLICY.md)을 읽는다. 매핑은 [MusicXML·OSMD 매핑](../../../docs/SCORE-MUSICXML-OSMD-MAPPING.md), 표시는 [SVG 규칙](../../../docs/SVG-SCORE-RULES.md), 저장·가사는 [canonical 계약](../../../docs/MUSICXML-CANONICAL.md), 패키지는 [완성 파일 계약](../../../docs/SCORE-PACKAGE.md)을 따른다. 이 스킬은 이 정본들의 대체 매핑을 만들지 않는다.
- 기존 승인과 입력으로 해결할 수 있는 내용을 사용자에게 다시 묻지 않는다. 문서가 헷갈리면 구조·현재/과거 상태를 정리한다. 모순 해결은 history → 관련 문서 → 과거 악보 제작 세션 → 웹 근거 순서로 확인하고 수정 이유를 기록한다.

## 입력별 경로

- **PDF:** 변환 정책의 벡터 구조 추출 또는 스캔·사진 Audiveris 초벌/교정 경로를 적용한다. 새 양식은 대표 구간을 먼저 평가하고 원본·자동 초벌·기존 결과를 보존한다.
- **유튜브:** 아래 절을 적용한다. 기존 요청에서 실제 연주 채보인지 새 연습곡 제작인지 먼저 판별한다. 문맥으로 결정할 수 없고 결과가 실질적으로 달라지면 그 차이만 확인한다.
- **음원:** 제공/요청된 버전과 악보의 길이·반복·첫 박·템포를 연결한다. 악보 가사 underlay와 실제 가창 시각을 혼동하지 않는다. 가창 타이밍 검색은 제작의 필수 단계가 아니다.
- **새 드럼 음원 제작:** [GarageBand 드럼킷 소개·선택 기준](../../../docs/GARAGEBAND-DRUM-KITS.md)을 먼저 읽고 현재 프로젝트에 보존된 키트 중 곡·연습 목적에 맞게 선택한다. 현재 보유 목록은 연결 문서를 정본으로 따른다. 선택 이유·샘플 출처·매핑·검증을 곡별 문서에 남긴다. MusicXML만 요청된 작업에 음원 제작을 추가하지 않는다.

## 유튜브로 제작

1. **영상 내용 확인.** URL·영상 ID·채널·제목·확인 날짜와 제작 대상 구간을 기록한다. 본문 조회가 막히면 실제 실패를 남기고, 해당 범위에 승인된 Safari MCP로 설명·챕터·스크립트·재생 장면을 확인한다. GUI와 외부 접근은 현재 지침의 승인 범위를 따른다. 이미 승인된 같은 범위는 다시 묻지 않는다. 제목/oEmbed/썸네일만으로 본문이나 패턴을 확인했다고 쓰지 않는다.
2. **근거의 한계 확인.** 자동 스크립트의 음표 이름 오인식은 실제 설명·화면·해당 구간과 대조한다. 스크립트는 타격 채보의 정답이 아니다. 탐색 직후에는 이전 프레임이 보일 수 있으므로 실제 재생 시각과 표시 내용이 바뀌었는지 확인한다. 직접 확인한 구간·음향·프레임과 미확인 부분을 구분한다.
3. **실제 연주 채보 모드.** 확인 가능한 악보 화면·타격 장면·음향에서 대표 구간의 마디·박자·시작·길이·악기·손·주법을 판독한다. 영상 시각과 음악적 위치를 연결한 이벤트 표와 독립 기대값을 만든 뒤 전체로 확장한다. 기존 악보가 있으면 함께 대조한다. 가려진 손이나 불분명한 타격은 후보로 표시하고 근거를 추가해 교정한다. 보이지 않는 패턴을 제목·자막·규칙성만으로 확정하지 않는다. 음원 분리/다운로드·재사용은 실제 요청과 허용 범위에 있을 때 수행한다.
4. **영상 참고 새 연습곡 모드.** 영상에서 확인한 교육 개념과 근거 시각을 기록한다. 그 개념에 맞는 독립적인 이동 경로·리듬·손·템포·마디 구성을 정하고 이벤트 표로 저장한다. 원본의 정확한 채보라고 부르지 않는다. 새 음원 요청이 있으면 위 드럼킷 선택 기준에 따라 같은 이벤트 시각으로 제작하고 음색·입력/샘플 출처·첫 공격·후미·디코딩 길이·재생성 해시를 확인한다.
5. **범위에 맞는 다음 단계.** PDF가 없는 제작에 PDF 유형 검사나 인쇄 가사 대조를 강제하지 않는다. 가사가 있으면 현재 정본의 표준 MusicXML 가사·음악적 위치 계약을 적용한다. 자료와 이전 시도는 프로젝트 안 Git 제외 실험 폴더에 보존하고, 영상 근거와 새 결과를 구별한다.

## 교정·검증·인계

- 마디별 시작·음가·동시음·악기·주법·손과 독립 fixture, MusicXML XSD 및 재읽기를 검사한다. 드럼 파트만으로 전곡 길이를 집계한다. 별도 가사 파트의 마디를 더하지 않는다.
- 요청된 음원은 악보 이벤트·첫 박·카운트오프 OFF/ON·배속을 검사한다. 수치 scheduling, 디코딩, 실제 청취를 각각 기록한다. 합성 결과는 가능하면 동일 입력 재생성도 확인한다.
- 실제 앱 공통 renderer와 패키지 API를 사용한다. 전체 Song·XML·음원 왕복과 실제 SVG를 확인한다. R/L 개수가 맞아도 위치가 틀릴 수 있으므로 빔·줄기·머리와의 배치를 시각 대조한다. 과거 곡의 전용 helper·해시 가드·고정 경로를 새 입력에 그대로 사용하지 않는다.
- 막히면 프로젝트 정본 → 과거 제작 세션 → 웹 자료 순서로 조사한다. 원인을 고치고 관련 검증을 반복해 요청한 완료 조건까지 진행한다. 같은 실패를 근거 없이 반복하지 않는다. 해결한 문제는 원인·해결·검증·다음 적용 기준을 [문제 해결 기록](../../../docs/MUSICXML-TROUBLESHOOTING.md) 또는 곡별 문서에 남기고 history에 연결한다.
- 생성 완료, 표시 검수, 실제 앱 수록/저장·재열기, 청취를 구분한다. 앱 개발자가 수록·표시 수정을 맡는 경우 산출물 절대경로·검증 근거·미해결 표시/재생 문제를 인계한다. 다른 채팅에 메시지를 보내는 것은 직접 확인 가능한 사용자 위임 범위에서 수행한다. 자동 commit·push·공개 배포는 하지 않는다.

## 확인된 적용 사례

[탐탐 무빙 제작 기록](../../../docs/TOM-MOVING-PRODUCTION.md): 웹 조회 실패를 승인된 Safari 본문/스크립트 확인으로 해결하고, 영상 교육 개념을 참고한 새 MusicXML·합성 음원·패키지를 제작했다. 실제 영상 전곡 채보·전곡 청취 검증 사례는 아니다. 구체적 마디 수·템포·탐 구성은 이 사례의 값이며 다음 곡에 고정하지 않는다.
