## 2026-09-21 — 합본 전체 데이터 추가 gzip 실험

- 사용자 최신 결정: SVG·PDF 합본으로 단일화하고, 전체 내부 데이터의 추가 gzip은 실측 효율로 판단한다. 기존 단일 형식 제한을 대체한 결정이다.
- 같은 실행 코드·CSS·Worker·라이선스를 사용한 동일 합본 HTML에서 portable-data JSON만 gzip+Base64로 교체했다. 압축 해제 후 JSON 전체 동등성과 데이터 외 HTML 동일성을 재검증했다.
- 최종 파일: 11,534,696 → 11,076,554 bytes. 458,142 bytes(약458KB), 3.9719% 감소. 원시 JSON은11,326,985 bytes, gzip 이진은8,151,608 bytes지만 단일 HTML에 넣는 Base64 envelope가10,868,843 bytes로 늘어난다. 최종 파일 절감률로 판단한다.
- 데이터 구성: SVG는 이미 application/vnd.drum-practice.svg+gzip, PDF 표시 페이지는 PNG, 음원은 MP3다. 원본 PDF 파일을 새로 넣거나 미디어 품질을 낮추지 않았다.
- macOS 로컬 5회 실험의 중앙값: 일반 데이터 읽기10.8ms, 압축 데이터 읽기/해제363.1ms, 내보내기 압축416.7ms. 전체 앱 시작 시간이나 실제 iPad 측정값은 아니다.
- 결정: 약4%의 절감은 추가 해제 처리·지연을 감수할 만큼 크지 않아 전체 payload 추가 gzip은 적용하지 않는다. 기존 SVG gzip은 유지한다. 제품은 일반 JSON payload를 생성/읽으며 시험용 압축 함수는 로컬 실험 자료에만 남긴다.
- 증거: docs/experiments/html-playback/gzip-comparison.json, gzip-verification.json, combined-plain.html, combined.html. 내보내기 집중 테스트5건 통과. 합본/제스처 전체 QA 통과와 구분한다.
