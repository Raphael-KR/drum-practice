# 공개 사이트 보안과 음원 분석 경계

2026-10-14 최신 결정: 기기에서 가져온 음원의 곡명·가수·박자 분석과 캐시를 브라우저 내부로 한정한다. 서버 분석정보 저장·조회와 익명 등록·검토/승인을 폐기한다. 최신 코드의 경계이며 공개 Site 반영은 다음 발행 때 수행한다.

## 남기는 보호 조치

- `server/player-worker.ts`는 HTML 문서와 정적 자산만 제공한다. `/api/` 요청은 404이며 분석정보 읽기/쓰기 경로가 없다. 서버 악보 다운로드는 유지한다.
- Worker 문서 응답: nosniff, Referrer-Policy, X-Frame-Options, HTTPS HSTS. CSP의 frame-ancestors/object/base는 강제하고 전체 리소스 CSP는 보고 전용이다. JS/CSS 정적 전달에도 모두 같은 헤더가 적용된다고 보증하지 않는다.
- 음원 사전 검사: 전체 읽기 전 100MiB, 디코딩 전 30분/2채널/32kHz PCM 256MiB 상한. 메타정보가 거짓일 수 있으므로 디코더의 모든 메모리 사용을 보증하지 않는다.
- 브라우저 캐시: 분석기 버전·해시·유효 숫자/박 배열 검사. 저장 실패 시 기기에서 분석하며 네트워크로 우회하지 않는다. 음원 원본과 기존 보관함·수동 설정은 보존한다.

## 폐기와 배포 경계

로컬 API, 승인 정본 내보내기, 비밀 키, SQLite, 검토 UI/CSS/문구와 관련 테스트를 제거한다. 공개 서버의 분석·대기·요청제한 테이블은 `hosting/drizzle/0002_regular_jetstream.sql`의 DROP TABLE로 삭제한다. 이 마이그레이션은 사용자 요청에 따른 자료 삭제이며 롤백 명령이 아니다.

Sites는 발행 시 마이그레이션을 적용한다. 이미 적용한 0000/0001 이력은 수정하지 않는다. D1 바인딩/마이그레이션 도구는 마지막 DROP 적용을 위해 일시 유지하며 런타임 Worker는 DB를 사용하지 않는다. 최종 삭제가 공개 환경에서 확인되기 전에는 원격 자료까지 삭제됐다고 보고하지 않는다.

과거 0.7.8 검토/승인 보강의 발행 식별자와 검증 결과는 `history.md`와 `SITES-PUBLICATION.md`의 역사 기록으로만 유지한다.
