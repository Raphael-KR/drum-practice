# 악보 편집창 UX 개선 제안

2026-09-21. 상태: 사용자 승인 후 악보 편집 탭 적용. 곡 정보·가사·파일의 추가 개선은 제안 단계로 유지한다.

## 실제 화면 검토

Safari 로컬 웹앱에서 네 탭을 열고 내용을 확인했다. 곡 정보와 악보 편집 탭은 화면 캡처로 검토했다.

- 공통 상단: 칩·탭·저장 도구가 공간을 경쟁한다. 저장의 파란 강조와 탭의 선택 색상은 별도 의미다.
- 곡 정보: 탭과 본문의 제목이 중복되고 입력칸과 여백이 커서 음원 연결 영역이 첫 화면 밖으로 밀린다.
- 악보 편집: PDF와 SVG 전체 보기의 위치·모양이 서로 다르다. 미리보기보다 주변 조작이 크게 보이며 긴 내부 박 좌표가 기본 화면을 차지한다.
- 가사: 전체 보기·교체, 가사 배치 편집, 보컬 XML 가져오기와 설명이 같은 영역에 있다. 다음 상세 시안에서 작업 빈도에 따라 그룹화할 후보이다.
- 파일: 세 항목은 간결하다. 진입 타일과 공통 버튼 체계 적용을 검토할 수 있다.

## 이번 목업: 악보 편집 탭

- 기존 큰 편집창과 네 글자 탭, 본문에 연결된 선택 탭을 유지한다.
- 공통 상단 저장·되돌리기·이력·닫기는 같은 터치 크기로 정돈한다.
- 페이지·마디 선택과 PDF/SVG 전체 보기를 한 도구막대에 둔다.
- 왼쪽은 큰 악보 미리보기와 영역 지정 동작, 오른쪽은 선택 마디 설정으로 구분한다.
- 이름·박자·시작/끝 시각 → 마디 적용 → 듣기·첫 박 연결 → 세부 박 위치 → 구조 편집 순으로 묶는다.
- 내부 박 위치는 펼쳐서 편집하며 기능을 삭제하지 않는다. 마디 삭제는 일반 작업과 시각적으로 분리한다.
- 기존 마디 적용과 전체 저장의 의미를 유지한다. 임의로 적용 버튼을 없애거나 저장 동작을 바꾸지 않는다.
- 좁은 화면에서는 열을 쌓고 본문 내부 스크롤을 사용한다. 정확한 반응형 치수와 실제 입력 검수는 구현 단계에서 확정한다.

생성 목업의 악보 음표는 배치 설명용이며 음악적 정확성 검수 자료가 아니다. 새 가사 자동 처리, 전체 도움말 및 1.0 이전 일괄 QA 보류 항목은 이번 범위에 포함하지 않는다.

## 승인 후 적용

박 수는 정수 단계, 분모는 기존 2·4·8·16 값으로 공통 드래그와 휠 조절을 사용한다. 화살표 UI는 표시하지 않는다. 이름 및 시작·끝 시각은 키보드 입력을 유지하고 시각 필드의 숫자 드래그는 제외한다. 기존 마디 적용 및 편집 세션 저장 동작을 보존한다.
