# 붉은 노을 후반 음원 단독 재분석

2026-10-15. 사용자 승인: 후반 126~133마디에 해당하는 음원을 악보 없이 재분석·비교.

- 목표: 후반 기존 추적값과 음원 타격의 대응을 확인하고 지연 발생 위치·원인을 좁힌다.
- 범위: 동일 원본 음원, 기존 자동 분석의 입력·출력과 music-tempo 추적 경로. 악보 시각은 재분석 입력·후보 선택에 사용하지 않는다.
- 완료 조건: 기존값 재현, 구간별 재분석·타격 근거 비교, 확인된 원인과 미확정 사항 구분.
- 제외: 앱·악보·기기 저장값 변경, 전곡 보정·커밋·발행.
- 검증: 사용자 허가된 실제 음원 비교 검사. 기존 32kHz stereo PCM 사용, 결과는 `.tmp/red-sunset-late-audio/`에 보존한다.

## 결론

약230.67초(3:50.67) 이후 추적 경로가 갈라진다. 기존 추적은 검출된 타격 중 일부를 받지 못해 빈 박을 보간하고, 이후 더 늦은 타격을 채택한다. 이 경로 선택은 재생 이전의 분석 배열에 이미 들어 있다. 단순 재생 지연이나 전곡에 적용할 일정한 시간차로 설명할 수 없다.

음원만으로 새로 찾은 경쟁 경로는 231.920초부터 기존값보다 앞쪽 타격을 따라가며 후반 첫 박 차이를 약440~460ms 줄이는 후보다. 그러나 기존 경로도 실제 검출 타격을 많이 사용하고, 경쟁 경로가 모든 박의 정답이라는 근거는 아직 부족하다. **앞선 악보 대비 최대710ms를 전부 자동 분석의 오류로 확정하지 않는다.**

## 음원 단독 분석 계약과 재현

- 새 분석 스크립트는 `.drumscore`, MusicXML, 악보 시각·BPM을 읽지 않는다. 이전 검사에서 정한 후반 범위를 포함하도록 200/210/220초부터244초까지를 분석하고,250초까지 포함하는 민감도 검사도 수행했다. 구간의 정확한 끝값을 특정 악보 마디 끝에 맞추지 않았다.
- 입력은 기존 32kHz stereo PCM이며, 원본 MP3 해시 `e1af6bbfb2f9ed16e6c7e91ff1a30f9e97f198de5a537cddabecd51ac7047a29`. 원본/PCM의 동일성 검사는 직전 전곡 비교 기록을 따른다.
- 전체 음원 기준 기존578박을 밀리초 단위까지 모두 재현했다. 악보 기반 보정값을 섞지 않았다.
- 전체·244초 절단·200/210/220초 시작 등6개 범위에서 추종 계수20/10으로12개 경로를 계산했다. 초기 BPM은 전체 음원의 기존 자동 추정137.9 또는 해당 구간 자체의 자동 추정135.6~138.5를 사용했다.
- 비교는 공통으로 검출된224.960초 타격을 기준으로 순번을 맞췄다. 마디 이름은 이전 비교와 연결하기 위한 표기이며 분석·선택 입력이 아니다.
- 라이브러리의 채택 이벤트·보간 전 배열·추적 오차를 임시 복사본에 계측했다. 앱과 설치 라이브러리 코드는 수정하지 않았다.

## 왜 기존 경로가 계속 늦어지는가

1. **초기 박 근거 약화:** 별도로 계산한3개 주파수대 spectral flux의 자기상관에서220~230초의 주기 상관 최대값은0.606(약0.44초),230~237초는0.078까지 낮아진다. 단순한 일정 박 주기가 흐려졌다는 신호이며, 드럼 필인·보컬·악기 중 무엇 때문인지는 분리음원 없이 확정하지 않는다.
2. **이미 선택한 타격을 기준으로 다음 후보를 거른다:** 기존 경로가231.58초를 채택한 뒤 예측하는 다음 박은232.018초다. 실제 검출 후보231.92초는 예측보다98ms 빠르다. 이 경로의 허용창은 앞64.7ms/뒤129.5ms이므로 앞쪽 후보가 허용창 밖으로 밀려난다. 이후232.91초를 채택하고 사이를 보간한다.
3. **늦은 타격 채택과 템포 추정의 누적 변화:** 기존 경로는238.81·239.35·241.72초 등 예측보다 약99·94·119ms 늦은 타격을 수용한다. 전자는 허용 범위 안이다. 그때마다 주기를 조금 늘린다. 230.22초 타격을 평가할 때 주기는 약434ms,241.72초 채택 직전 약451ms로 바뀐다. 다만 이 변화 중 실제 연주 감속과 잘못된 타격 선택의 비율은 미확정이다.
4. **국소 정확도 대신 전곡 누적 점수로 한 경로를 고른다:** music-tempo1.0.3은 후보 경로의 누적 점수가 가장 높은 것을 선택한다. 200~244초·계수20 분석에서만 이 경쟁 경로가 선택됐고 나머지11조건은 이 후반부에서 기존 경로와 같은 결과였다. 시작점을 바꾸면 경로가 달라지는 민감성을 확인했지만 다수결로 어느 쪽을 정답이라 판단하지 않는다.

코드 근거는 `node_modules/music-tempo/src/Agent.js`의 `considerEvent/acceptEvent/fillBeats`, `src/MusicTempo.js`의 최고점 경로 선택이며, 앱은 `src/modules/audio/audio-beat-tracking.ts`에서 계수20을 사용한다.

## 경쟁 경로를 지지하는 별도 음원 신호

동일 mono 평균 음원에 중앙 시각을 명시한1024샘플 Hann 창·10ms 간격 FFT를 새로 적용했다. 30~180Hz,180~3000Hz,3000~7900Hz 대역의 양의 로그 스펙트럼 변화량을 각각95백분위로 정규화했다. 각 후보 박 ±35ms의 최대 신호를 평균했다. 타격의 강도 비교이며 박의 의미를 확정하는 정확도 점수는 아니다.

| 구간 | 기존 저주파 지지값 | 경쟁 저주파 지지값 |
| --- | ---: | ---: |
| 220~230초 | 1.883 | 1.883 |
| 231~234초 | 0.668 | 1.280 |
| 234~238초 | 0.602 | 0.876 |
| 238~244초 | 0.713 | 0.796 |

분기 직후 경쟁 경로가 저주파 타격과 더 잘 겹친다. 중·고주파에서는 우열이 혼재하며 후반부까지 완전히 독립적인 정답 박을 확보한 것은 아니다.

## 배제한 설명과 남은 판단

- 전체 입력을244초에서 잘라도220~244초의 기존 박 배열은 동일하다. 따라서 이 차이를 자유 엔딩 이후 자료가 전곡 분석을 오염시킨 결과로만 설명할 수 없다.
- 계수20→10만 바꿔도 이 후반부 경로는 동일하다. 앞부분41마디에 유효했던 조절이 후반부 해결책이라는 근거는 없다.
- 기존 경로의 늦은 값 중 많은 수가 실제 검출 타격이다. 단순히 검출 타격에 가까운 박만 고르는 기준으로는 두 경로를 구별할 수 없다.
- 다음 보정 판단에서는231~234초의 박 연결과238~244초의 위상 유지 여부를 우선 확인해야 한다. 현재는 후보·원인 조사 결과이며 앱에 자동 교체하지 않았다.
- Apple STT/AFM은 타격 시각 계측에 필요한 도구가 아니므로 호출하지 않았다. 앱 테스트·빌드·배포는 이번 분석 범위에 포함하지 않았다.
