# 악보의 MusicXML · OSMD 매핑 방식

관리 정본 · 2026-09-20

## 목적과 적용 원칙

악보의 연주 의미를 보존하면서 **OSMD에서 정상 지원하는 통상적인 표기를 먼저 선택하고, 그 표기를 지원하는 유효한 MusicXML로 저장한다.** 원본 PDF의 글리프 외형을 그대로 복제하는 것은 목표가 아니다.

- 적용 범위: 드럼 악기, 오선 위치, 음표머리, 주법, 쉼표, 스티킹 및 가사 저장.
- 완료 기준: 의미가 구분되고, 저장한 XML을 OSMD로 다시 열었을 때 선택한 표기가 표시된다.
- 이번 변경 범위: 매핑 정책 문서화. 이 문서 작성 자체로 기존 곡 데이터나 렌더러를 변경하지 않는다.
- 검증: 아래 기존 소스 조사·Safari 렌더링 증거를 기준으로 한다. 새 항목과 OSMD 버전 변경은 재검증한다.

OSMD는 악기 이름에 따라 모든 기호를 자동 결정하는 드럼 범례를 제공하지 않는다. 아래 표는 **OSMD 지원 기능으로 구성한 이 프로젝트의 표기 규칙**이다. MusicXML의 악기 ID, 표시 위치, 음표머리 모양을 각각 명시한다. 표시 편의를 위해 악기·리듬·연주 의미를 다른 것으로 바꾸지 않는다.

## 선택과 보고 절차

1. 원본 악보에서 악기와 연주 주법을 식별한다.
2. 아래 승인된 OSMD 호환 표기를 선택한다.
3. 해당 악기 정보와 위치·모양·기호를 MusicXML로 저장한다.
4. 앱의 임의 SVG 보정 없이 OSMD가 표시하는지 검증한다.
5. 같은 의미를 나타내는 지원 표기가 있으면 그것을 사용한다. 원본 외형 차이만으로 미지원 보고나 upstream 수정 작업을 만들지 않는다.
6. **의미를 보존하는 표기 방법이 OSMD에 없는 경우만 사용자에게 보고한다.** 미검증 항목은 먼저 조사하며, 조사만으로 미지원이라고 단정하지 않는다. 미지원 기호를 조용히 누락하지 않는다.

보고에는 항목, 필요한 의미/모양, 검사한 OSMD 버전, 시도한 MusicXML, 실제 결과와 재현 근거를 담는다. 외부 버그 리포트/PR 제출은 별도 요청 범위에 따른다.

## 악기와 음표머리 매핑

오선은 아래부터 제1선~제5선. 좌표는 MusicXML `unpitched/display-step`과 `display-octave`이며 실제 음높이가 아니다. 각 음표의 `instrument`는 곡의 `score-instrument` ID를 참조한다. 소리/MIDI 재생 지원은 시각 표기 지원과 별도로 검증한다.

| 악기/주법 | 오선 좌표 | 선택한 OSMD 표기 | MusicXML 저장 | 상태 |
|---|---|---|---|---|
| 베이스 드럼/킥 | F4 | 일반 머리, 아래 줄기 | normal, stem=down | 지원 |
| 스네어 | C5 | 일반 머리 | normal | 지원 |
| 크로스 스틱 | C5 | × | x + 별도 악기 ID | 지원 |
| 탐 1 | E5 | 일반 머리 | normal | 지원 |
| 탐 2 | D5 | 일반 머리 | normal | 지원 |
| 플로어 탐 | A4 | 일반 머리 | normal | 지원 |
| 닫힌 하이햇 | G5 | × | x + Closed hi-hat 악기 ID | 지원 |
| 오픈 하이햇 | G5 | 원 안의 × | circle-x + Open hi-hat 악기 ID | 지원·채택 |
| 하이햇 열기 지시 | G5 | × 위 ○ | x + technical/open-string | 지원 |
| 하이햇 닫기 지시 | G5 | × 위 ＋ | x + technical/stopped | 지원 |
| 풋 하이햇 | D4 | ×, 아래 줄기 | x + 별도 악기 ID, stem=down | 지원 |
| 크래시 | A5 | 원 안의 ×, 덧줄 | circle-x | 지원 |
| 라이드 | F5 | × | x | 지원 |
| 라이드 벨 | F5 | 채운 삼각형 | triangle filled="yes" + Ride Bell 악기 ID | 지원 |
| 고스트 노트 | 해당 악기 위치, 스네어는 C5 | 일반 머리 양옆 괄호 | normal, parentheses="yes" | 미지원·아래 보고 |

`normal`, `x`, `circle-x`, `triangle`은 `notehead`의 값이다. 일반 머리는 음가에 맞는 기본 채움 상태를 사용한다.

- **오픈 하이햇:** 기존 PDF의 빈 타원 `normal filled="no"`를 재현하지 않는다. 지원되는 circle-x를 사용한다. 빈 타원 처리 패치는 이 표기 정책의 필수 조건이 아니다. 기존 곡의 변환은 별도 구현 시 수행한다.
- **라이드 벨:** triangle은 OSMD의 일반 음표머리 도형이다. OSMD가 Ride Bell 전용 표준으로 지정하거나 악기 이름에서 자동 선택하는 모양이라는 뜻이 아니다. 사용자 범례에 따라 이 프로젝트에서 선택했다.
- **열기/닫기:** 각각 실제 악보 위치에 기록한다. open-string은 본래 개방현 기호이므로 이것만으로 하이햇 의미를 대신하지 않는다. 드럼 악기 ID와 함께 사용한다.

## 쉼표

| 상황 | 저장/표시 규칙 |
|---|---|
| 전체 마디가 쉼 | `rest measure="yes"`를 사용하고 display-step/display-octave를 넣지 않는다. OSMD 기본 중앙 배치를 사용한다. |
| 다른 성부가 연주하는 마디의 쉼표 | 심벌=상단, 드럼=중단, 킥=하단 역할 높이를 유지한다. 전체 쉼 마디와 구분한다. |
| 일반 2분·점2분 등 부분 쉼표 | 음가와 시작 박 위치를 보존한다. 긴 쉼표라는 이유만으로 쉬는 구간 가운데로 옮기지 않는다. |

온마디쉼표 높이 미지정은 앱에 적용되어 있다. MusicXML이 높이를 금지해서가 아니라, OSMD 기본 중앙 배치를 사용하는 호환 정책이다.

## R/L 스티킹

- R=오른손, L=왼손. 명칭은 sticking이며 fingering(손가락 운지)으로 저장하지 않는다.
- OSMD의 일반 텍스트 표시를 사용한다. `direction/direction-type/words`로 각 타격 음표의 악보 위치에 R 또는 L을 배치한다.
- 서로 다른 타격의 R/L을 한 음표에 쌓지 않는다. 성부와 대상 음표의 위치를 유지한다.
- 전용 sticking 요소가 없어도 words로 필요한 표기가 가능하므로 **OSMD 미지원 보고 대상이 아니다.** 다른 소프트웨어가 텍스트를 손 지시 의미로 자동 인식한다고 보장하지 않는다.
- `other-technical` 문자열과 fingering 우회는 채택하지 않는다.

## 메타 정보와 가사

- 해당 곡의 MusicXML에 악보, 원제·표시제목·가수·작사·작곡 등의 메타 정보, 가사 리듬 성부를 모아 관리한다. 기존 프로젝트의 MusicXML 저장 계약을 유지한다.
- 가사는 드럼과 독립된 가사 리듬 성부의 음표에 `lyric/text`로 연결한다. 보컬 악보가 있으면 그 리듬을 사용하고, 없으면 음원으로 정한 마디·박·음가를 기록한다.
- 가사 위치 정본은 초 단위 타임스탬프가 아니라 악보 위치다. 음원과 악보의 재생 동기화 정보는 이와 별개다.
- 영어는 영어로 유지한다. 이 문서는 기존 가사 싱크나 메타데이터 필드 이름을 새로 변경하지 않는다.

## 현재 미지원 보고

**고스트 노트의 음표머리 괄호**

- 필요한 표기: 해당 음표머리 양옆의 괄호.
- 표준 입력: `<notehead parentheses="yes">normal</notehead>`.
- 결과: OSMD 2.1.2 및 조사한 develop에서 괄호가 누락된다. VoiceGenerator가 해당 속성을 보존하지 않는다.
- 내부 `GhostNote` 클래스는 보이지 않는 리듬 공간용이며 드럼 고스트 주법 지원이 아니다.
- 일반 괄호 텍스트를 임의로 놓는 것은 음표머리에 연결된 괄호 지원으로 간주하지 않는다.
- 작은 음량과 괄호 표시는 별개이며, 괄호만으로 음량 재생을 보장하지 않는다.

현재 조사한 범례에서 사용자에게 남겨 보고할 미지원 항목은 이것이다. filled=no와 other-technical의 기존 조사 결과는 이력에 보존하지만, 채택한 circle-x/words로 목적을 달성하므로 현재 매핑의 차단 항목으로 취급하지 않는다.
