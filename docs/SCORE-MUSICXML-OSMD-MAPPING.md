# 악보의 MusicXML · OSMD 매핑 방식

관리 정본 · 2026-09-20

> **악기·주법 표시는 OSMD에서 확인된 악기 전용 표기 규칙을 기본으로 사용한다. 전용 규칙이 없거나 확인되지 않으면 먼저 보고한다. 일반 도형·일반 텍스트를 이용한 대체 매핑은 구체적인 방식을 보고한 뒤, 사용자가 해당 방식을 명시적으로 결정한 경우에만 사용한다.**

## 목적과 적용 원칙

악보의 연주 의미를 보존하면서 **OSMD에서 해당 악기·주법을 어떻게 정의하고 표기하는지 먼저 확인하고, 확인된 전용 매핑 또는 공식 표기 규칙에 맞는 유효한 MusicXML로 저장한다.** 원본 PDF의 글리프 외형을 그대로 복제하는 것은 목표가 아니다.

- 적용 범위: 드럼 악기, 오선 위치, 음표머리, 주법, 쉼표, 스티킹 및 가사 저장.
- 완료 기준: 의미가 구분되고, 저장한 XML을 OSMD로 다시 열었을 때 선택한 표기가 표시된다.
- 이번 변경 범위: 매핑 정책 문서화. 이 문서 작성 자체로 기존 곡 데이터나 렌더러를 변경하지 않는다.
- 검증: 아래 기존 소스 조사·Safari 렌더링 증거를 기준으로 한다. 새 항목과 OSMD 버전 변경은 재검증한다.

OSMD는 악기 이름에 따라 모든 기호를 자동 결정하는 드럼 범례를 제공하지 않는다. 아래 표의 기존 렌더링 성공은 **일반 도형/좌표가 표시된다는 증거**이며, OSMD가 해당 악기의 공식 표기로 지정했다는 증거가 아니다. 전용 규칙의 근거가 없는 항목은 자동 채택하지 않는다. 사용자 승인으로 채택한 대체 매핑도 OSMD 전용 규칙과 구분하여 기록한다. MusicXML의 악기 ID, 표시 위치, 음표머리 모양을 각각 명시한다. 표시 편의를 위해 악기·리듬·연주 의미를 다른 것으로 바꾸지 않는다.

## 선택과 보고 절차

1. 원본 악보에서 악기와 연주 주법을 식별한다.
2. OSMD의 악기 식별 정보와 전용 매핑·공식 표기 규칙을 소스/문서에서 확인한다. 악기 이름 또는 MIDI 번호만 존재하는 것은 표기 규칙의 근거가 아니다.
3. 확인된 규칙의 출처와 버전을 기록하고, 그 규칙에 맞춰 악기 정보·위치·기호를 MusicXML로 저장한다.
4. 앱의 임의 SVG 보정 없이 OSMD가 표시하는지 검증한다. 표시 성공만으로 전용 표기 지원을 판정하지 않는다.
5. 전용 규칙을 확인할 수 없으면 **“해당 악기의 전용 표기 규칙을 확인할 수 없음”**으로 보고한다. 첨부 범례와 닮은 일반 도형을 임의로 골라 매핑하지 않는다.
6. 규칙 미확인과 실제 렌더링 미지원을 구분한다. 미확인은 기능 부재의 확정이나 버그 판정이 아니다. 일반 도형·일반 텍스트 대체 방식을 제안할 때는 대상 악기/주법, 표시 모양, MusicXML 저장 방식, 의미·호환성의 한계를 먼저 보고한다. 사용자가 해당 방식을 명시적으로 선택한 경우에만 그 대상과 범위에 적용한다. 무응답이나 다른 항목의 승인은 승인으로 간주하지 않는다. 기존 데이터의 변경은 별도 구현 범위에서 수행한다.

보고에는 항목, 필요한 의미/모양, 검사한 OSMD 버전, 시도한 MusicXML, 실제 결과와 재현 근거를 담는다. 승인된 대체 매핑은 대상·방식·사용자 결정·적용 범위·검증 결과를 이 문서와 history.md에 기록한다. 이번 정책 변경 자체는 특정 대체 매핑의 적용 승인이 아니다. 외부 버그 리포트/PR 제출은 별도 요청 범위에 따른다.

## 기존 실험 기록 — 사용 가능한 매핑 목록이 아님

오선은 아래부터 제1선~제5선. 좌표는 MusicXML `unpitched/display-step`과 `display-octave`이며 실제 음높이가 아니다. 각 음표의 `instrument`는 곡의 `score-instrument` ID를 참조한다. 소리/MIDI 재생 지원은 시각 표기 지원과 별도로 검증한다.

| 악기/주법 | 오선 좌표 | 기존 렌더링 시험 표기 | 시험한 MusicXML | 검증 범위 |
|---|---|---|---|---|
| 베이스 드럼/킥 | F4 | 일반 머리, 아래 줄기 | normal, stem=down | 표시 성공·전용 규칙 미확인 |
| 스네어 | C5 | 일반 머리 | normal | 표시 성공·전용 규칙 미확인 |
| 크로스 스틱 | C5 | × | x + 별도 악기 ID | 표시 성공·전용 규칙 미확인 |
| 탐 1 | E5 | 일반 머리 | normal | 표시 성공·전용 규칙 미확인 |
| 탐 2 | D5 | 일반 머리 | normal | 표시 성공·전용 규칙 미확인 |
| 플로어 탐 | A4 | 일반 머리 | normal | 표시 성공·전용 규칙 미확인 |
| 닫힌 하이햇 | G5 | × | x + Closed hi-hat 악기 ID | 표시 성공·전용 규칙 미확인 |
| 오픈 하이햇 | G5 | 원 안의 × | circle-x + Open hi-hat 악기 ID | 표시 성공·전용 규칙 미확인 |
| 하이햇 열기 지시 | G5 | × 위 ○ | x + technical/open-string | 표시 성공·전용 규칙 미확인 |
| 하이햇 닫기 지시 | G5 | × 위 ＋ | x + technical/stopped | 표시 성공·전용 규칙 미확인 |
| 풋 하이햇 | D4 | ×, 아래 줄기 | x + 별도 악기 ID, stem=down | 표시 성공·전용 규칙 미확인 |
| 크래시 | A5 | 원 안의 ×, 덧줄 | circle-x | 표시 성공·전용 규칙 미확인 |
| 라이드 | F5 | × | x | 표시 성공·전용 규칙 미확인 |
| 라이드 벨 | F5 (첨부 범례 좌표) | 삼각형 시험 결과만 보존 | triangle filled="yes"는 채택 철회 | 전용 규칙 미확인·임의 매핑 금지 |
| 고스트 노트 | 해당 악기 위치, 스네어는 C5 | 일반 머리 양옆 괄호 | normal, parentheses="yes" | 미지원·아래 보고 |

`normal`, `x`, `circle-x`, `triangle`은 기존 시험에서 사용한 `notehead` 값이다. 이 표는 과거 실험 사실만 보존하며 어떤 행도 일반 도형 대체 방식을 사용할 수 있다는 허용 목록이 아니다.

- **오픈 하이햇:** 기존 PDF의 빈 타원 `normal filled="no"`를 재현하지 않는다. circle-x의 일반 도형 표시 성공만 확인되었으며 자동 채택하지 않는다. 대체 매핑으로 보고 후 명시적 사용자 결정이 있어야 적용할 수 있다. 악기 전용 공식 규칙의 근거는 아직 확인되지 않았다. 앞선 채택 표현을 정정하며, 근거 확인 없이 기존 곡을 변환하지 않는다. 빈 타원 재현을 필수 조건으로 삼지 않는 사용자 결정은 유지한다.
- **라이드 벨:** triangle은 OSMD의 일반 음표머리 도형이다. OSMD가 Ride Bell 전용 표준으로 지정하거나 악기 이름에서 자동 선택하는 모양이라는 뜻이 아니다. 첨부 범례에 맞춰 선택한 이전 결정을 철회한다. 일반 triangle 지원을 이용한 라이드 벨 매핑은 보고 후 사용자가 명시적으로 선택한 경우에만 사용한다. 현재 이 정책 변경으로 triangle 적용이 승인된 것은 아니다.
- **열기/닫기:** open-string/stopped의 표시 실험은 과거 기록이다. 이를 드럼 악기 ID와 결합하는 것만으로 전용 규칙이 되지 않으며 하이햇 대체 표기로 자동 사용하지 않는다. 보고 후 명시적 사용자 결정이 있을 때만 적용한다. 전용 규칙을 확인하면 그 규칙에 따라 실제 악보 위치에 기록한다.

## 쉼표

일반 도형으로 악기 기호를 대체하지 않는 원칙은 기본 악보 요소인 쉼표·음가·박자 또는 가사/메타데이터 자체를 금지한다는 뜻은 아니다. 아래는 기존 승인된 기본 악보 처리 규칙이다.

| 상황 | 저장/표시 규칙 |
|---|---|
| 전체 마디가 쉼 | `rest measure="yes"`를 사용하고 display-step/display-octave를 넣지 않는다. OSMD 기본 중앙 배치를 사용한다. |
| 다른 성부가 연주하는 마디의 쉼표 | 심벌=상단, 드럼=중단, 킥=하단 역할 높이를 유지한다. 전체 쉼 마디와 구분한다. |
| 일반 2분·점2분 등 부분 쉼표 | 음가와 시작 박 위치를 보존한다. 긴 쉼표라는 이유만으로 쉬는 구간 가운데로 옮기지 않는다. |

온마디쉼표 높이 미지정은 앱에 적용되어 있다. MusicXML이 높이를 금지해서가 아니라, OSMD 기본 중앙 배치를 사용하는 호환 정책이다.

## R/L 스티킹

- R=오른손, L=왼손. 명칭은 sticking이며 fingering(손가락 운지)으로 저장하지 않는다.
- `direction/direction-type/words`로 R/L이 표시된 것은 과거 실험 결과다. 전용 sticking 규칙이 아니므로 일반 텍스트 대체 방식으로 자동 사용하지 않는다. 보고 후 명시적 사용자 결정이 필요하다.
- 서로 다른 타격의 R/L을 한 음표에 쌓지 않는다. 성부와 대상 음표의 위치를 유지한다.
- **전용 sticking 규칙 미확인으로 보고한다.** words 표시 성공과 전용 지원을 구분하며 일반 텍스트 대체 방식은 보고 후 사용자가 명시적으로 선택한 경우에만 채택한다. 다른 소프트웨어가 텍스트를 손 지시 의미로 자동 인식한다고 보장하지 않는다.
- `other-technical` 문자열과 fingering 우회는 채택하지 않는다.

## 메타 정보와 가사

- 해당 곡의 MusicXML에 악보, 원제·표시제목·가수·작사·작곡 등의 메타 정보, 가사 리듬 성부를 모아 관리한다. 기존 프로젝트의 MusicXML 저장 계약을 유지한다.
- 가사는 드럼과 독립된 가사 리듬 성부의 음표에 `lyric/text`로 연결한다. 보컬 악보가 있으면 그 리듬을 사용하고, 없으면 음원으로 정한 마디·박·음가를 기록한다.
- 가사 위치 정본은 초 단위 타임스탬프가 아니라 악보 위치다. 음원과 악보의 재생 동기화 정보는 이와 별개다.
- 영어는 영어로 유지한다. 이 문서는 기존 가사 싱크나 메타데이터 필드 이름을 새로 변경하지 않는다.

## 현재 보고: 규칙 미확인과 렌더링 미지원

**고스트 노트의 음표머리 괄호**

- 필요한 표기: 해당 음표머리 양옆의 괄호.
- 표준 입력: `<notehead parentheses="yes">normal</notehead>`.
- 결과: OSMD 2.1.2 및 조사한 develop에서 괄호가 누락된다. VoiceGenerator가 해당 속성을 보존하지 않는다.
- 내부 `GhostNote` 클래스는 보이지 않는 리듬 공간용이며 드럼 고스트 주법 지원이 아니다.
- 일반 괄호 텍스트를 임의로 놓는 것은 음표머리에 연결된 괄호 지원으로 간주하지 않는다.
- 작은 음량과 괄호 표시는 별개이며, 괄호만으로 음량 재생을 보장하지 않는다.

**전용 규칙 미확인:** 라이드 벨을 포함한 위 악기별 도형/좌표 매핑 및 R/L 스티킹. 기존 실험은 일반 표시 기능을 검증했으며 악기별 공식 규칙의 근거는 확보하지 않았다. 이 상태를 “OSMD에 모두 없다”로 단정하지 않는다. 추가 조사에서 근거가 확인된 항목만 확정 매핑으로 승격한다.

filled=no와 other-technical의 기존 조사 결과는 이력에 보존한다. circle-x/words의 표시 성공을 근거로 전용 표기 미확인 상태를 해소했다고 보고하지 않는다.
