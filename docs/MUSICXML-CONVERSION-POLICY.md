## 선택 순서

1. 원본이 벡터 PDF인지, 스캔·사진 이미지인지 먼저 확인한다. 혼합 PDF는 페이지별로 확인한다.
2. 음표·선·좌표를 추출할 수 있는 깨끗한 벡터 PDF는 Codex가 구조 추출 코드를 사용해 직접 변환하고 원본과 대조·검증한다. 이미지 관찰만으로 음표를 추측해 작성하는 것을 뜻하지 않는다.
3. 스캔·사진은 Audiveris로 초벌한 뒤 Codex가 원본 대조·교정하는 경로를 먼저 시험한다. 이는 모든 이미지에서 우수하다는 보장이 아니다.
4. 새로운 악보 양식은 대표 2~3줄(복잡한 리듬·악기·박자 변화 포함)로 먼저 평가한 뒤 전체 변환 방식을 결정한다. 벡터 구조 추출이 불가능하거나 초벌 누락이 많으면 근거를 기록하고 방법을 재평가한다.
5. 기존 변환 코드는 특정 악보에 맞춰져 있으므로 다른 악보에 그대로 적용 가능하다고 가정하지 않는다.

## 보존과 검증

- 원본, 기존 결과, 교정 전 자동 인식 결과를 보존하고 새 결과를 별도 경로에 저장한다.
- 마디 수·박자·템포·음표 시작과 길이·다성부·악기 매핑·장식음·연음·반복을 원본과 대조하고 MusicXML 규격 검사와 재렌더링 검증을 수행한다.
- 악기·주법 표기에는 프로젝트의 `docs/SCORE-MUSICXML-OSMD-MAPPING.md`, SVG 출력에는 `docs/SVG-SCORE-RULES.md`를 적용한다. 이 선택 기준은 기존 매핑 결정을 변경하지 않는다.
- 미확정 매핑, 누락, 교정 내용과 남은 검증을 명시한다. 표본 F1을 전곡 정확도로 표현하지 않는다.

## 가사 기준 — 악보 우선

2026-10-03 최신 사용자 결정: **악보가 표준이다.** 가사 시작·길이는 원본 악보의 마디·박·음가와 인쇄 음절 대응을 기준으로 기록한다. 가수가 악보와 다르게 부른 시작·끝·길이는 악보 가사에 반영하지 않는다. 실제 가창 시각·길이의 별도 측정·기록, STT·강제 정렬·시간 가사 검색은 이 변환의 완료 조건이 아니다.

악보 판독상의 추정은 계속 구분한다. Loveholic의48/99/107/109마디4개 위치는 원본 평행 구절에 따른 추정이며, 가창 미검증과는 별개의 판독 근거다. 음원과 악보의 재생 연결 및 악보 위치에서 계산한 초 단위 재생 캐시는 유지한다. 이 캐시는 가수가 실제로 부른 시각·길이의 전사가 아니다. 과거 음원 실험은 이력으로 보존하며 미완료 과제로 다루지 않는다.

## 막혔을 때 확인 순서와 해결 기록

2026-10-03 사용자 확정. 실패가 발생하면 같은 추측이나 명령을 반복하기 전에 다음 순서로 확인한다.

1. **문서:** 현재 전역·프로젝트 지침, 이 정책, 확정 매핑, SVG 출력 규칙, 정본 XML 계약, 해당 곡 제작 기록과 [문제 해결 기록](MUSICXML-TROUBLESHOOTING.md)을 확인한다. 이미 확정된 내용을 사용자에게 다시 질문하지 않는다.
2. **과거 악보 제작 세션:** 같은 유형의 문제를 처리한 세션의 실제 명령·원인·교정·검증을 재검토한다. 이전 세션 `01a0b7de-deef-7572-8833-02cf6080ddb1`은 `MUSICXML-CONVERSION.md`, 통합 상태는 `MUSICXML-INTEGRATION.md`에서 먼저 찾는다. 다른 곡이나 양식의 전용 예외를 그대로 적용하지 않는다. 세션 기록이 접근되지 않으면 확인 가능한 제작 문서로 대조하고 접근 한계를 남긴다.
3. **웹:** 앞의 근거로 해결되지 않는 사항을 검색한다. 기술 문제는 MusicXML/W3C·OSMD·Audiveris 등 해당 기술의 공식 문서와 공식 저장소를 우선한다. 사용한 버전·URL·확인 날짜와 이번 입력에서의 적용 결과를 남긴다.

과거 세션과 웹 자료는 현재 사용자 결정과 정본을 덮어쓰지 않는다. 해결 후에는 구현뿐 아니라 기록까지 마친다. 다음 항목을 `MUSICXML-TROUBLESHOOTING.md` 또는 해당 곡 제작 문서에 남기고 `history.md`에 짧게 연결한다.

- 증상과 재현 조건: 입력 식별·환경·버전·실패한 명령/구간.
- 원인: 확인한 근거. 미확정 원인은 미확정으로 표시.
- 해결: 바꾼 코드·설정·명령·파일 경로와 보존한 원본.
- 검증: 실제 재실행·원본 대조·규격/재읽기·화면 증거 및 결과.
- 다음 적용 기준: 재사용 조건, 다시 하면 안 되는 처리, 남은 한계.

재시도로 성공했지만 원인이 확인되지 않은 경우에는 실행 회복과 원인 미확정을 구분한다. 렌더러 미지원·미확정 주법·추정 타이밍은 해결 완료로 포장하지 않는다.

## 문서 정리와 모순 해결

2026-10-03 사용자 확정. 문서가 헷갈리면 제목·구조·용어를 정리하고 현재 규칙, 과거 조사, 구현 상태, 미확정 사항을 구분한다.

문서가 모순되면 **history.md → 다른 관련 문서 → 과거 악보 제작 세션 → 웹 자료** 순서로 확인한다. 각 단계에서 근거와 날짜·버전·적용 범위를 대조하고, 수정 이유와 참조 경로를 문제 해결 기록 및 history.md에 남긴다. 이 순서는 근거 확인 순서다. 과거 history나 웹 자료로 현재 사용자 결정과 승인 규칙을 덮어쓰지 않는다.

내용을 확인할 수 없으면 상태를 미확정으로 표시한다. 같은 결정을 반복 질문하거나 과거 기록을 삭제해 모순을 숨기지 않는다. 현재 안내를 바로잡고 과거 기록에는 당시의 범위를 표시한다.

## 방식 선택의 과거 근거 — Real Paradis

「風と丘のバラード」 벡터 드럼 PDF에 Audiveris 5.11.0을 CLI로 적용한 결과 110마디를 출력했지만, 기존 7마디·92음표 표본의 시작+길이 F1은 50.68%였다. 기존 원본 대조를 거친 Codex 결과는100%, Claude 결과는41.08%였다. Audiveris에는 음표 및 박자·템포 정보 누락이 있었다.

위 Real Paradis 벡터 악보에서는 기존 Codex 결과를 유지했다. 순수 자동 인식끼리의 동등 조건 비교가 아니며 두 경로의 총 교정 시간도 실측하지 않았다. 새 곡의 방식은 이 문서의 선택 순서로 판단하고 이 결과를 모든 악보로 일반화하지 않는다.
