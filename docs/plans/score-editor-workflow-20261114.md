# 악보 제작 워크플로우에 맞춘 제작기 수정 계획

상태: **승인된 작업대·파일 저장·프로젝트 연결 경로 구현, 정적 검사 통과**(2026-11-14). 실제 사용자 자료 이관·화면·저장 왕복·제작자 송신 검증은 수행하지 않았다. 아래 기능 완료 조건은 실제 검증 때 별도로 판정한다.

단일 HTML 제작 화면 목업 `data/production/score-editor-workbench.html`은 파일을 직접 열어 확인한다. CSS·글꼴·악보 그림을 파일 안에 포함하며 서버나 별도 파일을 요구하지 않는다. 악보 목록은 목업 범위에서 제외한다. 이전 서버 의존 목업은 사용자 요청에 따라 삭제했다.

[공동작업 워크플로우](../how-to/collaborate-on-score.md)와 [제작 Rule](../reference/score/production.md#score-session-collaboration)을 현행 앱에 구현하는 기준이다. 화면 배치의 검토 결과는 단일 HTML 목업 `data/production/score-editor-workbench.html`에 반영했다. 기존 구현 상태와 저장 매체 비교는 [선행 계획](local-score-projects-20261113.md)에 보존한다.

## 목표와 범위

- 목표: **악보 하나 = 제작 프로젝트 하나 = 전용 폴더 하나**로 제작하며, 사용자·악보제작기·악보제작자가 같은 파일로 작업한다.
- 범위: PC 로컬 제작기의 프로젝트 열기·저장, PDF·MusicXML 검수, 가사 편집, 수정 이력, 제작자 알림·진행 확인, 제작 도구의 프로젝트 읽기·쓰기.
- 완료 조건: 직접 편집과 채팅 지시가 같은 프로젝트에 기록되고, 재열기·재제작 후에도 확정 교정이 유지된다. 사용자가 자료를 다시 첨부하거나 제작 결과를 다시 가져오지 않아도 된다.
- 제외: 실제 자료 이관·서버 재시작·악보 정본 교정, 공개 재생 앱의 저장소 전환, 원본 삭제, 자동 Git 작업·공개 배포. 이 문서의 승인 후 기존 제작기·공통 코드에서 구현했다.
- 검증: 구현 코드·검사 코드의 정적 검사와 문서 대조를 수행한다. 이번에 화면·회귀 실행을 추가하지 않으며 실제 저장·교정·제작자 연결은 아래 검증 단계로 남긴다. 목업 검토를 실제 앱 검증으로 대신하지 않는다.

## 1. 사용자가 작업하는 흐름

| 단계 | 사용자의 행동 | 제작기·제작자의 처리 |
| --- | --- | --- |
| 첫 제작 | 이 채팅에 곡과 원본을 알려준다. | 제작자가 곡별 폴더를 준비하고 악보를 제작·자체 검증한다. 검수본이 준비되면 제작기에서 해당 프로젝트를 연다. |
| 프로젝트 열기 | 목록에서 작업할 악보를 연다. | 그 폴더의 최신 저장본과 초안을 읽는다. 제목이 바뀌어도 같은 프로젝트를 이어간다. |
| 전체 검수 | PDF·MusicXML을 함께 보고 필요한 구간을 재생·정지한다. | 두 악보의 같은 마디를 보여준다. 가사 교정 중에도 검수 구간과 화면 위치를 유지한다. |
| 직접 교정 | 가사를 선택해 위치를 옮기고 저장한다. | 편집은 초안에, 저장 확정은 MusicXML과 변경 이력에 반영한다. |
| 채팅 교정 | 이 채팅에서 가사나 다른 오류의 수정을 지시한다. | 제작자가 같은 프로젝트를 읽어 수정·저장·검증한다. 사용자에게 앱 편집을 다시 요구하지 않는다. |
| 작업 요청·결과 확인 | 저장한 교정에 후속 작업이 필요하면 **악보제작자에게 요청**을 누른다. | 프로젝트 식별 정보만 알린다. 진행과 질문을 보여주고, 제작자가 저장한 결과를 같은 프로젝트에서 다시 읽는다. |
| 완성 | 수정 결과를 확인한다. | 제작자가 검증 범위와 남은 사항을 기록하고 완성본을 앱 담당에게 인계한다. 재생 앱 수록·발행 상태는 별도로 확인한다. |

일반 저장은 제작 요청이 아니다. 요청 버튼도 미확정 초안을 자동으로 확정하지 않는다. 새 제작을 위한 별도 접수 양식은 만들지 않는다.

## 2. 검수·가사 편집 개선안

### PC 작업대 배치

2026-11-14 사용자 지정: **PC의 키보드와 마우스 작업**을 기준으로 설계한다. 터치·태블릿용 조작으로 제작기를 설계하지 않는다.

- **상단바 → 악보 → 컨트롤바 → 작업대**의 기존 큰 틀을 유지한다. 기존 공통 UI·버튼·테마·편집 구성요소를 재사용하며, 별도의 화면 디자인으로 교체하지 않는다.
- 곡 제목·가수는 상단바에 둔다. 현재 마디·박·음원 시각은 **PDF · MusicXML 검수에서만** PDF 표기와 같은 높이의 악보 중앙에 표시한다. 상단바에 반복하지 않으며 한 줄·두 줄 보기에서는 숨긴다.
- 상단바의 제목·가수·템포·버전/빌드는 기존 공통 표시를 그대로 사용한다. `제목 - 가수`를 한 줄에 같은 서체로 표시하고, 그 아래 버전·빌드와 오른쪽의 테두리 있는 템포 표시를 유지한다. 목업 전용 글자 크기·배치를 덮어씌우지 않는다.
- 기존 **한 줄로 이어 보기 / 두줄로 고정 보기 / PDF · MusicXML 검수**를 모두 유지한다. 상단바에서 바로 선택하며, 전환할 때 선택 가사·편집 내용·되돌리기 이력을 보존한다.
- 작업대는 악보 아래에 항상 표시한다. 옆에 배치하거나 악보를 덮지 않으며 접기 버튼·접힘 상태를 만들지 않는다.
- 악보는 기존 공통 조판의 높이·배율을 유지한다. 남는 화면 높이에 맞춰 악보를 확대하지 않는다.
- 컨트롤바에는 검수용 재생·정지·마디 이동과 되돌리기·수정 이력·저장·제작자 요청을 배치한다. 작업대는 항상 표시하므로 가사 탭 선택 버튼은 제거한다. 프로젝트 폴더 열기는 저장 버튼 옆에 폴더 아이콘으로 둔다. 악보 편집 탭과 원본 영역 수정·마디 추가·삭제 영역은 제거한다.
- 작업대에 별도 상단 버튼줄을 만들지 않는다. 컨트롤바에서 고른 편집 내용만 아래 작업대에 표시한다.
- 제작 도구를 깊은 설정 메뉴 없이 컨트롤바에서 바로 선택할 수 있게 한다.
- 연습용 속도 조절·반복·카운트·메트로놈·마커 조작 등 제작에 불필요한 기능은 제작 화면에서 제거한다.
- 악보 목록에는 제작·교정 요청을 두지 않는다. 요청 종류·제목·내용·첨부를 다시 입력하는 구형 요청 모달을 폐기한다. 열린 프로젝트에 대한 요청 버튼은 제작 화면의 컨트롤바에 둔다.
- 가사 클릭·수평 드래그·방향키를 중심으로 만든다. 곡 정보 등 입력칸에서는 일반 키보드 조작을 유지한다.

### 설정을 없애고 필요한 항목을 직접 배치

제작기의 설정 버튼·창은 제거한다. 공통 컨트롤과 동작을 재사용해 아래 항목만 제작 화면에 둔다.

| 항목 | 배치·처리 |
| --- | --- |
| 보기 방법 | 상단바의 한 줄 / 두 줄 / PDF · MusicXML 검수. |
| 전체 악보 보기 | 상단바에서 PDF 전체 악보와 MusicXML 전체 악보를 연다. 별도의 PDF/MusicXML 악보 종류 선택은 없앤다. 한 줄·두 줄은 MusicXML로 고정하고 검수는 PDF와 MusicXML을 함께 표시한다. |
| 악보 크기 | 상단바의 공통 크기 조절과 현재 배율 표시. 기존 공통 네 마디 맞춤을 쓰는 두 줄 보기에서는 조절기를 비활성 100%로 표시하며 한 줄·비교 보기에서 조절한다. |
| 버전·빌드 | 상단바의 선택·복사 가능한 공통 버전 표시. 곡 정보와 구분한다. |

음량, 악보 제목 표시 순서, 음표 빛나기, 전체화면으로 악보 보기와 설정의 재생·악보·정보 섹션은 제거한다. 버전·빌드는 위 표처럼 밖에 남긴다. 곡 정보·섹션 편집·전체 악보 보기는 직접 배치한다. 후속 사용자 결정에 따라 원본 영역 수정·마디 추가/삭제와 악보 편집 탭은 제거한다.

제작기의 재생 설정은 모두 끈 상태로 고정한다. 숨긴 설정의 과거 저장값이 켜져 있어도 적용하지 않는다. 검수용 재생·정지는 유지하며, 드럼연습실의 설정·저장값에는 영향을 주지 않는다.

### 비교 화면 안에서 교정

- PDF·MusicXML 동시 비교를 작업의 중심에 둔다. 이 방식을 지원하는 화면 배치와 조작은 개선한다.
- 기존 `src/apps/editor/score-review.ts` 검수 모듈을 재사용한다. PDF와 MusicXML의 같은 마디는 같은 너비·좌우 경계를 사용하고 오선 높이를 맞춘다. 두 악보를 각각 줄 전체 그림으로 확대해 마디 경계가 어긋나게 만들지 않는다.
- 화면의 악보 구분명은 **PDF / MusicXML**로 표시한다. MusicXML의 화면 표시 방식인 SVG를 이름에 덧붙이지 않는다. 한 줄·두 줄 보기도 기존 공통 악보·설정 모듈을 재사용한다.
- 비교 화면에 **선택 마디의 가사 교정 영역**을 둔다. 가사를 고치려고 큰 편집창과 검수 화면을 반복해서 오가지 않게 한다.
- 악보 위 가사와 교정 영역의 항목을 같은 ID로 연결한다. 어느 쪽에서 선택해도 같은 가사를 강조한다.
- 별도 곡 정보 탭은 제거하되 곡 정보 항목은 가사 편집 아래에 제목 없이 배치한다. 선택 가사·마디/시작 박 입력·앞/뒤 버튼·격자 설명·순서 보존 설명으로 구성된 별도 위치 조정 영역은 제거한다. 가사 문구·시작 박은 가사 카드에서 확인하고, 이동 중에는 악보 위에 위치를 표시한다. MusicXML 저장과 병합·분리 복원에 필요한 음가는 내부 자료로 유지한다.
- 가사 작업대는 **현재 마디의 가사만** 표시한다. ‘가사 / 현재 마디 / 전체 가사’ 범위 선택 영역은 없애며 현재 마디·가사 개수·선택 상태만 표시한다.
- 별도 섹션 탭을 없애고 섹션 편집 구성요소만 가사 작업대에 배치한다. 곡 정보와 가사 편집은 유지하고, 별도 섹션 설명 영역은 제거한다.
- 수정 후에도 선택한 가사, 목록 위치, PDF·MusicXML 검수 구간과 정지 위치를 유지한다. 입력 중에는 재생 단축키가 개입하지 않게 한다.

### 위치를 고치는 조작

1. MusicXML 악보에 표시된 가사를 클릭해 선택한다. 아래 교정 영역에서도 같은 가사를 선택할 수 있다.
2. 컨트롤바에서 **8분·16분·32분·64분음표** 중 이동 격자를 고른다. 가사를 좌우로 드래그하거나 방향키로 옮기면 선택한 격자에 맞춘다.
3. 변경된 배치를 즉시 확인한다. 되돌리기·다시 실행은 같은 편집 이력을 사용한다.
4. 저장을 확정하면 변경 전후와 수정 시각을 남긴다.

**조작 격자와 정본 해상도를 구분한다.** 정본은 [64분음표 공통 기본 단위](../reference/score/production.md#score-production-rules--오선-부착-표기의-공통-기본단위)를 유지한다. 4/4에서 이동 간격은 각각 0.5·0.25·0.125·0.0625박이며, 다른 박자표는 공통 음악 좌표 함수로 계산한다. 격자 전환만으로 기존 위치·음가를 반올림하지 않으며 잇단음 등 예외 위치도 보존한다. 선택한 가사를 실제로 움직일 때만 해당 이동 격자를 적용한다.

드래그 중에는 격자와 이동할 박 위치를 보여준다. 한 번의 드래그는 한 번의 되돌리기로 복원하며 Esc로 진행 중인 이동을 취소한다. 실제 앱 구현은 SVG 픽셀만 옮기지 않고 MusicXML의 가사 시작 위치를 수정·저장한다. 단일 HTML 목업은 17~24마디의 조작과 배치만 시뮬레이션하며 실제 악보 파일은 변경하지 않는다.

선택 대상은 [정본의 최종 가사 묶음](../reference/score/musicxml.md#musicxml-canonical--최종-가사-묶음)이다. 위치 이동은 문구·길이를 유지한다. 다른 가사의 위치는 아래 순서 보존에 필요한 경우에만 바꾼다. 묶음 내부 가사를 편집할 때는 프로젝트의 제작 작업 자료를 사용한다.

### 가사 순서 보존과 최소 밀기

- 가사 ID의 원래 순서를 유지한다. 이동한 위치로 목록을 다시 정렬해 문장 순서를 바꾸지 않는다.
- 옮긴 가사가 뒤 가사의 시작점과 같거나 더 늦어지면, 그 뒤 가사를 **현재 선택한 격자의 바로 다음 칸**으로 옮긴다. 연속 충돌에만 같은 처리를 반복한다.
- 순서를 지키는 원래 위치는 그대로 둔다. 전체 뒤 가사를 같은 양만큼 옮기거나, 이미 유효한 세부 위치를 현재 격자에 다시 맞추지 않는다.
- 마디 끝을 넘는 밀기는 다음 마디까지 같은 규칙을 적용한다. 앞쪽으로 옮길 때는 앞 가사를 추월하지 않는 첫 격자 위치에서 멈추며 앞 가사를 자동으로 당기지 않는다. 곡 끝을 넘는 변경은 적용하지 않는다.
- 묶음 이동은 구성 가사의 상대 위치를 보존하고, 분리 후에도 그 가사들의 순서가 뒤바뀌지 않게 한다. 시작점 순서와 가사 길이 중첩은 구분한다. 길이 중첩만으로 가사를 밀지 않는다.
- 드래그 중에는 드래그 시작 상태에서 매번 다시 계산한다. 멀리 옮겼다가 돌아오면 더 이상 밀 필요가 없는 가사도 원래 위치로 돌아온다.
- 직접 이동과 연쇄 이동을 한 번의 편집으로 되돌리거나 취소한다. 저장 확정 이력에는 자동으로 밀린 항목까지 ID·변경 전후 위치를 함께 기록한다.

### 작업대에서 묶음 병합·분리

- 병합·분리는 **작업대에서만** 제공한다. 악보 위 드래그는 위치 교정에 사용한다.
- 클릭은 한 항목을 선택하고, 드래그는 범위에 들어온 항목들을 선택한다. Shift+클릭은 기준 항목부터 클릭한 항목까지 연속 선택한다. 선택 상태는 악보에서도 강조한다.
- **M:** 연속된 선택 항목들을 원래 순서대로 병합한다. 시작·ID는 첫 항목, 끝은 구성 항목의 가장 늦은 끝을 사용한다. 문구 결합은 기존 `lyric-groups.ts::joinLyricText`를 재사용한다. 떨어진 항목을 중간 가사 너머로 병합하지 않는다.
- **S:** 선택한 각 묶음을 보존된 구성 가사로 분리한다. 구성 ID·문구·상대 위치·길이를 복원하며, 묶음 이동 이후에는 이동된 시작점을 기준으로 한다. 문자열만 보고 원음절이나 위치를 만들어 내지 않는다. 구성 자료가 없는 항목은 분리 가능하다고 표시하지 않는다.
- 구성 자료는 프로젝트 작업 파일에 보존한다. 병합·분리·이동을 한 편집 이력에서 되돌리며, 저장 확정 때 구성 ID 대응과 전후 값을 기록한다. 정본에는 최종 묶음 계약에 따른 값만 쓴다.
- M·S는 가사 작업대에 포커스가 있을 때만 동작한다. 입력칸·한글 조합 중·다른 편집 탭·악보에 포커스가 있으면 병합·분리를 실행하지 않는다. ⌘M·⌘S 등 운영체제/브라우저 단축키도 가로채지 않는다.

## 3. 곡별 프로젝트와 저장

### 구현한 폴더 구성

저장 위치는 `data/production/projects/<곡 ID>/`다. 폴더는 안정된 ID로 식별하고 목록에는 제목·가수를 표시한다. 같은 악보의 교정·재제작 때 새 프로젝트를 만들지 않는다.

```text
data/production/projects/<곡 ID>/
  project.json                   프로젝트 정보와 최신 저장본 참조
  saves/<저장 ID>/
    record.json                  자산 참조·메타정보·교정 이력
    canonical.musicxml           해당 저장본의 음악 정본
  assets/                        원본 PDF·음원 등 보존 자산
  draft.json                     미확정 편집과 기준 저장본
  work.json                      진행·검수 지적·질문·답장·처리 결과
  work/                          판독·음절·곡별 설정 등 제작 작업 자료
  review/                        검증 보고서·검수 자료
  output/                        요청된 완성 산출물
```

세부 스키마와 충돌·초안 보존 규칙은 [파일 계약](../reference/score/file-formats.md#local-score-projects)에 기록했다. 곡마다 필요한 자료만 만들며 빈 결과물을 채우지 않는다. 공통 코드는 프로젝트 밖의 기존 공통 도구를 사용하고, 곡별 설정·판독 자료는 해당 곡 폴더에 둔다.

음악 데이터의 정본은 MusicXML이다. JSON은 프로젝트 관리·편집 초안·자산 참조·교정 이력을 맡는다. 앱 모델은 정본을 읽어 만들고 저장 후 정본과 대조한다. 서로 다른 음악 정본을 앱과 제작자가 따로 유지하지 않는다.

### 초안과 확정 저장

| 구분 | 처리 |
| --- | --- |
| 편집 중 | 화면은 메모리 상태로 즉시 반응한다. 입력이 잠시 멈추면 로컬 JSON 초안을 저장한다. PDF·음원을 매 입력마다 복제하지 않는다. |
| 저장 확정 | MusicXML·메타정보·교정 이력을 새 저장본으로 기록한 뒤 최신 저장본 참조를 갱신한다. 파일 쓰기가 끝난 뒤 저장 완료를 표시한다. |
| 변경 이력 | 가사 ID·문구·마디·음악적 시작/길이·확인 상태의 전후 값, 수정 시각, 변경 수행 경로와 기준/결과 저장본을 기록한다. |
| 재열기 | 폴더의 최신 저장본을 읽고 남은 초안을 구분한다. 초안은 확정 교정으로 취급하지 않는다. |
| 제작자 수정 후 | 새 저장본을 읽어 표시한다. 미확정 편집이 남아 있으면 이를 보존하고 새 저장본과의 차이를 확인한다. |

앱과 제작 CLI는 같은 저장 모듈을 사용한다. 쓰기 순서를 보장하고, 저장 직전에 읽었던 기준 저장본이 바뀌었는지 대조한다. 충돌 시 오래된 상태로 덮지 않고 해당 변경을 보존해 해결한다. 파일 하나의 실패 때문에 다른 프로젝트 작업을 중단하지 않는다.

로컬 JSON 초안을 사용한다. 사용자가 마지막으로 편집한 내용을 제작자도 파일로 확인할 수 있기 때문이다. 확정 저장은 별도 행동으로 유지한다. 매체 비교 근거는 [선행 검토](local-score-projects-20261113.md#임시-편집-저장-매체-검토)에 둔다.

현재 `data/production/`은 Git 추적 제외다. 이번 안의 변경 기록은 프로젝트 저장본과 교정 이력으로 남긴다. 소스 Git과 제작 자료의 저장 이력은 구분하며, 원본·음원·생성물을 자동 커밋하지 않는다.

## 4. 이 채팅과 작업 이어가기

- **악보제작자에게 요청** 버튼은 프로젝트 ID·폴더 경로를 알린다. 제목·대상 마디·변경 내용 입력과 원본 재첨부는 없앤다.
- 제작자는 폴더의 최신 저장본·초안·이력·진행 기록을 읽는다. 마지막으로 처리한 저장본과 대조해 필요한 작업을 이어간다. 초안을 읽었다는 이유로 확정 교정으로 승격하지 않는다.
- 진행 상태·해결한 지적·남은 판단·검증 결과는 프로젝트에 기록한다. 앱은 해당 프로젝트의 파일 변경을 받아 갱신하며 수동 새로고침도 제공한다.
- 필요한 질문은 앱에서 확인·답장하거나 이 채팅에서 답할 수 있게 한다. 같은 질문을 중복 처리하지 않고, 파일 복사·명령 실행·바이트 반환 같은 내부 작업을 사용자에게 요청하지 않는다.
- 제작자의 수정은 같은 프로젝트에 저장한다. 결과 다운로드·패키지 재가져오기·별도 결과 반입은 일반 교정 흐름에서 제거한다.
- 알림 접수, 제작자 작업 완료, 사용자 검수 완료는 구분한다. 알림 실패는 저장 실패로 취급하지 않으며, 이 채팅에서 같은 프로젝트를 지정해 이어갈 수 있다.
- 저장 뒤 별도 교정 자료를 전달하는 상태 표시는 프로젝트의 파일 저장 상태로 정리한다. 제작자에게 보낸 알림의 전송 상태는 요청 버튼에서 따로 보여준다.

기존 Session Bridge와 로컬 서버를 재사용한다. 프로젝트 알림을 담당 세션의 임의 변경이나 새 외부 작업 권한으로 확대하지 않는다. 구형 요청 파일과 [기존 요청 절차](../how-to/collaborate-on-score.md#legacy-production-requests)는 참조용으로 남긴다.

각 단계의 기능 완료 조건은 실제 검증 후에만 통과로 기록한다. 정적 검사만 끝난 단계는 구현·정적 확인 상태로 표시한다.

악보제작자가 워크플로우와 음악 데이터 계약·교정 재적용을 맡고, 기존 앱 개발 담당이 앱·서버·공통 저장 구현을 맡는다. 사용자는 목업을 검토하고 현행 제작기를 수정해 구현하도록 요청했다. 이미 작성된 타입·직렬화 초안과 다른 작업의 변경은 보존한다.

구현하면서 [제작기 화면](../reference/product/editor.md), [UX](../reference/product/ux.md), [파일 계약](../reference/score/file-formats.md)의 요청별 복사·반입·교정 자료 전달 동작을 새 흐름에 맞춘다. 변경된 저장 계약과 제작 CLI 사용법도 함께 기록한다. 구형 자료 확인 절차는 참조용으로 유지한다.

## 7. 기존 자료 전환과 검증

### 자료 전환

- 프로젝트 폴더가 없는 기존 악보를 처음 편집할 때 원본·정본·초안·가사 작업 자료·교정 이력·이전 저장본을 함께 전환한다. 완성 `.drumscore`만 복사해 제작 자료 전체를 대체하지 않는다.
- 파일을 다시 읽어 보존 여부를 확인한 뒤 그 곡의 편집 기준을 로컬 프로젝트로 전환한다. 기존 브라우저 자료는 삭제하지 않고 이관 여부를 구분한다.
- 한 곡 전환 실패 시 그 자료와 오류 근거를 보존한다. 다른 곡은 처리할 수 있게 한다. 실제 사용자 자료의 일괄 삭제·초기화는 하지 않는다.

### 검증 단계

계획 검토에는 문서 검사만 적용했다. 구현에서는 [검증 Rule](../reference/engineering/verification.md#verification-rules--변경-영향과-검사-선택)에 따라 관련 정적 검사와 문서 정합성을 확인한다.

실제 기능 검증은 사용자가 지정한 검증 단계 또는 릴리스 때 수행한다. 다음 항목을 완료 조건으로 사용한다.

1. 제작자 작성 → 앱 열기 → 사용자 직접 교정 → 저장 → 제작자 재제작 → 앱 재열기.
2. 채팅 가사 교정 → 같은 파일의 전후 이력 → 앱 갱신 → 재제작 후 교정 보존.
3. 초안과 확정본의 구분, 저장 실패 시 편집 보존, 제작자 수정 중 추가 사용자 저장의 충돌 처리.
4. 가사·정본·원본 PDF·음원·메타정보·기존 이력의 저장 왕복 대조. 자료 이관 실패와 재시도도 포함한다.
5. 실제 앱의 프로젝트 알림·진행·필요한 질문/답장·수정 결과 확인. 정상 작업에 시험 질문을 넣지 않는다.
6. 가사가 없는 악보, PDF가 없는 입력, 다른 박자표·잇단음의 해당 동작. 재생 앱은 제작 코드 유입과 저장 호환성의 영향만 확인한다.

검사 명령·환경·부수 효과는 [검사 카탈로그](../reference/engineering/check-catalog.md)를 따른다. 개발 중 화면 시험을 자동으로 추가하지 않는다. 실제 연결·전송, 사용자 자료 쓰기, 새 시험 자료가 필요한 검사는 실행 전에 기존 승인 범위와 대조한다. 이 계획의 검토를 공개 발행이나 기존 자료 삭제 승인으로 해석하지 않는다.

## 8. 확정된 구현 방향

사용자는 목업 검토 후 현행 제작기를 아래 방향으로 수정하도록 요청했다.

1. **저장:** 곡 ID별 폴더와 로컬 JSON 초안, 명시적 저장 확정, 저장본별 MusicXML·이력 보존.
2. **가사 교정:** PDF·MusicXML 비교를 유지한 채 가사를 클릭·드래그·방향키로 교정하고, 가사 편집 아래에 곡 정보를 표시한다.
3. **전환·연결:** 기존 악보를 처음 편집할 때 곡별로 파일 전환하고, 요청 버튼은 프로젝트만 알리며 결과는 같은 파일에서 갱신.

단일 HTML 목업은 배치·조작의 참고 자료다. 별도 앱을 만들지 않고 현행 제작기와 공통 모듈에서 구현한다. 단계별 완료 여부는 실제 코드와 검증 근거로 기록한다.
