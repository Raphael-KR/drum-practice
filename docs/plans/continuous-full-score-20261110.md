# SVG 전체 악보 연속 보기

- 목표: 원본 줄별 마디 구성을 유지하면서 종이 쪽 경계·번호·쪽 사이 여백을 없앤다.
- 범위: 두 앱의 공통 전체 보기 조판·표시와 현행 조판 규칙을 변경한다.
- 완료 조건: 인접한 줄의 표기 경계 사이 여백을 오선 두 칸으로 유지하고, 제목 아래 왼쪽 기본 BPM·오른쪽 가수를 같은 높이에 표시한다. 오선 시작 Y 간 거리는 각 줄의 표기 높이에 따라 달라진다.
- 제외: MusicXML 정본·수록 패키지·저장 데이터·연주 화면·PDF 전체 보기·버전·Git 게시·발행은 변경하지 않는다.
- 검증: 관련 코드·타입·서식·문서·링크·앵커와 공통 정적 검사만 한다. 실제 조판·화면 확인은 릴리스 검수에 남긴다.

## 구현

1. 가사 유무와 무관하게 `prepareFullScore`에서 같은 전용 조판을 사용한다. OSMD의 연속 세로 용지를 쓰며 XML `new-system`과 `new-page`의 줄 시작 의미를 유지한다. 쪽 나눔을 끄고 기본 1500px로 조판한다. 폭 부족으로 원본 줄이 나뉘면 native 최소 폭에 맞춰 한 번 넓혀 다시 조판한다.
2. native 가사·섹션·지시문·음표의 위/아래 경계 계산 후, 앞줄 하단에서 두 칸 아래에 다음 줄 상단을 놓고 반복한다. 같은 줄 내부의 표기 위치와 native 충돌 보호 여유는 유지한다. 전곡 최대 높이·기존 종이 여백은 계산에 넣지 않는다. 기호별·곡별 위치표나 반복 충돌 탐색을 추가하지 않는다.
3. 제목 아래의 공통 OSMD SVG 라벨에 왼쪽 `♩ = <Song.bpm>`, 오른쪽 `노래 - <Song.artist>`를 배치한다. 부제목의 `SheetSubtitleHeight`와 굵은 글씨를 사용한다. 연습 배속 BPM과 구분하며 글꼴·확대축소는 악보 SVG와 공유한다. 가수가 없으면 값을 만들지 않는다.
4. 전체 보기 전용 캐시 정책과 헤더 입력 키를 갱신한다. 연주용 캐시·조판은 유지한다. 두 앱은 쪽 캡션·figure 여백 없이 같은 연속 SVG 표면을 표시한다.
5. 각 줄 첫 마디 번호는 정본 XML의 번호를 OSMD로 출력한다. 1번·섹션 있는 줄도 포함하고 위치는 엔진 기본값을 따른다. HTML 번호 overlay를 제거하며 상세 계약은 [마디 번호 Rule](../reference/score/rendering.md#전체-보기의-마디-번호)을 따른다.

## 최초 구현·정적 확인 결과 — 2026-11-10

- 두 앱의 전체 보기 진입점과 공통 조판·캐시·표시를 연결했다. XML 원문을 수정하지 않고 전체 보기에서만 `Endless` 용지와 줄 시작 옵션을 사용한다. 공통 `full-score-layout.ts`에서 전체 시스템 경계를 계산한 후 Y 위치와 페이지 높이를 갱신한다.
- Node22.22.2·pnpm12.18.0의 `pnpm run check`를 통과했다. lint·478파일 서식·앱/도구/hosting 타입·의존성·i18n·공통 경계·153문서/링크/앵커를 확인했다. 마지막 하단 경계 보완 후 집중 lint·서식·앱 타입을 다시 확인했고 `git diff --check`도 통과했다.
- 원본 XML6개·수록 패키지6개의 SHA-256과 기존 ADR 이관 원문·history 기록을 보존했다. 버전은 두 앱0.11.0, 소스 빌드는 `fc459bf37076`이다. 근거는 `.tmp/full-score-continuous-20261110/`에 보존한다.
- 실제 조판 결과·화면·재생·저장/재열기는 아직 검증하지 않았다. 아래 릴리스 검수 항목은 구현 완료와 구분한다. 커밋·푸시·발행은 하지 않았다.

## 줄 사이 여백 정정 — 2026-11-11

- 사용자 캡처에서 표기 사이 빈 공간이 두 칸보다 크게 나타났다. 최초 구현이 전곡 최대 위/아래 돌출을 모든 줄에 적용해 다른 줄의 표기 높이까지 빈 공간으로 남기는 방식이었기 때문이다.
- 현재 구현은 native 표기 경계를 사용해 인접한 줄 사이 여백만 두 칸으로 맞춘다. 첫 줄도 제목·메타정보 아래에 같은 계산으로 배치하며, 시스템 전체 Y와 캔버스 높이만 갱신한다. 선명한 선을 위한 격자 올림은 0.1칸 미만이다.
- 전체 보기 전용 캐시를 `v6-adjacent-clearance`로 구분한다. 정본·수록 패키지·연주용 조판·두 앱 공통 경로는 유지한다. 이번 검증은 정적 검사이며, 사용자 캡처는 수정 전 상태의 근거다. 수정 후 화면 확인은 아직 수행하지 않았다. 결과는 [변경 기록](../../history.md#2026-11-11--svg-전체-보기의-줄-사이-여백-정정)에 남긴다.

## 릴리스 검수

- 수록 6곡의 원본 줄별 마디 묶음·마디 수와 연속 보기 결과를 대조한다. 이전 쪽 경계도 같은 줄 간격이어야 한다.
- 줄마다 오선 첫 선의 거리를 강제하지 않고, 가사·섹션·지시문·크레센도가 인접 줄과 겹치지 않으며 표기 경계 사이에 두 칸의 여유가 있는지 확인한다. native 보호 여유와 0.1칸 미만의 픽셀 격자 올림은 구분한다.
- 가사 없는 곡에도 `♩ = <기본 BPM>`·가수가 표시되고, 부제목 크기의 굵은 글씨로 제목 아래 같은 높이에서 좌우 정렬되는지 확인한다.
- 첫 줄의 1번·이후 줄·섹션 있는 줄에서 정본 XML의 첫 마디 번호가 하나씩 나오는지 확인한다. OSMD 기본 위치인 마디 시작점 위쪽에서 잘림·중복이 없고, 확대·축소할 때 악보와 함께 변해야 한다. HTML 번호가 남거나 내부 SVG 식별자가 보이면 실패다. 이전 캐시가 재사용되지 않는지도 확인한다.
- 창 닫기·재열기, 캐시 hit, 메타정보 변경 시 갱신, 두 앱의 동일 출력과 PDF/연주 화면 보존을 확인한다.
