# 음원 가져오기 안정화 (2026-10-13)

- 목표: 캐시 요청 지연으로 인한 불필요한 재분석을 줄이고, 실제 MP3의 곡명·가수와 BPM 추정을 개선한다.
- 범위: player의 캐시 클라이언트·분석 계약·곡 정보 추출·템포 추정 및 동일16개 음원 로컬 검증.
- 완료 조건: 지연/일시 오류 후 재조회·저장 회귀, 구형 캐시 배제,16개 이름 추출·가져오기·두 번째 캐시 사용 검증,94/136BPM 기준 및 합성음 테스트.
- 제외: 원본 업로드·편집, 공개 재배포·커밋·버전 상승, 불확실한 곡 정보를 외부 음악검색으로 전송, 실제 모바일 기기 보증.
- 검증: 집중 단위/통합 검사 → 동일16개 실제 브라우저 가져오기 → 전체 테스트·타입·빌드. 공개 런타임에는 발행 전까지 기존 코드가 남는다.

## 변경 방향
- 조회/저장의1.5초 제한을 분리해 늘리고 일시 오류에만 최대1회 재시도한다.404/잘못된 계약은 재시도하지 않는다. 저장은 재생을 막지 않고 작은JSON에keepalive를 사용한다.
- 태그를 우선하되 태그 안의‘가수 - 곡명’과 파일명의 명확한 구분자를 해석한다. 가사/영상 접미사를 정리하고 업로더가 가수로 들어간 경우 구조화된 제목과 파일명이 일치할 때 보정한다. 원본 파일명·경로는 전송하지 않으며 정리된 곡명·가수만 캐시에 담는다. 구조가 불명확한 파일명은 로컬 대체 제목으로만 유지한다.
- player 전용 템포 분석에서 여러 시간 구간의 주기를 합산하고 반/두배 후보를 비교한다. 검증 가능한 기준은 명시하고16개 모두의 음악적 정답을 안다고 가정하지 않는다.
- 분석기 버전과API 경로를2로 올려1의 오추정값을 읽지 않는다. 기존 행은 보존한다.

## 완료 결과
- 로컬 5173에서 같은 16개 첫 저장/두 번째 재사용 모두 성공, 시간 초과 0건. 곡명·가수 전부 자동 입력. 독립 HTTP 조회도 동일했다.
- 2초 조회 지연, 첫 조회 503, 첫 저장 연결 오류를 주입해 지연 허용·한 번 재시도를 검증했다. v1 캐시와 v2 분리도 검사했다.
- 기준 94BPM 음원의 추정값을 188에서 94.1로 개선했다. 나머지 추정값과 정확도 한계는 `docs/QA-AUDIO-CACHE-2026-10-13.md`의 수정 후 재검증에 기록했다.
- 전체 578개 및 최종 관련 34개 테스트, 타입/i18n/분리 빌드/앱 경계 검사 통과. 원본 보존·시험 목록 정리 완료. 공개 반영은 후속 발행 요청 시 수행한다.
