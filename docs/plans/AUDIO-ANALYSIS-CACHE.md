# 음원 해시 기반 분석 결과 재사용

- 목표: 동일 파일을 다시 가져오면 서버의 분석 결과를 재사용한다. 음원 바이트는 기기를 떠나지 않는다.
- 범위: 브라우저 SHA-256/조회·등록, 버전 있는 분석 계약, 서버 JSON API와 SQLite 저장. 개발 앱은 기존 5173 안에서 제공한다.
- 완료 조건: 첫 요청 저장·두 번째 요청 재사용, 서버 재시작 후 보존, 실패 시 로컬 분석, 음원/파형/개인 상태 미전송을 검사한다.
- 제외: 자동 발행·Git 작업, 로그인·기기 간 개인 설정 동기화, 음악 인식, 변속곡 분석, 수동 보정값 공용 게시.
- 검증: 계약/클라이언트/HTTP·DB 통합 회귀, 실제 5173 API, 타입·빌드·전체 드럼 테스트.

## 저장 계약
파일 전체 바이트 SHA-256 + 분석기 버전이 키다. 곡명/가수는 파일 태그만 저장하며 태그가 없으면 서버에는 빈 문자열을 저장한다. 기기 파일명은 전송하지 않고 화면에서만 대체 제목으로 쓴다. BPM, 첫 박, 박자표, 길이, 신뢰도를 저장한다. 파형·오디오·파일명·경로·사용자 ID·마커·반복·재생 설정은 저장하지 않는다.

서버는 자동 분석 결과만 받아 첫 값을 보존한다. 수동 보정은 기존 개인 Song에만 유지하며 공용 값을 덮어쓰지 않는다. 분석기 변경 시 버전을 올려 이전 자동값과 분리한다. 서버 결과도 형식·버전·해시·길이를 검증하고 불일치 시 로컬 분석한다. 낮은 신뢰도의 임시 120 BPM 기본값은 공용 캐시에 올리지 않는다.

조회 실패/시간 초과/404/잘못된 값은 로컬 분석으로 진행한다. 저장 실패가 연습을 막지 않는다. 자동 재시도 루프·음원 업로드 경로는 만들지 않는다. 재사용해도 기기에서 해시 계산·오디오 디코딩·파형 생성은 필요하다.

## 운영 경계
로컬은 Vite middleware + 프로젝트 내부 SQLite로 제공한다. 공개 운영은 같은 JSON API의 Worker/D1으로 전환하도록 발행 준비를 완료했다. 실제 활성화 결과는 history.md의 발행 기록으로 확인한다. 자동 게시 값은 클라이언트의 추정값이지 검수된 정답이 아니다.

### 실행 및 운영
- 개발: `npm run dev`, 기존 http://127.0.0.1:5173 안에서 `GET/PUT /api/audio-analysis/v1/<sha256>`를 제공한다. `node:sqlite`를 제공하는 Node 22.13 이상이 필요하다.
- 보관: `data/runtime/audio-analysis.sqlite`(Git 제외). SQLite WAL로 저장하며 개발 서버 종료 후에도 유지한다. 음원 Blob은 기존 브라우저 IndexedDB에만 있다.
- 제한: JSON 본문 최대 4 KiB, 허용된 11개 필드만 수신, 분석값 최대 10,000건. 기존 결과 덮어쓰기·삭제·전체 목록 API는 제공하지 않는다. 용량 초과 때도 기기 분석/연습은 계속된다.
- 공개: `server/audio-analysis-worker.ts`가 API와 ASSETS를 제공하고, `hosting/drizzle/`의 생성 SQL/journal이 Sites D1 마이그레이션 정본이다. `scripts/prepare-sites.mjs`가 public 범위를 유지하며 DB 바인딩, Worker 소스, player 자산을 배포 checkout에 준비한다. 해당 checkout에서 설치/빌드 후 Sites source helper로 패키징·발행한다. 로컬 DB는 공개 DB로 자동 복제하지 않는다.
- 공개 검토: 익명 클라이언트가 보낸 자동 추정값을 재사용하는 구조이며 서버가 음악적 정확도를 인증하지 않는다. 현재의 범위/크기 검증과 덮어쓰기 금지 외에 공개 트래픽 제한은 실제 호스팅 연결 시 점검한다.

### 검증 기록
- 실제 5173 브라우저 MP3: 첫 가져오기 GET404 → PUT200, 두 번째 GET200만 관측. 곡명/가수 태그 유지와 재생/정지 확인. 서버 DB의 저장 필드가 계약과 일치하고 원본/파형/파일명이 없음을 확인했다. 검증용 신규 2개 목록 항목과 해당 해시 캐시만 제거했다.
- SQLite 닫기/재열기 지속성, 잘못된 필드/버전/본문/외부 Origin 거부, 서버 장애 fallback, 길이 불일치 재분석, 불확실한 기본 BPM 미게시를 자동 검사했다.
- Safari MCP Transport closed로 ego-browser를 사용했다. iPhone/iPad Safari 실제 검증과 공개 서버 동작 검증은 수행하지 않았다.
- 전체106파일561개 통과 후 Worker/D1 어댑터 추가 검사를 포함한 집중3파일8개 통과. 최종 타입/i18n/분리 빌드/앱 경계 검사 통과. 로그: `.tmp/analysis-cache-all-final.log`, `.tmp/cache-final-focused.log`, `.tmp/cache-final-build.log`. public 사이트는 미발행.
