# 음원 박 추종 복구와 파형 스크롤 분리

- 목표: 기존 음원에서도 개별 박 시각을 확보하여 원곡 BPM 표시·메트로놈에 적용하고, 파형 스크롤로 정지 재생 위치가 바뀌지 않게 한다.
- 범위: 음원 열기·캐시 재사용·분석 실패 처리, 파형 전용 스크롤, 파일 선택 중 focus 갱신 방지, 관련 테스트·도움말.
- 완료 조건: 박 정보 없는 음원을 열면 분석 후 보존 저장, 추종 설정을 끈 기존 박 정보는 존중, 분석 실패를 숨기지 않음, 파형 스크롤·관성 이동 중 seek 0회, 파일 선택 후 focus/change 순서가 바뀌어도 선택 input 보존.
- 제외: 사용자 파일 수정·원본 음원 전송·기존 악보 제스처 변경·자동 커밋/발행. 실제 iPad 증상 원인 확정과 코드에서 재현된 경로를 구분한다.
- 검증: 가져오기/기존 레코드 보완/Worker 실패/스크롤 회귀 테스트, 로컬 브라우저 smoke, 전체 테스트·빌드. 원곡 모드에서 가변 박 시각의 표시와 예약을 확인한다.

## 확인 결과와 한계
- 개별 박 시각 없는 기존 음원/캐시를 재사용하고 Worker 오류를 삼키는 경로를 확인했다. 지원 길이의 기존 음원은 열 때 박 정보를 보완하고, 이미 저장한 박 정보와 추종 끄기 선택은 존중한다. 실패 시 기존 데이터는 보존하며 오류를 표시한다.
- 재분석 시 곡명·가수·마커·반복 구간·재생 위치를 유지한다. 연습 BPM은 기존 목표값을 유지하되 새 대표 BPM의 지원 배속 범위(0.5~1.2)를 적용한다.
- Safari 합성 가속 음원(24초)에서 45개 박 시각을 얻었다. 박 정보 없는111 BPM 레코드를 열어 보완 저장한 뒤 실제 재생 중 표시가107.1,108.6,109.6,111.1,112.7,114.3으로 변했다.
- Safari에서 파형 scrollLeft350→500→530 동안 position/current는3.2초를 유지했다. 합성 시험 레코드는 검증 후 제거했다.
- 공개 player-DHyvGvzG.js에도 파일 선택창 복귀 focus에서 목록을 다시 만드는 코드가 있음을 HTTP로 확인했다. focus→change 순서의 회귀 시험에서 input 교체를 재현했고 수정 후 보존됐다. 로컬 Safari에서도 같은 순서로 보존·오류 안내·버튼 재활성화를 확인했다.
- 사용자의 실제 iPad 기록/이벤트 순서는 읽지 않았다. 해당 기기에서111.0 고정 또는 DAY6 무응답의 원인이 이 경로인지, 실음원 중반 청감 박자 정합성은 아직 확정하지 않았다. 공개 사이트에는 아직 반영하지 않았다.
