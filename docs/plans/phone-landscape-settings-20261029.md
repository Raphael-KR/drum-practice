# 폰 가로 설정 최적화

상태: **구현 반영·0.10.1 로컬 릴리스 검증 완료**. 2026-10-28~29 사용자 요청과 보완안에 따라 두 앱의 공통 경로에 반영했다. 아래 검증 결과는 macOS Safari와 로컬 회귀검사 범위이며 iOS 실기기·청취 검증을 뜻하지 않는다.

- 목표: 폰 가로에서 연습에 필요한 설정에 직접 접근하고 화면·연습 BPM 카드를 스크롤 없이 조작한다.
- 범위: 두 앱의 공통 폰 가로 1줄·2줄 악보 화면에 있는 설정 메뉴·카드·유효 표시값. 기존 가로 방향·너비1023px 이하·높이480px 이하 조건을 재사용한다.
- 완료 조건: 네 메뉴에서 선택한 카드 하나만 표시하고 화면·연습 BPM 카드의 전체 조작이 현재 카드 공간 안에 들어간다. 폰 가로에서만 MusicXML·음표 빛나기 ON을 적용하며 기존 저장값을 보존한다.
- 제외 범위: 다른 화면의 설정 구성 변경, 악보·음원·저장 포맷 변경, PDF 전용 예외 경로 추가, 커밋·푸시·발행.
- 검증: 구현 중에는 정적 검사만 수행한다. 동작·회전·Safari 응답형 화면 검수는 릴리스 때 수행한다. 실기기·시뮬레이터는 별도 사용자 지시 범위다.

## 확정된 화면 구성

상단의 `설정 … 음량 / 슬라이더 / 퍼센트 … ×`와 공통 Liquid Glass를 유지한다. 음량은 본문과 독립적으로 항상 조작할 수 있게 한다.

| 왼쪽 메뉴            | 오른쪽 카드                                                               |
| -------------------- | ------------------------------------------------------------------------- |
| 화면                 | 한 줄로 이어 보기 / 두 줄로 고정 보기, 악보 크기 슬라이더, 균등 모드 토글 |
| 재생                 | 기존 재생 시작 방식, 카운트오프                                           |
| 메트로놈             | 기존 공통 `4분 / 8분 / 끄기` 알약형 선택                                  |
| 음표와 현재 BPM 숫자 | 연습 BPM 숫자 조절, 변환 상태, 3×3 프리셋, 원곡·악보 BPM 버튼             |

- 기존 악보·정보 메뉴와 해당 카드는 폰 가로에서 제외한다. 다른 화면에서는 기존 구성을 유지한다.
- 메트로놈 메뉴는 기존 악보 자리를, BPM 메뉴는 기존 정보 자리를 사용한다. 네 버튼의 폭·높이·간격·선택 표시를 공통 메뉴 CSS로 통일한다.
- 메트로놈은 기존 픽토그램과 이름을 표시한다. BPM 메뉴는 캡처처럼 `♩ = 현재 BPM`을 표시하며 접근 가능한 이름은 ‘연습 BPM’으로 유지한다.
- 두 메뉴는 해당 카드 선택 동작이다. 메트로놈 메뉴 자체가 모드를 순환시키거나 BPM 메뉴가 별도 모달을 열지 않는다.
- 선택한 카드 하나만 표시한다. 기존의 여러 카드 사이 스크롤 이동은 폰 가로에서 사용하지 않는다. 숨긴 카드의 입력이 키보드 초점을 받지 않게 한다.
- 회전으로 현재 메뉴가 표시 대상에서 제외되면 화면 카드를 선택한다. 다른 화면의 기존 메뉴·스크롤 탐색 방식은 유지한다.

## 화면 카드와 모드 한정 고정값

- 화면 카드에는 줄 보기·악보 크기·균등 모드만 남긴다.
- 곡명 먼저 / 가수이름 먼저, 전체화면으로 악보 보기, PDF 원본 / MusicXML 선택, 음표 빛나기 선택 항목을 폰 가로에서 숨긴다.
- 폰 가로에서 실제 표시 형식은 MusicXML, 음표 빛나기는 ON으로 적용한다. 설정창을 열었을 때만 적용하는 것이 아니라 해당 화면 모드 전체에 적용한다.
- **저장한 선호값과 현재 모드의 유효값을 구분한다.** 모드 진입·회전 때문에 저장값을 덮어쓰거나 별도 설정 저장을 하지 않는다. 폰 가로를 벗어나면 기존 선호값을 사용한다.
- 사용자가 명시한 프로젝트 전제에 따라 연주 악보의 필수 데이터는 MusicXML이고 PDF는 원본 보기용 부가 자료다. MusicXML 없는 PDF 전용 연주 악보를 위한 대체 표시 경로를 추가하지 않는다.
- 줄 보기·악보 크기·균등 모드를 사용자가 변경하는 기존 적용·저장 경로는 유지한다. 제목 표시 순서·브라우저 전체화면 선호값은 숨김만으로 변경하지 않는다.

## 메트로놈과 연습 BPM 카드

- 기존 재생 카드의 메트로놈 선택을 폰 가로에서 독립 카드로 옮긴다. 기존 설정값·이벤트·공통 알약형 CSS와 8분의 Warm 색상을 재사용한다. 메트로놈 음량100% 고정 정책은 유지한다.
- 연습 BPM 카드는 기존 모달의 입력부를 재사용한다. 숫자 조절·변환 상태·원곡/악보 BPM 버튼을 왼쪽에, 3×3 프리셋을 오른쪽에 배치한다.
- 현재 캡처의 마지막 설정 카드 크기를 기준으로 여백을 조정하고 터치 영역을 유지한다. 변환 상태 문구가 나타나도 버튼 배치가 밀리거나 카드가 넘치지 않게 한다.
- 기존 숫자 조절과 프리셋은 같은 처리 경로를 유지한다. 숫자가 먼저 바뀌고, 변환 뒤 실제 적용값과 BPM 표시가 갱신된다.
- 정수 올림 프리셋, 최저0.5배속 범위, 원곡·악보 BPM의 의미, 기존 변환 오류·진행률 처리를 유지한다.
- 모달 표시와 내용 준비만 분리한다. 같은 입력 요소·처리 함수를 카드와 기존 모달에서 재사용하며 중복 ID·이벤트·변환 경로를 만들지 않는다. 회전·재진입·설정 다시 열기에서도 이 계약을 유지한다.

## 구현 순서

1. 공통 설정 메뉴·카드 선택에 폰 가로의 네 메뉴와 단일 카드 표시를 반영한다. 화면에서 제외한 항목의 표시·키보드 접근을 함께 정리한다.
2. MusicXML·음표 빛나기의 모드별 유효값을 공통 표시 경로에 연결한다. 저장과 복원 경로에는 강제값을 쓰지 않는다.
3. 기존 메트로놈 입력부를 독립 카드로 배치하고 BPM 내용 준비를 모달 열기에서 분리해 공통 설정에 연결한다.
4. 기존 카드·메뉴·아이콘·Liquid Glass CSS로 화면과 BPM 카드가 한 화면에 들어오도록 배치한다.
5. [UX](../reference/product/ux.md)·[재생](../reference/product/playback.md)·[조판](../reference/score/rendering.md) 정본과 [기존 가로 모드 계획](landscape-score-only-20261028.md)의 달라진 부분을 구현과 함께 갱신한다. 현재 구현과 확정 계획을 혼동하지 않는다.

## 검증 기준

- 구현 시 `pnpm run check`와 diff 정적 검토를 수행하고 소스 빌드번호를 갱신한다.
- 릴리스에서 두 앱·1줄/2줄·폰 가로 경계 안팎을 확인한다. 특히667×375,852×393 크기에서 화면·BPM 카드의 전체 입력과 네 메뉴가 스크롤 없이 보이는지 확인한다.
- 메뉴를 누르면 카드 하나만 표시되는지, 선택 표시·닫기·초점 복귀·설정 재열기와 긴 누르기 도움말이 유지되는지 확인한다.
- 세로→가로→세로 전환에서 저장한 PDF 표시·음표 빛나기 선호값이 보존되고, 폰 가로의 실제 표시는 MusicXML·ON이 되는지 확인한다. 초기부터 가로인 경우와 설정창이 열린 상태의 회전도 포함한다.
- 메트로놈4분/8분/끄기와 BPM 숫자 조절·프리셋·원곡·악보 BPM, 변환 진행률·오류 표시·입력 중복·회전 중 변환을 확인한다. 재생 위치·기존 저장 데이터 보존도 확인한다.
- 검증 전에는 화면 적합성·동작 성공을 완료로 보고하지 않는다. 수행 결과는 [작업 기록](../../history.md)에 남긴다.

## 구현 결과 — 2026-10-29

- 공통 `playback-shell.ts`·`playback-forms.ts`에서 네 메뉴와 단일 카드 선택을 구성했다. `playback-settings-layout.ts`가 메트로놈 입력과 기존 BPM 모달 본문을 옮기고 회전 시 같은 DOM을 복원한다. 숨긴 카드의 입력과 제외한 화면 설정은 표시·초점 대상에서 제외한다.
- `playback-tempo.ts`에서 내용 준비와 모달 열기를 분리했다. 기존 입력·프리셋·원곡/악보 버튼과 변환 처리·오류/진행률을 재사용하고 프리셋은 소스 BPM이 달라질 때만 준비한다.
- 공통 화면이 유효 빛나기 값을 적용하고 두 호스트의 기존 자산 전환 경로에 폰 가로 표시 형식을 전달한다. 드럼연습실 저장 snapshot과 제작기 저장 record에는 저장 선호에 맞는 형식을 사용해 자동 저장으로 강제값이 섞이지 않게 했다.
- 기존 두 줄 보기는4마디 고정 폭이므로 악보 크기 적용은 기존 한 줄 범위를 유지한다. 폰 가로 두 줄 카드에는 현재 크기를 비활성 조절기로 표시하며 한 줄로 바꾸면 같은 값으로 조작한다. 오디오 파형 연습은 형식 강제 대상에서 제외한다.
- 기존 UI 회귀검사에 단일 카드, 모달 미개방, 세 번 전환 후 입력 DOM·값·ID·카테고리 복원을 추가했다. 실행은 릴리스 때 수행한다.
- 정적 검사: `pnpm run check` 전체와 `git diff --check` 통과(445파일 서식·186소스·150문서). 화면 크기·터치·음향·회전 중 변환·저장/재열기는 위 릴리스 검증 기준에 따라 확인한다. 앱 버전0.10.0 유지, 커밋·푸시·발행 없음.

## 릴리스 검증 — 2026-10-29

- 0.10.1 후보에서 `pnpm run verify` 전체 통과(131파일797테스트·두 앱 빌드 포함). 공통 설정의 반복 이동·복원과 저장/반복/메트로놈 회귀를 확인했다.
- macOS Safari 응답형667×375/852×393에서 화면·BPM 카드가 스크롤 없이 보이고,768×1024 복귀 시 기존 설정 구성이 돌아오는 것을 확인했다. 별도 Safari MCP에서 두 앱의 같은 크기를 실제 viewport로 측정하고 BPM 카드 clientHeight=scrollHeight와 중복 ID 없음을 확인했다.
- 두 앱 실제 Loveholic의 프리셋69/원곡 복귀·1줄/2줄·카운트오프/재생 진행/일시정지, 같은 BPM 입력 DOM 복원을 확인했다. 드럼연습실의 저장 PDF/OFF→가로 MusicXML/ON→세로 PDF/OFF 전환을 확인했다. 시험 전 선택은 복원했다.
- Safari MCP 창의 네이티브 연결 한계로 외형과 기능 검수 창을 분리했다. 음향 청취·실기기·시뮬레이터는 수행하지 않았다. 세부 실행 범위와 결과는 [작업 기록](../../history.md)의0.10.1 릴리스 검증을 따른다.
