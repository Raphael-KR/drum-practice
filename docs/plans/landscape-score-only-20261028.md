# 폰 가로 자동 악보 전용 모드

후속 구현: [폰 가로 설정 최적화](phone-landscape-settings-20261029.md). 선택 카드 하나 표시·메트로놈/BPM 카드·모드 한정 MusicXML·음표 빛나기를 반영했다. 정적 검사와 릴리스 화면 검수는 구분하며 아래 설정·표시 기준에 함께 적용한다.

- 목표: 폰용 화면을 가로로 돌리면 자동으로 악보 전용 모드로 전환하고 세로로 돌리면 원래 화면으로 돌아간다.
- 범위: 두 앱의 공통 재생 화면, 기존 수동 전환 설정·버튼 제거와 재생바·우상단 조작 버튼 배치, 폰 가로 도움말·설정 음량바.
- 완료 조건: 폰용 가로에서 악보가 준비되면 별도 설정 없이 악보 전용 모드를 적용하고 우상단에 설정·도움말 버튼을 표시한다. 한 줄에서는 기존 재생바 하나가 하단에 겹쳐 표시되며 오선 제3선의 중앙 정렬을 유지한다. 재생바는 좌우로 스크롤하지 않고, 폰 화면에서는 주변 마디 반복 묶음을 숨긴다. 세로·목록·태블릿/데스크톱용 화면에서는 기존 화면을 유지한다.
- 제외 범위: 브라우저 전체화면 API 변경, 원본 악보·저장 포맷 변경, 커밋·푸시·발행.
- 검증: 개발 중 정적 검사만 실행하고, 기능·회전·Safari 화면 검수는 릴리스에서 수행한다.

## 구현 기준

1. 기기 종류가 아니라 기존 폰용 가로 CSS 조건인 가로 방향·너비1023px 이하·높이480px 이하의 뷰포트로 적용 여부를 판단한다. 악보가 준비되면 자동 적용하며, 이미 가로인 상태에서 곡을 열어도 동일하게 적용한다. 초기 목록에는 적용하지 않는다.
2. ‘가로화면에서 악보영역만 보기’ 설정과 악보 우상단 확대·복귀 버튼을 제거한다. 버튼·설정의 명칭표·도움말·이벤트·CSS도 함께 제거한다. 과거 `drum-practice.landscape-score-only` 선호값은 읽거나 갱신하지 않으며 삭제 작업도 하지 않는다. 곡별 설정과 `.drumscore` 형식은 변경하지 않는다.
3. 세로 또는 폰용 가로 범위를 벗어나면 원래화면으로 돌아가고 이전 외부 스크롤 위치를 복구한다. 다시 폰용 가로가 되면 자동으로 적용한다. 우상단에 기존 설정·도움말(?) 버튼을 이 순서로 한 줄에 겹쳐 표시한다. 두 앱의 실제 버튼·이벤트·공통 버튼 CSS를 재사용하고 노치 안전 여백을 확보하며 악보 높이를 차감하지 않는다. 악보선택은 세로로 돌려 사용하고 메트로놈·연습 BPM은 가로 설정 카드에서 조작한다. 창 크기 변경과 회전은 기존 미디어 쿼리 변경 이벤트를 재사용하며 반복 검사나 기기 식별을 추가하지 않는다.
4. 브라우저 자체 전체화면과 독립적으로 동작한다. 회전으로 숨겨진 상단바·조작판에 초점이 있으면 악보 영역으로 초점을 돌려준다. 보이는 우상단·재생바 버튼의 초점과 긴 누르기 도움말은 유지한다. 설정을 닫을 때는 기존 공통 모달의 초점 복귀 경로를 사용해 설정 버튼으로 돌아간다.
5. 악보 자산·음표 크기·줄 보기·음원 위치·저장 반복 구간·카운트오프는 바꾸지 않는다. 활성 반복은 아래 폰 화면 정책에 따라 해제한다. 폰용 가로의 악보 전용 모드에서 한 줄은 오선 제3선을 화면의 세로 중앙에 맞춘다. 기존 오선 위치와 배율로 제3선의 표시 좌표를 구하며, 마디 번호·가사를 포함한 박스 중심으로 대신하지 않는다. 위쪽 표기 여백과 전체 악보 높이는 보존하고, 확대 시에는 외부 세로 스크롤 위치를 맞춰 위아래 내용에 접근할 수 있게 한다. 모드 진입·악보 재배치·화면 크기 변경 때만 중앙을 맞추며 수동 스크롤을 반복해서 되돌리지 않는다. 일반 화면·두 줄·검수 보기·오선 좌표가 없는 PDF와 음원 연습은 기존 정렬을 유지한다. 기존 너비 변경 재배치와 ResizeObserver를 재사용한다.
6. 한 줄 보기에서는 기존 `.playback-dock`의 `.transport`를 하단 고정 오버레이 한 줄로 표시한다. 마커·마디 위치·처음으로·재생/일시정지·되감기의 실제 DOM과 이벤트를 재사용한다. 별도 재생바나 복제 버튼을 만들지 않는다. 기존 버튼 규격·반응형 배치·표면 색·안전 영역을 사용한다. 가로 스크롤은 제공하지 않는다. 폰 화면에서는 주변 마디 반복 묶음(`.dock-repeat`)을 너비와 무관하게 숨긴다. 상단바는 우상단의 두 버튼만 표시하고 구간 조작판은 숨기며 두 줄·검수 보기에서는 재생바도 숨긴다. 오버레이는 악보 높이와 제3선 중앙 정렬에 공간을 차감하지 않으며, 보이는 재생바 버튼의 키보드 초점을 유지한다.
7. 1줄·2줄의 `(?)`는 공통 Liquid Glass 모달 하나로 악보 영역의 조작 방법만 안내한다. `×`는 원래 우상단 `(?)` 좌표에 두고 영역 테두리·영역명 오버레이·개별 버튼 설명·하단 안내·악보 기호 버튼을 생성하지 않는다. 탭 재생/정지·마디 선택은 공유하고, 비활성화된 구간 지정 설명을 제외한다. 1줄 좌우 드래그와 2줄 정지 후 상하 스크롤만 구분한다. 공통 닫기·확대/축소 전환·접근성 모달을 재사용하고, 닫기·폰 가로 이탈·화면 종료 때 유리 장식과 필터를 정리한다. 다른 화면의 도움말과 평소 긴 누르기는 유지한다.
8. 같은 모드의 설정 제목줄은 `설정 … 음량 / 가로 슬라이더 / 퍼센트 … ×` 순서로 배치한다. 기존 음량 패널 DOM을 메뉴 아래에서 제목과 닫기 사이로 옮기고 기존 가로형 CSS를 함께 사용한다. 입력·이벤트·저장 경로를 복제하지 않으며 모드 이탈 시 원래 위치로 돌린다. 설정 본문과 메뉴 스크롤에 관계없이 음량을 조작할 수 있어야 한다.
9. 음량 패널의 왼쪽은 아래 설정 카드와 같은 메뉴 폭·열 간격에 맞추고 오른쪽과 닫기 버튼의 간격은 유지한다.폰 가로의 메뉴는600px 이하에서도 왼쪽 세로 배치를 유지하고 음량·닫기를 제목줄에 둔다. 초기 초점은 공통 닫기 버튼에 두어 음량 슬라이더의 자동 포커스 테두리를 없애되 키보드 조작 시 초점 표시는 유지한다.

## 폰 화면 반복 구간 비활성화 — 2026-10-28 추가 결정

- 목표: 반복 구간 조작판이 없는 폰 화면에서 보이지 않는 반복 기능이 실행되지 않게 한다.
- 범위: 두 앱 공통 재생 화면의 구간 입력·반복 재생·표시·도움말. 세로 너비480px 이하 또는 가로 너비1023px 이하·높이480px 이하의 기존 반응형 기준을 사용한다.
- 완료 조건: 폰에서 더블탭/더블클릭·Enter·구간 버튼·주변 마디 반복을 비활성화하고, 저장 구간·활성 반복·선택 미리보기 표시를 숨긴다. 폰 진입 시 구간 지정은 취소하고 재생 위치를 유지하며 반복만 해제한다. PC·태블릿 크기로 돌아오면 저장 구간 표시와 조작을 제공하되 자동 재활성화하지 않는다.
- 제외 범위: 저장 `loops`·`repeatSlots`, 원본 악보, 마디 선택·탐색·마커·섹션 바로가기, 커밋·푸시·발행.
- 검증: 정적 검사만 실행한다. 기존 로컬 악보 fixture 기반 회귀 검사를 보완하고 실행 및 화면 검수는 릴리스 때 수행한다. 두 앱·1줄/2줄·초기 폰 진입·선택/반복 중 크기 변경·저장 데이터 보존·PC/태블릿 복귀를 확인한다.

## 릴리스 확인 항목

- 폰 가로 1줄·2줄의 도움말 본문이 설정 > 화면과 같은 불투명 카드 배경 위에 나오는지 확인한다. 배경 악보와의 겹침 없음, 긴 문구 스크롤, 제목·닫기 버튼 위치와 바깥 Glass 유지, 두 앱의 공통 테마 색 적용을 확인한다.
- 폰 가로 1줄·2줄의 도움말에서 악보 조작 설명과 우상단 공통 `×`만 나오는지 확인한다. `×` 위치·Glass 효과·Esc/초점 복귀·다시 열기·회전 후 정리, 다른 화면의 기존 도움말과 긴 누르기를 확인한다.
- 폰 가로 1줄·2줄의 설정에서 음량 패널이 제목줄에 보이고 본문/메뉴를 스크롤하지 않아도 조작 가능한지 확인한다. 카드와 왼쪽 정렬·오른쪽 위치 유지·열기/다시 열기 때 닫기 초점·슬라이더의 자동 테두리 없음·키보드 초점 표시를 확인한다.600px 경계 양쪽의 배치, 퍼센트·실제 음량·저장값·회전 전후 입력 DOM 동일성과 원래 배치를 확인한다.
- 폰 가로의 우상단 두 버튼은 [공통 Liquid Glass](liquid-glass-unification-20261028.md)를 각각 사용한다. 세로 복귀 시 기존 버튼 외형으로 돌아가며, 폰 세로 악보 제목 옆에는 공통 모듈의 버전·빌드가 표시되는지 확인한다. 긴 제목의 줄임표와 버전·빌드 복사도 확인한다.
- 두 앱의 세로→가로→세로 자동 전환, 가로에서 곡 열기·새로고침, 우상단 설정·도움말의 순서와 공통 버튼 외형. 가로의 악보선택 버튼 숨김과 키보드 접근 제외, 세로 복귀 후 악보선택 표시·목록 이동을 확인한다. 수동 설정·확대·복귀 버튼과 해당 도움말이 남지 않는지 확인한다.
- 폰용 가로 경계(1023×480px) 안팎의 자동 진입·해제, 다시 축소 시 자동 적용, 숨겨지는 조작 요소의 초점 이동. 태블릿/데스크톱용 화면에서는 기존 배치를 유지하며, 기기와 무관하게 창이 폰용 가로 크기가 되면 자동 적용한다. 과거 선호값의 켜짐/꺼짐/없음이 적용 여부에 영향을 주지 않는지도 확인한다.
- 한 줄·두 줄·음원 연습과 제작기 검수 보기, 가로 화면의 안전 영역, 가로 설정의 BPM과 세로 복귀 후 상단 BPM 접근. PDF 선호가 있어도 폰 가로에서는 MusicXML이 표시되고 복귀 시 선호가 보존되는지 확인한다.
- 폰용 가로 악보 전용 모드의 한 줄에서 MusicXML의 제3선이 화면 세로 중앙에 있는지 확인한다. 마디 표제·가사·변박·균등 간격·배율50~300%·브라우저 도구막대 높이 변경을 포함한다. 큰 악보의 상하 스크롤 접근, 수동 스크롤 유지, 일반 화면 복귀 후 기존 정렬도 확인한다.
- 재생·일시정지·반복 중 전환, 긴 누르기 도움말, 설정 모달 닫기와 키보드 초점.
- 하단 오버레이의 모든 기존 재생바 기능, 단일 DOM/이벤트 유지, 가로 스크롤 없음·안전 영역·긴 누르기 도움말·키보드 접근, 한 줄/두 줄·일반 화면 전환 시 표시와 기존 배치 복귀. 폰 가로900px 경계 안팎 모두 주변 마디 반복 묶음이 숨겨지고 한 줄 배치가 유지되는지 확인한다. 오선 중앙이 재생바 높이만큼 위로 이동하지 않는지도 확인한다.
- 전체화면 API 미지원 Safari와 지원 환경에서 브라우저 전체화면 설정과의 독립성.

자동 전환으로 제거한 우상단 버튼의 유리 효과는 더 이상 생성하지 않는다. 다른 표면의 공통 유리 효과는 [통일 계획](liquid-glass-unification-20261028.md)에 따라 유지한다.
