# 재생 UI 공통화

목표: 웹앱과 오프라인 HTML의 공통 화면 구성·스타일을 한 번만 정의한다. 공통 재생 상태·이벤트까지 단일 화면이 소유하고, 파일 로딩·저장·편집·관리 등 실제 환경 연결만 각 진입점에 둔다.

- 공통 아이콘, 마디 렌더링, 재생바 배치, 반복 프리셋을 순수 UI 모듈로 추출한다.
- 재생 UI CSS를 공통 파일로 추출하고 두 빌드에서 사용한다. 편집·관리 CSS는 HTML 번들에 넣지 않는다.
- 기존 DOM ID와 이벤트 연결은 어댑터로 유지하며 공통 컴포넌트의 스타일은 의미 있는 클래스로 지정한다.
- 검증: 타입 검사, 관련 테스트, 관리 코드 제외 번들 감사, Safari에서 마디·마커·재생바 및 반응형 화면 확인.
- 사용자 지정: 곡 데이터가 포함된 HTML 재생 파일은 내보내거나 저장하지 않는다. 공개 배포·커밋은 이 작업에 포함하지 않는다.

## 이전 단계 구현 결과 (아래 최신 구조로 확장됨)

- `src/playback-ui.ts`: 재생바·반복 프리셋·악보 영역·현재 박 표시의 공통 구성. 기존 DOM 노드를 이동해 이벤트와 입력 상태를 보존한다. 호스트별 ID는 bindings로 전달한다.
- `src/playback-measure.ts`: 마디 이미지, 가사, 마커, 하이라이트, 크롭의 공통 렌더러. 원본 데이터 조회와 가사 매핑은 호스트가 담당한다.
- `src/playback-base.css`: 공통 글꼴·색상·입력·버튼·상단바.
- `src/playback-ui.css`: 악보, 재생바, 반응형 배치, 설정창 외곽·탐색, 템포, 마커와 하이라이트의 공통 스타일.
- `src/icon-svg.ts` / `src/marker-icon.ts`: 공통 재생 아이콘. 편집·파일 관리 전용 아이콘은 `icons.ts`에 유지한다.
- `style.css`는 웹앱의 홈·악보 목록·편집·관리 등 전용 스타일, `portable-player.css`는 단일 파일 환경의 상태 안내·설정 내용·스위치 등 호스트 차이만 담당한다.
- 웹앱은 공통 CSS를 import하고, HTML 빌더는 동일한 CSS 원문과 공통 TS 모듈을 번들에 넣는다. 재생 화면을 복사하여 따로 수정하지 않는다.
- `main.ts`와 `portable-player.ts`는 데이터 로딩·저장·이벤트 연결 진입점으로 유지한다. 웹앱 전체를 HTML에 넣고 관리 기능을 숨기는 구조가 아니다.
- 향후 공통 화면 변경은 위 공통 파일에 구현한다. 호스트 전용 CSS에 공통 선택자를 재정의하지 않는다.

## 검증 기록

- 전체 60개 테스트 파일/255개 테스트 통과 후, Footer 순서 보존 회귀 테스트 추가 및 관련 재검증.
- 빌드·타입 검사·i18n 검사 통과. 번들 감사에서 공통 모듈 포함 및 편집·스토리지·소스 렌더러/관리 CSS 제외 확인.
- Safari: 웹앱 및 메모리에서만 제공한 HTML 런타임 화면, 1024px/744px 폭, 마커, 한 줄·두 줄 보기, HTML 재생·정지 확인. 744px의 document scrollWidth=744.
- 최초 스크립트 클릭으로는 오디오 재생을 검증할 수 없었으나 새 세션의 Safari 클릭 도구에서 일시정지 상태와 마디 진행을 확인했다.
- 웹앱 Footer 위치 이동 회귀를 스크린샷에서 발견해 수정하고 테스트에 기록했다.
- iPad 실기기 검증은 수행하지 않았다. HTML 재생 파일 저장·새 내보내기·공개 배포는 수행하지 않았다. 기존 내보낸 파일과 사용자 데이터는 유지했다.

## 2026-09-23: 공통 동작 및 앱 내부 중복 통합

앞선 단계는 UI 구조·스타일 추출이었으며 재생 제어와 레이아웃 정책에는 중복이 남아 있었다. 이번 단계는 다음 소유권으로 확대한다.

- `playback-layout.ts`: 두 줄 재생/정지 배치, 정지 중 스크롤 위치 보존, 가사 충돌과 기준선, 마디 너비·연속 위치·engraving 크기 계산. 두 호스트가 동일 함수를 호출한다.
- `playback-actions.ts`: 악보 제스처 연결, 드래그 시작/완료/취소, 반복 구간 검증·전환, 키보드 입력, 휠 단위 변환. 취소 시 시간·반복 범위·중심/반경을 함께 복원한다. 모달이 열린 동안 악보 탐색을 막고 길게 누른 Space는 무시한다.
- `dialog-ui.ts`: 제목·닫기 버튼 생성과 동적 모달 생성, 바깥 클릭 닫기. 안쪽에서 시작한 드래그가 밖에서 끝나도 닫히지 않는다. 편집/목록/설정/교체/HTML 모달이 공통 헤더를 사용한다.
- `score-assets.ts`: 가사·MusicXML·PDF·음원 보유 상태 판정. 가사는 편집 데이터와 canonical XML을 함께 확인한다. 목록의 열기 버튼과 상태 칩은 목적이 달라 별도 표현을 유지한다.
- 호스트에는 원본 자료 조회, 웹앱 편집·저장·비교 보기, HTML 파일 읽기·전체화면 진입 같은 환경 차이와 상태 연결을 유지한다. 공통 동작을 호스트에 다시 복사하지 않는다.

검증: 타입·빌드·전체 드럼 테스트, 공통 모듈 번들 포함/관리 모듈 제외 감사. HTML 파일은 내보내지 않고 기존 곡 데이터를 로컬 HTTP 응답의 메모리에서만 결합하여 확인한다.

이번 단계 검증 결과: 61개 테스트 파일/263개 테스트, 빌드·타입·i18n 및 번들 감사 통과. Safari 웹앱/HTML에서 110마디·폭 1024px 확인. HTML 두 줄 정지 28행 확인. 웹앱은 visibilityState=hidden으로 프레임 갱신 검증이 제한됨. HTML 설정 모달 확인. 오디오 출력은 Safari의 `Failed to start the audio device` 때문에 미검증이며 테스트 통과로 대체하지 않는다. 실제 iPad 검증·공개 배포·HTML 파일 저장은 수행하지 않았다.

## 2026-09-23: 재검토에서 확인한 여섯 항목 통합

- `playback-frame.ts`: 트랙 생성·높이 계산, native 스크롤의 시간 역산, 매 프레임의 진행·강조·반복 시작/끝 표시를 공유한다. 각 호스트는 상태와 비교 보기 콜백만 전달한다. 트랙 배열은 교체하지 않고 내용을 갱신하여 스크롤 리스너의 참조를 보존한다.
- `playback-actions.ts`의 `seekPlaybackFreely`: 스크롤·마커·탐색 시 반복 범위를 벗어나면 같은 조건으로 해제한다. 호스트는 최근 반복·중심 상태 갱신만 담당한다.
- `repeat-ui.ts`: 프리셋, 필드 채우기, 마디·박의 시간 변환, 반복 프리셋 표시를 공유한다. HTML 조정 창도 세부 종료 박을 복원하며 마디 끝으로 바꾸지 않는다.
- `marker-ui.ts`: 최근 마커 슬롯 마크업·접근성 이름·클릭 탐색·악보 배지 갱신을 공유한다. 웹앱의 이름 수정/삭제 관리 목록만 별도이다.
- `settings-ui.ts`: 제목·설명·체크 상태·disabled·접근성 연결을 가진 스위치 마크업. 스타일은 `playback-ui.css`로 이동했으며 HTML 전용 checkbox 스타일을 제거했다.
- 호출부 검사: 두 진입점의 이진 탐색, 반복 경계 class 갱신 등 중복 본문 제거 확인. 소스 회귀 검사와 런타임 로직 검사를 함께 추가했다. 전체 프로젝트의 모든 유사 코드를 제거했다고 일반화하지 않는다.

검증: 드럼 앱 62개 파일/271개 테스트, 빌드·타입·i18n 검사 통과. HTML 번들에서 새 공통 모듈 포함과 관리/스토리지 제외 확인. 사용자 요청대로 곡 포함 HTML 저장·배포 없음.

Safari DOM 확인 중 기존 `.setting` 선택자 참조를 발견해 수정하고 271개 테스트로 재검증했다. 양쪽 110마디 로드, HTML 설정 모달 및 스위치 확인. Safari가 hidden 상태이고 캡처가 흰색으로 반환되어 최종 시각 프레임 검증은 미완료로 구분한다. iPad·실제 오디오 검증을 통과했다고 주장하지 않는다.

## 최신 구조: 단일 재생 화면 소유자 (2026-09-23)

`createPlaybackScreen(PlaybackScreenHost)`가 화면 렌더링·프레임·스크롤/드래그·재생·템포·음량·반복·마커·설정 입력과 수명주기를 한 곳에서 정의한다. `main.ts`와 `portable-player.ts`는 각각 한 번 mount하며 데이터/Player/자산 및 저장·편집 확장 훅만 연결한다. `playback-forms.ts`는 양쪽 폼·설정 탐색·제목·반복바의 공통 마크업이다.

새 재생 기능은 화면 컨트롤러와 공통 폼/CSS에 구현하고, 호스트에 별도 동작을 추가하지 않는다. 편집·비교·영구 저장 및 내장 파일 decode 차이만 계약을 확장한다. 단일 거대 함수로 합치는 대신 기존 렌더/제스처/반복 모듈은 화면 소유자 아래에서 재사용한다.

전체 기능·이전 호출부·통합 후 소유자·검증·제한은 [PLAYBACK-SCREEN-INVENTORY.md](./PLAYBACK-SCREEN-INVENTORY.md)를 기준으로 한다. `check:playback`을 빌드 필수 단계에 포함했다. 이전 날짜/단계의 Safari 기록은 이번 검증 결과가 아니다. 이번 시각 확인은 로컬 Chromium이며 실제 iPad 확인과 HTML 파일 저장은 수행하지 않았다.

## 2026-10-02 조립·자산·유틸리티 단일 소유권

`playback-shell.ts`가 두 진입점의 공통 화면을 조립하고 `playback-assets.ts`가 자산 준비/교체/해제를 담당한다. `icon-button.ts`, `dialog-ui.ts`, `download.ts`, `binary-asset.ts`를 공통 호출한다. 환경별 authoring 슬롯과 저장·입력 검증만 주입한다. 전체 재검수 및 남긴 예외는 `COMMON-COMPONENTS-FINAL-PASS.md`에 기록했다.
