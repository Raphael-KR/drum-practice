# 같은 드럼 보표 가사 성부의 정본 채택

## 1차 구현 — 공통 저장·표시 경로

- 목표: 사용자가 채택한 같은 드럼 파트·보표의 독립 가사 성부를 새 저장 기준으로 적용한다.
- 범위: 공통 정본 읽기·쓰기, SVG 전체 보기, 제작 인계 메타데이터 조회와 현행 문서.
- 완료 조건: 드럼 리듬·독립 가사 시각·겹침·마디 연장·마디 문구·ID·음원 연결을 유지하며 재저장해도 중복되지 않는다.
- 당시 제외 범위: 기존 원본·수록 패키지·사용자 DB의 일괄 변환, 연주 화면의 가사 출력 방식 변경, 커밋·푸시·발행. 원본·수록 패키지 전환은 아래 후속 요청에서 별도로 승인되었다.
- 검증: 갑자기 실자료의 기존 시험 결과와 이번 정적 검사 결과를 구분한다. 후속 선택에 따라 추가 실행 검사는 하지 않는다.

### 적용 경계

새 저장은 `drum-practice:score:v2`로 구분한다. 기존 v1은 계속 읽고 저장할 때 공통 작성기로 전환한다. SVG 전체 보기에서 기존 자료를 표시할 때는 같은 가사 성부 작성 모듈을 읽기용 사본에 적용한다. 실제 파일과 DB는 자동 저장하지 않는다.

가사 음표는 숨기되 가사는 표시하며 음원은 추가하지 않는다. 순서대로 이어지는 가사는 성부를 재사용하고 겹치는 구간만 성부를 나눈다. 음절 ID는 성부 번호와 분리한다. 원래 드럼 음표로 가사를 스냅하거나 보컬 음높이를 추정하지 않는다.

### 구현과 검증 상태

- 공통 writer는 v2 성부·note ID를 기록하고 reader는 v1·v2를 구분한다. 새 가사 블록만 교체하며 드럼과 가져온 보컬 원문을 유지한다. 음원/PDF만 있는 기존 자료는 가사 전용 XML을 유지한다.
- SVG 전체 보기는 새 정본을 직접 사용하고, 구형 자료는 공통 성부 작성기를 읽기용 사본에 적용한다. 연주용 조판에서는 소유 가사 리듬을 제외하여 음표 기준점·간격을 유지한다.
- 기존 갑자기 실제 수록본만 사용한 집중 검사 3개와 별도 XSD·유리수 시간축 대조를 통과했다. 93마디·드럼 음표/쉼표 1,047개·301음절·7마디 문구·음원 연결·음절 ID가 동일하며 반복 저장이 같은 XML을 만든다. 새 성부는 voice2 하나다.
- 근거: `.tmp/shared-staff-adoption-20261110/candidate.musicxml`, `semantic-verification.json`. 원본 수록 패키지 SHA-256은 `d3a64dcf9512cf849801acc9535f7f748ba0cd29f247d36611d7d438738c3323`으로 시험 전과 같다.
- CLI의 첫 Vite SSR 준비가 HMR 소켓을 열려다 환경의 `EPERM`으로 거부되었다. 파일 변환·대조는 완료했고 SSR 서버는 종료했다. 후속 CLI는 WebSocket/HMR을 끄고 기존 5173 서버와 분리한다.
- Node22.22.2·pnpm12.18.0에서 `pnpm run check`를 통과했다. lint·477파일 서식·앱/도구/hosting 타입·의존성·i18n·공통 경계·151문서/링크/앵커를 확인했다. 정적 검사 로그는 `static-check.log`, 앞선 실자료 검사 결과는 `real-tests.json`에 구분해 남겼다.
- 최종 정적 검토에서 MusicXML이 허용하는 양의 소수 divisions를 새 작성기가 거부하지 않도록 공통 단위 환산을 보완했다. 해당 보완은 lint·서식·앱 타입 검사만 확인했으며 앞선 갑자기 실행 결과를 이 분기의 실행 근거로 사용하지 않는다.
- 사용자는 후속 시험 범위를 **정적 검사만**으로 선택했다. 이에 따라 동시 음절·마디 연장·fake-indexeddb 등의 추가 실행은 보류한다. 새 운영 구현의 화면·청취·전곡·릴리스 검증은 이번 결과에 포함하지 않는다. 앱 버전은0.11.0이며 커밋·푸시·발행은 하지 않는다.

## 후속 작업 — 현행 악보 전체와 두 앱 반영

- 목표: 사용자가 승인한 새 저장 규칙을 현행 악보 정본 전체와 두 웹앱의 수록 자료에 적용한다.
- 범위: 악보제작자가 최신 제작 정본을 식별·변환하고, 웹앱 개발 담당이 수록 패키지와 공통 앱 경로에 반영한다.
- 완료 조건: 인계 파일과 앱 패키지의 XML이 일치하고, 드럼·가사·마디 문구·음원 연결·곡 식별자와 사용자 편집값을 보존한다. 가사 없는 곡은 빈 가사 성부를 만들지 않는다.
- 제외 범위: 과거 후보·실험·검증 기록의 재작성, 음원/PDF 원본 변경, 브라우저 DB의 일괄 덮어쓰기, 화면·재생 시험, 커밋·푸시·발행.
- 검증: 정본의 XSD·음악 의미 정적 대조, 패키지 내용과 자산 해시 비교, 두 앱 공통 경로·타입·lint·문서/링크/앵커 검사. 실행·청취 검증과 구분한다.

악보 정본 전환은 기존 악보제작자(`01a0fd08-ba73-7482-b10e-40e637a1efc0`)에게 전달했다. 제작자는 제작 자료·곡별 기록을, 이 개발 채팅은 앱 코드·수록 패키지·공통 문서·history.md를 담당한다. 인계 접수와 실제 반영 결과는 구분해 기록한다.

### 인계와 앱 반영

- 제작자가 현행 6곡의 새 정본을 인계했다. 가사 3곡은 독립 성부로 옮겼고, 가사 없는 3곡은 빈 가사 파트만 제거했다. 정적 대조 대상은 총587마디·1,085가사 ID·1,131가사 구간·마디 문구7개다. 원시 입력과 과거 후보는 보존한다. [정본 경로·해시·제작 검증](../records/archive/shared-staff-score-migration-20261110.md).
- 개발 담당은 인계 해시를 직접 대조한 뒤 `public/scores/`의 6패키지에서 `manifest.canonicalXML`과 XML 원본 자산만 바꾸고 해당 자산의 바이트 크기를 갱신했다. 두 XML은 정본과 바이트까지 동일하다. 나머지41자산과 `Song`·음원·PDF·페이지·악보 변형·기타 manifest 필드를 보존했다.
- 두 앱은 같은 카탈로그·패키지 입력과 공통 `prepareFullScore` 경로를 사용한다. 제작기는 공통 v1/v2 reader·v2 writer를, 연습 화면은 가사 성부를 제외한 기존 드럼 조판·HTML 가사 경로를 유지한다. 전체 SVG는 새 정본의 OSMD 가사를 출력한다. 이번 수록 반영을 위해 곡별 코드나 별도 가사 변환을 추가하지 않았다.
- 구형 사용자 파일은 읽기 호환을 유지하고 다음 명시적 저장 때 공통 writer를 적용한다. 사용자 브라우저 저장본·연습 정보를 일괄 갱신하지 않는다. 가사가 없는 원시 `public/demo/score.musicxml`과 기존 PDF 연결은 변경 대상이 아니다.
- 패키지 변경 전 복사·해시와 변경 후 정적 대조는 `.tmp/shared-staff-packages-20261110/`에 보존한다. 화면·재생·앱 저장/재열기와 릴리스 검증은 이번 범위에 포함하지 않는다.
- 정적 결과: Node22.22.2·pnpm12.18.0에서 `pnpm run check`와 `git diff --check`를 통과했다. lint·477파일 서식·앱/도구/hosting 타입·의존성·i18n·공통 경계·문서/링크/앵커를 확인했다. 두 앱 버전0.11.0, 소스 빌드 `16ab7d6d603f`를 유지한다.
