# 0.7 안정화 — 2026-10-13

- 목표: 0.7 음원 연습의 가져오기·취소·저장·재열기와 기존 악보 흐름에서 재현되는 결함을 수정한다.
- 범위: player와 음원 처리/설정, 관련 저장·재생 회귀 검사. 현재 0.7.1 기준.
- 완료 조건: 집중 회귀 검사와 전체 드럼 검사, 빌드 통과 및 가능한 로컬 브라우저에서 핵심 흐름 확인. 실제 기기 미확인은 별도 기록.
- 제외: 검색·자동 BPM 상승 등 신규 기능, 서버 업로드, 버전 상승·커밋·푸시·발행.
- 검증: 취소/손상 파일/저장 실패/연속 요청/재열기, 음원 채널과 박자 보정, 기존 서버 악보 다운로드. Safari MCP 우선, 연결 실패 시 승인된 로컬 Chromium 확인.

## 최신 사용자 결정
- 음원 선택 후 BPM·첫 박을 자동 분석하고 태그에서 곡명·가수를 읽어 즉시 저장·연습 화면 진입. 최초 수동 확인 창은 제거한다.
- 태그 누락/손상 시 파일명을 제목으로 사용하고 알 수 없는 가수는 비운다. 음원/메타정보는 외부로 전송하지 않는다.
- 박자 맞추기는 선택적 보정으로 유지한다. 박자표는 4/4 기본이며 변속곡 추종·음악 인식 서비스는 범위 밖이다.

## 점검 결과
- 왼쪽 채널만 분석하던 결함 수정: 채널 에너지를 합쳐 분석하고 파형은 전체 채널 피크를 반영한다. 오른쪽만 소리가 있거나 좌우 위상이 반대인 120 BPM/0.2초 펄스로 회귀 검증했다.
- 최초 수동 확인 제거, 파일 태그 자동 입력, 손상 태그 fallback, 중복 요청 잠금 및 실패 후 재시도 검사 추가. 기존 빈 목록 문구 테스트를 최신 음원 안내에 맞췄다.
- 로컬 태그 파서 music-metadata 12.2.0 사용. 공식 parseBlob 계약 확인: https://github.com/Borewit/music-metadata#parseblob-function . 브라우저에서 파일을 읽으며 외부 음악 인식/업로드는 없다. parser는 필요할 때 로드한다. 라이선스 생성기는 package.json 비공개 export와 Licence 표기를 처리하도록 수정했고 분리 빌드에서 검증했다.
- 집중 검사 23개, 전체 103파일/554테스트, build:apps(타입/i18n 포함), check:playback 통과.
- 로컬 Chromium 실제 MP3: 태그 제목/가수 자동 표시, 설정 창 없이 진입, 재생/정지, 재열기, 보정 창 취소, 손상 파일 오류 및 재시도 가능 상태 확인. 이번 검증에서 만든 음원 항목만 삭제했다.
- Safari MCP Transport closed. 실제 iPhone/iPad Safari 검증은 미완료. Chromium 자동화 중 잘못된 CSS 선택자 및 hidden input에 대한 visible 대기로 타임아웃이 있어 실제 DOM을 확인해 검증을 이어갔다.
- 박자 분석은 기존 일정 템포 추정기 기반이며 음악적 첫 마디/박자표 인식·변속 추종은 보장하지 않는다. 낮은 신뢰도에서는 기존 120 BPM/0초 기본값을 유지한다. 태그 없는 가수는 음악 인식으로 찾지 않는다.
- 설치 audit에 기존 source-map-js 1.2.1 경고가 남는다(신규 태그 파서 의존성 아님). 무관한 의존성 일괄 갱신은 하지 않았다.
- player 0.7.1 유지. 커밋·푸시·발행 미수행.
