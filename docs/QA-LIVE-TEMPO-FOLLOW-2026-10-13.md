# 라이브 음원 템포 추종 검증 — 2026-10-13

## 구현과 범위

- 기존 자체 BPM 추정기를 유지하고 `music-tempo@1.0.3`(MIT)의 전체 박 시각 추적을 Worker에 추가했다.
- 대표 BPM 주변 후보로 시작하고 박 간격 변화를 따라간다. 분석한 시각을 균일 BPM 격자로 다시 펴지 않는다.
- 새 음원은 자동 적용한다. 기존 음원은 `박자 맞추기 → 음원 박자 다시 분석 → 저장하고 연습`으로 적용한다.
- 추종과 고정 BPM 전환, 재분석 취소, Worker 실패·시간 제한 정리, 마지막 잔향 구간의 카운트오프를 처리했다.
- 원본 음원은 브라우저에 남는다. 캐시 v4에는 해시·태그·분석값·박 시각만 허용한다. 공개 배포는 미수행이다.

## 정답이 있는 합성 신호

60초 동안 100→150 BPM 가속 및 150→100 BPM 감속 신호를 각각 생성했다. 정답 박과 ±50ms로 비교한 precision/recall이 각각 98%를 넘는 테스트가 통과했다. 고정 BPM 대신 실제 변하는 간격을 반환하는지도 확인했다. 무음은 추적 결과를 만들지 않으며 반대 위상 스테레오는 에너지가 큰 채널을 사용한다.

## 로컬 브라우저와 재생

5173 개발 앱에서 ego-browser 파일 선택으로 실제 YB MP3를 가져왔다. Safari MCP의 파일 선택 지원 부재로 해당 흐름은 승인된 대체 브라우저에서 검증했다. iPad Safari 실기기 검증을 뜻하지 않는다.

- 전체 분석 Worker를 거쳐 578개 시각·추종 상태가 IndexedDB에 저장되고 파형 화면으로 진입했다.
- 재열기, 고정 BPM 전환, 재분석, 추종 복귀 및 저장을 확인했다. 설정 캡처: `.tmp/live-tempo/setup.png`.
- 실제 재생기의 `pulse` 호출을 관측했다. 원본 14.29초부터 5개 클릭이 0.47, 0.46, 0.43, 0.43초 간격으로 예약됐다. `musicAt + (beatTime - from) / rate`와의 예약 시각 차이는 각각 0초였다. 이는 오디오 예약 검증이며 스피커 지연의 물리 측정은 아니다.
- 같은 파일 재읽기에서 Worker 생성 0회, 서버의 578개 시각과 완전 일치, 약 473ms(캐시 조회·디코드·파형 생성 포함)였다. 원본 음원 전송은 없다.
- 테스트를 위해 추가한 곡 1개만 제거했고 기존 브라우저 곡·파일은 보존했다.
