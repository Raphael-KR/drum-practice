# SVG 전체 악보 생성 규칙

관리 정본 · 2026-09-21 · 현재 구현: OSMD 2.1.2

이 문서는 이 프로그램의 **MusicXML → 전체 페이지 SVG → 연습 화면** 표시 규칙을 한곳에서 정의한다. SVG 생성·보정·캐시·마디 표시를 변경할 때 먼저 이 문서를 확인하고, 승인된 변경을 반영한 뒤 구현한다. 과거 QA 문서와 history.md는 검증 이력이며 현재 규칙을 대체하지 않는다.

## 1. 범위와 원본 보존

- 정본은 해당 곡의 MusicXML이다. SVG는 다시 만들 수 있는 렌더 결과다.
- 제목·작사·작곡·악기·성부·음가·가사는 MusicXML의 의미를 보존한다.
- 표시 보정은 렌더용 문서 복제본과 SVG에만 적용한다. 원본 XML을 표시 편의 때문에 덮어쓰지 않는다.
- PDF 원본은 변경하지 않는다. PDF에서 보이는 모양을 보고 악기를 임의로 추정하지 않는다.
- 악기·주법을 XML로 인코딩하는 결정은 `SCORE-MUSICXML-OSMD-MAPPING.md`의 확정 범례를 따른다. 그 문서는 입력 의미의 정본, 이 문서는 SVG 출력의 정본이다.
- 일반 도형·텍스트 대체 매핑의 신규 채택은 보고 후 사용자 명시적 결정이 필요하다. 기존 승인된 고스트·스티킹 보완은 아래 규칙대로 적용한다.

## 2. 전체 페이지 생성

| 항목 | 규칙 |
|---|---|
| 엔진 | OpenSheetMusicDisplay, SVG backend |
| 렌더 폭 | 1500px, 자동 리사이즈 없음 |
| 페이지 | A4 세로. 페이지 수를 4쪽으로 고정하지 않으며 곡에 따라 결정 |
| 한 시스템 | 원본 PDF의 줄별 마디 구성과 동일. 고정 4마디 규칙은 폐기 |
| 다중 마디 쉼표 | 자동 합치기와 자동 생성 모두 끔. 마디별 탐색 가능하게 유지 |
| 제목 | 전체 SVG에는 표시 |
| 작사·작곡자 | 표시하지 않음. 원본 메타 정보는 유지 |
| BPM | 메트로놈 표시와 BPM 숫자 지시문은 표시하지 않음. 원본 tempo와 재생 BPM 유지 |
| 마디 번호 | OSMD 자동 번호는 끔. 연습 화면에서 별도로 표시 |
| 파트 이름·약칭 | 표시하지 않음 |
| 가사 | OSMD 가사 출력은 끔. MusicXML 가사 데이터는 유지하고 연습 화면에서 별도 배치 |
| 배경·기본 색 | 악보는 검정 계열, 페이지 표시는 흰 배경. 원본에 지정된 색은 승인된 보정 외에 임의 변경하지 않음 |
| 파일 | 독립된 SVG 페이지, xmlns와 viewBox 유지. PNG로 바꾸어 정본 캐시로 저장하지 않음 |

전체 페이지에는 연습 화면의 재생선·선택 배경·마커 버튼·불빛 효과가 들어가지 않는다.

### 줄 간격과 페이지 나눔의 정본

- 곡별 MusicXML의 `system-layout/system-distance`, `top-system-distance`, `print new-system`, `print new-page`가 배치 의도의 정본이다.
- 새로 만드는 악보의 공통 간격은 XML 작성 초기값이다. 각 악보에서 따로 지정할 수 있으며 기존 XML의 값을 공통값으로 덮어쓰지 않는다.
- SVG 전체 보기에는 독립적인 줄 간격 설정을 두지 않는다. 렌더 복제본에서도 XML 간격 정보를 삭제하지 않는다.
- OSMD의 XML 줄/페이지 나눔 적용을 켠다.
- 현재 한계: OSMD 2.1.2 소스에는 `system-distance`를 읽어 시스템 간격에 적용하는 처리가 없다. `top-system-distance`의 일부 읽기 처리만 있다. 따라서 XML 간격의 정확한 출력 지원은 아직 미완료다. 렌더러의 상수 간격 강제로 이 지원을 대신했다고 보고하지 않는다.
- 현재 곡은 PDF와 같이 1–36 / 37–76 / 77–110마디의 3페이지로 검증했다. XML 페이지 경계는 유지하고 PDF 줄 시작에 new-system을 기록한다. 마지막 두 줄은 105–106 / 107–110마디다. 1500px 조판 폭에서 OSMD 자동 넘침 없이 이 구성을 확인했다. RenderXMeasuresPerLineAkaSystem=0으로 고정 마디 수를 강제하지 않는다. XML system-distance의 정확한 지원과는 별개이며 임의의 다른 악보까지 같은 결과를 보장하지 않는다.

## 3. 타악기 음자리표와 세로줄

- 타악기 음자리표 `||`는 첫 마디와 시스템 시작을 포함해 앱 생성 SVG에서 숨긴다.
- 원본 MusicXML의 `<clef><sign>percussion</sign></clef>`와 악기 정보는 유지한다.
- 실제 세로줄·겹세로줄·마침줄·도돌이표는 유지한다. 모양이 비슷하다고 지우지 않는다.
- 현재 구현은 렌더 문서의 모든 명시된 clef가 percussion일 때 `.vf-clef` 그룹만 제거한다. 혼합 음자리표 파트의 선택적 제거는 아직 구현되지 않았으므로 일반 음자리표를 함께 제거하지 않는다.

## 4. 구간 시작 표시

- Intro, A, 후렴, C, Interlude, Ending 등 rehearsal 표시의 내용은 유지한다. 임의 번역하지 않는다.
- 표시의 X좌표와 테두리 크기는 유지하고 Y좌표만 보정한다.
- 오선 제5선 위로 5칸에 해당하는 여유 영역을 사용한다.
- 테두리 상단은 제5선 Y좌표 − 70 SVG 단위로 맞춘다. 선 두께를 포함해 화면 상단에 약 1 SVG 단위 여유가 남는다.
- text와 해당 테두리를 함께 이동한다. VexFlow가 사이에 생성한 빈 path는 건너뛴다.
- 시스템 시작 여부 때문에 표시 높이가 달라지지 않게 한다. 이름이 길어도 텍스트를 잘라 숨기지 않는다.
- 현재 규칙은 세로 위치 정렬이다. 구간 표시와 다른 지시어의 모든 가로 충돌을 해결하는 범용 배치 엔진은 아니다.

## 5. 음표·주법 보완

| 대상 | 출력 규칙 |
|---|---|
| 악기별 머리·위치 | 확정된 XML의 unpitched 표시 좌표와 notehead를 사용. 이름만 보고 다른 기호로 바꾸지 않음 |
| Open Hi-Hat | 확정 범례의 원 안 ×. 빈 타원을 하이햇의 기본 대체 기호로 만들지 않음 |
| Hi-Hat Open/Close | 열린/닫힌 상태와 별개의 동작 지시. 서로 합치지 않음 |
| 빈 일반 머리 | OSMD가 짧은 음표의 filled=no를 누락하면 해당 화음 구성음의 머리만 흰 fill·원래 색 stroke(1.1)로 보완 |
| 고스트 | notehead parentheses=yes를 해당 머리 양옆 괄호로 보완. 머리 경계에서 좌우3, 위아래2 SVG 단위 여유, 선 두께1.4 |
| R/L 스티킹 | 해당 타격마다 R 또는 L 하나. 저장은 words, 출력은 줄기 중앙 X·줄기/머리 중 높은 위치보다9 SVG 단위 위. 16px serif, 중앙 정렬 |
| 스티킹 대상 연결 | divisions, backup, forward, offset, voice로 정확한 타격에 연결. 하나의 타격에 서로 다른 R/L을 쌓지 않음 |
| 실험용 문구 | `R words`, `R other-technical` 같은 진단 설명을 악보에 표시하지 않음 |

고스트·스티킹 대상 식별용 임시 색은 렌더링 후 원래 색으로 되돌린다. 대상 머리를 찾지 못하면 조용히 생략하지 않고 오류를 보고한다.

## 6. 쉼표

- 심벌/드럼/킥의 역할별 높이는 확정 XML 표시 좌표를 따른다. 모양이나 가까운 음표만으로 성부를 재분류하지 않는다.
- 모든 성부가 쉬는 온마디쉼표는 원본 정규화 단계에서 명시적 높이를 제거하여 기본 중앙 배치를 사용한다.
- 명시적 높이가 남아 자동 중앙 정렬이 우회되는 온마디쉼표는 머리의 실제 경계를 기준으로 마디 가운데로 보정한다. 리듬 시작과 재생 좌표는 이동하지 않는다.
- 부분 마디 쉼표는 리듬상 시작 위치를 유지한다. 2분·점2분이라는 이유만으로 모두 마디 중앙에 옮기지 않는다.

## 7. 마디 좌표와 자르기

- OSMD GraphicSheet의 실제 마디·성부·페이지 좌표를 사용한다. 화면 픽셀을 음가로 추측하지 않는다.
- OSMD engraving unit 1은 현재 SVG 10단위다.
- 마디 좌우는 BorderLeft/Right, 위쪽은 마디·오선·SkyLine 및 최소 −4단위 중 최솟값에서1단위를 추가 확보한다.
- 아래쪽은 최소9단위와 BorderBottom 중 큰 값에0.5단위를 더한다. 페이지 경계를 넘지 않는다.
- 마디별 beatXs는 staff entry의 실제 timestamp를 박자 분모에 맞게 변환하고 인접 좌표 사이를 보간한다. 셋잇단음표를 정수 박으로 반올림하지 않는다.
- 음표와 빔이 잘리거나 옆 시스템의 기호가 들어오면 좌표와 표시 변환을 검수한다. 리듬 데이터를 바꾸어 맞추지 않는다.
- SVG 페이지와 대응 마디 영역은 항상 함께 갱신한다.

## 8. 연습 화면 전용 배치

- 전체 페이지 SVG와 마디별 연습 화면을 구별한다. 전체 페이지에 연습 화면 크기/배경/버튼을 굽지 않는다.
- 두 줄 보기: 한 줄4마디, 가로 틈0. 상단·행 사이·하단 여백28 CSS px.
- MusicXML 음표 크기는 마디 너비×0.52를100~180px로 제한한 budget으로 계산한다. 오선 간격은 budget/15과 마디 너비/25 중 작은 값이다.
- crop 높이는 오선 간격×15, 제5선은 crop 상단에서7칸 아래. 가사는 crop 아래6px에 배치한다.
- 공통 행 높이는 실제 최대 crop 높이+가사 영역30px. stage 높이는 두 행+28px 여백3개다.
- 재생·정지 모두 같은 음표 배율·행 높이·간격을 사용한다. 정지 상태에서 전체 악보 상하 스크롤을 허용한다.
- 한 줄 보기와 비교 검수 화면의 개별 레이아웃은 전체 SVG 파일의 형상을 변경하지 않는다.

## 9. 음표 따라가기 — 화면 효과

- MusicXML 한 줄/두 줄 연습 화면에만 적용한다. PDF와 비교 검수에는 적용하지 않는다.
- 정확한 음표 시작에 켜지고 약140ms 안에 꺼진다. 최대¼박이며 다음 음표 시작에서 이전 효과를 끈다. 동시음은 동시에 켜진다.
- 흰 중심·청록 광륜, 머리가 가장 밝고 기둥/빔은 은은하게 표시. 밝기는 점등 후 감쇠한다.
- 빔은 해당 성부에 연결된 실제 음표 X좌표를 따라 짧은 빛이 이동한다. 지나간 부분을 누적 색칠하지 않는다.
- 카운트오프에는 숨긴다. 되감기·반복·탐색 시 현재 위치로 재계산한다.
- 효과의 타이밍 메타데이터는 SVG 캐시에 담되, 실제 색 효과는 화면 overlay로 만든다. 오선·가사와 원본 XML 색은 변경하지 않는다.

## 10. 저장·캐시·안전

- 저장 캐시는 gzip SVG (`application/vnd.drum-practice.svg+gzip`). 표시할 때 image/svg+xml로 풀어 사용한다.
- 현재 페이지 버전: data-rest-layout=`svg-geometry-sync-v17`, 음표 메타데이터: data-note-highlight=`2`.
- 생성 규칙 변경으로 기존 파일이 달라지면 캐시 버전을 올려 이전 페이지와 마디 영역을 함께 다시 만든다.
- 현재 갱신 코드는 첫 페이지의 버전을 검사한다. 재생성 후 마디 식별자의 일치를 검증하고 페이지 수와 마디 영역을 함께 갱신한다.
- XML의 script, foreignObject, image, link, opus 및 이벤트/href 속성을 차단한다. 활성 콘텐츠를 SVG에 유입하지 않는다.
- 재생 강조 overlay는 허용된 벡터 도형과 기하 속성만 복사한다.

## 11. 변경 검증

1. 원본 XML 의미·음가·악기 정보가 보존되는지 검사한다.
2. 전체 페이지와 마디별 화면을 모두 확인한다. 첫 마디·시스템 시작·페이지 경계도 포함한다.
3. 모든 구간 표시의 테두리와 음표/쉼표/빔이 잘리지 않는지 확인한다.
4. 타악기 음자리표가 숨겨지고 실제 세로줄/반복기호가 남는지 확인한다.
5. 재생·정지 크기, 가사 위치, 재생선과 음표 좌표를 대조한다.
6. 관련 테스트·빌드와 Safari 실제 화면을 확인한다. iPad 실기기 검증과 데스크톱 Safari 검증을 혼동하지 않는다.
7. 검증 결과는 history.md에 남긴다. 새 규칙은 이 문서에 갱신한다.

## 구현 위치

- `src/musicxml.ts`: 입력 검증, OSMD 옵션, 표시 보정, 전체 SVG와 마디 영역 생성
- `src/drum-notation.ts`: 고스트·스티킹 보완과 알려진 예제 악기의 정규화
- `src/whole-rest-layout.ts`, `src/score-rest-correction.ts`: 온마디쉼표 보정·캐시 갱신
- `src/score-pages.ts`: SVG 압축/해제
- `src/practice-staff-layout.ts`, `src/main.ts`, `src/style.css`: 마디 표시·공통 행 배치
- `src/note-highlight.ts`: 타이밍 메타데이터와 화면 발광 효과

이 문서는 규칙의 단일 진입점이다. 현재 구현값도 함께 기록했지만 실행 코드를 하나의 파일로 합친 것은 아니다.

## 앱에서 전체 악보 열기
- 설정 → 악보 → 편집 → 악보 탭에서 `PDF 전체 악보 보기`와 `SVG 전체 악보 보기`를 제공한다. 각 형식이 있는 곡에 해당 버튼을 표시한다.
- PDF는 기존 페이지 넘김 방식, SVG는 모든 페이지를 세로로 이어 보여준다. SVG를 닫으면 편집 화면으로 돌아간다.
- SVG 보기에서는 저장된 전체 페이지를 표시하며 새로 마디를 자르거나 음악 데이터를 변경하지 않는다. 닫을 때 표시용 URL을 해제한다.
- SVG 전체 보기의 마디 번호는 HTML 오버레이로만 표시한다. 각 실제 시스템의 맨 왼쪽 마디 번호를 오선 앞 여백에 배치한다. 4마디씩이라고 가정하지 않고 SVG 오선 좌표에서 줄 시작을 판별한다. 원본/캐시 SVG와 연주 화면에는 이 번호를 추가하지 않는다.

### 현재 곡의 PDF 페이지별 줄 시작 마디

- 1쪽: 1, 5, 9, 13, 17, 21, 25, 29, 33
- 2쪽: 37, 41, 45, 49, 53, 57, 61, 65, 69, 73
- 3쪽: 77, 81, 85, 89, 93, 97, 101, 105, 107
- 참조: data/reference/geometry.json. 다른 곡에 이 번호표를 적용하지 않는다. 페이지 경계·줄 시작·줄별 마디 목록을 모두 PDF와 대조한다.

### 연습 화면 Trim
- 마디 crop은 같은 시스템의 실제 SVG 음표·쉼표·구간 표시 bounding box에 상하 5 SVG 단위만 더한다. 고정 하단 9.5칸으로 다음 줄을 포함하지 않는다.
- 제목은 전체 SVG에 보존하며 연습용 페이지 복제본에서만 제거한다.
- 두 줄 보기의 공통 높이/정렬은 유지하되 원본 시스템 경계 밖의 잉크는 clip-path로 가린다.

### 2026-09-21 캡처 검수 보정

- 한 줄 보기에서도 마디 crop 높이가 아닌 오선 간격을 기준으로 배율을 정한다. 온마디쉼표에서 일반 음표 마디로 넘어가도 오선 높이와 간격이 이어진다.
- 연습 화면 공통 프레임은 오선 간격 15개 높이이며 제5선 위에 7개 간격을 확보한다. 구간 표시는 음표 연결선 위에 배치한다.

### 제목 여백과 페이지 아래 빈 공간 (2026-09-21)

- 알려진 기본 곡의 첫 마디 `print/system-layout/top-system-distance`가 없으면 180 tenths를 기록한다. 이미 곡별 값이 있으면 보존한다.
- 값은 제목과의 직접 간격이 아니라 페이지 상단 여백부터 첫 오선까지의 거리다. [MusicXML 공식 정의](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/top-system-distance/).
- OSMD 2.1.2는 이 값을 실제 첫 시스템 Y에 적용하지 않으므로 렌더 직전 XML 값을 OSMD TitleBottomDistance로 변환한다. 제목 높이·상단 거리를 빼며 음수 간격은 허용하지 않는다. 제목을 SVG 후처리로 이동시키지 않는다.
- 각 페이지의 마지막 기호 아래 30 SVG 단위만 남기도록 출력 캔버스 높이를 줄인다. 페이지 나눔·마디·줄 구성과 XML 페이지 용지 정보는 유지한다. 마디 좌표는 최종 캔버스 높이로 함께 정규화한다.
- 기본 곡 84마디 오른쪽 마디선은 XML `barline location="right" / bar-style = light-light`. 84마디 5/4와 85마디 4/4를 유지한다. 타악기 음자리표 숨김과 겹세로줄은 별개다.
