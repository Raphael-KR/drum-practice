# SVG 전체 악보 생성 규칙

관리 정본 · 2026-09-21 · 현재 구현: OSMD 2.1.2

이 문서는 이 프로그램의 **MusicXML → 전체 페이지 SVG → 연습 화면** 표시 규칙을 한곳에서 정의한다. SVG 생성·보정·캐시·마디 표시를 변경할 때 먼저 이 문서를 확인하고, 승인된 변경을 반영한 뒤 구현한다. 과거 QA 문서와 history.md는 검증 이력이며 현재 규칙을 대체하지 않는다.

## 1. 범위와 원본 보존

- 정본은 해당 곡의 MusicXML이다. SVG는 다시 만들 수 있는 렌더 결과다.
- 제목·작사·작곡·악기·성부·음가·가사는 MusicXML의 의미를 보존한다.
- 표시 보정은 렌더용 문서 복제본과 SVG에만 적용한다. 원본 XML을 표시 편의 때문에 덮어쓰지 않는다.
- PDF 원본은 변경하지 않는다. PDF에서 보이는 모양을 보고 악기를 임의로 추정하지 않는다.
- 악기·주법을 XML로 인코딩하는 결정은 `SCORE-MUSICXML-OSMD-MAPPING.md`의 확정 범례를 따른다. 그 문서는 입력 의미의 정본, 이 문서는 SVG 출력의 정본이다.
- 일반 도형·텍스트 대체 매핑의 신규 채택은 보고 후 사용자 명시적 결정이 필요하다. 기존 승인된 고스트·스티킹 보완은 아래 규칙대로 적용한다.

## 2. 전체 페이지 생성

| 항목 | 규칙 |
|---|---|
| 엔진 | OpenSheetMusicDisplay, SVG backend |
| 렌더 폭 | 1500px, 자동 리사이즈 없음 |
| 페이지 | A4 세로. 페이지 수를 4쪽으로 고정하지 않으며 곡에 따라 결정 |
| 한 시스템 | 원본 PDF의 줄별 마디 구성과 동일. 고정 4마디 규칙은 폐기 |
| 다중 마디 쉼표 | 자동 합치기와 자동 생성 모두 끔. 마디별 탐색 가능하게 유지 |
| 제목 | 전체 SVG에는 표시 |
| 작사·작곡자 | 표시하지 않음. 원본 메타 정보는 유지 |
| BPM | 메트로놈 표시와 BPM 숫자 지시문은 표시하지 않음. 원본 tempo와 재생 BPM 유지 |
| 마디 번호 | OSMD 자동 번호는 끔. 연습 화면에서 별도로 표시 |
| 파트 이름·약칭 | 표시하지 않음 |
| 가사 | OSMD 가사 출력은 끔. MusicXML 가사 데이터는 유지하고 연습 화면에서 별도 배치 |
| 배경·기본 색 | 악보는 검정 계열, 페이지 표시는 흰 배경. 원본에 지정된 색은 승인된 보정 외에 임의 변경하지 않음 |
| 파일 | 독립된 SVG 페이지, xmlns와 viewBox 유지. PNG로 바꾸어 정본 캐시로 저장하지 않음 |

전체 페이지에는 연습 화면의 재생선·선택 배경·마커 버튼·불빛 효과가 들어가지 않는다.

### 줄 간격과 페이지 나눔의 정본

- 곡별 MusicXML의 `system-layout/system-distance`, `top-system-distance`, `print new-system`, `print new-page`가 배치 의도의 정본이다.
- 새로 만드는 악보의 공통 간격은 XML 작성 초기값이다. 각 악보에서 따로 지정할 수 있으며 기존 XML의 값을 공통값으로 덮어쓰지 않는다.
- SVG 전체 보기에는 독립적인 줄 간격 설정을 두지 않는다. 렌더 복제본에서도 XML 간격 정보를 삭제하지 않는다.
- OSMD의 XML 줄/페이지 나눔 적용을 켠다.
- 현재 한계: OSMD 2.1.2 소스에는 `system-distance`를 읽어 시스템 간격에 적용하는 처리가 없다. `top-system-distance`의 일부 읽기 처리만 있다. 따라서 XML 간격의 정확한 출력 지원은 아직 미완료다. 렌더러의 상수 간격 강제로 이 지원을 대신했다고 보고하지 않는다.
- 곡별 검증 사례: 「風と丘のバラード」(Real Paradis, 110마디)는 2026-09-21에 PDF와 같은 1–36 / 37–76 / 77–110마디의 3페이지로 검증했다. XML 페이지 경계는 유지하고 PDF 줄 시작에 new-system을 기록한다. 마지막 두 줄은 105–106 / 107–110마디다. 1500px 조판 폭에서 OSMD 자동 넘침 없이 이 구성을 확인했다. RenderXMeasuresPerLineAkaSystem=0으로 고정 마디 수를 강제하지 않는다. XML system-distance의 정확한 지원과는 별개이며 다른 곡의 페이지 경계를 이 값으로 강제하지 않는다.
- Loveholic(123마디)은 별도 [제작 기록](LOVEHOLIC-CONVERSION.md)의 1–36 / 37–79 / 80–123마디 3페이지 검증을 따른다. 곡별 배치 증거와 공통 SVG 규칙을 구분한다.

## 3. 타악기 음자리표와 세로줄

- 타악기 음자리표 `||`는 첫 마디와 시스템 시작을 포함해 앱 생성 SVG에서 숨긴다.
- 원본 MusicXML의 `<clef><sign>percussion</sign></clef>`와 악기 정보는 유지한다.
- 실제 세로줄·겹세로줄·마침줄·도돌이표는 유지한다. 모양이 비슷하다고 지우지 않는다.
- 현재 구현은 렌더 문서의 모든 명시된 clef가 percussion일 때 `.vf-clef` 그룹만 제거한다. 혼합 음자리표 파트의 선택적 제거는 아직 구현되지 않았으므로 일반 음자리표를 함께 제거하지 않는다.

### 줄 앞 타악기 표시 자르기 — 최신 확정 결정 (2026-10-03)

> 타악기 표시 자르기를 하고, 그걸 하면서 가사나 숫자가 잘려도 괜찮다.

- PDF 연습 화면의 줄 앞 타악기 표기·여백을 표시 영역에서 잘라 다른 마디와 길이를 맞춘다. 이 과정에서 인쇄 가사·마디 숫자가 잘리는 것은 허용한다.
- 이 자르기에 대해서는 과거의 “마디 번호 유지” 조건보다 위 최신 결정이 우선한다. 가사·숫자 보존 때문에 타악기 표시를 남기는 예외를 두지 않는다.
- 원본 PDF와 MusicXML은 보존한다. 첫 음표·박자표·실제 마디선과 진행선 좌표는 보존·대조한다. 줄 전체의 상하 내용 자르기는 별도 규칙을 따른다.
- [결정 대조 기록](MUSICXML-TROUBLESHOOTING.md#줄별-마디-구성과-줄-앞-타악기-표기의-과거-결정-대조)에 승인 이력을 남긴다. 결정 기록과 현재 곡의 구현·검증 완료를 구분한다.

## 4. 구간 시작 표시

- Intro, A, 후렴, C, Interlude, Ending 등 rehearsal 표시의 내용은 유지한다. 임의 번역하지 않는다.
- 표시의 X좌표와 테두리 크기는 유지하고 Y좌표만 보정한다.
- 오선 제5선 위로 5칸에 해당하는 여유 영역을 사용한다.
- 테두리 상단은 제5선 Y좌표 − 70 SVG 단위로 맞춘다. 선 두께를 포함해 화면 상단에 약 1 SVG 단위 여유가 남는다.
- text와 해당 테두리를 함께 이동한다. VexFlow가 사이에 생성한 빈 path는 건너뛴다.
- 시스템 시작 여부 때문에 표시 높이가 달라지지 않게 한다. 이름이 길어도 텍스트를 잘라 숨기지 않는다.
- 현재 규칙은 세로 위치 정렬이다. 구간 표시와 다른 지시어의 모든 가로 충돌을 해결하는 범용 배치 엔진은 아니다.

## 5. 음표·주법 보완

| 대상 | 출력 규칙 |
|---|---|
| 악기별 머리·위치 | 확정된 XML의 unpitched 표시 좌표와 notehead를 사용. 이름만 보고 다른 기호로 바꾸지 않음 |
| Open Hi-Hat | 확정 범례의 원 안 ×. 빈 타원을 하이햇의 기본 대체 기호로 만들지 않음 |
| Hi-Hat Open/Close | 열린/닫힌 상태와 별개의 동작 지시. 서로 합치지 않음 |
| Hi-Hat Half-Open | half-muted[smufl="pictHalfOpen1"]에만 공식 Bravura U+E7F6의 정확한 path를 사용. 일반 도형 조합·글자 대체나 다른 half-muted 자동 변환은 하지 않음 |
| 빈 일반 머리 | OSMD가 짧은 음표의 filled=no를 누락하면 해당 화음 구성음의 머리만 흰 fill·원래 색 stroke(1.1)로 보완 |
| 고스트 | notehead parentheses=yes를 해당 머리 양옆 괄호로 보완. 머리 경계에서 좌우3, 위아래2 SVG 단위 여유, 선 두께1.4 |
| R/L 스티킹 | 해당 타격마다 R 또는 L 하나. 저장은 words, 출력은 줄기 중앙 X·줄기/머리 중 높은 위치보다9 SVG 단위 위. 16px serif, 중앙 정렬 |
| 스티킹 대상 연결 | divisions, backup, forward, offset, voice로 정확한 타격에 연결. 하나의 타격에 서로 다른 R/L을 쌓지 않음 |
| 실험용 문구 | `R words`, `R other-technical` 같은 진단 설명을 악보에 표시하지 않음 |

고스트·스티킹 대상 식별용 임시 색은 렌더링 후 원래 색으로 되돌린다. 대상 머리를 찾지 못하면 조용히 생략하지 않고 오류를 보고한다.

반열림 경로는 2026-10-03 앱 보완으로 검증했다. 공식 OTF revision `37b194378b710cc40e406ab6c4b07608bb9548ae`, SHA256 `cdf0f893ee1fdb64b7f6713d71ee0dcfc349c0ac01429a8e451b01a9e79f5f3b`, SIL OFL 1.1이다. fontTools가 U+E7F6 cmap의 uniE7F6에서 추출한 bbox는 (0,0,286,286), unitsPerEm=1000이며 SVG에서 Y축을 반전한다. 코드·라이선스는 `src/vendor/pict-half-open.json`과 개발 세션의 third-party 기록을 따른다. Loveholic 20개 확대 검수와 새 패키지 전곡 규격 검사 통과. 제작 측 화면 검증은 Safari MCP Transport closed 이후 ego-browser에서 수행했으며 Safari 검증으로 대신 보고하지 않는다. OSMD 원생 half-muted 미지원은 유지된다.

## 6. 쉼표

- 심벌/드럼/킥의 역할별 높이는 확정 XML 표시 좌표를 따른다. 모양이나 가까운 음표만으로 성부를 재분류하지 않는다.
- 모든 성부가 쉬는 온마디쉼표는 원본 정규화 단계에서 명시적 높이를 제거하여 기본 중앙 배치를 사용한다.
- 명시적 높이가 남아 자동 중앙 정렬이 우회되는 온마디쉼표는 머리의 실제 경계를 기준으로 마디 가운데로 보정한다. 리듬 시작과 재생 좌표는 이동하지 않는다.
- 부분 마디 쉼표는 리듬상 시작 위치를 유지한다. 2분·점2분이라는 이유만으로 모두 마디 중앙에 옮기지 않는다.

## 7. 마디 좌표와 자르기

- OSMD GraphicSheet의 실제 마디·성부·페이지 좌표를 사용한다. 화면 픽셀을 음가로 추측하지 않는다.
- OSMD engraving unit 1은 현재 SVG 10단위다.
- 마디 좌우는 BorderLeft/Right, 위쪽은 마디·오선·SkyLine 및 최소 −4단위 중 최솟값에서1단위를 추가 확보한다.
- 아래쪽은 최소9단위와 BorderBottom 중 큰 값에0.5단위를 더한다. 페이지 경계를 넘지 않는다.
- 마디별 beatXs는 staff entry의 실제 timestamp를 박자 분모에 맞게 변환하고 인접 좌표 사이를 보간한다. 셋잇단음표를 정수 박으로 반올림하지 않는다.
- 음표와 빔이 잘리거나 옆 시스템의 기호가 들어오면 좌표와 표시 변환을 검수한다. 리듬 데이터를 바꾸어 맞추지 않는다.
- SVG 페이지와 대응 마디 영역은 항상 함께 갱신한다.

## 8. 연습 화면 전용 배치

- 전체 페이지 SVG와 마디별 연습 화면을 구별한다. 전체 페이지에 연습 화면 크기/배경/버튼을 굽지 않는다.
- 두 줄 재생 보기의 최종 사용자 기준(2026-10-03): 각 행은 4마디로 표기한다. 원본 줄별 마디 구성을 따르는 것은 전체 SVG 출력이며 두 줄 재생 배치에 적용하지 않는다. 가로 틈0, 상단·행 사이·하단 여백28 CSS px.
- MusicXML 음표 크기는 마디 너비×0.52를100~180px로 제한한 budget으로 계산한다. 오선 간격은 budget/15과 마디 너비/25 중 작은 값이다.
- crop 높이는 오선 간격×15, 제5선은 crop 상단에서7칸 아래. 가사는 crop 아래6px에 배치한다.
- 공통 행 높이는 실제 최대 crop 높이+가사 영역30px. stage 높이는 두 행+28px 여백3개다.
- 마지막 행이 4마디 미만이면 남은 칸을 빈 칸으로 유지한다. 다음 행의 마디가 빈 칸으로 당겨져 올라오지 않게 하며, 정지 시 행 위치 판정에도 빈 칸을 포함한다.
- 재생·정지 모두 같은 음표 배율·행 높이·간격을 사용한다. 정지 상태에서 전체 악보 상하 스크롤을 허용한다.
- 한 줄 보기와 비교 검수 화면의 개별 레이아웃은 전체 SVG 파일의 형상을 변경하지 않는다.

## 9. 음표 따라가기 — 화면 효과

- MusicXML 한 줄/두 줄 연습 화면에만 적용한다. PDF와 비교 검수에는 적용하지 않는다.
- 정확한 음표 시작에 켜지고 약140ms 안에 꺼진다. 최대¼박이며 다음 음표 시작에서 이전 효과를 끈다. 동시음은 동시에 켜진다.
- 흰 중심·청록 광륜, 머리가 가장 밝고 기둥/빔은 은은하게 표시. 밝기는 점등 후 감쇠한다.
- 빔은 해당 성부에 연결된 실제 음표 X좌표를 따라 짧은 빛이 이동한다. 지나간 부분을 누적 색칠하지 않는다.
- 카운트오프에는 숨긴다. 되감기·반복·탐색 시 현재 위치로 재계산한다.
- 효과의 타이밍 메타데이터는 SVG 캐시에 담되, 실제 색 효과는 화면 overlay로 만든다. 오선·가사와 원본 XML 색은 변경하지 않는다.

## 10. 저장·캐시·안전

- 저장 캐시는 gzip SVG (`application/vnd.drum-practice.svg+gzip`). 표시할 때 image/svg+xml로 풀어 사용한다.
- 현재 페이지 버전: data-rest-layout=`svg-geometry-sync-v17`, 음표 메타데이터: data-note-highlight=`2`.
- 생성 규칙 변경으로 기존 파일이 달라지면 캐시 버전을 올려 이전 페이지와 마디 영역을 함께 다시 만든다.
- 현재 갱신 코드는 첫 페이지의 버전을 검사한다. 재생성 후 마디 식별자의 일치를 검증하고 페이지 수와 마디 영역을 함께 갱신한다.

- 재생 강조 overlay는 허용된 벡터 도형과 기하 속성만 복사한다.

## SVG 한 줄 보기의 시간 비례 배치 — 2026-10-03 승인·구현

- SVG 한 줄 재생 보기에서는 **같은 4분음표 시간 = 같은 가로 거리**다. 8분·16분·셋잇단음표는 음악적 길이의 비율대로 배치한다. 5/4 마디의 폭은 4/4의 5/4배다.
- 곡 전체의 가장 조밀한 음표·꾸밈음·기호가 들어갈 공통 박 간격을 구한다. 한 마디만 늘리지 않는다. BPM/연습 속도는 시간당 이동량만 바꾸며 악보 너비는 바꾸지 않는다.
- VexFlow tick context를 native 조판 단계에서 이동한다. 음표·오선 이미지를 가로로 압축하지 않는다. 빔·붙임줄·꾸밈음의 조판은 렌더러를 사용한다. 꾸밈음은 본음 앞에 붙으며 시간 축을 늘리지 않는다. 온마디 쉼표는 마디 중앙을 유지한다.
- 재생 전용 캐시는 전체 SVG 첫 페이지의 비표시 `metadata[data-ribbon-timeline]`에 저장한다. 원본 MusicXML/PDF와 전체 SVG의 인쇄 배치, 두 줄 보기의 4마디 구성은 별도 규칙 그대로다. 재생용 캐시의 내부 페이지 나눔은 원본 페이지 나눔이 아니다.
- 공통 `preparePlaybackAssets`와 `playback-screen`이 웹앱·HTML 템플릿에서 같은 캐시/동작을 사용한다. player에 OSMD를 추가하지 않는다. 제작앱이 캐시를 생성하며 이전 캐시는 제작앱에서 열 때 갱신한다. 캐시가 없는 기존 완성 파일은 기존 표시를 유지하며 새 기능 적용에는 제작앱에서 재저장이 필요하다.
- SVG `viewBox`와 렌더러의 오선 좌표를 사용한다. 이미지 naturalHeight 정수 반올림이나 픽셀 검출 오차를 박 간격에 전파하지 않는다.

## 브라우저 직접 조판 (2026-10-03 최신 승인)

드럼연습실도 제작실과 같은 `renderMusicXML`을 호출한다. 완성 패키지의 MusicXML(canonicalXML 우선)을 정본으로 사용하고, 동봉된 인쇄 SVG를 최신 조판의 정본으로 삼지 않는다. 한 줄 시간 비례 규칙, 두 줄4마디, 인쇄 XML 줄/페이지 구성은 유지한다. `score-render-cache.ts`의 키는 원문·파트·실제 OSMD 버전·표시 정책이다. 표기/배치 구현 변경 시 정책 버전도 올린다. 화면 크기/BPM/보기 전환은 벡터 조판 입력을 바꾸지 않으므로 같은 결과에서 공통 화면 배치만 갱신한다. 조판이 반환한 오선 좌표를 재사용하고 새 SVG에서 픽셀 오선을 다시 탐지하지 않는다. PDF/구형 SVG만 탐지 경로를 유지한다. 원본과 연습 상태는 캐시 DB에 쓰지 않는다.

검증·성능·예외 정본: [브라우저 직접 조판 전환](BROWSER-MUSICXML-RENDERING.md). 기존 renderer-free 빌드 제한은 재생앱에 한해 폐기하며 편집/제작 모듈 금지는 유지한다. 독립 HTML 생성은 이번 범위가 아니다.


## 한 줄 보기의 읽기 편한 밀도·이동 (2026-10-03 사용자 승인)

목적은 악보를 쫓는 반응 게임이 아니라 다음 연주를 미리 준비하는 드럼 연습이다. 동일 음가·동일 거리만으로 사용성 통과를 판정하지 않는다.

- 음표와 오선은 읽을 수 있는 크기를 유지하고, 불필요한 가로 간격을 줄인다. SVG 전체를 가로 압축하거나 글리프까지 축소하는 방식으로 해결하지 않는다.
- 진행선 앞에 여러 마디가 보여 다음 연주를 준비할 여유를 제공한다.
- 동일 표시 조건에서 동일 음가는 동일 거리다. BPM/연습 배속은 이동 속도만 변경하며 음표 간격을 자동 변경하지 않는다.
- 빠른 곡에서 불필요한 여백 때문에 이동이 과도하게 빨라지지 않게 한다. 음원과 어긋나도록 스크롤 속도만 제한하지 않는다.
- 확대율·회전·보기 전환 시 연습 위치와 반복 구간을 보존한다. 재생 도중 마디별 밀도를 자동 변경하지 않는다.
- 기존의 ‘곡 전체 최대 필요 간격’ 방식은 충돌 방지 수단이지 사용성 목표가 아니다. 이 방식 때문에 밀도 기준을 충족하지 못하면 원인을 개선해야 하며, 곡 전체를 계속 늘려 해결됐다고 판단하지 않는다.

정량화 후보·계산식·검증 계획은 [한 줄 가독성 정량 검토](RIBBON-READABILITY.md)를 따른다. 원칙은 승인됐으나 수치 후보는 사용자 검토/실행 검증 전이며 아직 코드에 적용하지 않았다. 두 줄4마디·인쇄 배치·PDF 보존 규칙은 그대로다.

## 2026-10-03 PDF 대응 음표의 가사 위치

PDF의 파란 가사는 검증된 `Region.lyricAnchors`가 있으면 lyricId와 현재 scorePosition의 마디/quarterOffset이 일치할 때만 대응 음표 중심에 배치한다. 좌표는 원본 PDF 영역 기준이며 표시 자르기를 함께 변환하고 crop의 실제 너비로 계산한다. 이 좌표는 일반 가사 겹침 방지의 가로 이동으로 바꾸지 않는다. SVG 또는 사용자가 음악적 위치를 바꾼 가사는 기존 표시 위치 계산을 유지한다. XML·박 진행선은 그대로다. Loveholic265직접대응·4추정 및 실제 검증은 [PDF 가사 위치 수정](LOVEHOLIC-PDF-LYRIC-PLACEMENT.md)을 따른다.

## 드럼 연결선의 높이 방향 (2026-10-03 승인·적용)
- 묶음의 음표 높이가 같거나, 올라갔다 내려가는 등 방향이 바뀌면 수평으로 조판한다.
- 같은 높이가 반복되는 구간을 포함해 한 방향으로만 진행하면 그 방향으로 완만하게 기울인다.
- 화음은 연결선 쪽 음표머리를 기준으로 한다(위줄기: 가장 높은 머리, 아래줄기: 가장 낮은 머리).
- 공통 `drum-beams.ts`가 OSMD/VexFlow의 원생 연결선·줄기 계산 전에 적용한다. 기울기 절댓값은 0.08 이하, 양끝 높이 차이는 오선 간격의 절반 이하로 한다. 기존 최소 줄기 길이는 줄이지 않는다.
- MusicXML 정본, 음가·빔 묶음, 원본 페이지·줄 배치는 유지한다. 캐시 정책 v9-beam-contour로 이전 조판을 무효화한다.
- 이 수정은 연결선 규칙에 한정한다. 두 줄 보기의 가로/세로 비균등 확대 문제는 별도 미해결 사항이다.

## 두 줄 보기의 음표 비율과 기둥 (2026-10-03, v10 초안·아래 v11로 보완)
- 두 줄 보기에서도 공통 재생용 원생 조판을 사용한다. 인쇄 마디를 각 셀에 맞춰 가로로 늘이거나 누르지 않는다. 한 줄 4개 셀은 유지한다.
- 같은 박자 길이의 곡은 한 줄용 조판 자산을 재사용한다. 박자 길이가 섞이면 가장 긴 마디를 기준으로 같은 원생 마디 너비를 확보하고, 짧은 마디의 음표 간격을 조판 단계에서 재배치한다. 음표/기둥/기호의 도형을 변형하지 않는다.
- 화면 배치는 원생 페이지 종횡비대로 동일 배율을 두 축에 적용한다. 음표 강조도 같은 조판 좌표를 사용한다.
- 기둥은 EngravingRules.StemWidth=0.1(원생 SVG 1단위, 기존 1.5단위)로 한다. 보통 머리 너비 약12단위 대비 약8%이다. 머리·꼬리 도형은 유지하며 오선·연결선을 일괄 가늘게 만들지 않는다.
- 파생 캐시 정책 v10-uniform-rows-stems. 원본 XML/PDF 및 인쇄 페이지·줄별 마디 구성은 보존한다.
- 전곡 동일 음표 크기와 4마디를 함께 유지하므로 밀집 음형이 있는 곡의 음표는 작아질 수 있다. 읽기 편한 최소 크기를 무조건 충족한다고 보증하지 않는다.

## 두 줄 가독성 보완 v11 (2026-10-03)
- v10의 한 줄 조판 자산 재사용은 균등 배율은 보장했으나, 짧은 음가 하나 때문에 전곡 음표가 지나치게 작아졌다. 두 줄용 간격 조판을 별도로 생성한다. 공통 조판 엔진과 음표 도형은 그대로 공유한다.
- 원생 마디 너비는 최소320단위이며, 전곡에서 필요한 머리·주법·장식음 간격 합계보다 작지 않게 한다. 각 마디에서 필요한 최소 간격을 먼저 확보하고 남는 폭을 음가에 따라 배분한다. 이 시간 비선형 간격은 두 줄 보기에만 적용한다. 재생선은 해당 조판의 beatXs를 따른다.

- 악보 크기 슬라이더는 실제50~200% 범위이고 중간 위치는50%가 아니다. 현재 수치를 output으로 항상 표시한다. 저장된 배율을 임의로 초기화하지 않는다.
- 홈 본문18px·곡 제목20px. 재생 화면 전체 글꼴에 영향을 주는 전역 변경은 하지 않는다.

## 배율 중앙 기준 정정 (2026-10-03 사용자 최신 결정)
- 앞선 '50%'는 배율50%가 아니라 슬라이더 이동 구간의 중앙이라는 사용자 정정에 따른다. 기존50% 기준은 폐기하고, 중앙=100%에서 한 줄 전체에4/4 약4마디(16quarter)가 보이게 한다.

- 현재 퍼센트와 눈금을 함께 표시. 포인터 드래그는 눈금에서 슬라이더 구간3% 이내이면 흡착하고, 밖으로 움직이면 해제. 키보드 미세조정에는 흡착을 적용하지 않는다.
- 화면 크기·BPM·배속 및 두 줄 보기 조판에는 영향을 주지 않는다. 이는 화면 확대 기준 변경이므로 MusicXML조판 캐시를 다시 생성할 필요가 없다.

### 2026-10-03 크레셴도 마디 끝 오프셋 (v14)

### 균등 모드 최종 정정: 고정 마디·32분 격자 (2026-10-04)

- 별도 grid SVG는 고정 좌우 여백 없이 마디 전체 폭에 시간 격자를 둔다. 양 끝은 격자 반 칸씩으로, 음표 중심은 (quarterOffset×8+0.5)×마디폭/격자수에 놓는다. 마디선은 앞마디 마지막 격자와 다음 마디 첫 격자의 정중앙이다. 4/4는32칸이며 quarterOffset×8을 격자 좌표로 삼는다. 음표와 쉼표가 적어도 격자 공간은 유지한다. 셋잇단·더 짧은 음가는 반올림하지 않고 분수 위치를 보존한다.
