# 원곡 BPM 표시 / 연습 박 간격 정규화 검증

- 대상: 로컬 `http://127.0.0.1:5173/player.html`, player 0.7.2, source `a217c29f2d81`.
- 설계: [AUDIO-TEMPO-NORMALIZATION](plans/AUDIO-TEMPO-NORMALIZATION.md).
- 커밋·푸시·배포·앱 버전 증가는 이번 범위에 포함하지 않았다.

## 구현

원곡은 원본 AudioBuffer와 1배속을 사용한다. 상단에는 최근 최대 4개 완료된 박 간격의 평균 BPM을 소수점 한 자리로 표시하며 매 박 갱신한다. 정지·선택 이동은 마지막 표시값을 유지한다. 원곡 버튼과 BPM 입력은 기준 BPM을 유지한다.

연습 모드의 출력 박 간격은 `60 / 선택BPM`이다. 원본↔출력 구간 선형 시간표 하나를 음원 오프셋·메트로놈·재생 커서·탐색·반복에 적용한다. 원본 초 단위의 마커·구간 데이터는 그대로 둔다. 박 경계 주변 최대 35ms의 타격음을 보존하고 사이 구간을 SoundTouch WSOLA로 변환한다. 경계는 최대 12ms 교차 페이드로 연결한다. 첫 박 이전과 마지막 박 이후는 기준 배속으로 변환한다.

설정은 `settings.tempoMode=original|practice`로 구분한다. 같은 숫자/배율에서도 모드를 구별하며, 변환 성공 후에만 설정·출력 버퍼를 함께 교체한다. 실패·취소·다른 곡 로드는 기존 재생 의도를 보존한다. 구형 저장값은 rate=1이면 원곡, 그 외 연습으로 해석한다. 추적 박이 없는 음원과 악보는 기존 균일 배속을 유지한다.

## 자동 검사

- 전체 `npm run test:drum`: **112개 파일 / 611개 검사 통과**.
- `npm run build:apps`: TypeScript·번역 키·분리 빌드·앱 경계 통과.
- `npm run check:playback`: 공통 재생 소유권·중복 검사·portable 번들 검사 통과.
- `git diff --check`: 통과.
- 합성 변속 신호: 배율 0.5 / 1 / 1.2에서 출력 길이, 각 타격 피크 목표 ±30ms, 좌우 440/660Hz 음높이 오차 <12Hz, 원본↔출력 시간 역변환 검사 통과. 동일 구간은 샘플 그대로 보존.
- 재생기: 같은 BPM의 원곡/연습 구분, 변환 오류·구 모드 요청 취소, 카운트오프, 탐색, 위치 유지, 반복 경계, JSON 저장 왕복 검사 통과.
- 기존 UI 검사 한 건은 `94` → `94.0` 표시 계약을 갱신했다. 별도 간헐 실패는 데모 표시 직후 아직 저장/로딩 중인 상태에서 BPM을 조작하던 검사였다. 로딩 완료 표시를 기다리도록 수정하고 전체 재검사했다.

## 실제 음원 / 브라우저

음원은 사용자 제공 YB 「붉은 노을」 MP3, 길이 267.8335초, 기존 분석 박 578개다. 원본 파일은 변경하지 않았다.

원곡 시험은 실제 버튼 재생으로 확인했다. 음원은 시험 중 무음으로 두고 pulse 호출의 Web Audio 예약 시각을 기록했다. 이는 스케줄링과 PCM 변환 증거이며 스피커 지연이나 사람의 청음 품질 평가를 뜻하지 않는다. 개발 페이지가 첫 변환 시험 도중 재로딩되어 그 실행은 무효로 하고, 같은 TaskSpace에서 재개해 완료했다. 셀렉터 불일치는 현재 DOM을 다시 확인하여 해결했다. 새로 만든 검증용 라이브러리 레코드만 삭제하고 시험 탭을 닫았다.

로컬 실측 원자료: `.tmp/tempo-warp/bench.json`, `browser.json`, `tests.log`, `build.log`, `playback.log`. 생성 음원과 원자료는 Git 제외 대상이며 외부에 전송하지 않는다.

## 한계

- 분석된 박 시각의 정확도에 의존한다. 잘못 추적된 박 자체를 이번 변환이 교정하지는 않는다.
- WSOLA/교차 페이드의 청감 품질과 iPhone·iPad 실제 기기의 처리 시간·메모리는 이번에 실측하지 않았다. 위 시간은 이 Mac의 측정값이다.
- 원곡의 소수점 한 자리는 표시 해상도이며 분석 정확도 보증이 아니다. 최근 4박 평균이므로 변화가 완만하게 반영된다.
