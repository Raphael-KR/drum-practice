## 사용자 표시 문구와 i18n

결정 근거: [ADR-0024](../../decisions/0024-korean-message-catalog.md). 실행: [절차](../../how-to/develop.md#i18n--앱-문구-변경-절차).

<a id="i18n--정본과-호출"></a>

### 정본과 호출

- 모든 앱 문구의 한국어 정본: `src/shared/i18n/locales/ko.json`.
- 조회/변수 치환/숫자·날짜·시간 형식: `src/shared/i18n/i18n.ts`.
- 컴포넌트 구조 정본: `src/shared/ui/ui-catalog.json`. `name.ko`, `accessible.ko`, 공통 상태의 `ko`는 문구 자체가 아니라 한국어 정본의 키다.
- 초기 HTML 제목: `vite.config.ts`가 정본에서 채운다. 두 웹앱의 제목·본문은 같은 문구 정본을 사용한다.

영어 전체 번역과 언어 선택기는 아직 제공하지 않는다. 기술 명칭(PDF, MusicXML, BPM 등)과 기존 영어 검증 문구도 키로 관리한다. 라이선스 원문과 외부 라이브러리가 반환하는 오류 원문은 외부 콘텐츠로 보존한다.

<a id="i18n--문구-계약"></a>

### 문구 계약

1. 의미가 같은 기존 키가 있으면 재사용하고, 새로운 문구는 의미를 설명하는 안정적인 키로 등록한다. 기존 자동 이관 키는 호환성을 위해 유지한다.
2. 호출은 `i18nText(key, {count, measure})`. 숫자·이름 등의 변수 위치를 문구에 `{count}`처럼 넣는다. 단어 조각을 이어 붙이는 새 문구를 만들지 않는다.
3. HTML 태그·속성 이름·CSS·파일 형식 식별자·저장 데이터 키는 번역하지 않는다. 화면의 텍스트와 접근성 이름만 분리한다. HTML 삽입 시 외부 값의 기존 escape 처리는 호출 측에서 유지한다.
4. 날짜·시간은 공통 형식 함수와 필요한 시간대를 사용한다. 빌드 시각은 Asia/Seoul과 KST 표시를 유지한다. 저장용 ISO 시각·좌표·MusicXML 숫자는 표시 번역과 분리한다.

<a id="i18n--콘텐츠-예외"></a>

### 콘텐츠 예외

곡 제목·가사·한국어 발음·교정 전후 자료는 앱 문구가 아니다. `scripts/checks/i18n-content-exceptions.json`에 검토한 파일과 **정확한 리터럴 값**만 허용한다. 파일 전체를 검사에서 제외하지 않는다. 같은 파일 안의 앱 오류는 i18n으로 관리한다. 콘텐츠 추가 시 실제 곡 자료인지 확인한 뒤 예외 목록을 명시적으로 갱신한다.

<a id="i18n--빌드의-문구-포함-범위"></a>

### 빌드의 문구 포함 범위

재생 웹앱 빌드는 tree shaking 후 남은 키를 한국어 정본에서 골라 포함한다. 카탈로그 정본을 복사해서 따로 수정하지 않는다. 제작 코드·저장소 유입의 앱 경계 검사를 유지한다. 독립 HTML 저장·내보내기는 [제품 범위](../../../PRD.md#앱과-입력)에 따라 지원하지 않는다.

<a id="i18n--검수-범위"></a>

### 검수 범위

AST 기반 한글 리터럴 잔여, 모든 정적 호출 키·필수 변수, 컴포넌트 키 연결, HTML 태그의 카탈로그 혼입을 검사한다. 정규식/프로토콜 토큰/아이콘 기호/사용자 콘텐츠는 번역 대상이 아니다. 영어 전체 화면 검수는 번역을 추가할 때 별도로 수행한다.
