# 문서 관리

문서 역할: **현행 Rule**. 현재 요구·계약과 지원 한계를 다룬다. [전체 정본](../../RULES-INDEX.md), [실행 안내](../../README.md), [결정 이력](../../decisions/README.md)을 함께 참고한다.

<a id="documentation-rules--프로젝트-문서-관리-rule"></a>

## 프로젝트 문서 관리 Rule

현행 계약·명령·이유·관측을 구분한다. 전체 목록은 [Rule 목록](../../RULES-INDEX.md), 분리 결정은 [ADR-0001](../../decisions/0001-separate-svg-rules-and-decisions.md)이다. 이 규칙은 이 프로젝트 문서 관리에만 적용하며 전역 지침을 복제하거나 다른 프로젝트에 강제하지 않는다.

<a id="documentation-rules--문서-역할"></a>

### 문서 역할

| 역할 | 담는 내용 | 위치 원칙 |
| --- | --- | --- |
| Rule | 현재 요구·금지·저장/표시/검증 계약 | `reference/`의 주제별 정본. 루트 AGENTS·PRD는 기존 위치 |
| 실행 절차 | 입력·선행 조건·순서·명령·완료 확인 | `how-to/`의 작업별 절차와 기존 스킬. 상세 규칙은 정본으로 연결 |
| 결정 이력 | 문맥·대안·선택·결과·대체 관계 | `decisions/NNNN-title-with-dashes.md`, MADR 4.0 |
| 사실 기록·참고 | 곡별 판독·검수·실측·배포 식별자·지원 상태·연구 후보 | `records/`, 곡별은 `records/songs/`, 완료 계획·연구는 `records/archive/`. 날짜·범위·한계를 명시 |
| 생성 문서 | 코드 정본에서 생성한 참조 목록 | 생성 스크립트로 갱신하며 수동으로 별도 규칙을 만들지 않음 |
| 목록 | 정본·절차·기록으로 가는 경로 | 규칙 본문을 복제하지 않음 |

<a id="documentation-rules--변경과-보존"></a>

### 변경과 보존

- 현행 동작을 바꾸면 해당 정본과 `history.md`를 함께 갱신한다. 같은 규칙을 다른 문서에 복제하기보다 정본을 연결한다.
- 혼합 문서는 현행 요구를 먼저 구분하고 실행 순서·이유·실측을 각 역할로 옮긴다. 곡별 예외나 검토 후보를 승인된 공통 Rule로 승격하지 않는다.
- 같은 결정은 기존 ADR을 재사용한다. 실제 새 결정이 이전 결정을 대체하면 새 ADR과 대체 링크/상태를 남긴다. 기존 문서의 결정 이관을 새 승인으로 취급하지 않는다.
- ADR의 YAML status는 결정 상태, date는 마지막 갱신일이다. 원래 날짜·버전·승인 범위·대체 전 시안은 본문에 보존한다. `accepted`는 구현·모든 기기 검증·배포 완료와 다르다.
- 원문·식별자·수치·검증 한계와 이전 경로·앵커의 대응표를 보존한다. 옮긴 문단은 현행 문서의 대응 내용으로 연결하고 상대 링크를 새 위치에서 다시 계산한다. 이전 주소 안내를 삭제할 때는 아래 경로 관리 기준을 따른다.
- 사용자 원본·악보·미디어·Git 제외 자료는 별도 보존 정책을 따른다. 과거 삭제된 증거를 필수 입력으로 안내하거나 존재를 가정하지 않는다. 당시 경로와 삭제/미확인 상태는 기록으로 남긴다.
- UI 컴포넌트 문서 등 생성물은 정본/생성 스크립트와 일치시킨다. 앱 코드 변경이 금지된 문서 정리에서 생성 코드를 수정해 검사를 우회하지 않는다.

<a id="documentation-rules--문서-변경-검증"></a>

### 문서 변경 검증

현재 규칙의 필드·값·표·권한 범위를 대조하고, 이관 원문·기존 ADR·파일/문단 링크를 확인한다. 이관 대상은 원문 절별 이전표에 빠짐없이 분류한다. Rule 목록에는 주 정본과 기계 입력 예외만 싣는다. 앱·악보 변경 금지 범위에서는 변경 전 해시와 대조하며 테스트/빌드의 생성 쓰기를 실행하지 않는다.

`npm run check:docs`는 생성 UI 문서와 상대 파일 링크만 확인한다. 상대 링크는 실제 파일이 존재하고 Git 추적 파일·비제외 신규 파일 또는 그 상위 폴더에 포함돼야 한다. 로컬에만 있는 Git 제외 자료는 보존 경로를 일반 텍스트/코드로 기록하여 CI에서 열 수 있는 링크와 구분한다. 문단 앵커·절대경로·외부 URL·규칙 의미·앱 동작까지 검증했다고 보고하지 않는다. 추가 원문/앵커/범위 대조 결과와 미확인을 `history.md`에 남긴다.

## 경로와 정본 관리

- 일반 문서의 새 파일명은 소문자 하이픈을 사용한다. 루트 관례 파일명과 기존 ADR 식별자는 유지한다.
- 한 규칙·절차·원문 기록에는 하나의 주 보존 목적지를 둔다. 다른 문서는 링크로 연결한다. 곡별 예외를 공통 규칙에 복사하지 않는다.
- 공통 Rule에서 제작 사례를 안내할 때는 [곡별 제작 기록 목록](../../records/README.md#곡별-제작-기록)으로 연결하고 원본 형식·문제·검증 범위가 유사한 사례를 선택한다. 특정 곡·과거 작업을 기본 사례로 고정하지 않는다. 승인된 곡별 예외·호환성 계약·성능 기준의 범위를 식별하는 참조는 목적과 범위를 명시하여 유지한다. 과거 통합·실측 기록은 조회 근거이며 새 실행 결과의 기록 목적지로 안내하지 않는다.
- `plans/`에는 진행 중 계획만 두고 완료 후 기록으로 옮긴다. 코드가 읽는 화면 소유권 표는 명시적 예외이며 같은 표를 복제하지 않는다.
- 유지가 필요한 이전 문서 주소에는 제목·이전 안내·기존 앵커별 링크만 둔다. 사용자가 삭제를 승인한 안내는 내부 링크를 새 목적지로 바꾸고 이전표에 삭제 상태를 기록한 뒤 제거한다. 코드/설정 참조가 남은 주소는 소비 코드를 함께 변경할 권한이 없으면 유지한다. 삭제한 주소의 과거 대화·외부 링크는 더 이상 연결되지 않으며 Markdown 안내도 자동 HTTP 리다이렉트로 취급하지 않는다.
- 내부 Markdown·지침·스킬의 현재 참조는 새 위치를 쓴다. 코드/설정이 읽는 기존 경로는 소비 코드 변경 권한이 없는 문서 작업에서 유지한다. 과거 명령·증거 경로는 소급 변경하지 않는다.
- 원문 절별 출발 경로·앵커·목적지·상태와 의미 대조 결과는 문서 기록에 둔다. Git 미추적 원문도 실행 전 스냅샷으로 보존한다.

공통 문서 구성은 ISO/IEC/IEEE 15289의 정보 항목 구분과 Diátaxis를 프로젝트에 맞춰 적용하고, 결정 이력은 MADR 4.0을 따른다. 전체 표준 적합 인증을 의미하지 않는다. 선택 이유와 경로 유지 예외는 [ADR-0001](../../decisions/0001-separate-svg-rules-and-decisions.md)에 기록한다.
