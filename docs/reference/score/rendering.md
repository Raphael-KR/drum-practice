## SVG 전체 악보 생성 규칙

MusicXML에서 파생한 전체 보기·연습용 SVG에 적용한다. 이유·폐기 시안·과거 검증은 [결정 기록](../../decisions/README.md)을 참조하며 새 구현의 통과 증거로 쓰지 않는다.

<a id="svg-score-rules--1-범위와-원본-보존"></a>

### 1. 범위와 원본 보존

- 정본은 곡별 MusicXML이며 SVG는 재생성 가능한 파생 결과다. PDF 원본은 변경하지 않는다.
- 제목·작사·작곡·악기·성부·화음·음가·가사·동기화 의미를 보존한다. 표시 편의로 성부·chord·stem·beam·rest·backup/forward를 재작성하지 않는다. 구형 가사 전환은 [공통 작성기·읽기용 사본 규칙](#svg-score-rules--전체-보기-가사)을 따른다.
- [수정 책임](musicxml.md#musicxml-canonical--정본과-앱의-수정-책임)에 따라 정본 오류는 정본에서, 해석·표시 오류는 공통 렌더러에서 고친다. 렌더 사본·SVG로 정본의 오류·누락·규칙 위반을 감추지 않는다.
- 입력 의미·악기/주법 인코딩은 [MusicXML 매핑 정본](notation.md#score-musicxml-osmd-mapping--악보의-musicxml--osmd-매핑-규칙), 저장은 [정본 계약](musicxml.md#musicxml-canonical--musicxml-정본-계약)을 따른다.
- 일반 도형·텍스트 대체 매핑은 보고 후 사용자 명시적 결정이 필요하다. 기존 고스트·스티킹 보완은 §5의 승인 범위에서 적용한다.

**전체 보기의 메타정보**

- 재생선·선택 배경·마커 버튼·발광 효과는 넣지 않는다.
- 기본 BPM·가수는 공통 조판기의 OSMD `GraphicalLabel`로 출력한다. 부제목과 같은 `SheetSubtitleHeight`(기본 2단위, 20 SVG px), `FontStyles.Bold`, Pretendard를 사용한다.
- 글꼴 크기를 별도로 하드코딩하거나 HTML로 표시하지 않는다. 두 라벨은 악보와 함께 확대·축소한다.
- 악보 안의 메트로놈·중복 BPM 지시문과 작사·작곡자 표시는 숨긴다. 템포·제작자 데이터는 보존한다.

**줄·페이지 구성과 폭**

- 줄·페이지 배치 의도는 XML의 `system-distance`·`top-system-distance`·`new-system`·`new-page`에 기록한다. 정본의 값을 지우거나 덮어쓰지 않는다.
- 전체 보기는 종이 쪽·XML 세로 간격 대신 아래 연속 배치를 사용한다. `new-system`·`new-page`는 모두 줄 시작이며 원본의 줄별 마디 구성을 유지한다. 고정 마디 수를 강제하지 않는다.
- OSMD가 폭 부족으로 XML에 없는 줄을 추가하면 원본 줄별 native 음표·가사 최소 폭과 시작/끝 지시 폭·여백을 합산한다. 가장 넓은 줄을 담도록 한 번 재조판한다. 음표 간격을 억지로 줄이거나 정본·완성 SVG를 수정하지 않는다. 악보·글자 전체를 화면 폭에 맞춰 확대·축소한다.
- 명시한 줄 경계가 없으면 OSMD 자동 줄바꿈을 유지한다.

- 연습용 인쇄 조판은 XML 줄/페이지 나눔·간격을 유지한다. 알려진 기본 곡의 첫 top-system-distance가 없으면 제작 단계에서 정본에 180tenths를 기록한다.
  TitleBottomDistance로 변환할 때 제목 높이·상단 거리를 제외하고 0 이상으로 한다. 전체 보기 첫 줄은 제목·메타정보·실제 줄 경계로 계산한다.

**캔버스 경계**

- 마지막 기호 아래 30 SVG 단위만 남기도록 출력 캔버스 높이를 줄인다. 원본 XML 용지 정보·마디·줄 구성은 보존하고 파생 마디 좌표는 최종 viewBox로 정규화한다.
- SVG 상단은 오선 맨 위 선의 8간격 위와 최상단 기호 위 5 SVG단위 여유를 모두 포함한다. 첫 시스템 기호가 Y=0 위로 나가면 viewBox 시작 Y와 높이를 확장한다.
  기호 좌표·원본 XML은 유지한다. 마디 영역·오선 위치를 최종 viewBox로 정규화하고 연습 사본의 섹션 가로 보정·음표 빛나기에도 같은 원점을 쓴다.

- 전체 SVG 보기에는 쪽 캡션·페이지 사이 여백을 만들지 않는다. 번호·기호·가사는 같은 SVG 이미지로 표시하고 닫을 때 표시 URL을 해제한다.

#### 전체 보기의 마디 번호

- 번호의 기준은 MusicXML 정본의 `<measure number="…">`다. `Song.measures[].label`이나 내부 SVG 식별자를 사용하지 않으며, 정본·Song 메타정보에 번호용 텍스트·지시문을 추가하지 않는다.
- 두 앱의 전체 보기에서 [OSMD 옵션](https://opensheetmusicdisplay.github.io/classdoc/interfaces/IOSMDOptions.html) `drawMeasureNumbers`·`drawMeasureNumbersOnlyAtSystemStart`·`UseXMLMeasureNumbers`를 켠다. 각 줄 첫 마디에 하나씩 표시하며 곡 시작 1번·섹션 있는 줄도 포함한다.
- OSMD 2.3의 첫 1번 생략은 `full-score-layout.ts`에서 보완한다. SVG 생성 전 전체 보기 인스턴스의 `calculateMeasureNumberPlacement`만 교체한다. 각 줄 첫 마디를 `calculateSingleMeasureNumberPlacement`에 한 번 전달한다.
  XML 번호 읽기·라벨 생성·위치·skyline·그리기는 OSMD를 재사용한다. 엔진 업데이트 시 내부 함수 연결과 첫 줄·이후 줄·섹션 있는 줄을 검증한다.

- 번호는 OSMD 기본인 **마디 시작점 위쪽**에 두고 악보와 함께 확대·축소한다. 앱의 X/Y·정렬·오프셋 지정, SVG 이동·추가·삭제, HTML 번호 overlay·좌표 계산·전용 CSS는 사용하지 않는다.
- 전체 보기 전용 캐시 정책을 `full-score-continuous-v10-xml-system-width`로 구분한다. 이전 HTML 번호 방식·자동 줄바꿈 결과의 파생 SVG를 재사용하지 않고 연주 화면의 번호·마커·선택·조작과 캐시 경로는 유지한다.

#### 표시제목과 원제

- 표시제목은 `drum-practice:display-title`, `movement-title` 순서로 앞뒤 공백을 제외한 내용이 있는 값을 읽고, 원제는 `work/work-title`에서 읽는다.
- 두 제목이 같으면 표시제목만, 다르면 표시제목과 원제 부제를 출력한다. 표시제목이 없으면 원제만 출력한다. 빈 부제는 만들지 않는다.
- 동일 여부는 앞뒤 공백 제거·Unicode NFC 정규화 후 비교한다. 저장된 MusicXML·`Song`의 제목은 변경하지 않는다.
- 공통 `renderMusicXMLEngine`은 XML 복제 직후 `prepareEngravingTitles`를 적용한다. 조판용 사본의 `work-title`에는 제목, `movement-title`에는 부제의 원래 문자열을 배치한다. 부제가 있을 때만 `RenderSubtitle`을 켠다.
- OSMD가 부제에 붙이는 `work-number`와 제목을 덮어쓰는 `credit-type=title/subtitle`은 조판용 사본에서만 제외한다. 연습용 제목 식별도 이 사본의 문자열을 사용한다.
- 정본을 다시 저장하거나 곡별 예외·완성 SVG 후처리로 중복을 지우지 않는다.
- 제목 출력 정책은 전체 보기·연습용 키가 공유하는 `SCORE_RENDER_POLICY`에 포함된다. 이전 정책의 파생 SVG는 재사용하지 않으며 원본·연습 정보 저장 형식은 유지한다. 현재 정책은 아래 [SVG 가사 배치](#svg-score-rules--전체-보기-가사)를 따른다.

#### 연속 보기의 일정한 오선 간격

- OSMD가 음표·섹션·지시문·크레센도·가사의 경계를 계산한 뒤, 절대 좌표 변환·그리기 전에 시스템 전체의 Y만 한 번 배치한다. 각 시스템 내부의 기호·음표·가사 관계는 유지한다.
- **앞줄 표기 하단과 다음 줄 표기 상단 사이 여백을 두 칸**으로 한다. 오선 시작 Y 간격을 전곡 동일하게 강제하거나 다른 줄의 돌출로 현재 여백을 늘리지 않는다.
- 각 줄의 native skyline/bottomline을 오선 기준 좌표로 읽는다. 앞줄 하단을 `B`, 다음 줄의 상단 돌출 좌표를 `T`라고 하면 다음 오선 Y는 `B + 2 - T`다. 다음 줄을 놓은 뒤 그 줄의 하단으로 `B`를 갱신하며 한 번 순회한다.

  첫 줄은 제목·메타정보의 하단을 `B`로 사용한다. OSMD의 1단위는 오선 한 칸이며 선명한 선의 픽셀 격자에 맞추는 올림은 0.1단위 미만이다. native 충돌 경계에 포함된 기호 보호 여유는 유지한다.

- 전체 보기 전용이며 연주 조판·PDF에는 적용하지 않는다. 전곡 최대 돌출·기존 페이지/시스템 간격, 곡별 보정표·개별 기호 이동·반복 충돌 탐색·스크롤 중 재조판은 사용하지 않는다.
- 구현·검수 범위는 [연속 보기 계획](../../plans/continuous-full-score-20261110.md), 정책 변경 근거는 [ADR-0002](../../decisions/0002-svg-page-output.md#연속-보기와-메타정보-표시--2026-11-10)에 기록한다.

#### SVG 가사 배치

##### 가사 원천과 성부

- 두 앱의 전체·연주 1줄·2줄·균등 보기는 `musicxml-engine.ts`의 OSMD `drawLyrics`를 사용한다. 별도 HTML 가사 행과 그 행의 충돌 재배치·전용 CSS는 두지 않는다. PDF에는 원본 인쇄 가사만 표시한다.
- v2 정본의 독립 가사 성부를 드럼과 같은 보표에 전달한다. 가사 성부의 음표·쉼표는 숨기고 `HiddenVoicesKeepLayout`·`RenderLyricsOfHiddenVoices`로 가사만 출력한다.
- 가까운 드럼 음표로 스냅하거나 가사 성부를 제거하지 않는다. 가사·크레센도·보표 간격은 OSMD 배치를 기본으로 하며, 아래 공통 충돌 처리 조건을 적용한다.
- v1 가사 파트는 `prepareScoreLyrics`에서 조판 pass 전에 한 번 읽어 사본만 같은 보표 성부로 전환한다. `canonical-lyric-read.ts`·`canonical-lyric-voice.ts`를 재사용해 ID·독립 onset/duration·마디 연장·겹침을 보존한다. 파일·DB·패키지·원래 XML은 변경하지 않는다.

##### 마디 문구

- XML manifest의 `measureLyrics`를 마디 순서로 연결해 `installScoreLyrics`의 OSMD `GraphicalLabel`로 출력한다. 전체 보기의 미저장 편집은 전달된 Song의 같은 마디 문구를 사용한다.
- 음절·가짜 음표·박 위치를 만들지 않는다. 마디 중앙에 배치하고 마디 폭에서 줄바꿈하며 native 하단 경계에 높이를 반영한다. 음절 가사 아래에 놓고 원본 마디가 없는 `IsExtraGraphicalMeasure`는 제외한다.
- 문구가 없으면 그리기 훅을 등록하지 않는다.

##### 크기·색·표시 경계

- 음절·마디 문구는 Pretendard·`scoreTextHeight`를 공통 사용한다. `LyricsHeight = (RehearsalMarkFontSize + 3) × (96/72) ÷ 10`으로 섹션·지시문보다 3pt 크게 한다.
  현재 13pt = 17⅓ SVG px, `DefaultColorLyrics = #3f74d4`다. 악보와 같은 SVG에서 함께 확대·축소하며 별도 HTML 배율은 없다.

- 연주용 마디 경계에는 OSMD 음절·연장선·하이픈·마디 문구의 실제 SVG 잉크를 포함한다. 제3선 정렬·동일 배율·원래 음가를 유지하면서 가사 아래까지 프레임을 확장한다. 숨은 가사 음표는 음표 강조와 드럼 온쉼표의 중앙 배치 대상에서 제외한다.

  일반 시간축 조판의 최소 간격에는 가사 폭을 포함하고 균등 보기의 박 격자는 유지한다.

- 연주용 시간축에서는 OSMD의 좁은 X 구간 충돌 검사로 아래 줄기와 가사가 겹치지 않도록, 가사 배치 직전 마디 전체의 native bottomline을 하한으로 사용한다.

  음절 상단이 이 경계와 `LyricsYMarginToBottomLine` 여유보다 높으면 해당 마디의 모든 절을 같은 양만큼 아래로 이동한다. 절 사이 간격·연장선·하이픈은 native 경로로 유지하고 마디 문구는 그 아래에 배치한다.

  전체 보기는 기존 native 배치를 유지하며 정본·완성 SVG는 수정하지 않는다.

##### 캐시와 데이터 보존

- 전체 연속 보기와 연주용 페이지·시간축 배치는 분리한다. 전체 보기 키는 원문·파트·마디 ID·마디 문구·가수·기본 BPM·전용 정책을 포함한다.
  공통 정책 `drum-print-ribbon-v47-stem-initialization`로 이전 전체·연주 SVG 캐시를 구분한다. 이전 가사 배치·격자·스티킹 글꼴 캐시를 재사용하거나 스크롤·재생 프레임마다 재조판하지 않는다.

- 드럼연습실 설정 > 악보에는 전체 PDF·SVG 보기만 제공한다. 전체 가사 보기 메뉴와 별도 HTML 가사 행은 제공하지 않는다.
- 전체 원문은 `drum-practice:lyric-text`, 마디 문구는 manifest, 음절은 `note/lyric`에 보존한다. 표시 메뉴가 없다는 이유로 삭제하지 않는다. 제작기의 가사 편집·텍스트 읽기·내보내기와 저장 호환성은 유지한다.

##### 출력 검수

- 전체·1줄·2줄의 가사 색/배율·잘림·독립 리듬·마디 연장·겹침·마디 문구와 PDF 중복 표시를 확인한다. 정적 검사로 출력 검수를 대신하지 않는다. 근거: [전환 기록](../../records/archive/osmd-native-lyrics-review-20261110.md). 저장: [정본 계약](musicxml.md#musicxml-canonical--저장-계약).

<a id="svg-score-rules--3-타악기-음자리표와-세로줄"></a>

### 3. 타악기 음자리표와 세로줄

- 타악기 음자리표 `||`는 첫 마디·시스템 시작을 포함한 앱 SVG에서 숨긴다. XML의 percussion clef와 악기 정보는 유지한다.
- 실제 세로줄·겹세로줄·마침줄·도돌이표는 유지한다.
- 모든 명시 clef가 percussion인 렌더 문서에서만 `.vf-clef`를 제거한다. 혼합 clef의 선택적 제거는 미지원이며 일반 음자리표를 함께 지우지 않는다.
- PDF 연습 화면은 줄 앞 타악기 표기·여백을 잘라 다른 마디와 길이를 맞춘다. 그 과정의 인쇄 가사·마디 숫자 잘림은 허용하며 이를 보존하려고 타악기 표시를 남기는 예외를 두지 않는다.
- 원본 PDF/XML, 첫 음표·박자표·실제 마디선·진행선 좌표는 보존·대조한다. 가로 prefix 자르기와 상하 내용 보존을 구분한다.

<a id="svg-score-rules--4-구간-시작-표시"></a>

### 4. 구간 시작 표시

<a id="svg-score-rules--섹션연주-지시-7가지-원칙"></a>

#### 섹션·연주 지시 7가지 원칙

아래 7가지를 현재 제작 기준으로 적용한다.

1. **섹션 테두리를 해당 마디의 오선 시작점에 좌측 정렬한다.**
   줄 중간의 섹션도 해당 마디 시작점을 기준으로 한다. 테두리 여백과 선 두께를 포함한 **바깥선의 왼쪽**을 맞춘다.

2. **연주 지시의 음악적 적용 박은 원본과 동일하게 유지한다.**
   표시 위치도 기본적으로 원래 적용 박을 따른다. 표시를 옮겨도 연주·재생의 적용 시점은 바꾸지 않는다.

3. **섹션과 겹치거나 최소 여백이 부족하면 표시 위치만 뒤로 이동한다.**
   **64분음표 길이(사분음표의 1/16)씩** 탐색하고, 조건을 만족하는 가장 작은 offset을 선택한다. 최소 여백은 **인접한 오선 두 선 사이 간격의 ¼**로 한다. 테두리 선 두께와 실제 글자 경계를 포함해 판정한다.

4. **모든 배치 의도를 MusicXML에 기록한다.**
   섹션은 `rehearsal`, 연주 지시는 별도 `words`로 저장한다. 섹션 위치·정렬과 지시문의 표시 offset을 XML에 기록하며, 표시 이동에는 **`<offset sound="no">`**를 사용한다. 해당 `words`에는 offset을 무효화하는 `default-x`를 병용하지 않는다. 별도 좌표표나 수정된 SVG 없이 재생성할 수 있어야 한다.

5. **미지원 속성은 최신 안정판에서 먼저 확인하고 공통 조판 단계에서 보완한다.**
   호환성 검증 후 필요한 업데이트를 적용한다. 여전히 미지원이면 제작기·재생기가 공유하는 조판 단계에서 XML 속성을 반영한다. 재현 기준은 **동일한 공통 조판기·Pretendard·조판 폭**으로 한다.

6. **가로 이동은 같은 줄 안으로 제한하고, 공간이 없으면 높이를 분리한다.**
   지시문 전체가 같은 줄 안에 들어가야 한다. 배치할 공간이 없으면 추가 표시 offset을 **0으로 되돌려 원래 적용 박 위에 놓고**, 별도 높이에 배치한다. 세로 이동도 `words`의 `relative-y` 등으로 MusicXML에 기록한다. 최종 배치는 섹션·음표·다른 지시문·인접 줄과 겹치지 않고 최소 여백을 확보해야 한다.

7. **섹션 표제는 원본에 명시된 것만 사용한다.**
   전사에서는 원본의 섹션 이름·순서·적용 마디를 보존한다. 직접 작곡·편곡에서는 승인된 작곡·편곡 명세를 기준으로 한다. 제작자의 분석이나 설명을 임의 표제로 추가하지 않는다. 승인된 연습곡의 표제를 PDF가 없다는 이유만으로 제거하지 않는다.

기술 단위: MusicXML의 divisions는 사분음표 기준이다. divisions가 96이면 64분음표 길이(사분음표의 1/16)는 6divisions이며, 오선 한 간격 10tenths의 ¼은 2.5tenths다. [offset 규격](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/offset/)은 `sound="no"`의 적용 위치 보존과 `default-x` 우선순위를 정의하고, [words 규격](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/words/)은 세로 위치 속성을 정의한다.

<a id="svg-score-rules--공통-xml-위치-계약"></a>

#### 공통 XML 위치 계약

마디 앞 섹션은 제작 단계에서 정본에 `default-x="0"`, `relative-x="0"`, `halign="left"`, `justify="left"`를 기록한다. 필수 속성의 누락을 앱이 추정·보충하지 않는다. 정상 속성의 해석 오류는 공통 렌더러에서 고친다.

- rehearsal의 default-x 원점은 자기 마디 오선 전체 시작점이다. relative-x를 더하고 오선 간격/10으로 tenths를 환산한다. halign을 우선하고 생략 시 justify, 둘 다 없으면 left다. native 단일행 범위이며 여러 줄 내부 정렬을 보장하지 않는다.
- 글자 폭·padding·stroke를 포함한 테두리 바깥선을 앵커에 맞춘다. left/default-x0은 바깥선=오선 시작을 뜻한다. glyph·음표 좌표를 사후 이동하지 않고 native StaveSection 그리기 인자를 계산한다.
- 모든 보기·줄 첫머리·중간에서 섹션 테두리 상단 경로를 오선 맨 위 선의 7간격 위에 둔다. 선 두께는 경로 양쪽에 걸친다.
  실제 마디 SVG 그룹의 native 섹션(`.vf-stavesection`) 테두리·글자를 함께 이동한다. 높이는 native 오선 좌표로 구하며 곡별·마디별 보정표는 두지 않는다.

- 섹션이 있는 시스템은 native 세로 배치 전에 **오선 위 최소 8칸을 줄 전체 skyline에 확보**한다. 기존 skyline이 더 높으면 유지한다.
  최종 words 배치 후 줄 경계를 계산하고 공통 조판에서 줄 간격을 확보한다. XML 줄 시작·섹션 적용 마디·음표 크기는 유지한다. 섹션이 이전 줄과 겹치거나 연습 crop에 이웃 줄 오선·섹션이 들어오지 않게 한다.

- 일반 words의 default-y·relative-y는 native 라벨·skyline 계산 전에 반영한다. Y 양수는 위쪽, default-y의 원점은 오선 맨 위 선이며 relative-y는 default/native 위치에 더한다. 실제 글자 경계를 시스템 crop에 포함한다.
- 템포로 분류된 지시·서로 다른 Y가 합쳐진 라벨에 개별 위치를 적용할 수 없으면 기존 배치를 보존하고 경고한다. 전체 악보를 거부하거나 지원 완료로 보고하지 않는다.
- 원본에 지시 높이의 근거가 있으면 XML `default-y`에 기록한 뒤 최소 표시 offset을 탐색한다. 공통 도구의 지원 범위는 [지시문 offset 도구](tools.md#common-tools--지시문-offset)를 확인한다. 재현은 두 앱이 공유하는 `renderMusicXML`을 사용한다.
- 섹션 편집은 정본 rehearsal을 변경하고 기존 렌더 경로로 SVG와 마디 영역을 함께 재생성한다. PDF 원본은 유지한다.

#### 좁은 연습 조판의 지시문

- 한 줄·두 줄·균등 연습 조판은 XML의 적용 박·표시 offset을 유지하고 마디 상단 전체 폭을 활용한다. 중앙 앵커 좌우 중 작은 폭으로 줄바꿈하지 않는다.
- 오선 경계·시스템 간격 계산과 SVG 그리기 전에 실제 글꼴 폭으로 배치한다. 들어가는 문구는 한 줄로, 넘는 문구는 전체 폭에서 최소 줄바꿈·왼쪽 정렬한다. 첫 박 지시문이 가운데에서 시작하지 않게 한다.
- 텍스트 상자는 마디 폭 안에서 원래 왼쪽 위치를 최대한 유지한다. 상자 정렬과 시간축의 표시 이동을 구분한다. 섹션과 충돌하면 위쪽으로 분리하며 최소 여백은 오선 간격의 ¼이다.
- 섹션 오른쪽에 한 줄로 들어가면 그 공간을 먼저 사용한다. 들어가지 않을 때만 위쪽으로 높이를 분리한다. 글자의 기준선 아래 부분도 간격 계산에 포함한다.
- 원본 줄바꿈을 보존하고 공백 사이 단어 단위로 추가 줄바꿈한다. 공백 없는 긴 문자열 분할은 보장하지 않는다. 인쇄 조판·정본·완성 SVG 좌표는 유지하며 곡별 좌표표를 두지 않는다.
- 실제 여러 줄 글자 경계를 시스템 crop에 포함한다. 표시 프레임도 그 crop을 수용하도록 확장해 마디 번호나 프레임 위에서 지시문이 잘리지 않게 한다.

<a id="svg-score-rules--악보-텍스트-글꼴"></a>

#### 악보 텍스트 글꼴

- 섹션·연주 지시·가사·제목 등 악보의 모든 텍스트는 Pretendard로 통일한다. 음악 기호 전용 글리프는 유지한다. 일반 앱 UI 글꼴 변경으로 확대하지 않는다.
- 모든 보기의 섹션·연주 지시는 같은 native 크기를 사용한다. VexFlow의 pt와 OSMD의 SVG px는 96/72로 환산한다. 섹션은 굵게, 지시는 원래 굵기로 표시하며 XML 글자 속성은 보존한다.
- 가사·마디 문구의 `scoreTextHeight` 환산과 3pt 확대는 [가사 배치](#svg-score-rules--전체-보기-가사)를 따른다.
- 로컬 Regular/Bold WOFF2를 측정 전에 로딩한다. DefaultFontFamily·VexFlowTextFontFamily·native rehearsal 측정/출력·OSMD 가사에 같은 글꼴을 사용한다.
- XML word-font·lyric-font·텍스트 font-family에 이름을 기록한다. 독립 SVG에는 원본 WOFF2·OFL 고지를 포함한다. XML 글꼴명은 바이너리 내장을 뜻하지 않는다.
- 독립 SVG의 테두리 안 글자 포함과 ko/en/언어 미지정 환경의 동일 폭을 확인한다. 글꼴 변경 시 최소 표시 offset도 재계산한다.

관련 결정과 검증 범위: [ADR-0009](../../decisions/0009-musicxml-section-direction-layout.md), [ADR-0010](../../decisions/0010-pretendard-score-text.md).

| R/L              | 타격마다 하나, words 저장. native getStemX/getStemExtents의 줄기 중심 X·줄기/머리 상단보다 9 SVG단위 위,16px·중앙 정렬·§4 글꼴 |
| 스티킹 연결      | divisions·backup·forward·offset·voice로 정확한 타격에 연결. 상충 R/L 중첩 금지                                                 |
| 진단 문구        | R words·R other-technical 등 실험 설명을 악보에 표시하지 않음                                                                  |
| 연음 숫자        | 모든 묶음의 숫자 유지. TupletNumberLimitConsecutiveRepetitions=false를 전 경로에 적용. 일반 문자로 대체하지 않음               |

- 고스트·스티킹 식별용 임시 색은 출력 후 복원한다. 대상 머리를 찾지 못하면 근거와 함께 오류를 보고한다.
- pictHalfOpen1은 연결선/기둥 위에 native stem extents 기준으로 배치한다. 입력·전용 glyph는 유지한다. 일반적인 circle-x 원 확대 및 특정 곡의 빈 머리 예외를 재도입하지 않는다.
- beam의 높이 방향은 같은 높이·방향 전환이면 수평, 한 방향 진행이면 완만한 경사다. 화음은 연결선 쪽 머리를 기준으로 하고 경사는 ≤0.08·양끝 높이 차이는 ≤오선 간격½, 최소 줄기 길이는 줄이지 않는다.
- StemWidth=0.1(원생 SVG 1단위)을 사용하고 머리·꼬리·오선·빔을 일괄 가늘게 하지 않는다.
- 도움말은 닫기→열었다 닫기→반열림 순서와 같은 note의 native ○＋를 사용한다. 정적 그림 생성은 [범례 문서](../../design/legend-diagram/README.md)를 따르며 악보 좌표 보정에 사용하지 않는다.

<a id="svg-score-rules--native-조판-계약"></a>

#### native 조판 계약

- harmonic·stopped는 native VexFlow ah/vb9·a+/v8b glyph를 유지한다. 일반 harmonic 의미와 이 프로젝트의 승인된 하이햇 용도는 [입력 매핑](notation.md#score-musicxml-osmd-mapping--o-복합-지시의-승인-범위)에서 구분한다.
- 명시 좌표가 있는 개체만 getXShift/getRenderY에 연결하고 geometric skyline 계산 전에 설치한다. 완성 SVG를 옮기지 않으며 좌표가 없으면 native 기본값을 유지한다.
- X 원점은 정확한 chord member 머리 왼쪽, Y 원점은 오선 맨 위 선이다. 오선 간격/10으로 tenths를 환산한다. glyph 중심을 XML 좌표에 연결하며 같은 default-y는 중심 높이를 맞춘다. Y 양수는 위쪽, relative-x/y는 default/native 값에 더한다.
- 지원 범위는 한 VoiceEntry에 harmonic·stopped가 각각 하나인 입력이다. 같은 종류를 여러 chord member에 반복 지정하는 일반 지원으로 확대하지 않는다.

<a id="svg-score-rules--6-쉼표"></a>

### 6. 쉼표

- 역할별 높이는 확정 XML 좌표를 따른다. 가까운 음표나 모양으로 성부를 재분류하지 않는다.
- 모든 드럼 성부가 쉬면 제작·편집 준비의 정본 교정에서 온마디쉼표 높이를 제거하고 기본 중앙 배치를 쓴다. 가사 성부는 쉼 판정에서 제외한다.
- 읽기 호환 경로에서 명시 높이로 중앙 정렬이 우회되면 기호 경계로 보완한다. 음악적 시작·재생 좌표는 마디 시작, 표시 기호만 중앙에 둔다. 균등 보기에도 적용하며 새 정본의 입력 위반을 감추는 데 쓰지 않는다.
- 부분 마디 쉼표는 리듬 시작을 유지한다. 2분·점2분쉼표라는 이유로 중앙에 옮기지 않는다.

<a id="svg-score-rules--7-마디-좌표와-자르기"></a>

### 7. 마디 좌표와 자르기

- GraphicSheet의 마디·성부·페이지 좌표를 사용한다. engraving unit1=SVG10단위다. 픽셀로 음가를 추정하지 않는다.
- 마디 가로 영역은 GraphicSheet의 BorderLeft/Right를 쓴다. 전체 SVG 상단은 [최소 8오선 간격·높은 기호 확장](#svg-score-rules--2-전체-페이지-생성)을 따른다.
  연습 상하 경계는 실제 시스템 잉크로 구하고 최종 viewBox 안으로 제한한다. 고정 상하 여백 계산은 정상 경로에서 사용하지 않는다.

- 연습용 trim은 같은 시스템의 실제 음표·쉼표·표제 경계에 상하5 SVG단위를 확보한다. 원래 시스템 밖 잉크는 clip-path로 가린다. 제목은 전체 SVG에 두고 연습 복제본에서만 제거한다.
- 시스템 경계는 실제 마디 SVG 그룹(`getSVGGElement`)의 전체 잉크·native 오선 좌표(`getVFStave().getYForLine(0)`)로 구한다. 중첩 `.vf-stave`의 섹션·주법·음표도 포함한다. `.vf-measure` 직속 path만 보거나 path 문자열로 줄을 식별하지 않는다.

- 두 앱의 1줄·2줄·균등 마디 표시는 실제 시스템 경계로 clip한다. 별도 8 CSS px 상단 확장은 쓰지 않는다. 하단 잉크+5 SVG단위까지만 표시해 다음 줄 음표의 유입을 막는다.
  배율·박/가사 시각·PDF 표시·정본은 유지한다. 경계 변경 시 캐시 정책을 올려 이전 고정 fallback 경계를 재사용하지 않는다.

- words 실제 경계와 마디 바깥 native wedge·음절/마디 가사·하이픈·연장선도 포함한다. 음표·빔 잘림이나 옆줄 기호 유입은 좌표·변환을 고쳐 해결하며 리듬을 바꾸지 않는다.
- `beatXs`는 악보의 음악적 timestamp를 박자표 분모로 환산하고 인접 좌표를 보간한다. 녹음의 개별 타격 시각을 의미하지 않는다. 연음을 정수 박으로 반올림하지 않으며 페이지와 대응 마디 영역을 함께 갱신한다.
- wedge의 명시된 마디 내부 stop은 native `Timestamp + EndOffsetFraction`에 있는 음표 머리 오른쪽 앵커를 사용한다. 음표 사이의 분수 박은 실제 인접 앵커 사이를 보간한다. 직전 음가·다음 음표와 섞은 native 여백 계산으로 종료 박을 당기지 않는다.
- 인쇄·한 줄·두 줄·균등 조판은 같은 wedge 앵커를 사용한다. native 선·경계·skyline을 SVG 그리기 전에 갱신하며 원본 XML·음악 시각은 유지한다. 마디 끝 stop의 기존 경계 처리·soft accent·verbal dynamic은 유지한다.
- PDF 상하 프레임은 인쇄 가사까지 포함하는 공통 오선 배율/기준선을 구한다. 일부 검출이 실패하면 전체를 종전 crop으로 유지한다. 같은 인쇄 줄은 한 번 검출하고 원본 PDF·박 좌표는 보존한다.
- PDF/MusicXML 비교의 오선도 같은 페이지·y·높이의 인쇄 줄 전체에서 검출해 공유한다. 오선 없는 영역은 검수 오류로 남긴다.
- 곡별 prefix crop은 곡 ID·영역·박 앵커가 검증된 경우에만 displayRegion에 적용한다. 오른쪽 경계·원래 음표/박 절대좌표를 유지하며 표제는 재생 복제본에서만 함께 조정한다.

<a id="svg-score-rules--8-연습-화면-전용-배치"></a>

### 8. 연습 화면 전용 배치

- 전체 페이지와 연습 화면 배치를 구분한다. 두 앱은 공통 playback-layout·playback-frame을 사용한다. 화면 크기·BPM·보기 전환은 연습 위치·저장 반복 구간을 보존한다. 폰 화면 진입 시 활성 반복의 해제는 [폰 화면 반복 정책](../product/playback.md#반복-구간의-개수와-등록)을 따른다.
- 기본 두 줄은 행마다 4마디·가로 틈 0이다. 마지막 미완성 행은 빈 칸을 유지하고 다른 줄을 당겨 넣지 않는다. 마지막 행은 직전 행 아래에 유지하며 한 줄뿐이면 첫 줄에 표시한다.
- native SVG·nativePageRatio로 두 축에 같은 배율을 적용한다. 한 줄은 사분음표 수 비례 폭의 timeline, 두 줄은 고정 폭의 row다.
  native 간격 계산·글리프 크기·4/4 기준 폭은 같다. 변박은 마디 폭만 늘리고 오선·음표 확대나 비균등 변형은 하지 않는다. grid는 아래 계약을 따른다.

- 세로 정렬은 crop·이미지 중심 대신 오선 제3선(`top + 2 × gap`)을 기준으로 한다.
  MusicXML은 같은 SVG viewport에 원본 페이지 이미지를 배치해 CSS 배경 크기·오프셋의 개별 반올림을 피한다. 페이지 URL은 재사용하고 마디마다 전체 SVG 복제·파일 저장은 하지 않는다. 기존 PDF 배경과 음표 빛나기 overlay는 유지한다.

- 두 줄용 조판은 native 마디 너비≥320과 필요한 머리/주법/장식음 최소 간격을 확보하고 남는 폭을 음가에 배분한다. 전곡의 같은 크기를 유지하되 밀집 곡의 최소 가독성을 무조건 보증하지 않는다.
- MusicXML 프레임은 맨 위 선 기준 위 8·아래 8, 총 16간격이 최소다. 실제 연습 crop이 넘으면 전곡 공통 프레임을 확장한다. 최상단 기호 위 5 SVG단위 여유를 포함한다.
  섹션 위치인 위 7간격과 최소 표시 여백 8간격을 구분한다. native 오선 간격·동일 배율을 유지한다. PDF는 최소 위 7·아래 8간격과 실제 내용의 공통 확장 프레임을 유지한다.
  SVG 가사는 crop에 포함하며 별도 HTML 가사 영역은 예약하지 않는다.

- 두 줄 높이는 화면 내부 폭/4와 전곡 최대 crop 높이에서 고정한다. 상단28px·줄 사이28px·외곽선2px를 확보하고 하단 추가28px는 예약하지 않는다. 남은 세로 공간 때문에 마디 폭을 줄이지 않는다.
- 두 줄의 마디 번호는 예약된28px 위쪽 영역에 둔다. 번호의 배경이 마디 안의 연주 지시문을 가리지 않게 한다.
- 한 줄/두 줄의 외부 악보 영역 높이·재생바·조작판 시작 위치를 통일한다. 경계 간격0px, 두 줄 제목 아래 외부 여백0·재생바 간격2px다. 작은 창은 외부 세로 접근을 허용하며 조작판 안에 스크롤을 만들지 않는다.
- 일반 화면의 한 줄은 마디 번호·악보·가사를 세로 중앙에 둔다. 프레임 위24px·진행선 위40px 연장·상태표시 위53px를 확보하고 확장 영역으로 중앙 정렬한다. 폰용 가로 악보 전용 모드는 아래 §9의 제3선 중앙 정렬을 따른다. 좁은 마디나 온쉼표 때문에 오선 크기를 줄이지 않는다.
- 확대 중앙은 100%, 한 줄 범위는 50~300%다. 100%는 두 줄 마디의 실제 오선 크기다. 한 줄의 박자 기반 폭·시간축과 4/4 약 4마디(16quarter), 저장 배율을 유지한다. 눈금 주변 3% 포인터 흡착과 키보드 미세조정 비흡착을 유지한다.
- 진행선 앞의 여러 마디를 읽을 여유를 제공한다. BPM/배속은 이동 속도만 변경한다. 시간축·불필요한 여백 문제를 SVG 압축이나 음원과 어긋나는 스크롤 제한으로 해결하지 않는다.
- 한 줄 진행선은 timeline 공통 머리 offset·박자 비율로 등속 계산한다. 일반 두 줄은 현재 선택된 row Region, 균등 모드는 grid 좌표를 사용한다. row 그림에 인쇄 Region의 beatXs를 적용하지 않는다.

<a id="svg-score-rules--균등-간격-모드"></a>

#### 균등 간격 모드

- uniformSpacing은 곡 설정에 저장하며 기본 꺼짐, PDF/검수에서는 비활성화한다. 꺼짐은 보기별 timeline/row, 켜짐은 grid를 사용하며 토글 시 재변환·위치 이동을 하지 않는다.
- 모든 마디는 같은 native rowWidth·두 줄 4마디를 유지한다. [상위 기본 단위](production.md#score-production-rules--오선-부착-표기의-공통-기본단위)의 공통 시간축으로 모든 표기의 앵커를 배치한다. §4 연주 지시의 표시 offset도 같은 단위를 사용한다.
- 격자수는 `마디의 사분음표 길이×16`이며, 머리 중심은 `(quarterOffset×16+0.5)×마디폭/격자수`다. 양 끝은 반 칸, 마디선은 인접 마디 머리 격자 중간이다. 연음·기본 단위보다 세밀한 원본 리듬은 분수 위치를 유지한다.
- tick context만 조판 단계에서 이동하고 beam·stem·rest·가사 앵커도 그 좌표를 사용한다. 음표 종횡비·오선 크기·실제 음악/오디오 시각은 유지한다. grid는 metadata.grid에 보관하고 row/timeline을 보존한다.
- grid 진행선은 같은 격자 식을 사용한다. 저장상 beatXs의 끝값1을 보간해 마지막 박을 감속하지 않는다. 같은 박자·템포의 마디 경계는 위치·속도를 연결한다.

요구 좌표식과 현재 구현·캐시의 반영 상태는 [64분음표 이행 기록](../../records/archive/staff-grid64-rule-20261112.md#implementation-status)에서 구분한다. 문서 변경만으로 기존 SVG·재생 캐시가 갱신된 것으로 판단하지 않는다.

<a id="svg-score-rules--9-음표-따라가기탐색화면-효과"></a>

### 9. 음표 빛나기·탐색·화면 효과

- 폰 가로 1줄·2줄의 연주 악보는 MusicXML로 표시하고 음표 빛나기를 켠다. 저장된 표시 형식·빛나기 선호값과 분리된 모드 유효값이며 일반 화면 복귀 시 저장값을 복원한다. MusicXML은 필수 연주 데이터이고 PDF는 원본 보기 부가 자료다.

  음원만으로 연습하는 파형은 유지하며 PDF 전용 악보의 대체 표시 경로는 추가하지 않는다.

- 폰용 가로 악보 전용 모드의 한 줄 재생바는 기존 컴포넌트를 하단에 고정한 오버레이다. 악보 높이에서 재생바 높이를 차감하지 않으며 아래 제3선의 세로 중앙 기준도 유지한다. 두 줄·검수 보기와 일반 화면의 배치에는 적용하지 않는다.
- 폰용 가로 화면에서 악보가 준비되면 악보 전용 모드로 자동 전환한다. 세로로 바뀌거나 폰용 가로 범위를 벗어나면 복귀한다. 수동 설정·확대·복귀 버튼은 없으며 상단바·구간 조작판을 숨긴다. 원본·음표 크기·보기·재생 위치는 유지한다.
  범위는 [UX 기준](../product/ux.md#ux-principles--화면-설정의-선택-버튼)을 따른다. 한 줄의 제3선을 화면 세로 중앙에 둔다. 표시 좌표는 공통 프레임 위 여백 + 오선 2간격 + 한 줄 여백 24px로 계산한다.
  위쪽 상태표시 여백·전체 높이를 확보하고 필요하면 외부 세로 스크롤로 중앙 정렬·확대 내용 접근을 제공한다. 모드 진입·악보 재배치·크기 변경 때만 정렬하며 수동 스크롤을 되돌리지 않는다.
  두 줄·검수·오선 좌표 없는 PDF·음원 연습은 기존 정렬을 쓴다. 화면 높이를 채우려 악보를 늘리거나 재조판하지 않는다.

- 음표 빛나기는 MusicXML 한 줄/두 줄에만 적용하고 PDF/검수에는 적용하지 않는다. 실제 음표 시작에 켜고 약 140ms 이내·최대 ¼박에 끈다. 다음 타격에서 이전 효과를 끄며 동시음은 함께 켠다.
- 흰 중심·청록 광륜과 감쇠를 사용한다. 머리가 가장 밝고 줄기/빔은 은은하게 표시한다. 빔의 짧은 빛은 성부의 실제 X를 따라 이동하고 지나간 부분을 누적 색칠하지 않는다.
- 카운트오프에는 숨기고 되감기·반복·탐색 때 재계산한다. timing metadata는 캐시에, 실제 색 효과는 overlay에 둔다. 오선·가사·원본 XML 색은 변경하지 않는다.
- 진행선은 두 보기 모두 빨강#e53935다. 파란 진행 음영은 실제 진행선 이전만 표시한다. 정지 방향키는 선택만 옮기며 시각·진행선·음영은 유지한다. 재생 시작은 선택 마디를 사용한다.
- 선택은 파란 테두리만 표시하고 선택 배경은 쓰지 않는다. 마커는 빨간 북마크24×24px와 빨간 음영이며 활성 마디에서도 유지한다.9개 저장 구간은 옅은 오렌지와 하단선으로 표시하고 겹쳐 중첩하지 않는다. 마커 빨강을 우선하고 선택 테두리는 함께 유지한다.
- 폰 화면에서는 반복 구간 조작·재생을 비활성화하고 저장 구간 음영·하단선·활성 반복 경계·선택 미리보기를 표시하지 않는다. 저장 데이터와 일반 마디 선택·진행선·마커는 유지하며 PC·태블릿 화면에서는 저장 구간 표시와 조작을 다시 제공한다. 적용 크기와 전환 동작은 [재생 정책](../product/playback.md#반복-구간의-개수와-등록)을 따른다.
- 빈 구간 슬롯은 흰 배경·기본 테두리/글자이며 hover에도 유지한다. 등록 대기·저장 구간·버튼/편집/반복/미리보기는 공통 오렌지 변수로 표시한다.
- 정지 두 줄은 원래 DOM 마디 순서를 유지한다. 멈춘 아래줄/위줄 위치·마지막 두 줄을 유지하고 사용자 스크롤을 반복 frame으로 되돌리지 않는다. 화면 안 선택은 스크롤하지 않으며 밖으로 이동할 때 아래 방향은 둘째 줄, 위 방향은 첫째 줄에 새 선택을 둔다.
- 정지·두 줄 wheel listener는 `passive: true`로 등록한다. native 관성과 기존 `y mandatory`·행 시작 정렬을 유지한다. `preventDefault()`·가로 입력의 재생 탐색·별도 DOM 감시·관성 계산·종료 보정은 사용하지 않는다.
  재생 상태·보기/트랙 갱신에서 옵션을 맞춘다. 재생 중·한 줄·검수는 non-passive를 유지한다. 옵션 변경 때만 같은 listener를 다시 등록하고 화면 해제 시 제거한다.

- 정지 두 줄의 자동 frame은 같은 곡·시각·선택·포커스에서 전곡 표시를 반복 갱신하지 않는다. 재생 상태·레이아웃·목록/설정·시각/선택·복사 알림 상태가 바뀌거나 탐색/구간 미리보기가 진행될 때 갱신한다.

  명시적인 frame 호출은 즉시 반영하고 재생 중 갱신은 유지한다. 세로 휠 탐색은 현재 선택 마디를 사용하며 정지된 음악 위치로 선택/스크롤을 되돌리지 않는다. 진행 음영 CSS 값이 같으면 다시 쓰지 않는다.

  SVG 제3선 정렬·상하 crop·마디 DOM/원본·연습 저장은 유지한다.

- 재생 시작은 보이던 위/아래줄 위치를 유지한다. 활성 반복으로 시작 마디가 달라지면 구간 시작을 우선하고 화면 밖은 기존 위줄 기준을 사용한다.
- 두 줄의 좌우 드래그/휠 탐색은 사용하지 않는다. 정지 상하 탐색·탭 선택·재생 중 탭 정지를 유지한다. 한 줄의 좌우 탐색·진행률 조작은 유지한다.
- PC·태블릿 화면의 정지 더블클릭/Enter는 구간 시작·끝 포함 등록을 공유하고 실제 정지 시각은 바꾸지 않는다. 빈 슬롯의 구간 선택 상태에서는 터치 탭/마우스 원클릭으로 등록한다.8px초과 이동·pointercancel은 등록하지 않고 시작 대기를 유지한다.

  스크롤은 native로 허용하고 구간 드래그·자동 스크롤을 만들지 않는다. Esc·슬롯 재클릭·바깥 터치는 취소한다. 폰 화면에서는 이 구간 지정 동작을 실행하지 않는다.

- 구간 선택 진입은 화면/트랙을 재구성하거나 현재 재생 위치로 이동하지 않는다. 진행 중이었다면 기존 일시정지 순서 복원만 수행한다.
- PDF에는 원본 인쇄 가사만 표시한다. 기존 `lyricAnchors`는 판독·이전 자료의 메타데이터로 보존하며 PDF 위의 새 가사 행 생성에 사용하지 않는다. SVG 가사는 [공통 가사 배치](#svg-score-rules--전체-보기-가사)를 따른다.

<a id="svg-score-rules--10-저장캐시안전"></a>

### 10. 저장·캐시·안전

- 두 앱의 renderMusicXML·입력 권위·캐시 키는 [브라우저 계약](#browser-musicxml-rendering--브라우저-공통-musicxml-조판-계약)을 따른다. 동봉 인쇄 SVG를 최신 조판의 정본으로 삼지 않는다.
- 출력 변경 시 정책을 올리고 SVG 페이지·마디 영역을 함께 재생성한다. cache DB에는 원본·연습 상태를 쓰지 않는다.
- 저장 페이지는 gzip SVG(`application/vnd.drum-practice.svg+gzip`)이며 표시 시 image/svg+xml로 푼다. 기존 페이지 속성 검사는 첫 페이지에서 수행하고 재생성 후 마디 ID·페이지 수·영역 일치를 확인한다.
- 조판이 준 오선 좌표를 재사용하며 새 SVG를 픽셀로 다시 검출하지 않는다. PDF/구형 SVG만 탐지 경로를 유지한다.
- XML script·foreignObject·image·link·opus 및 이벤트/href를 차단한다. 강조 overlay는 허용된 벡터와 기하 속성만 복사한다.
- 재생 SVG의 외부 URL·CSS import·실행 코드 차단은 유지한다. 공통 글꼴 모듈이 만든 현재 Pretendard WOFF2 내장 CSS는 앱에 동봉된 실제 바이트·라이선스·선언 전체가 정확히 일치할 때만 외부 URL 검사에서 구분한다.

  검사 복제본의 해당 CSS 본문만 제외하며 원본 SVG와 요소 속성은 보존한다.

<a id="svg-score-rules--11-변경-검증"></a>

### 11. 변경 검증

[변경 영향](../engineering/verification.md#verification-rules--변경-영향과-검사-선택)에 따라 아래 항목을 선택한다. 개발은 정적 검사, 화면·재생 검수는 릴리스·별도 요청 때 수행한다. 문서만 변경하면 악보 재생성·화면 검수는 하지 않는다. 릴리스 필수 검사는 유지한다.

1. XML 의미·음가·악기·성부·원래 적용 박의 보존을 검사한다.
2. 전체 페이지와 마디 화면의 첫 마디·시스템 시작·페이지 경계를 확인한다.
3. 섹션 테두리·글자·음표/쉼표/빔·주법·지시문 경계와 최소 여백·같은 줄 범위를 확인한다. 최소 offset은 더 작은 격자 후보와 재열기로 검증한다.
4. 타악기 clef 숨김과 실제 세로줄·반복기호 보존을 확인한다.
5. 재생/정지 크기·가사·진행선·강조 좌표를 대조한다.
6. 관련 검사·빌드와 Safari 실제 화면을 확인하고 독립 SVG도 검수한다. iPad 실기기·시뮬레이터·데스크톱 결과를 구분한다.
7. 검사 실행은 전역 지침의 영향별 허가 범위를 따른다. 실행/미실행·대상·정확한 입력·버전·근거·한계를 history.md와 제작/개발 기록에 남긴다. 과거 PASS를 새 결과로 쓰지 않는다.

<a id="browser-musicxml-rendering--승인된-표시-계약"></a>

### 승인된 표시 계약

1. 한 줄은 동일 음가 동일 거리, BPM은 이동 속도만 변경.
2. 두 줄은 한 줄4마디. 인쇄 SVG는 XML 페이지·시스템 구성을 보존.
3. PDF와 원본 XML/PDF를 보존. 표시 자산은 원본에 덮어쓰지 않는다.
4. 현재 마디·박/재생 시각/반복/마커는 조판과 독립. 렌더 결과에서 연습 상태를 복원하거나 초기화하지 않는다.
5. 매 프레임 재조판 금지. 벡터 좌표는 화면 크기와 독립적으로 조판하고, 화면 크기·보기 변경은 공통 화면 배치만 갱신한다. 조판에 영향을 주는 조건은 캐시 키에 포함한다. 공통 재생 표시는 텍스트·가시성·SVG clip 값이 달라질 때만 DOM에 기록하며, 정지 중 native 스크롤에 같은 값의 노드 교체를 반복하지 않는다.
   - 두 줄의 전곡 높이는 track 재배치에서 계산하고 프레임 간 재사용한다. 보기·확대·폭·악보 자산 변경과 reset에서 무효화한다. DOM SVG의 음표 onset/beam 좌표는 해당 SVG 수명 안에서만 재사용하며 새 줄/SVG에는 새 데이터를 읽는다.
   - 두 줄 재생의 행 교체는 계속 표시할 마디 DOM과 강조 SVG를 보존하고 나가는 네 칸만 새로 만든다. 마지막 행의 위아래 교환·빈 칸·가사 배치를 유지하며 폭·track 무효화 때는 새로 만든다. 정지 탐색은 기존 시간순 전체 행을 유지한다. 가로 transform을 사용하지 않는 두 줄 ribbon에는 `will-change: transform`을 강제하지 않는다.
   - 재생 자산의 준비 단계도 페이지당 한 번 파싱한 SVG 문서를 공유한다. 강조는 연습용 보정 전에 추출하고 내장 글꼴·출력 바이트·비율·안전 검사를 보존한다. 디코딩된 불변 Blob의 재복사와 큰 임시 메타데이터의 불필요한 보관은 하지 않는다. 표시 내용이 같으면 캐시 정책 번호나 저장 형식을 바꾸지 않는다.
   - 큰 내장 글꼴 CSS·보기별 timeline JSON의 단순 XML 문자 데이터는 파싱 중에만 분리할 수 있다. 요소·속성은 native XML 파서로 검사하고 본문은 표준 엔티티와 유효한 XML 문자만 복원하며, 소비·글꼴/URL 안전 검사 전에 모두 돌려놓는다. 선언·주석·CDATA·숫자/알 수 없는 엔티티·예상과 다른 문서는 원래 native 파싱 경로를 유지한다. 분리 대상 표식 자체를 신뢰 근거로 삼거나 검사·내장 글꼴 바이트·라이선스를 생략하지 않는다.
6. 제작앱과 재생앱의 렌더러·표기 보완은 같은 구현. 재생앱은 공통 렌더러를 사용하되 편집/제작/원본 저장 모듈을 포함하지 않는다.

<a id="browser-musicxml-rendering--캐시와-입력-권위"></a>

### 캐시와 입력 권위

- 입력은 패키지의 `canonicalXML`을 우선한다. 없으면 MusicXML variant의 원본을 사용한다.
- 기본 키는 원문·선택 파트·렌더러 버전·표기/배치 정책의 SHA-256이다.
- 연습 배속·재생 시각·루프·viewport는 벡터 조판 입력이 아니므로 키에서 제외한다. 전체 보기 헤더의 기본 BPM·가수는 전용 키에 포함한다.
- 출력 결과에 영향을 주는 조판 변경은 정책 버전을 올린다.
- 별도 IndexedDB에 최근 생성한 캐시 4개를 보관하며 SVG 바이트 SHA-256을 확인한다. 실패한 렌더는 저장하지 않고 손상 캐시는 재생성한다. 같은 동시 요청은 합친다.
- 캐시 저장에 실패해도 정상 렌더 결과의 표시는 유지한다. 원본·보관함 저장 데이터는 변경하지 않는다.

간격 계산은 `quarter`·`offset`·`rowWidth`로 배치에 반영한다. 소비자가 없는 음표 간격 진단 목록(`constraints`)은 생성·정렬하거나 새 SVG 메타데이터에 넣지 않는다. 기존 SVG에 이 부가 필드가 있어도 읽기는 허용하며, 이 정리만으로 캐시 정책·마디 좌표·저장 자료를 바꾸거나 재생성하지 않는다.

<a id="browser-musicxml-rendering--검증-기준"></a>

### 검증 기준

- 정확성: 마디 수·박자 일치, 원본/가사/음원/연습 상태 불변. 대표 회귀 마디의 동일 너비와 오선 크기 유지. 대상은 [검수 절차](../../how-to/review-score.md#ui-review--조판-회귀-대상)를 따른다. 변박·꾸밈음·쉼표·빔·주법 검수.
- 캐시: 최초 요청은 miss, 같은 입력의 재열기는 hit, 원문·파트·정책 변경은 miss여야 한다. 연습 BPM 변경은 기존 조판을 재사용한다. 전체 보기 헤더의 기본 BPM·가수가 바뀌면 전용 키를 바꾼다. 실패한 렌더는 저장하지 않는다.
- 성능: 동일 환경 기존 캐시 준비와 직접 조판/재사용을 각각 측정. cold 조판 시간은 별도 보고, warm에는 OSMD 조판0회. 123마디 화면 표시 목표 cold10초 이내, warm2초 이내(음원 decode 별도). 초과하면 원인 개선 후 재측정.
- 메모리: 가능하면 실제 프로세스 측정. Safari에서 JS heap API 미제공 시 미측정을 수치로 꾸미지 않는다. DOM/자산 수·반복 열기·닫기 후 자원 해제로 누수도 확인.
- iPad: 승인된 검수 범위에서 재생·보기 전환·회전·루프 보존을 확인한다. Safari 응답형·시뮬레이터·실기기 결과를 구분한다. 실기기·시뮬레이터는 별도 요청이 있을 때만 수행하며 시뮬레이터 수치를 실제 기기 성능으로 보고하지 않는다.

<a id="browser-musicxml-rendering--보정-유지-조건"></a>

### 보정 유지 조건

올바른 정본의 공통 조판·확인된 호환 경로만 유지한다. 아래 목록·과거 검수로 정본 오류를 감추는 새 보정을 허용하지 않는다. [수정 책임](musicxml.md#musicxml-canonical--정본과-앱의-수정-책임)으로 판정한다.

- 시간 비례 재조판: 유지, OSMD 기본 음표밀도 배치만으로 대체 불가.
- filled=no, ghost, sticking, half-open, 온쉼표: 엔진 지원 공백을 메우는 공통 구현 유지.
- PDF crop/anchor: PDF 경로만 유지.
- 기존 곡별 SVG crop: 기존 패키지 호환 경로와 구분하여 공통 렌더 좌표로 대체할 수 있는지 검증한 후 제거 여부를 결정한다. MusicXML 문제를 가리는 새 곡별 예외는 추가하지 않는다.
- 원본 XML 쉼표/메타데이터 교정: 제작 책임, 재생앱에서 실행하지 않는다.

<a id="browser-musicxml-rendering--구현-경계"></a>

### 구현 경계

조판 진입점은 `musicxml.ts::renderMusicXML`, 표시 좌표 연결은 `browser-score.ts`다. [캐시 계약](#browser-musicxml-rendering--캐시와-입력-권위)을 따르며 원본·보관함·연습 상태와 조판 자산의 수명을 분리한다. 새 조판 옵션은 키에 포함한다.

입력 읽기/검증(`musicxml-parse`) → 엔진 설정·훅·조판(`musicxml-engine`) → 공통 기호 표시(`musicxml-glyphs`) → SVG 경계 확정(`musicxml-geometry`) → 글꼴 내장·압축 → 마디/박 좌표 추출(`musicxml-geometry`) 순서를 유지한다. 임시 host의 생성·해제와 다중 pass는 `musicxml.ts`가 소유한다. 기존 공개 함수·자료형 경로를 유지하며, 책임 분리만으로 캐시 정책이나 MusicXML 정본·표시 규칙을 바꾸지 않는다.

`finishMusicXMLGlyphs`는 타악기 음자리표 제외 → 섹션 높이 정렬 → 연습용 박자표 제외/SVG 확인 → 빈 음표 머리 처리 → 온쉼표 가운데 배치 → 음표 강조 정보/표시 버전 기록 → 제목 식별 순서를 연결한다. 음자리표·섹션·음표 머리·온쉼표·제목 처리는 같은 파일의 비공개 함수로 나누며 기존 좌표 계산·표시 속성·오류 처리를 유지한다.

호환성 주석의 OSMD 2.1/2.2 표기는 해당 문제의 최초 확인·대응 도입 시점을 뜻한다. 현재 설치 버전은 카탈로그와 lockfile을 따른다. 주석에는 지금 유지하는 입력/출력 계약과 제거 전 확인할 엔진 출력 조건을 구분해 기록한다. 버전이 올랐다는 이유만으로 공통 처리를 제거하거나, 과거 주석을 현재 엔진의 재현 결과로 해석하지 않는다.

엔진·글꼴·캐시 정책 식별자는 [SVG 규칙의 구현 참조](rendering.md#svg-score-rules--현재-구현-참조), OSMD 업데이트의 당시 증거는 [업데이트 기록](../../records/archive/rendering-experiments.md#osmd-upgrade-20261023--osmd-221-업데이트)에서 확인한다.

<a id="pdf-display-trim--pdf-연습-화면-표시용-자르기"></a>

## PDF 연습 화면 표시용 자르기

결정 근거: [ADR-0003](../../decisions/0003-source-systems-and-cropping.md). 실행: [절차](../../how-to/verify.md#ui-review--화면악보재생-검수-절차).

원본 PDF·MusicXML을 변경하지 않고 재생 화면에서 줄 앞 타악기 표시와 여백을 잘라 다른 마디 길이와 맞춘다. 인쇄 가사·마디 번호 잘림은 승인된 범위다. 전체 페이지는 원본 줄 구성, 기본 두 줄 연습은 행당 4마디다. 세부 정본은 [SVG 규칙](rendering.md#svg-score-rules--3-타악기-음자리표와-세로줄)이다.

<a id="pdf-display-trim--적용-계약"></a>

### 적용 계약

- 제작 세션이 원본에서 확인한 줄별 경계를 사용한다. 기존 다른 곡의 수치를 재사용하지 않는다.
- 확인된 PDF 영역에만 적용하고 SVG 및 사용자가 수정한 다른 영역에는 적용하지 않는다.
- 박 기준점의 원본 페이지 좌표, 첫 음표·박자표·실제 마디선, 원본 파일을 보존한다.
- 한줄/두줄 공통 화면, 진행선과 탐색 좌표를 검사하고 Safari 화면으로 검수한다.
- 단위/회귀 검사와 분리 빌드를 통과한다. 구현 상태와 배포 상태를 구분한다.

확인된 원본 region fingerprint에만 적용한다. PDF 처리와 SVG 경로를 구분하고 자르기 전 박 기준점은 음수 좌표도 보존한다. 입력 Region을 수정하거나 왼쪽으로 강제 이동하지 않는다. 가로 prefix 자르기를 상하 가사·내용 잘림 허가로 확대하지 않는다.

가사는 [정본 계약](musicxml.md#musicxml-canonical--musicxml-정본-계약)의 악보 위치를 따른다. 실제 가창 시각 검증은 PDF 가사 제작의 완료 조건이 아니다.
