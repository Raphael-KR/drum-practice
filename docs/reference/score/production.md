## 악보 제작 범위와 보존 Rule

문서 역할: **현행 Rule**. 선택 이유는 [ADR-0018](../../decisions/0018-reusable-score-production-and-handoff.md), 실행 순서는 [제작 프로세스](../../how-to/produce-score.md#score-production-process--악보-제작-프로세스), 등록 절차는 [제작 스킬](../../../.agents/skills/produce-drum-score/SKILL.md)이다. 변환·매핑·저장·SVG의 세부 정본을 대체하지 않는다.

<a id="score-production-rules--접수와-출력"></a>

### 접수와 출력

- 역할은 악보제작자다. 사용자 제공 PDF·음원과 유튜브 참고 자료를 다룬다. 웹앱 기능 개발은 해당 담당 범위로 구분한다.
- 기본 원본 폴더는 `/Users/raphael/Documents/드럼 악보`다. 곡명만 주어지면 이곳에서 PDF·음원을 찾으며 NFC/NFD를 고려한다. 별도 지정 경로를 우선하고 후보가 여러 개/자료 없음 때만 필요한 확인을 요청한다.
- 악보 출력은 MusicXML이다. 인쇄용 PDF·독립 HTML 재생 파일은 생성하지 않는다. 원본 PDF의 보존·대조·앱 내 표시는 유지한다. 새 음원·패키지는 요청 범위에 맞춰 준비한다.
- 원본·교정 전 자동 초벌·기존 결과를 보존하고 새 시도는 Git 제외 `data/production/`의 새 경로에 둔다. 원본 미디어·생성물·샘플을 자동 Git 추가·public 배포하거나 삭제하지 않는다.
- 일반 곡은 실제 가수를 유지하며 세션 연주자·강사·채널을 가수로 넣지 않는다. 드럼 연습 악보는 선택한 드럼킷 이름을 가수란에 반드시 기록한다. [메타정보 계약](musicxml.md#musicxml-canonical--저장-계약)을 따른다.

<a id="score-production-rules--원본-판단과-재사용"></a>

### 원본 판단과 재사용

변환 방법은 [변환 정책](production.md#musicxml-conversion-policy--pdf--musicxml-변환-정책), 주법은 [확정 매핑](notation.md#score-musicxml-osmd-mapping--악보의-musicxml--osmd-매핑-규칙), 줄/섹션/지시는 [SVG Rule](rendering.md#svg-score-rules--svg-전체-악보-생성-규칙), 가사·템포·음원 연결은 [정본 계약](musicxml.md#musicxml-canonical--musicxml-정본-계약)을 따른다. 과거 후보 매핑·곡별 fixture로 최신 승인을 덮어쓰지 않는다.

영상의 실제 연주 채보와 교육 개념을 참고한 새 작곡을 구분한다. 제목·스크립트만으로 타격을 확정하지 않고 실제 프레임·시각·음향을 대조한다. 요청 없이 채보를 임의 작곡으로 대체하지 않는다. 영상 녹음 추출·재사용은 실제 요청 범위를 확인한다.

공통 코드에는 정형 처리·후보 계산을, 곡별 설정·어댑터·독립 기대값에는 경로/해시·반복/성부·가사 판독·자유 엔딩·특수 주법의 판단과 근거를 둔다. 새 양식의 범용 OMR 완성을 주장하지 않는다. 바뀐 입력의 의존 결과는 재생성하고, 변경 없는 음악 검증은 보고서만을 위해 반복하지 않는다.

<a id="score-production-rules--검증과-종료"></a>

### 검증과 종료

원본 의미·규격·왕복·표시·실제 앱·청취는 [검증 Rule](../engineering/verification.md#verification-rules--검증-범위와-증거)에 따라 각각 판정한다. 못 확인한 사항과 앱 결함을 구분해 인계하며 일부가 남았다는 이유로 준비된 제작 결과 전달을 미루지 않는다. 문제 해결은 원인·해결·검증·다음 적용 조건을 문서와 history에 남긴다.

<a id="score-production-rules--완성-악보의-상시-인계"></a>

### 완성 악보의 상시 인계

[상시 위임 범위](../../decisions/0018-reusable-score-production-and-handoff.md)에 따라 새 악보와 교정·재제작한 수정본은 제작을 마치면 기존 **드럼연습실 웹앱 개발** 담당에게 실제 메시지로 전달한다. 동일 대상·범위의 승인을 매번 다시 묻지 않는다. 절차에서 현재 담당·thread ID·host를 확인하고 최종 파일/해시·상태·한계·다음 조치·실제 전송/접수 근거를 남긴다. 파일 링크만 최종 응답에 남겨 전달 완료로 간주하지 않는다.

이 범위는 해당 악보 결과의 기존 개발자 전달이다. 새 담당 배정·무관한 메시지·별도 시험·Git 통합·공개 발행의 권한을 만들지 않는다. 코드 공통화나 문서 정리만 수행한 작업을 새 악보 제작으로 인계하지 않는다.

<a id="musicxml-conversion-policy--선택-순서"></a>

### 선택 순서

1. 원본이 벡터 PDF인지, 스캔·사진 이미지인지 먼저 확인한다. 혼합 PDF는 페이지별로 확인한다.
2. 음표·선·좌표를 추출할 수 있는 깨끗한 벡터 PDF는 Codex가 구조 추출 코드를 사용해 직접 변환하고 원본과 대조·검증한다. 이미지 관찰만으로 음표를 추측해 작성하는 것을 뜻하지 않는다.
3. 스캔·사진은 Audiveris로 초벌한 뒤 Codex가 원본 대조·교정하는 경로를 먼저 시험한다. 이는 모든 이미지에서 우수하다는 보장이 아니다.
4. 새로운 악보 양식은 대표 2~3줄(복잡한 리듬·악기·박자 변화 포함)로 먼저 평가한 뒤 전체 변환 방식을 결정한다. 벡터 구조 추출이 불가능하거나 초벌 누락이 많으면 근거를 기록하고 방법을 재평가한다.
5. 기존 변환 코드는 특정 악보에 맞춰져 있으므로 다른 악보에 그대로 적용 가능하다고 가정하지 않는다.

<a id="musicxml-conversion-policy--보존과-검증"></a>

### 보존과 검증

- 원본, 기존 결과, 교정 전 자동 인식 결과를 보존하고 새 결과를 별도 경로에 저장한다.
- 마디 수·박자·템포·음표 시작과 길이·다성부·악기 매핑·장식음·연음·반복을 원본과 대조하고 MusicXML 규격 검사와 재렌더링 검증을 수행한다.
- 악기·주법 표기에는 프로젝트의 `docs/reference/score/notation.md`, SVG 출력에는 `docs/reference/score/rendering.md`를 적용한다. 이 선택 기준은 기존 매핑 결정을 변경하지 않는다.
- 미확정 매핑, 누락, 교정 내용과 남은 검증을 명시한다. 표본 F1을 전곡 정확도로 표현하지 않는다.

<a id="musicxml-conversion-policy--첫-박과-카운트오프"></a>

### 첫 박과 카운트오프

새 곡이나 음원 교체 시 음원 0초와 악보 첫 박을 구분하고 firstBeat·첫 마디 start를 대조한다. 첫 박 앞 무음·도입을 보존한다. OFF/ON·처음/중간·배속·반복 검수는 [제작 절차](../../how-to/produce-score.md#score-production-process--5-음원-첫-박bpm마디-시간-연결)를 따른다. OFF가 정상이고 ON에서만 어긋나면 앱 예약 문제로 분류하고 정상 곡 데이터를 이동하거나 음원을 잘라 우회하지 않는다. 수치와 실제 청취의 결과를 구분한다.

<a id="musicxml-conversion-policy--가사-기준--악보-우선"></a>

### 가사 기준 — 악보 우선

가사 시작·길이는 원본 악보의 마디·박·음가와 인쇄 음절 대응을 기준으로 기록한다. 가수가 다르게 부른 시작·끝·길이는 반영하지 않는다. 실제 가창 시각 측정·STT·강제 정렬·시간 가사 검색은 PDF 변환 완료 조건이 아니다. 음악적 위치에서 계산한 재생 캐시는 가창 전사가 아니다. 판독 추정은 대상·근거·다른 가능성을 구분해 남긴다. 상세 저장은 [정본 계약](musicxml.md#musicxml-canonical--musicxml-정본-계약), 결정은 [ADR-0013](../../decisions/0013-score-based-lyric-positions.md)을 따른다.

<a id="musicxml-conversion-policy--막힘과-문서-모순"></a>

### 막힘과 문서 모순

이미 확정된 내용을 다시 질문하기 전에 **현재 문서 → 과거 악보 제작 세션 → 공식 웹 자료** 순서로 확인한다. 모순의 근거 조사는 **history.md → 다른 관련 문서 → 과거 제작 세션 → 웹 자료** 순서다. 이는 확인 순서이며 현재 사용자 결정·승인 정본의 우선순위를 바꾸지 않는다.

해결하면 증상/조건·원인과 근거·수정과 보존·검증·다음 적용 기준·남은 한계를 곡별 `docs/records/songs/<곡 식별자>.md` 또는 공통 [제작 도구 기록](../../records/production-tools.md)에 남기고 history에 연결한다. 확인 못 한 원인·렌더 미지원·추정 시각은 미확정으로 기록한다. 실행 순서와 항목은 [제작 절차](../../how-to/produce-score.md#score-production-process--악보-제작-프로세스)를 따른다.

<a id="lyric-feedback-rules--수동-가사-싱크-피드백-접수"></a>

## 수동 가사 싱크 피드백 접수

문서 역할: **범위가 한정된 Rule**. 사용자가 별도로 가사 싱크 교정을 요청한 경우의 접수 계약이다. 새 PDF 변환은 [악보 우선 가사 정책](production.md#musicxml-conversion-policy--가사-기준--악보-우선)을 따르며 실제 가창 측정을 완료 조건에 추가하지 않는다. [ADR-0013](../../decisions/0013-score-based-lyric-positions.md)의 당시 결정과 구분한다.

- 구절만 전달하면 구절 첫 음절 시작으로 해석한다. 별도 지정이 없으면 해당 교정 목록 행의 “확인할 첫 가사”가 대상이며 굵은 글씨 여부로 고르지 않는다. 음절을 명시하면 그 지정을 우선하고 같은 확인을 반복 질문하지 않는다.
- 위치 전달은 누적 접수다. 사용자가 일괄 반영을 요청할 때 적용하며 좌표 전달만으로 앱·가사 데이터를 바꾸지 않는다. 통합한 고유번호도 같은 행으로 접수한다.
- 순차 청취에서는 사용자가 새로 체크한 지점보다 앞의 미지적 가사를 현재 위치가 맞는 것으로 기록한다. 이전 개별 교정값은 보존하며 포괄 확인으로 취소·덮어쓰지 않는다. 체크 지점 자체는 전달 좌표로 교정하고 뒤 구간은 확인으로 취급하지 않는다. 실제 confirmed/데이터 반영은 일괄 적용 요청 범위를 따른다.
- 현재 확인 경계·대상 ID·실제 시각·적용 판본은 해당 곡의 제작 기록에 남긴다. 기존 사례는 [곡별 제작 기록](../../records/README.md#곡별-제작-기록)에서 찾는다. 과거 경계를 새 곡으로 복사하거나 음원 분석 추정으로 사용자 청취 확인을 만들지 않는다.
