## 악보 작성 상위 규칙 — 64분음표 공통 기본 단위

**오선에 연결되는 모든 표기의 음악적 위치·음가와 허용된 표시 이동에는 64분음표를 공통 기본 단위로 사용한다. 이 규칙은 악보 작성·교정·저장과 모든 조판 방식에 적용한다.**

적용 대상은 음표·쉼표·가사·섹션 표제·연주 지시·셈여림·크레센도/디크레센도의 시작과 끝·아티큘레이션·주법·스티킹 등 오선에 연결되는 모든 표기다. 종류별 표기·MusicXML 저장·SVG 출력의 하위 규칙은 이 기준을 따른다.

1. **단위와 원점**

   마디 시작을 0으로 한다. 한 칸은 64분음표 길이, 즉 사분음표의 1/16(0.0625)이다. 사분음표당 16칸이며 4/4 한 마디는 64칸, 6/8 한 마디는 48칸이다. 박자표에 따라 달라지는 ‘한 박’과 사분음표 길이를 구분한다.

   기본 단위는 위치와 길이를 표현하는 간격이다. 8분음표는 8칸 길이의 한 음표로 유지하며, 빈 칸을 채우려고 음표·쉼표를 추가하지 않는다.

2. **위치 결정**

   원본 악보 또는 승인된 작곡·교정 기준에서 각 표기의 대응 위치와 음가를 먼저 결정한다. 격자에 맞추기 위한 임의 분할·이동·반올림은 하지 않는다. 근거가 부족한 위치·음가는 미확정으로 기록한다. 기본 단위 변경만으로 기존 음표·가사의 시작이나 길이를 바꾸지 않는다.

3. **배치 기준점**

   음표에 붙는 기호는 해당 음표, 마디에 붙는 표제는 해당 마디 시작, 구간 표기는 구간의 시작과 끝을 기준점으로 사용한다. 가사와 독립 지시문도 같은 시간축의 대응 위치를 사용한다. 글자·기호의 폭, 테두리 여백과 세로 위치는 각 표기의 조판 규칙을 따른다.

4. **충돌에 따른 표시 이동**

   하위 조판 규칙에서 허용한 표기에 한해 표시 위치를 이동한다. 시간축상의 가로 표시 이동량은 64분음표 단위로 하며 음악적 적용 시점은 유지한다. 음표에 붙는 기호 사이의 간격 조정과 시간축상의 표시 이동은 구분한다.

5. **원본의 세분 리듬 보존**

   원본에 명시된 연음·점음표·더 짧은 음가 등 기본 단위의 정수배로 표현되지 않는 리듬은 같은 시간축에서 정확한 분수 위치·음가로 보존하고 근거를 기록한다. 이 예외를 임의의 가사 분할이나 배치 편의를 위해 사용하지 않는다.

6. **저장과 검증**

   MusicXML의 음표 연결·시간 정보·위치 속성으로 배치 의도를 재현할 수 있어야 한다. 기본 단위와 원본의 분수 리듬을 모두 정확히 표현하도록 `divisions`를 선택한다. 모든 파일의 `divisions`를 16으로 고정하지 않는다. **그리드 준수와 원본 위치·음가 일치는 각각 검증한다.** 하나를 만족했다고 다른 하나까지 맞는 것으로 판단하지 않는다.

순차 가사의 시작점 중복 여부와 구체 저장·검사는 [가사 시작점 계약](musicxml.md#musicxml-canonical--서로-다른-음절의-시작점), 개별 배치·충돌 처리는 [SVG 출력 규칙](rendering.md#svg-score-rules--svg-전체-악보-생성-규칙)을 따른다.

결정 이유·이전 해석·적용 경계는 [ADR-0032](../../decisions/0032-common-sixty-fourth-unit.md)에 둔다. 구판 원본·기존 파일을 이 규칙만으로 자동 덮어쓰지 않는다.

## 악보 제작 범위와 보존 Rule

근거: [ADR-0018](../../decisions/0018-reusable-score-production-and-handoff.md). 실행: [제작 절차](../../how-to/produce-score.md#score-production-process--악보-제작-프로세스)·[스킬](../../../.agents/skills/produce-drum-score/SKILL.md).

<a id="score-production-rules--접수와-출력"></a>

### 접수와 출력

#### 담당과 입력

- 악보제작자는 사용자 제공 PDF·음원과 유튜브 참고 자료로 악보를 제작·교정한다. 웹앱 기능 개발은 개발 담당 범위다.
- 기본 원본 폴더는 `/Users/raphael/Documents/드럼 악보`다. 사용자가 다른 경로를 지정하면 그 경로를 우선한다.
- 곡명만 받으면 Unicode NFC/NFD 차이를 고려해 기본 폴더에서 PDF·음원을 찾는다. 후보가 여러 개이거나 없으면 확인을 요청한다.

#### 출력과 보존

- 악보 출력은 MusicXML이다. 인쇄용 PDF·독립 HTML 재생 파일은 생성하지 않는다.
- 원본 PDF는 대조·앱 내 원본 표시용으로 보존한다. 새 음원·패키지는 요청 범위에서만 준비한다.
- 원본·교정 전 자동 인식 결과·기존 결과를 보존한다. 새 시도는 Git 제외 폴더인 `data/production/` 아래의 새 경로에 저장한다.
- 원본 미디어·생성물·샘플을 자동으로 Git에 추가하거나 `public`에 배포하거나 삭제하지 않는다.
- 일반 곡의 실제 가수와 연습 악보의 드럼킷 표기는 [메타정보 계약](musicxml.md#musicxml-canonical--저장-계약)을 따른다. 세션 연주자·강사·채널을 가수로 입력하지 않는다.

<a id="score-production-rules--원본-판단과-재사용"></a>

### 원본 판단과 재사용

#### 정본과 앱의 수정 책임

[수정 책임](musicxml.md#musicxml-canonical--정본과-앱의-수정-책임)에 따라 정본 교정·근거를 인계한다. 올바른 정본의 표시 오류는 공통 렌더러 문제로 전달한다.

#### 영상 채보와 새 작곡

- 실제 연주 채보와 교육 개념을 참고한 새 작곡을 구분한다. 요청 없이 채보를 임의 작곡으로 대체하지 않는다.
- 실제 영상 프레임·시각·음향을 대조해 타격을 확정한다. 제목·스크립트만으로 확정하지 않는다.
- 영상의 녹음을 추출하거나 재사용할 때는 요청 범위에 포함되는지 확인한다.

#### 공통 처리와 곡별 판단

- 공통 코드는 정형 처리와 후보 계산을 맡는다.
- 곡별 설정·판독 어댑터·독립 기대값에는 경로·해시와 반복·성부·가사·자유 엔딩·특수 주법의 판단 근거를 둔다.
- 판독 어댑터는 원본에서 정본을 만든다. 재생 앱의 곡별 오류 은폐에 사용하지 않는다.
- 새 양식을 처리했다는 이유로 범용 OMR이 완성됐다고 보고하지 않는다.
- 입력이 바뀌면 의존 결과를 재생성한다. 보고서 작성만을 위해 변경 없는 음악 검증을 반복하지 않는다.

<a id="score-production-rules--검증과-종료"></a>

### 검증과 종료

- 원본 의미·MusicXML 규격·저장 왕복·표시·실제 앱·청취는 [검증 Rule](../engineering/verification.md#verification-rules--검증-범위와-증거)에 따라 각각 판정한다.
- 준비된 결과와 남은 검증을 인계한다. 미확인 사항과 확인된 앱 결함을 구분한다.
- 문제 해결은 [기록 기준](#musicxml-conversion-policy--막힘과-문서-모순)에 따라 남긴다.

<a id="score-production-rules--완성-악보의-상시-인계"></a>

### 완성 악보의 상시 인계

[상시 위임](../../decisions/0018-reusable-score-production-and-handoff.md)은 다음 범위에 적용한다.

- 새 악보·교정본·재제작본은 기존 **드럼연습실 웹앱 개발** 담당에게 메시지로 전달한다.
- 같은 대상·범위의 승인을 다시 묻지 않는다. 코드 공통화·문서 정리만 한 작업은 악보 인계 대상이 아니다.
- 현재 담당과 연락 경로(`thread ID`·`host`)를 확인한다. 최종 파일·해시·검증 상태·한계·다음 조치와 실제 전송·접수 근거를 남긴다.
- 최종 응답에 파일 링크를 남긴 것만으로 인계 완료라고 보고하지 않는다.
- 이 위임을 새 담당 배정·무관한 메시지·별도 시험·Git 통합·공개 발행 승인으로 확대하지 않는다.

### 선택 순서

| 원본 조건              | 기본 경로                                           | 판단 기준                                                                       |
| ---------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------- |

| 스캔·사진              | Audiveris 초벌 후 Codex 원본 대조·교정              | 먼저 시험할 경로다. 모든 이미지에서 가장 정확하다고 가정하지 않는다.            |
| 벡터·이미지가 섞인 PDF | 페이지별 판별 후 해당 경로 적용                     | 문서 전체를 하나의 형식으로 단정하지 않는다.                                    |

<a id="musicxml-conversion-policy--보존과-검증"></a>

### 보존과 검증

원본과 기존 결과의 보존은 [출력과 보존](#출력과-보존)을 따른다.

- 마디 수·박자·템포·음표 시작과 길이·다성부·악기 매핑·장식음·연음·반복을 원본과 대조한다.
- [표기 매핑](notation.md)·[SVG 규칙](rendering.md)에 따라 MusicXML 규격과 재렌더링을 검사한다. 변환 경로 선택은 매핑 변경 승인이 아니다.
- 미확정 매핑·누락·교정 내용·남은 검증을 명시한다. 표본 F1 점수를 전곡 정확도로 표현하지 않는다.

<a id="musicxml-conversion-policy--첫-박과-카운트오프"></a>

### 첫 박과 카운트오프

- 새 곡이나 음원을 교체한 곡은 음원 0초와 악보 첫 박을 구분한다. `firstBeat`와 첫 마디의 `start`를 대조한다.
- 첫 박 앞의 무음·도입을 보존한다. 수치 검증과 실제 청취 결과를 구분한다.
- 카운트오프를 껐을 때는 맞고 켰을 때만 어긋나면 앱 예약 문제로 분류한다. 정상 곡 데이터를 이동하거나 음원을 잘라 우회하지 않는다.
- 카운트오프 켜기·끄기, 처음·중간 시작, 배속·반복 검수는 [음원 연결 절차](../../how-to/produce-score.md#score-production-process--5-음원-첫-박bpm마디-시간-연결)를 따른다.

<a id="musicxml-conversion-policy--가사-기준--악보-우선"></a>

### 가사 기준 — 악보 우선

- 가사 시작·길이는 원본 악보의 마디·박·음가와 인쇄 음절의 대응을 기준으로 기록한다. 가수의 실연 차이를 반영하지 않는다.
- 실제 가창 시각 측정, STT, 강제 정렬, 시간 가사 검색은 PDF 변환의 완료 조건이 아니다.
- 악보 위치에서 계산한 재생 캐시를 실제 가창 전사 값으로 보고하지 않는다.
- 판독이 불확실한 위치는 대상·근거·다른 가능성을 기록한다. 그리드와 미확정 처리 기준은 [작성 상위 규칙](#score-production-rules--오선-부착-표기의-공통-기본단위)을 따른다.
- 서로 다른 음절의 시작점은 [가사 시작점 계약](musicxml.md#musicxml-canonical--서로-다른-음절의-시작점)에 따라 검사한다. 제작 대상 목록에는 수록 외 현행 제작 정본도 포함한다. 보관 원본·구판은 구분하고 자동 덮어쓰지 않는다.

저장: [정본 계약](musicxml.md#musicxml-canonical--musicxml-정본-계약). 검사: [가사 교정 절차](../../how-to/correct-lyrics.md#lyric-onset-audit). 근거: [ADR-0013](../../decisions/0013-score-based-lyric-positions.md).

<a id="musicxml-conversion-policy--막힘과-문서-모순"></a>

### 막힘과 문서 모순

| 상황                                         | 근거 확인 순서                                           |
| -------------------------------------------- | -------------------------------------------------------- |
| 제작 중 막혔거나 이미 결정된 내용이 불명확함 | 현재 정본 문서 → 과거 악보 제작 세션 → 공식 웹 자료      |
| 문서끼리 모순되어 보임                       | `history.md` → 다른 관련 문서 → 과거 제작 세션 → 웹 자료 |

이미 확정된 내용을 다시 묻기 전에 위 순서로 조사한다. 이 조사 순서는 현재 사용자 결정·승인된 정본의 우선순위를 바꾸지 않는다.

해결한 문제는 곡별 `docs/records/songs/<곡 식별자>.md` 또는 공통 [제작 도구 기록](../../records/production-tools.md)에 남기고 `history.md`에 연결한다.
기록에는 증상·조건, 원인·근거, 수정·보존 범위, 검증, 다음 적용 기준과 남은 한계를 포함한다.
확인하지 못한 원인·렌더러 지원 여부·추정 시각은 미확정으로 기록한다.

<a id="lyric-feedback-rules--수동-가사-싱크-피드백-접수"></a>

## 수동 가사 싱크 피드백 접수

사용자가 **가사 싱크 교정을 별도 요청한 경우**에만 적용한다. PDF 변환은 [악보 우선](#musicxml-conversion-policy--가사-기준--악보-우선)이며 실제 가창 측정을 기본 요구로 추가하지 않는다. 근거: [ADR-0013](../../decisions/0013-score-based-lyric-positions.md).

| 전달 내용·상황   | 접수 기준                                                                                                                                  |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 구절만 전달      | 해당 구절의 첫 음절 시작으로 해석한다. 별도 지정이 없으면 교정 목록 행의 “확인할 첫 가사”를 대상으로 한다. 굵은 글씨 여부로 고르지 않는다. |
| 음절을 명시      | 지정한 음절을 우선한다. 같은 대상을 다시 묻지 않는다.                                                                                      |
| 위치를 순차 전달 | 누적 접수한다. 통합된 고유번호도 같은 행으로 접수한다. 좌표 전달만으로 앱·가사 데이터를 변경하지 않는다.                                   |
| 일괄 반영 요청   | 요청한 범위에 한해 실제 데이터와 `confirmed`를 적용한다.                                                                                   |

순차 청취의 확인 범위는 다음과 같다.

- 사용자가 새로 체크한 지점보다 앞의 미지적 가사는 현재 위치가 맞는 것으로 기록한다.
- 이전 개별 교정값은 보존한다. 포괄 확인으로 취소하거나 덮어쓰지 않는다.
- 체크 지점 자체는 전달 좌표를 교정값으로 접수한다. 뒤 구간은 확인된 것으로 취급하지 않는다.
- 현재 확인 경계·대상 ID·실제 시각·적용 판본은 해당 곡의 제작 기록에 남긴다.
- 과거 경계를 새 곡에 복사하거나 음원 분석 추정으로 사용자 청취 확인을 만들지 않는다.

기존 사례는 [곡별 제작 기록](../../records/README.md#곡별-제작-기록)에서 찾는다.
