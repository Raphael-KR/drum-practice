## MusicXML 정본 계약

자료별 권위는 [정본과 파생 모델](#정본과-파생-모델)을 따른다.

<a id="musicxml-canonical--정본과-앱의-수정-책임"></a>

### 정본과 앱의 수정 책임

문제 구간의 XML을 현행 입력·표기·출력 규칙과 대조한다. [프로젝트 기본 규칙](../../../AGENTS.md#수정과-실행의-기본-규칙)에 따라 수정 위치를 정한다.

| 확인한 원인                                       | 수정 위치와 방법                                                                                  |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| MusicXML의 오류·누락 또는 프로젝트 표기 규칙 위반 | 제작 단계에서 정본을 교정한다. 앱의 기본값 보충·표시 보정·곡별 예외로 문제를 감추지 않는다.       |
| 올바른 정본을 앱이 잘못 해석하거나 표시함         | 공통 렌더링 코드를 수정한다. 정상 정본을 앱 오류에 맞춰 바꾸지 않는다.                            |
| 원인을 아직 구분하지 못함                         | 문제 마디·속성·적용 규칙·관측 결과를 좁혀 확인한다. 미확정으로 기록하며 추정으로 보정하지 않는다. |

- XSD 통과는 프로젝트 표기 규칙의 충족까지 보증하지 않는다.
- 프로젝트에서 요구하는 위치·정렬 속성은 정본에 기록한다. 교정 후에는 변경 속성과 음악·가사·메타정보의 보존을 대조한다.
- 기존 편집·저장·렌더링과 승인된 공통 조판은 유지한다. 이 책임 구분으로 코드·저장 자료를 일괄 삭제하지 않는다.
- 악보제작자는 원본·정본의 제작·교정·형식 전환을 맡는다. 웹앱 개발 담당은 인계 결과를 확인해 수록 패키지와 두 앱의 공통 경로에 반영한다.

관련 기준: [담당](../../../AGENTS.md#악보와-웹앱의-담당-구분) · [인계](production.md#score-production-rules--원본-판단과-재사용) · [XML 위치 해석](rendering.md#svg-score-rules--공통-xml-위치-계약) · [검사 선택](../engineering/verification.md#verification-rules--변경-영향과-검사-선택).

<a id="musicxml-canonical--현재-가사-제작-기준"></a>

### 현재 가사 제작 기준

- 가사 위치·음가는 [악보 우선 기준](production.md#musicxml-conversion-policy--가사-기준--악보-우선)을 따른다. 실연 차이로 위치·음가를 바꾸지 않는다. 실제 가창 측정은 완료 조건이 아니다.
- 음절 위치를 판독한 가사는 같은 드럼 파트·보표 안의 독립 성부에 저장한다.
- 마디 귀속만 확인되는 문구는 [마디 가사 계약](#measure-lyrics--마디-단위-인쇄-가사-계약)으로 보존한다. 음절별 위치와 음가를 임의로 만들지 않는다.

<a id="musicxml-canonical--저장-계약"></a>

### 저장 계약

#### 정본과 파생 모델

| 자료                      | 역할                                                                         |
| ------------------------- | ---------------------------------------------------------------------------- |
| `RecordData.canonicalXML` | 악보·가사·메타정보·음원 연결의 정본                                          |
| `Song`                    | XML에서 복원하는 화면·편집·오디오용 파생 모델                                |
| `time/end/grid`           | 악보 위치·음원 연결에서 계산한 재생·기존 표시 캐시. 실제 발음 전사 값이 아님 |
| SVG                       | 공통 조판기가 정본에서 생성하는 표시 결과                                    |

- 가사 편집은 앱 소유 가사 성부만 다시 쓴다. 드럼 음표·쉼표·기호·성부와 다른 메타정보·파트는 보존한다.
- 제목·제작자 변경은 정본 XML에 기록하고 열 때 `Song`을 복원한다.
- 정본을 렌더러 출력으로 다시 만들지 않는다. 앱 전용 확장 필드는 직접 보존하고 실험 전용 메타데이터는 운영 형식에 넣지 않는다.

#### 가사의 위치와 음가

| 필드               | 의미·단위                                    |
| ------------------ | -------------------------------------------- |
| `measureId`        | 음절이 시작하는 마디의 안정 ID               |
| `quarterOffset`    | 해당 마디 시작부터의 사분음표 길이 단위 위치 |
| `durationQuarters` | 사분음표 길이 단위의 음절 길이               |

- 화면의 ‘박’은 박자표 분모로 환산한다. 편집 조작 간격과 정본의 공통 기본 단위를 구분한다. 조작 간격이 더 크더라도 정본의 세부 위치·음가를 축소하거나 자동 반올림하지 않는다.
- XML에는 `divisions`·`duration`과 독립된 `unpitched` 음표의 `lyric`으로 기록한다. 보컬 음높이를 추정하지 않는다.
- 가사 음표는 `print-object="no"`, `print-lyric="yes"`, `dynamics="0"`으로 저장한다. 별도 가사 보표를 만들지 않는다.
- 순차 음절은 같은 `voice`를 재사용한다. 시작이 다른 음절의 길이가 겹치면 다른 성부를 사용할 수 있다. [같은 시작점의 중복](#musicxml-canonical--서로-다른-음절의-시작점)은 금지한다.
- 마디를 넘는 길이는 `extend`로 보존한다.
- 기존 드럼 `divisions`로 필요한 가사 위치·음가를 정확히 표현할 수 없을 때만 공통 배수로 환산한다. `divisions`와 모든 `duration`(`backup`·`forward` 포함)·`offset`을 함께 환산하고 드럼의 음악적 위치·음가를 유지한다. 기본 단위 통일만을 위해 기존 `divisions`를 일괄 변경하지 않는다.

#### 가사 성부의 소유 범위

- v2의 `partId`는 가사 성부가 있는 드럼 파트다. 각 음절의 `noteId`는 표준 `note`의 고유 `id`다.
- 음절 ID·확인 상태는 성부 번호와 분리한다.
- 앱이 추가한 가사 리듬은 시작·끝 XML 주석으로 구분한다. 재저장할 때 해당 블록과 연결된 `backup`만 교체한다.
- 주석이 없으면 메타데이터의 소유 성부로 연속 가사 블록을 확인한다. 드럼·가사가 섞여 경계가 불명확하면 원문을 유지하고 해당 마디·성부를 오류 근거로 알린다.
- 편집 준비의 드럼 쉼표 교정과 전체 쉼 마디 판정은 `canonical-lyric-voice.ts`의 공통 소유 블록 판별을 사용한다. 가사 음표와 시간 간격용 쉼표는 드럼 목록에서 제외한다.
- 판별은 읽기 전용이며 가사 블록·`backup`을 변경하지 않는다. 성부 번호 3·4나 숨김 속성만으로 제외하지 않는다. 비소유 성부의 오류 판정은 유지한다.

#### 정본 메타데이터

`drum-practice:score:v2`를 `miscellaneous-field`에 저장한다.

- 마디의 안정 ID·라벨·박자표, 음원의 시작·끝 연결점, 음원 SHA-256, 음절 ID·확인 상태를 보존한다.
- 현재 앱은 정본 XML의 마디 순서로 재생하며 반복 기호를 자동으로 펼치지 않는다. 일반 전사본은 인쇄 순서이고 `occurrence=1`이다.
- 제작자가 확인한 반복·괄호 순서를 펼친 연주본은 원본 전사본과 구분한다. 원본을 보존하고 원본 마디 → 연주 마디의 1:n 대응·회차를 제작 메타정보에 기록한다. 연주본의 마디 ID는 각각 고유하다. 앱이 반복을 다시 전개하거나 원본 마디 수로 축소하지 않는다.
- 임의 중간 박 앵커를 편집하는 UI는 제공하지 않는다. 명시적 `beatTimes`가 있으면 [박별 음원 연결 계약](#musicxml-canonical--악보의-박별-음원-연결)을 적용하고, 없으면 마디 시작·끝을 균등 보간한다.
- XML에 음원 해시가 있으면 열 때 실제 음원과 대조한다.

#### 제목·가수·제작자

| 값            | MusicXML 저장 위치                              |
| ------------- | ----------------------------------------------- |
| 원제          | `work-title`                                    |
| 표시 제목     | `movement-title`, `drum-practice:display-title` |
| 가수·아티스트 | `identification/creator type="artist"`          |
| 작곡자·작사자 | `creator`의 `composer`·`lyricist`               |

- **새로 제작·교정·재제작하는 드럼 연습 악보의 가수란에는 선택한 드럼킷 이름을 기록한다.** 예: `SoCal 드럼킷`, `Portland 드럼킷`.
- 드럼킷은 [선택 기준](drum-kits.md#garageband-drum-kits--드럼킷-선택과-보존-라이브러리)을 따른다. SoCal로 고정하지 않는다.
- MusicXML `artist`·`Song.artist`·패키지 XML/Song의 값은 같아야 한다. 제작·교정·재제작·저장 후 재읽어 누락·불일치를 검사한다.
- 이 메타정보 규칙을 요청하지 않은 음원 제작으로 확대하지 않는다.
- 일반 곡은 실제 가수·아티스트를 유지한다. 세션 연주자·강사·참고 영상 채널은 가수로 입력하지 않는다. 참고 출처는 제작 문서에 기록한다.

#### 이전 형식의 호환성과 편집 범위

- `drum-practice:score:v1`의 별도 `DrumPracticeLyrics` 파트와 음절별 성부 매핑은 계속 읽는다.
- v1은 다음 저장 때 v2로 전환하며 가사 파트를 중복 생성하지 않는다. 패키지·DB 열기만으로 일괄 저장하지 않는다. 구버전 앱의 v2 재저장은 미지원이다.
- 초 단위 자유 가사 편집과 끝 시각 입력은 제공하지 않는다. 과거의 초 단위 데이터는 복구 근거로 보존한다. 구형 데이터를 처음 이전할 때 기존 시작 격자를 유지하고 끝 길이는 음악적 단위로 변환한다.
- 드럼 악보가 있는 MusicXML의 마디 수·박자표 변경은 원본 악보에서 수행한다. 앱은 해당 편집을 막고 영역·음원 연결 편집은 제공한다.
- PDF만 있는 곡은 PDF를 유지하며 가사 XML부터 보존한다. 채보하지 않은 드럼 음표를 만들거나 이 XML을 전체 드럼 채보라고 표시하지 않는다.

<a id="musicxml-canonical--서로-다른-음절의-시작점"></a>

### 서로 다른 음절의 시작점

#### 새 작성 기준

- 새 제작·교정 정본의 서로 다른 음절은 곡 전체에서 음악적 시작점이 달라야 한다. 성부를 나눠도 같은 시작값은 금지한다.
- 텍스트 없는 `extend`는 새 음절이 아니다. 마디 경계의 동등한 음악적 시점은 같은 시작으로 비교한다.
- 시작이 다른 음절의 길이 중첩은 원본·교정 근거와 독립 성부로 보존할 수 있다.
- 원래 보컬 파트의 보존 사본은 현재 가사 정본과 구분한다.

#### 위치 결정과 검사

- 단위·위치 결정·배치 기준점·세분 리듬 예외는 [작성 상위 규칙](production.md#score-production-rules--오선-부착-표기의-공통-기본단위)을 따른다. 가사 앵커는 같은 음악적 위치의 조판 좌표를 사용한다.
- 그리드 준수·원본 위치 일치·서로 다른 시작점 여부를 각각 검사한다.
- 임의의 미소값(`epsilon`), 표시 좌표 이동, 음절 삭제·병합·순서 변경으로 중복을 숨기지 않는다.
- 원본과 기존 제작 기록을 대조해 시작·필요한 길이를 정본에 기록한다. 판독 근거가 부족한 위치는 미확정으로 남긴다.
- 추정·편집 판단을 원본 일치나 실제 가창 검증으로 보고하지 않는다. 드럼·박자·BPM·음원·곡/음절 ID·문구와 교정 전 자료를 보존한다.

#### 구형 자료의 읽기

구형 v1·v2는 동시 시작이 있어도 읽고 원문을 보존한다. 자동 이동·삭제나 앱 표시만으로 보정하지 않는다. 제작 검사로 대상을 식별하고 승인된 교정본을 인계한다.

결정 근거는 [ADR-0030](../../decisions/0030-distinct-lyric-onsets.md), 실행은 [가사 교정 절차](../../how-to/correct-lyrics.md#lyric-onset-audit)를 따른다.

<a id="musicxml-canonical--음원-템포와-연습-박"></a>

### 음원 템포와 연습 박

**연습 박은 선택한 속도의 일정한 메트로놈 박을 따른다.**
실연의 개별 타격이 앞서거나 늦는 그루브로 연습 격자를 흔들지 않는다. 기보된 리듬·음가·박자 변경은 보존한다.
승인된 곡별 일정 연결 정책을 자동 실연 추종으로 바꾸지 않는다.
Loveholic의 고정 연결·추가 추종 분석 제외 범위와 수치는 [ADR-0015](../../decisions/0015-score-tempo-and-recording-estimates.md#context-and-problem-statement)를 따른다.

음원 측정값은 악보 템포와 분리해 `miscellaneous-field`의 `drum-practice:recording-tempo:v1` JSON에 저장한다.

| 필드                       | 의미                   |
| -------------------------- | ---------------------- |
| `version`                  | 메타데이터 버전        |
| `scoreBpm`                 | 악보 BPM               |
| `bpmEstimate`              | 음원에서 추정한 BPM    |
| `firstBeatEstimateSeconds` | 음원의 첫 박 추정 시각 |
| `audioSHA256`              | 분석한 음원의 해시     |
| `method`, `status`         | 측정 방법과 확인 상태  |

- 측정값은 음원 해시에 결합된 프로젝트 전용 추정치다. 일반 MusicXML 앱의 필수 기능이 아니며 표준 템포·기존 마디 시각을 덮어쓰지 않는다.
- 앱은 원곡 추정값을 표시한다. ‘원곡’ 재생은 배속 1.0을 사용한다.

<a id="musicxml-canonical--악보의-박별-음원-연결"></a>

#### 악보의 박별 음원 연결

| 항목                                       | 계약                                                                                 |
| ------------------------------------------ | ------------------------------------------------------------------------------------ |
| 저장·복원                                  | v1·v2 마디 메타데이터의 선택적 `beatTimes`를 `Song.measures`로 복원한다.             |
| 배열 길이                                  | 기보 박 수와 같아야 한다.                                                            |
| 값                                         | 첫 값은 `start`, 이후는 엄격히 증가하며 모든 값은 `end`보다 작아야 한다.             |
| 배열 없음                                  | 마디 시작·끝의 균등 보간을 사용한다. 기존 악보에 자동 추정 박을 주입하지 않는다.     |
| 원곡 재생                                  | 원본 1배속과 저장된 박 시각을 사용한다. 현재 BPM은 완료된 최근 박 간격으로 계산한다. |
| 연습 모드                                  | 박자표 분모를 반영한 사분음표 위치로 음원을 정규화하고 고정 BPM을 사용한다.          |
| 시작·끝 연결점 편집                        | 내부 박 시각도 같은 비율로 이동한다.                                                 |
| 명시적 전체 템포 재배치·XML 표준 템포 적용 | 박별 배열을 제거하고 균등 연결로 바꾼다.                                             |

기보 음가·박자표·가사 위치와 승인된 곡별 일정 연결 정책은 유지한다.
정본에 배열이 없으면 파생 캐시의 배열도 제거한다.
붉은 노을의 `drum-practice:recording-grid:v1`은 제작 추정 근거로만 보존하며 런타임에서 임의 적용하지 않는다.

<a id="musicxml-canonical--보컬-악보-입력"></a>

### 보컬 악보 입력

- 선택한 보컬 MusicXML 파트는 드럼 악보와 마디 수·각 박자표가 같아야 한다. 전주와 반복 순서도 확인한다.
- 가사가 있는 음표의 리듬을 같은 드럼 보표의 독립 가사 성부에 기록한다. 원래 보컬 파트는 `DrumPracticeVocalSource`로 보존한다.
- 가사 교체는 사전 확인한 범위에서 수행하며 이전 가사는 이력에 보관한다.
- PDF 보컬 악보의 자동 채보와 음절별 노래 청취는 이 입력 계약에 포함하지 않는다.

조작 순서는 [보컬 입력 절차](../../how-to/correct-lyrics.md#score-production-process--보컬-musicxml-입력)를 따른다.

<a id="musicxml-canonical--보존과-교환"></a>

### 보존과 교환

- IndexedDB·전체 보관함 백업·`.drumscore`에서 정본을 보존한다.
- MusicXML 내보내기는 정본 XML을 직접 저장한다. 다시 가져오면 가사·메타정보·음원 연결점을 읽는다.
- 구형 개별 ZIP의 `canonical.musicxml` 복원과 독립 HTML 저장·내보내기는 제공하지 않는다.
- PDF만 있는 곡의 원본과 가사 XML은 [이전 형식의 호환성과 편집 범위](#이전-형식의-호환성과-편집-범위)를 따른다.

<a id="musicxml-canonical--렌더러-계약"></a>

### 렌더러 계약

두 앱은 OpenSheetMusicDisplay와 [공통 조판·캐시](rendering.md#browser-musicxml-rendering--브라우저-공통-musicxml-조판-계약)를 사용한다. 정본·파생 데이터의 구분은 [저장 계약](#musicxml-canonical--저장-계약)을 따른다. 근거: [ADR-0004](../../decisions/0004-browser-native-score-rendering.md)·[ADR-0012](../../decisions/0012-musicxml-canonical-source.md).

<a id="musicxml-canonical--검증"></a>

### 검증

- 저장한 정본을 재읽어 마디 ID·박자·메타정보·가사 위치·음가·음원 해시·연결점·선택적 `beatTimes`를 비교한다. 파생 캐시로 정본의 누락값을 다시 채우지 않는다.
- 음절 시작점 중복과 길이 중첩을 따로 검사한다. 마디 연장·보컬 세부 음가와 음원 연결점 편집 후 악보 위치의 보존을 확인한다.
- 구형 자료의 동시 시작 읽기 호환성과 새 정본의 중복 0건을 별도로 판정한다.
- MusicXML 규격 적합성과 실제 저장·재읽기 결과를 구분한다. 외부 프로그램의 확장 필드 보존은 별도 검증 없이는 보장하지 않는다.
- 실제 입력·환경·검사 범위·한계를 제작·개발 기록과 `history.md`에 남긴다. 과거 검사·시작 위치 이전·기기 검증을 이번 실행의 통과로 사용하지 않는다.

<a id="measure-lyrics--마디-단위-인쇄-가사-계약"></a>

## 마디 단위 인쇄 가사 계약

근거: [ADR-0013](../../decisions/0013-score-based-lyric-positions.md). 실행: [제작 절차](../../how-to/produce-score.md#score-production-process--악보-제작-프로세스).

<a id="measure-lyrics--목적과-범위"></a>

### 목적과 범위

인쇄 악보에서 마디 귀속만 확인되는 문구를 가창 시작·길이 추정 없이 보존한다.
마디 중앙은 문구의 표시 기준점이며 음절의 음악적 시작점을 뜻하지 않는다.
SVG 전체 보기·연주 화면은 이 기준으로 표시하고, PDF는 원본에 인쇄된 가사만 표시한다.
기존 음절 가사의 `Song.lyrics`·`scorePosition`은 유지한다.

<a id="measure-lyrics--데이터"></a>

### 데이터

`Song.measureLyrics?: { id: string; measureId: string; text: string; placement: "measure-center" }[]`

#### 저장과 왕복

- `measureId`는 실제 `measures` 항목을 가리켜야 한다. 항목 ID와 마디 귀속은 각각 중복되지 않는다. 한 마디의 문구는 하나의 `text`로 합친다.
- `time`·`end`·`quarterOffset`·`durationQuarters`를 갖지 않는다. 음절 강조나 가창 길이를 주장하지 않는다.
- 정본 MusicXML의 기존 `miscellaneous` manifest에 선택 필드로 저장한다. 가짜 음표를 생성하지 않으며 원본 성부를 유지한다. 예전 파일은 이 필드가 없어도 호환된다.
- `.drumscore`의 Song 데이터와 XML 왕복에서 보존한다. 마디 문구를 음절 가사로 임의 변환하지 않는다.

#### 표시와 편집

- 두 앱의 SVG 전체 보기·연주 1줄·2줄은 공통 `score/score-lyrics.ts`에서 같은 귀속·문구를 OSMD 라벨로 그린다. PDF에는 가사를 추가하지 않는다.
- 크기·색·공간 확보는 [가사 표시 규칙](rendering.md#svg-score-rules--전체-보기-가사)을 따른다.
- `lyricText`는 전체 가사 원문이며 XML의 `drum-practice:lyric-text`에 보존한다. 제작기의 읽기·편집·TXT 내보내기에 사용한다.
- 드럼연습실 설정에는 전체 가사 보기 메뉴를 제공하지 않는다. 이 표시 기능의 종료를 원문·마디 문구·음절 데이터 삭제로 확대하지 않는다.
- 박 단위 가사 편집 표는 기존 리듬 가사만 편집한다. 마디 문구용 편집 UI는 제공하지 않는다.

<a id="musicxml-input--musicxml-입력-계약"></a>

## MusicXML 입력 계약

**현재 앱의 가져오기 제한**이며 MusicXML 표준의 표현 한계가 아니다. 제한에 맞추려고 원본 리듬을 임의로 삭제·변경하지 않는다.
관련 기준: [저장](#musicxml-canonical--저장-계약) · [매핑](notation.md#score-musicxml-osmd-mapping--악보의-musicxml--osmd-매핑-규칙) · [출력](rendering.md#svg-score-rules--svg-전체-악보-생성-규칙). 근거: [ADR-0004](../../decisions/0004-browser-native-score-rendering.md).

<a id="musicxml-input--형식과-지원-경계"></a>

### 형식과 지원 경계

| 항목             | 지원 범위·제한                                         |
| ---------------- | ------------------------------------------------------ |
| 확장자           | `.musicxml`, `.xml`, `.mxl`                            |
| 문서 구조        | `score-partwise`, 선택한 한 파트의 단일 오선           |
| 여러 파트        | 가져올 파트를 선택할 수 있다.                          |
| 박자             | 박 수 1~16, 분모 2·4·8·16                              |
| 템포 변경        | 마디 경계에서 지원                                     |
| 자원 제한        | XML/MXL 12MB 이하, 최대 2,000마디                      |
| 반복·다카포·코다 | 인쇄 순서로 읽는다. 자동 연주 순서 확장은 하지 않는다. |
| 여러 마디 쉼표   | 각 마디로 표시                                         |

한 파트의 여러 오선, `score-timewise`, 못갖춘마디·불완전한 음가 합계, 마디 중간 템포 변경은 오류 안내 후 가져오기를 중단한다.

- 렌더러·문서 배치에 따라 페이지 수·글자 배치는 원본 PDF와 다를 수 있다. 악기 매핑은 변환 검증으로 확인한다.
- 정박 기준점은 렌더러의 음표·쉼표 좌표에서 구하고 박 사이는 보간한다. 입력 파싱 성공을 완전한 음표별 커서·악보 편집 기능의 지원으로 해석하지 않는다.
- XML 템포·가사 음가는 녹음의 첫 박·루바토·실제 발음 시각을 증명하지 않는다. 음원 연결 편집은 [음원 템포와 연습 박](#musicxml-canonical--음원-템포와-연습-박)을 따르며 가사 작성 기준과 구분한다.
- 원본 바이트는 `pdf`, 형식·선택 파트는 `scoreFormat`·`scorePartId`에 저장한다. MXL은 원본 ZIP 바이트를 유지한다. 이 가져오기에 별도 DB 마이그레이션은 필요 없다.

<a id="musicxml-input--곡별-악보-형식"></a>

### 곡별 악보 형식

#### 공통 데이터와 형식별 자산

- 곡 ID 하나에 음원·가사·시간축·마커·반복·설정을 공유한다.
- 목록의 유형 버튼에는 실제 원본이 보관된 PDF·MusicXML과 비어 있지 않은 가사만 표시한다.
- 활성 악보는 기존 `pdf`·`pages`·`song.regions` 슬롯을 사용한다. 비활성 유형의 원본·페이지·영역·마디 ID 대응은 `RecordData.otherScores`에 보존한다.
- 형식 전환 시 현재 영역 편집을 스냅샷으로 보관하고 대상 영역만 교체한다.

#### 갱신과 전환 조건

- 같은 유형을 다시 추가하면 확인 후 그 유형만 갱신한다. 다른 유형은 보존하고 제목이 같은 별도 곡을 임의로 합치지 않는다.
- 마디 추가·삭제·박자 변경으로 이전 유형과 구성이 달라졌으면 전환을 거절한다.
- 새 PDF는 감지한 마디 수, XML은 마디 수와 박자표가 현재 곡과 같아야 한다. PDF 감지가 틀렸으면 그대로 연결하지 않는다.

`bytes-v1`, 전체 보관함 백업·복원, `.drumscore`의 원본 자산 보존을 유지한다.
개별 `song.json` ZIP 백업의 생성·복원과 독립 HTML 저장은 지원하지 않는다.
기존 단일 악보 데이터는 계속 읽는다. 과거 소실된 원본을 복구했다고 표시하지 않는다.

<a id="musicxml-input--실행"></a>

### 실행

[제작·검수 절차](../../how-to/produce-score.md#score-production-process--악보-제작-프로세스)와 [완성 파일 사용](../../how-to/review-score.md#practice-files--완성-악보와-연습-정보-파일-사용-절차)을 따른다.
입력 파싱 성공은 채보 정확성이나 주법 표시 성공의 증거가 아니다.
