## 팀 UX 원칙과 맥락형 도움말

결정 근거: [ADR-0021](../../decisions/0021-contextual-help-and-shared-ui.md). 실행: [절차](../../how-to/verify.md#ui-review--화면악보재생-검수-절차).

<a id="ux-principles--목적과-적용-범위"></a>

### 목적과 적용 범위

반복 사용의 수고를 줄이고, 행동의 결과를 예측할 수 있게 만든다. 드럼연습실과 악보제작기의 화면 설계·구현·리뷰에 적용한다.

악보 선택 목록은 두 앱의 공통 카탈로그를 사용한다. 제작기에도 기본 연습곡과 내 악보를 모두 표시한다. 저장 전에는 ‘악보 불러오기’, 저장 후에는 ‘편집 열기’로 연결하며, 다운로드 뒤에는 편집창까지 연다. 음원 전용 항목은 연습실에서 관리한다.

두 앱의 목록 카드·즐겨찾기·곡명/가수 배치·간격은 공통 UI를 사용한다. 드럼연습실은 블루, 악보제작기는 오렌지 테마로 구분한다. 앱별 CSS 색상 변수로 제목 바·주요 버튼·선택 상태·배경만 바꾸고, 악보의 마커·반복 구간 등 의미 색상은 유지한다. 제작기의 새 악보 만들기는 목록 상단에 둔다. ‘내 악보 목록’은 재생을 멈추고 작업 내용을 저장한 뒤 이 공통 홈으로 돌아간다. 중복 목록 팝업을 만들지 않는다.

‘깔끔함’은 구별이 선명하고, 공간을 효율적으로 쓰며, 눌렀을 때 결과를 예상할 수 있는 화면을 뜻한다. 흐릿한 색이나 넓은 여백 자체를 목표로 삼지 않는다. 첫인상보다 실제 반복 사용 중 수고와 혼란 감소를 우선한다.

<a id="ux-principles--선호-원칙-8가지"></a>

### 선호 원칙 8가지

| 원칙 | 적용 지침과 사례 |
| --- | --- |
| 조작 단계 최소화 | 자주 쓰는 기능은 직접 접근하게 한다. 드문 기능까지 모두 노출하지 않으며, 백업 관리처럼 빈도가 낮은 기능은 우선순위를 낮춘다. |
| 불필요한 인지·판단 부담 감소 | 사용자의 행동에 도움이 되지 않으면서 주의를 끌거나 해석·선택을 요구하는 정보는 제거한다. 버튼명을 되풀이하는 설명, 중복 제목·정보, 불필요한 상태 문구를 줄인다. 정보 삭제보다 부담 감소가 목표이므로, 삭제·교체의 결과나 복구 방법처럼 판단에 필요한 정보는 제공한다. |
| 관련 기능 그룹화 | 재생1바·재생2바를 재생바 그룹으로 묶고, 곡 관리 기능은 편집창의 탭으로 묶는다. 작업 흐름을 기준으로 배치한다. |
| 모양으로 관계 표현 | 선택된 탭과 본문은 시각적으로 이어지게 한다. 영역은 색으로 구분하되 색만으로 상태를 전달하지 않는다. 모든 요소를 동시에 강조하지 않는다. |
| 목적에 맞는 아이콘과 글자 | 재생·닫기처럼 익숙한 행동은 픽토그램, 탭처럼 이름이 더 명확한 곳은 글자를 쓴다. 아이콘 사용을 강제하지 않는다. |
| iPad 터치 최적화 | 충분한 터치 영역과 자연스러운 스크롤을 제공한다. 조작 중 화면이 갑자기 이동하거나 재정렬되지 않게 한다. |
| 상태 기반 노출과 위치 안정성 | 가사가 없으면 업로드, 곡이 없으면 목록·추가처럼 현재 가능한 행동을 제시한다. 상태 변화로 조작 위치가 갑자기 바뀌지 않게 한다. 기능을 알려둘 필요가 있지만 일시적으로 실행할 수 없다면 비활성과 짧은 이유 표시를 검토한다. |
| 기존 동작 재사용 | 이미 있는 창·기능과 동작 경로를 활용한다. 같은 기능으로 가는 중복 메뉴를 줄이고, 필요한 진입점에서는 동일한 기존 동작을 연결한다. |

같은 의미의 조작은 화면이 달라도 일관된 결과를 제공한다. 아이콘과 글자의 선택은 목적에 맞게 달리할 수 있다.

<a id="ux-principles--설계와-리뷰의-태도"></a>

### 설계와 리뷰의 태도

실제 불편에서 출발한다. 작은 정지 버튼, 깊은 메뉴, 갑자기 움직이는 악보처럼 연습을 방해하는 요소를 우선 해결한다. 형식을 고집하기보다 작업 목적과 화면 사이의 관계를 살핀다.

취향을 희석하는 대신 간결함이 정보 부족으로, 직접 접근이 화면 복잡함으로 넘어가는 경계를 검토한다. 사용자 지시라도 사용성·접근성에 불리한 결과가 예상되면 구체적인 이유와 대안을 제시한다. 제작자에게 익숙한 화면이 초행자에게도 명확한지는 별도로 검수한다.

<a id="ux-principles--적용-사례--맥락형-도움말"></a>

### 적용 사례: [?] 맥락형 도움말

<a id="ux-principles--역할"></a>

#### 역할

필요한 사람이 필요한 순간에 여는 보완 수단이다. 강제로 진행하는 튜토리얼로 만들지 않는다. 핵심 행동은 도움말 없이 이해되도록 기본 화면을 설계하고, 도움말에서도 당연한 조작을 반복 설명하지 않는다.

온보딩은 첫 곡 열기·재생·구간 반복 등 첫 사용의 성공 과정 전체를 포함한다. 이 기능의 명칭은 온보딩 슬라이더가 아니라 **맥락형 도움말**이다.

<a id="ux-principles--동작과-구성"></a>

#### 동작과 구성

- 진입점은 메인 화면 제목줄의 공통 `[?]`로 유지한다. 모든 모달·팝업에는 `[?]` 없이 공통 닫기 `×`만 둔다. 모달·팝업 안의 설명은 버튼을 길게 누르고 있는 동안 말풍선으로 제공한다.
- 현재 활성 화면과 상태를 기준으로 관련 도움말을 선택한다. 아래에 가려진 재생 화면보다 현재 편집창 등 사용 중인 화면을 우선한다.
- 실제 버튼 위치를 기준으로 설명을 배치하는 반투명 오버레이를 사용한다. 고정 스크린샷으로 위치를 대신하지 않는다. 회전·해상도·번역에 따라 위치를 갱신한다.
- 도움말을 열면 공통 명칭표의 컴포넌트 이름을 해당 영역의 테두리 위에 표시한다. 버튼을 선택하면 영역 이름을 숨기고 버튼의 명칭(종류)과 설명을 표시한다. 숫자·곡 구간명 등 현재 값만으로 버튼 명칭을 대신하지 않는다. 빈 곳을 누르면 영역 이름으로 돌아간다. 평소 화면에는 영역 테두리를 추가하지 않는다.
- **페이지를 나누지 않는다.** 하단 안내 하나를 두고, 실제 버튼을 가리키거나 선택하거나 키보드 포커스를 옮기면 해당 말풍선 하나만 표시한다.
- 평소에도 모든 버튼을650ms 이상 길게 누르고 있는 동안 말풍선을 표시한다. 떼거나 스크롤·드래그·취소하면 숨긴다. 저장 반복 구간은 삭제 버튼 조작을 위해 손을 떼어도 유지하는 예외다. 동적으로 추가된 버튼에도 공통으로 적용한다.
- 사용 환경에 맞춰 터치 조작 또는 키보드 단축키를 안내한다. 현재 화면과 무관한 내용을 채워 넣지 않는다.
- `×` 또는 Esc로 닫는다. 도움말을 보는 동안 실제 기능 실행을 차단하되 스크롤과 버튼 포커스 이동은 허용하고, 닫으면 원래 작업 위치와 키보드 포커스로 돌아간다.
- 도움말 문구는 공통 i18n 정의를 사용한다. 색상 외의 구분, 읽을 수 있는 대비, 접근 가능한 이름과 키보드 이동을 함께 제공한다.

<a id="ux-principles--공통-검수-질문"></a>

### 공통 검수 질문

1. **처음 보는 사람도 도움말 없이 핵심 행동을 시작할 수 있는가?**
2. **익숙해진 사람은 설명과 불필요한 단계를 건너뛰고 반복 작업을 할 수 있는가?**
3. **잘못 눌렀을 때 무슨 일이 일어났는지 알고, 되돌아올 수 있는가?**

검수 기록에는 대상 화면·사용 상태·수행한 행동·관찰 결과를 남긴다. 실제 확인하지 않은 항목은 통과로 표시하지 않는다. 이 세 질문으로 시작하고, 실제 사용에서 발견한 문제를 근거로 기준을 보완한다.

<a id="ux-principles--관련-문서와-변경-관리"></a>

### 관련 문서와 변경 관리

- [UI 컴포넌트](../../product/UI-COMPONENTS.md): 화면과 컴포넌트 이름.
- [악보 관리 화면](editor.md#score-workspace--악보제작기-편집-화면): 개별 화면의 구조와 동작.

UX 원칙과 도움말 설계의 합의 정본은 이 문서다. 사용자의 새로운 결정으로 바뀌면 이 문서와 관련 화면 명세를 함께 갱신한다.

<a id="ux-principles--악보를-미리-읽을-여유"></a>

### 악보를 미리 읽을 여유

드럼연습실은 반응 속도를 겨루는 화면이 아니다. 음표의 읽기 좋은 크기를 유지하면서 불필요한 가로 간격을 줄이고, 앞으로 연주할 여러 마디를 볼 수 있게 한다. 동일 음가·동일 거리의 정확성뿐 아니라 선행 박 수와 선행 시간도 검수한다. 정량 후보는 [RIBBON-READABILITY.md](../../product/RIBBON-READABILITY.md)에 있으며 확정 수치와 구분한다.

<a id="ux-principles--설정-화면의-연속-탐색"></a>

### 설정 화면의 연속 탐색
- 설정은 [현행 순서](playback.md#settings-playback--설정-범위)에 따라 화면·재생·악보·정보 등 사용 가능한 섹션을 한 스크롤 영역에 모두 표시한다. 각 섹션은 제목과 서로 다른 옅은 배경색으로 구분한다.
- 좌측 메뉴는 화면 전환 대신 섹션으로 이동하는 바로가기다. 직접 스크롤할 때도 현재 섹션을 강조한다. 좌측 메뉴와 닫기 버튼은 내용 스크롤에 함께 사라지지 않는다.
- 좌측 버튼은 공통 CSS와 같은 너비를 사용한다. 기존 왼쪽 padding12px를 보존하고 오른쪽도12px로 맞춰 남는 폭을 줄인다. 좁은 화면에서는 기존 가로 메뉴 배치를 유지한다.

<a id="ux-principles--화면-설정의-선택-버튼"></a>

#### 화면 설정의 선택 버튼

- 재생 설정의 메트로놈은 카운트오프 아래에 제목과 `4분 | 8분 | 끄기` 공통 알약형 선택만 둔다. 우측 설명·빈 설명 공간은 만들지 않는다. 선택된 8분은 상단과 같은 Warm 배경/전경/테두리/포커스 변수를 사용하며, 다른 선택과 기존 알약형 버튼의 기본 외형은 유지한다.
- 보기 방식(한 줄/두 줄)과 악보 형식(PDF 원본/MusicXML)을 위쪽 두 행의 선택 버튼으로 표시한다. 네 버튼은 공통 CSS로 같은 너비·높이를 사용하고 설명 캡션은 오른쪽에 둔다. 좁은 화면에서는 캡션만 다음 줄로 배치한다.
- 음표 따라가기와 전체화면 스위치는 아래에 기존 스타일로 유지한다. 한 줄 보기에서 악보 크기 조절도 유지한다. 제작실의 검수 보기 기능은 추가 선택으로 보존한다.

<a id="ux-principles--4줄-svg-범례-적용"></a>

#### 4줄 SVG 범례 적용
- 범례 모달은 승인된 오선 4줄 SVG를 비율 유지(contain)로 표시한다.
- SVG 내부 배경에 굴절·반투명 면·반사를 적용하고, 음표·텍스트는 왜곡하지 않는다. 모달은 뒤 화면 흐림을 담당한다.
- 공통 src/modules/help/help-legend.ts가 생성된 src/modules/score/vendor/score-legend-svg.ts를 호출한다. 글리프 OFL은 src/modules/score/vendor/Bravura-OFL.txt에 보존한다. 생성기는 docs/design/legend-diagram/draw-four-staves.py이다.
- 모든 SVG CSS는 score-legend-illustration 아래에 한정해 실제 악보 스타일에 영향을 주지 않는다. 화면 읽기용 승인 범례 설명은 별도로 보존한다.

<a id="ux-principles--범례-중앙-배치전체-클릭-닫기"></a>

#### 범례 중앙 배치·전체 클릭 닫기
- 상하 동일 여백으로 SVG를 세로 중앙에 배치하고 공통 X 닫기를 제공한다.
- SVG 음표·설명·여백을 포함한 모달 전체 클릭으로 원래 범례 버튼으로 축소해 닫는다. Esc 및 Enter/Space도 지원한다. 도움말 자체 닫기 버튼은 유지한다.

<a id="ux-principles--모달-애니메이션"></a>

#### 모달 애니메이션
- 버튼 자체는 전환 대상으로 지정하지 않는다. 버튼의 현재 사각형을 기준점으로 삼아 모달 스냅샷만 확대/축소한다.
- 도움말과 범례에 동일한 모달 전용 expand/collapse 규칙을 적용한다.

- 모달 전환 중에만 SVG 배경 굴절 필터를 끈다. 정적 유리 면과 반사는 유지하며 전환 종료 후 굴절을 복원한다. 음표·텍스트와 버튼에는 확대 필터를 적용하지 않는다.
- 전환은 320ms·ease-out이며 중복 실행을 막고 임시 상태를 정리한다. 미지원·모션 감소는 즉시 전환한다. 스냅샷 생략 시에도 실제 열기·닫기를 수행하고 초점을 복원한다.

<a id="ux-principles--설정-사이드바-볼륨"></a>

#### 설정 사이드바 볼륨
- 음악·메트로놈 볼륨은 설정 왼쪽 메뉴 아래 공통 패널에 나란히 둔다. 위쪽은 현재 퍼센트, 가운데는 위로 올릴수록 커지는 세로 슬라이더, 아래는 채널 명칭이다. 오른쪽 설정 본문 스크롤과 독립적으로 표시한다.
- 600px 이하에서는 메뉴 아래 가로 슬라이더 두 개로 배치해 본문 높이를 확보한다. 기존 재생바 소리 버튼과 별도 소리 대화상자는 제거한다. 기존 음량 상태·저장·오디오 반영은 유지한다.

<a id="ux-principles--범례-가독성"></a>

#### 범례 가독성
- 범례 SVG의 호버 툴팁은 표시하지 않는다. 접근성 이름/텍스트 목록은 유지한다.
- 네 줄 전체 범례 구성에서 이름28·설명22 SVG 단위, 음표 도형1.3배를 사용한다. 8열 행의 설명은 위치/모양을 두 줄로 나누고 모달 여백은8px로 줄인다. 음표 위치와 표기 의미는 유지한다.

<a id="ux-principles--연속-배경"></a>

#### 연속 배경
재생 화면의 악보는 흰색, 재생바는 기존 회색, 조작판은 기존 연녹색 배경으로 구분한다. 바깥 테두리·모서리·그림자 제거. 개별 버튼, 오선, 선택 마디 강조는 유지한다. 세로 제목 위 내부 여백24px로 시스템 상단 효과와 거리를 확보한다. 실제 기기의 표시 품질은 해당 환경에서 확인한다.

<a id="ux-principles--마디-위치-숫자판"></a>

#### 마디 위치 숫자판
재생바 진행률(%) 표시는 현재 마디 순번/총 마디 수(예: 1/123)로 대체한다. 드래그와 키보드 조절은1마디 단위로 해당 마디 처음으로 이동한다. 마디 이동(되감기) 숫자의 초기값은4이다.

<a id="ux-principles--조작판9칸"></a>

#### 조작판9칸
바로가기·반복 구간을 각각3행×3열9칸으로 표시한다. 바로가기는 악보 순서대로 앞9개다. 마지막 행을 제거하고 조작판 높이만 줄인다. 줄어든 높이만큼 바깥 패딩을 추가하지 않으며 기존 배경색을 유지한다. 과거10~12번 반복 슬롯의 저장 데이터는 삭제하지 않고 화면에서만 제외한다.

<a id="ux-principles--드럼연습실-화면-명칭"></a>

### 드럼연습실 화면 명칭

악보를 고르는 화면과 재생 화면의 돌아가기 툴팁은 “악보 선택”으로 부른다. 상단 앱 이름은 “드럼연습실”, 위쪽 섹션은 “기본 연습곡”, 아래쪽 섹션은 “내 악보 목록”을 유지한다. 화면 이름과 개인 보관함 섹션 이름을 구분한다.

<a id="ux-principles--악보-선택-상단-공통-버튼"></a>

#### 악보 선택 상단 공통 버튼
- 악보 선택 화면도 새로고침·원형 도움말을 상단 오른쪽에 배치한다. 예약·로컬 악보제작기 링크는 그 앞에 동일한 흰색 버튼 스타일로 표시한다. 공통 조작 크기를 사용해 높이와 세로 정렬을 맞춘다.

<a id="ux-principles--다수-악보용-목록-밀도"></a>

#### 다수 악보용 목록 밀도
- 기본 연습곡/내 악보 목록 구분을 유지하고 페이지 구분 없이 문서 스크롤로 모두 탐색한다. 제목·가수는 한 줄로 나란히 표시하며 긴 문구는 말줄임과 전체 문구 툴팁을 제공한다.
- 행 여백6px/12px, 행 간격6px, 버튼 최소44px로 목록 밀도와 터치 영역을 함께 유지한다. 좁은 화면은 제목·가수 한 줄 아래에 조작부를 배치한다.
- 악보 가져오기는 고정 상단바에 두어 스크롤 중에도 접근한다. 재생 화면에는 이 목록 밀도 규칙을 적용하지 않는다. 제작기 홈의 목록 모양은 두 앱 공통 목록 CSS를 따른다.

<a id="ux-principles--제목-표시-순서-설정"></a>

#### 제목 표시 순서 설정
- 설정 > 화면에서 ‘악보 제목 표시 순서’를 곡명 먼저/가수이름 먼저로 선택한다. 기본값은 곡명 먼저이며 브라우저 공통 설정으로 저장한다. 악보 목록의 제목/가수 순서, 공통 재생 제목·악보 검수 제목·위치 복사에 모두 적용한다. 곡 메타데이터는 변경하지 않는다.

<a id="ux-principles--양자-선택-공통-분할-버튼"></a>

#### 양자 선택 공통 분할 버튼
- 상단 한 줄/두 줄, 설정 보기 방식·PDF/MusicXML·제목 순서는 `.segmented-control` 공통 CSS를 사용한다. 둥근 양끝과 맞닿은 가운데 경계, 선택 항목의 파란 테두리·밝은 배경을 유지한다.
- 상단 하이라이트·하단 음영·외부 그림자로 입체감을 표현하고 hover/active/focus/disabled도 공통 처리한다. 단순 기능 켜기/끄기 스위치와 실행·취소 버튼은 상호 배타적인 모드 선택과 구분한다. 제작기 비교 보기는 같은 컴포넌트의 세 번째 선택으로 유지한다.

<a id="ux-principles--악보-선택-설정-진입"></a>

#### 악보 선택 설정 진입
- 목록 상단 새로고침과 도움말 사이에 설정 버튼을 둔다. 화면 패널의 제목 표시 순서와 음원 JSON 백업 진입을 제공하며 재생 화면과 동일한 분할 버튼 마크업·저장값을 사용한다. 선택 즉시 목록 순서를 바꾸고 닫으면 설정 버튼으로 초점을 돌린다.

<a id="ux-principles--아이폰-세로-전용-화면"></a>

#### 아이폰 세로 전용 화면
아이폰 재생 화면은 세로 전용이다. 폭480px 이하의 세로 재생 화면은 제목 / 악보 선택·전체화면·새로고침·설정·도움말 / 템포·메트로놈·줄보기의 세 줄로 배치한다. 제목은 한 줄로 줄임 표시하고 빌드 정보는 설정의 정보에서 확인한다. 하단에는 처음·재생/정지·되감기 조작, 북마크5개, 섹션 바로가기를 유지하며 구간·현재/전체 마디·앞뒤 반복 조작은 숨긴다. 저장 데이터는 유지한다. 가로 사용 안내 화면과 Safari 회전 잠금 기능은 제공하지 않는다. iPad mini의 가로 배치는 유지하고 세로 재생바는 아래의 두 줄 배치 규칙을 따른다.

<a id="ux-principles--재생-중-화면-유지"></a>

#### 재생 중 화면 유지
공통 재생 화면은 OS 구분 없이 재생/카운트오프 중 Screen Wake Lock을 요청하고 일시정지·재생 종료·재생 화면 해제 때 반환한다. 문서가 숨겨지면 반환하며 다시 보일 때 재생 중이면 재요청한다. API 미지원·권한/전원 정책 거부는 재생을 중단하지 않고, 시스템이 반환한 잠금을 즉시 반복 요청하지 않는다. 요청이 늦게 완료되더라도 현재 정지/해제 상태라면 즉시 반환한다. 별도 설정 없이 자동 적용하며 알림·집중 모드·수동 잠금은 제어하지 않는다.

<a id="ux-principles--선택-마디-원클릭원터치-재생"></a>

#### 선택 마디 원클릭/원터치 재생
정지 중 다른 마디를 한 번 클릭/탭하면 기존처럼 선택한다. 이미 선택된 마디를 한 번 클릭/탭하면 그 마디 처음부터 재생한다. 키보드로 옮긴 선택에도 적용한다. 더블클릭 구간 시작/끝 등록을 유지하기 위해 기존260ms 단일/이중 탭 판정 이후 재생한다. 빈 악보 배경은 재생 트리거가 아니다. 구간 선택 모드 또는 Enter/더블클릭의 끝 마디 대기 중에는 단일 탭으로 재생하지 않는다. 이동8px 이상·스크롤·포인터 취소는 탭으로 처리하지 않는다.

<a id="ux-principles--아이폰-상단-조작-버튼-우측-정렬"></a>

#### 아이폰 상단 조작 버튼 우측 정렬
아이폰 세로 재생 화면의 두 번째 줄 조작 버튼은 오른쪽 끝에 정렬한다. 제목줄과 템포·메트로놈·줄보기 줄, 버튼 크기와 간격은 유지한다. 폭480px 이하 세로 규칙에만 적용한다.

<a id="ux-principles--아이폰-재생-버튼-중심북마크-줄"></a>

#### 아이폰 재생 버튼 중심·북마크 줄
아이폰 세로 재생바는 재생 버튼 자체를 화면 중앙에 둔다. 처음 버튼은 왼쪽, 되감기 버튼/숫자는 오른쪽에 배치한다. 바로 아래 줄에는 기존 마커(북마크)5개를 중앙 정렬한다. 현재/전체 마디와 구간·앞뒤 반복은 숨긴 상태를 유지하고, 섹션 바로가기는 그 아래에 둔다. iPad mini 배치는 변경하지 않는다.

<a id="ux-principles--ipad-mini-세로-재생바-두-줄-배치"></a>

#### iPad mini 세로 재생바 두 줄 배치
기존 재생·마커/마디이동·마디반복 그룹을 유지한다. 첫 줄에는 재생 그룹만 두고 재생 버튼 자체를 화면 중앙에 정렬한다. 둘째 줄에는 마커/마디이동 그룹을 좌측, 마디반복 그룹을 우측에 둔다. 폭720~899px 세로 재생 화면에 적용하고 아이폰·가로 화면 배치는 유지한다.

<a id="ux-principles--마디-숫자판-중앙-구분자"></a>

#### 마디 숫자판 중앙 구분자
현재/전체 마디는 같은 너비의 숫자 영역과 중앙 구분자 세 칸으로 배치한다. 현재 숫자는 우측, 총 마디는 좌측 정렬하고 `/` 양옆에 간격을 둔다. 1~3자리 숫자에서도 구분자는 버튼 중앙에 유지하며 0으로 채우지는 않는다. 버튼 전체 드래그 동작을 유지한다.

<a id="ux-principles--아이폰-세로-볼륨-두-줄"></a>

#### 아이폰 세로 볼륨 두 줄
아이폰 세로 설정의 음악/메트로놈 볼륨은 각각 전체 너비의 한 줄로 배치한다. 각 줄에서 왼쪽 채널명, 가운데 슬라이더, 오른쪽 퍼센트를 정렬한다. iPad와 가로 화면의 기존 볼륨 배치는 유지한다.

<a id="ux-principles--아이폰-세로-악보-선택-상단-버튼"></a>

#### 아이폰 세로 악보 선택 상단 버튼
제목 아래 첫 버튼 줄에는 드럼치는공방 예약을 좌측, 새로고침·설정·도움말을 우측에 둔다. 둘째 버튼 줄에는 악보제작기 열기를 좌측, 음원 불러오기를 우측에 둔다. 제작기 버튼은 로컬 개발 화면에만 표시한다. 폭480px 이하 세로 목록 화면에만 적용한다.

<a id="ux-principles--iphoneipad-음원-파일-선택"></a>

#### iPhone/iPad 음원 파일 선택
[음원 불러오기]는 사진 보관함/촬영 메뉴를 거치지 않고 파일 선택기로 진입하도록 음원 확장자만 명시한다. audio/*와 영상으로 분류되는 WebM은 선택 필터에 넣지 않는다. 선택 후 음원 검증과 로컬 저장은 그대로 유지한다.

<a id="ux-principles--음원-파형-스크롤"></a>

#### 음원 파형 스크롤
파형 드래그와 관성 스크롤은 화면 탐색이며 재생 위치를 바꾸지 않는다. 재생 중 드래그는 기존 일시정지·재개 절차를 따르되 위치를 보존한다. 마디 선택·진행률 숫자 조절의 명시적 위치 이동과 기존 악보 스크롤 동작은 유지한다.

<a id="ux-principles--음악메트로놈-기본값-및-아이폰-곡-목록"></a>

#### 음악·메트로놈 기본값 및 아이폰 곡 목록
새 곡·서버 악보·저장 곡의 음량/메트로놈 기본값과 보존은 [재생 설정](playback.md#settings-playback--기본값과-재생)을 따른다.
아이폰 세로(폭480px 이하)의 곡 목록은 곡명과 가수명을 카드 왼쪽부터 각각 한 줄씩 표시한다. 표시 순서 설정을 따르며 음원 배지는 오른쪽에 둔다. 아래 줄은 즐겨찾기 별을 왼쪽, 열기·삭제·박자 맞추기 등 조작 버튼을 오른쪽에 같은 높이로 정렬한다. iPad·가로·데스크톱 배치는 유지한다.

<a id="ux-principles--넓은-브라우저의-재생-배치"></a>

#### 넓은 브라우저의 재생 배치
- 재생 상단/하단은 화면 높이만으로 세로 태블릿 배치로 전환하지 않는다. 900 CSS px 이상이면 제목·템포·메트로놈·줄보기·동작 버튼을 한 줄에 유지하고 빌드정보는 제목 아래에 둔다.
- 재생바는 마커/마디이동 좌측, 재생버튼 화면 중앙, 반복버튼 우측을 유지한다. 900~1099px에서는 터치 영역44px 이상을 유지하며 간격을 줄인다. 바로가기/구간판도 가로 배치를 유지한다.
- 720~899px 세로는 iPad mini와 같은 두 줄 재생바, 480px 이하 세로는 기존 iPhone 세 줄 상단과 북마크 배치를 유지한다.

<a id="ux-principles--재생-오류-안내"></a>

#### 재생 오류 안내
- 정상 상태의 완료 문구는 표시하지 않는다. BPM 변환 진행률은 BPM 설정창에서만 안내한다.
- 오류는 악보 영역 안 하단 중앙의 붉은 상위 레이어에 표시한다. 별도 행이나 여백을 확보하지 않고 악보·재생바 배치를 움직이지 않는다.
- 긴 원인 문구는 줄바꿈하고 악보 영역 내에서 스크롤한다. 오류 레이어 조작으로 마디 선택·재생을 시작하지 않는다.
- 시간으로 자동 숨김하지 않는다. 재생 재개·저장 재시도·전체화면 전환 등 해당 동작이 성공하면 그 동작의 안내를 지운다. 다른 동작의 성공으로 무관한 오류를 숨기지 않는다.

<a id="ux-principles--태블릿-하단-버튼판의-남는-높이"></a>

#### 태블릿 하단 버튼판의 남는 높이
- 폭720px 이상 재생 화면은 악보와 재생바의 기존 높이를 유지하고, 남는 세로 공간을 바로가기·구간 버튼판의 3줄에 균등 배분한다.
- 높이가 부족하면 화면별 기존 버튼판 높이를 유지하고 스크롤한다. 하단 안전 여백과 iPhone 배치는 유지한다. 전체 악보 검토 화면에는 적용하지 않는다.

<a id="ux-principles--내-음원-목록-분리"></a>

#### 내 음원 목록 분리
- 즐겨찾기는 제목 없이 최상단에 표시하고 원래 섹션에는 중복 표시하지 않는다.
- 아래 섹션은 기본 연습곡 → 내 악보 목록 → 내 음원 목록 순서다. 기기에서 가져온 음원 연습 항목은 내 음원 목록으로 분류한다. 음원이 포함된 악보 패키지는 내 악보 목록을 유지한다.
- 즐겨찾기 해제 시 해당 종류의 원래 목록과 순서로 돌아간다. 표시할 항목이 없는 섹션은 숨긴다. 저장된 파일·분석·설정은 이동하거나 변경하지 않는다.

<a id="ux-principles--중복-음원-확인-팝업"></a>

#### 중복 음원 확인 팝업
- 최대 360px, 화면 좌우 16px 여백 안의 작은 중앙 팝업으로 표시한다. 앱 아이콘 아래에 파일명과 질문을 표시하며 별도 제목은 생략한다. 우상단에 공통 × 버튼을 둔다.
- 파일명을 굵게 별도 줄에 표시한다. [추가]·[취소]를 전체 폭의 세로 두 줄로 배치한다. 높이는 최소 48px이며 [추가]는 앱의 기본 강조 색상을 사용한다. 건너뛰기는 제공하지 않는다.
- 처음 열릴 때 대화상자에 초점을 두고, 키보드 이동 시 기존 버튼 포커스 표시를 유지한다. 접근성 이름과 설명을 연결하며 Esc는 취소로 처리한다.

<a id="ux-principles--박자-맞추기-설명-순서"></a>

#### 박자 맞추기 설명 순서
- 설명은 해당 기능 앞에 둔다. 첫 박 지정 안내 → 첫 박 조작, 태그 안내 → 곡명·가수 입력, BPM 안내 → 악보 BPM 입력, 박자 변경 안내 → 통합 [박자] 선택 순서로 배치한다. 저장은 고정 제목줄 아이콘을 사용하고 닫기(X)는 저장 없이 취소한다.
- 컴포넌트 범위: 파형·플레이어·첫 박 지정·메트로놈은 하나의 박자 맞추기 컴포넌트다. 첫 박 안내는 이 전체 기능의 앞, 즉 파형 위에 배치한다. 개별 버튼만을 설명의 적용 범위로 보지 않는다.
- 박자 맞추기 창은 제목줄과 본문 스크롤 영역을 분리한다. 제목은 창 상단에 고정하고 본문만 스크롤하여 제목 위로 파형이나 입력 내용이 비치지 않게 한다.

<a id="ux-principles--도움말-도구-위치"></a>

#### 도움말 도구 위치
- 시각적 ‘도움말’ 제목을 제거한다. 접근성 대화상자 이름은 유지한다. 공통 닫기 버튼을 도움말을 열었던 (?) 버튼 좌표에 놓고, 화면 크기 변경 시 갱신한다. 별도 닫기 도형·스타일을 만들지 않는다.
- ‘드럼 악보 기호’는 하단 안내 오른쪽에 둔다. 페이지 이동 도구는 제거한다. 음원 연습 모드에서는 기존대로 기호 버튼을 숨긴다.

<a id="ux-principles--연습-화면-도움말-안내-바-위치"></a>

#### 연습 화면 도움말 안내 바 위치
- 연습 화면에서는 안내 문구와 드럼 악보 기호 버튼을 악보 영역 하단, 재생바 바로 위에 겹쳐 표시한다. 악보 영역의 실제 좌표를 사용하고 창 크기·스크롤 변화에 따라 갱신한다. 별도 레이아웃 공간은 확보하지 않는다.
- 말풍선은 이동한 안내 바와 겹치지 않도록 배치한다. 목록·설정 등 악보가 없는 화면은 기존 하단 위치를 유지한다.

<a id="ux-principles--모든-모달팝업-공통-닫기"></a>

#### 모든 모달·팝업 공통 닫기
- 모달·확인 팝업의 (?)는 제거하고 기존 공통 닫기(X)를 사용한다. 메인 화면의 (?)는 유지한다. 드럼 악보 기호 창에도 공통 X를 표시한다.
- 확인 팝업은 앱 아이콘 오른쪽에 X를 배치하며, X는 취소/계속 수정과 같은 안전한 닫기다. 조정 창의 미저장 변경 확인과 기존 바깥 터치·Esc 정책을 유지한다.
- 버튼을 길게 누르고 있는 동안 말풍선 설명이 나오는 기능은 모달·팝업에서도 유지한다.

<a id="ux-principles--탐색반복템포의-정본"></a>

### 탐색·반복·템포의 정본

- 마커 5개·구간 9개와 M 단축키는 [마커 슬롯](playback.md#marker-slots--마디-마커-슬롯), 이동·카운트오프·구간 시작/삭제는 [재생 이동 Rule](playback.md#playback-actions--재생-이동과-반복-구간-동작)을 따른다.
- 방향키 선택·재생선·진행 음영·정지 두 줄 스크롤·구간 등록은 [SVG 정본](../score/rendering.md#svg-score-rules--9-음표-따라가기탐색화면-효과)을 따른다. Enter 등록은 정지하고 시작·끝 포함/역방향·같은 마디·FIFO·시작 마디 정렬을 공유하며 숨긴 10~12번 데이터는 삭제하지 않는다.
- 원곡 1배속·악보/기준 BPM·실제 박 시각·분석 자동 적용·박자 맞추기·프리셋 올림은 [음원 Rule](audio-practice.md#audio-practice--음원-연습)과 [설정](playback.md#settings-playback--설정과-재생-정책)을 따른다. 구형 추종 켜기/끄기·수동 재분석 안내를 새 UI에 추가하지 않는다.
- 연습실은 [제품 범위](../../../PRD.md)에 따라 악보의 자동 보관 이력·이전 버전 복원·자동 업데이트를 제공하지 않는다. 음원을 제외한 명시적 JSON 백업과 제작기 백업은 각각의 저장 계약을 따른다.

<a id="ux-principles--도움말의-범례와-확인-팝업"></a>

### 도움말의 범례와 확인 팝업

승인된 [악기·주법 매핑](../score/notation.md#score-musicxml-osmd-mapping--악보의-musicxml--osmd-매핑-규칙)의 모든 항목을 안내하고 변경 때 설명·접근성 목록도 대조한다. 범례 모양 안내가 음향 합성 지원을 뜻하지 않는다. 네 줄 SVG와 세로 전용 구성을 현재 범례 생성 경로로 사용한다. 실제 악보의 폰트·표시 정본은 SVG Rule을 따르며 범례 모달 CSS는 실제 악보에 영향을 주지 않는다.

확인 팝업은 공통 생성 함수로 앱 아이콘·굵은 제목·설명·전체 폭의 둥근 세로 버튼을 제공한다. 제목줄·버튼 간격은 공통 10px이다. 중복 음원 팝업의 제목 생략·파일명 강조와 취소 정책은 위 해당 절을 따른다. 도움말 전용 모드에서는 실제 구간 삭제 동작을 제공하지 않는다.
