# 제작기 편집과 악보 검수 화면

문서 역할: **현행 Rule**. 현재 요구·계약과 지원 한계를 다룬다. [전체 정본](../../RULES-INDEX.md), [실행 안내](../../README.md), [결정 이력](../../decisions/README.md)을 함께 참고한다.

<a id="score-workspace--악보제작기-편집-화면"></a>

## 악보제작기 편집 화면

결정 근거: [ADR-0021](../../decisions/0021-contextual-help-and-shared-ui.md). 실행: [절차](../../how-to/verify.md#ui-review--화면악보재생-검수-절차).

<a id="score-workspace--편집-화면"></a>

### 편집 화면

제작기는 **상단바 → 악보 → 컨트롤바 → 상시 작업대** 순서다. `editor-dialog`는 악보 아래의 section이며 모달·탭·접기 상태를 만들지 않는다. 현재 마디 가사 카드와 그 아래 곡 정보, 옆의 섹션 편집을 함께 표시한다. 설정창과 원본 영역·마디 추가/삭제 도구는 제공하지 않는다.

상단바에는 같은 서체의 `제목 - 가수`, 공통 버전·빌드·템포, 한 줄/두 줄/PDF · MusicXML 검수, 전체 PDF/전체 MusicXML, 공통 크기 조절을 둔다. 한 줄·두 줄은 MusicXML을 사용한다. 두 줄은 기존 네 마디 맞춤 배율을 유지하므로 크기 조절을 비활성화하고 100%로 표시한다. 한 줄과 비교 보기에서는 공통 배율을 조절한다. 남는 화면 높이에 맞춰 악보를 확대하지 않는다.

연습용 속도·반복·카운트·메트로놈·마커·음표 효과·전체화면 설정은 제거한다. 제작기 활성화 시 과거 저장 설정도 검수용 값으로 고정하며 드럼연습실의 설정과 저장소는 바꾸지 않는다. 전체 보기·업로드·내보내기만 기존 대화상자를 사용한다.

<a id="score-workspace--곡-정보-시각-체계"></a>

### 곡 정보 시각 체계

컨트롤바에 재생·정지·마디 이동, 8·16·32·64분음표 격자, 되돌리기·다시 실행·이전 저장본·저장, 폴더 열기·제작자 요청·새로고침을 모은다. 곡 정보는 가사 아래에 별도 제목 없이 표시한다. 공통 입력·버튼·색상 변수를 사용하고 제작기 PC 배치에만 적용한다.

<a id="score-workspace--설정-진입-타일"></a>

### 설정 진입 타일

이전 문서 앵커를 유지한다. 설정 진입 타일은 제거했으며, 목록의 **편집 열기**에서 상시 작업대로 들어간다. 새 악보 만들기와 보관함 백업·복원은 목록에 둔다.

<a id="score-workspace--악보-편집-탭"></a>

### 악보 편집 탭

이전 문서 앵커를 유지한다. 악보 편집 탭과 마디 영역·추가·삭제 입력은 제거했다. 가사 카드와 악보의 OSMD 가사 글리프를 정본 가사 ID로 연결한다. 악보 클릭·수평 드래그·좌우 방향키로 음악적 위치를 옮기며, 격자 변경만으로 잇단음 등 기존 위치를 반올림하지 않는다.

앞으로 옮기며 순서가 겹칠 때만 뒤 항목을 다음 격자로 최소 이동한다. 뒤로 이동할 때는 앞 항목 뒤로 제한한다. 길이만 겹치는 경우에는 밀지 않는다. 드래그 시작 상태에서 다시 계산하고 Esc로 취소하며 연쇄 이동을 한 번에 되돌린다. 곡 끝을 넘으면 전체 동작을 거절한다.

카드의 클릭·드래그·Shift+클릭은 연속 선택이다. 작업대에 포커스가 있을 때 M은 연속 항목을 병합하고 S는 제작 자료에 구성 정보가 있는 묶음을 분리한다. 병합은 첫 ID/시작과 가장 늦은 끝, 공통 문구 결합을 사용한다. 구성 음절·상대 위치·길이는 `lyricWork.groups`에만 보관하고 정본에 다시 넣지 않는다. 입력칸·IME·악보 포커스의 M/S는 병합·분리를 실행하지 않는다.

SVG 전체 보기는 드럼연습실과 같은 [공통 가사 조판](../score/rendering.md#svg-score-rules--전체-보기-가사)을 사용한다. 선택 표시는 투명한 조작 영역이며 별도 HTML 가사를 출력하지 않는다.

<a id="score-workspace--곡-정보와-저장"></a>

### 곡 정보와 저장

표시 제목·원제·가수·작사·작곡, 읽기 전용 마디 수, 기본 BPM·첫 박 시각을 표시한다. 공통 숫자 드래그·정밀 키보드 입력을 유지한다. 저장 시 입력 중인 문구·메타정보를 같은 편집 세션으로 반영한다. BPM·첫 박 변경은 기존 전체 다시 맞추기 절차로 적용한다.

초안은 입력 후 로컬 프로젝트에 자동 저장하고 **저장**은 별도 확정 동작이다. 이전 저장본·가사 교정·병합 구성 정보도 보존한다. 파일 쓰기 실패는 성공으로 표시하지 않는다. 최신 저장본이 바뀌면 이전 기준으로 확정 저장하지 않고 초안을 보존한다. [프로젝트 파일 계약](../score/file-formats.md#local-score-projects)을 따른다.

<a id="score-workspace--파일-작업-통합"></a>

### 파일 작업 통합

곡 정보 영역에 악보 교체·음원 교체·타이밍 조정·내보내기를, 가사 작업대에 전체 가사 확인·가사 입력을 둔다. PDF/MusicXML 전체 보기 버튼은 상단바에 둔다. 섹션 편집은 [공통 XML 위치 계약](../score/rendering.md#svg-score-rules--공통-xml-위치-계약)과 동일한 편집 세션을 사용한다.

목록은 공통 카탈로그와 곡별 로컬 프로젝트를 합치고, 같은 ID는 파일 프로젝트를 우선한다. 첫 편집 때 기존 브라우저 자료의 원본·정본·초안·이력·작업 자료를 옮겨 재조회하며 기존 DB를 삭제하지 않는다. 파일 프로젝트에는 목록 삭제 버튼을 두지 않는다. 목록의 제작 자료 백업은 현재 기록·초안·기존 이력을 담는 보관함 백업이며, 프로젝트의 모든 저장본·질문·제작 파일까지 보존하려면 프로젝트 폴더를 보관한다.

<a id="editor-production-requests"></a>

### 담당 세션에 제작·교정 요청

열린 프로젝트의 요청 버튼은 기존 담당자에게 프로젝트 ID·폴더·요청 식별자만 알린다. 제목·변경 내용·원본을 다시 입력하거나 첨부하는 구형 요청 모달은 없다. 요청은 초안을 보존하되 확정하지 않으며 전송 접수와 제작 완료를 구분한다.

작업대에서 파일에 기록된 진행·질문·답장을 확인한다. 제작자의 새 저장본은 파일 감시 알림과 수동 새로고침으로 읽는다. 미확정 편집이 있으면 자동 교체하지 않고 차이를 표시한다. 같은 프로젝트에서 수정 결과를 확인하므로 결과를 수동 다운로드·반입할 필요가 없다. 사용자는 이 채팅에서 바로 교정을 지시해도 된다.

[공동 제작 절차](../../how-to/collaborate-on-score.md#shared-score-workflow)와 [구현 계획·검증 상태](../../plans/score-editor-workflow-20261114.md)를 따른다. 구형 요청 자료와 CLI는 기존 기록 확인용으로 보존한다. 실제 저장 왕복·화면 조작은 [0.12.0 릴리스 검증](../../records/archive/release-0.12.0.md)에서 격리한 시험 프로젝트로 확인했다. 이 결과는 실제 사용자 자료 이관이나 제작자 채팅 왕복의 검증을 뜻하지 않는다.

<a id="score-review--pdf--musicxml-검수-계약"></a>

## PDF / MusicXML 검수 계약

결정 근거: [ADR-0005](../../decisions/0005-practice-layout-and-spacing.md). 실행: [절차](../../how-to/verify.md#ui-review--화면악보재생-검수-절차).

<a id="score-review--화면과-캡처"></a>

### 화면과 캡처

화면의 **PDF · MusicXML 검수**는 PDF와 MusicXML이 모두 있는 곡에 적용한다. 동일한 마디 ID와 박자표로 두 악보를 연결한다. 위아래 네 마디는 같은 구간이다. 각 악보의 박 위치 좌표에 따라 진행선을 별도로 그린다. 곡 제목은 상단바에, 마디·박·음원 시각은 비교 화면의 PDF 이름과 같은 높이 중앙에 표시한다. 한 줄·두 줄에는 이 상태 문구를 반복하지 않는다.

재생 중 스페이스를 누르면 즉시 일시정지하고 두 악보를 PNG 한 장으로 복사한다. 다시 스페이스를 누르면 현재 정지 위치에서 검수 재생을 이어간다. 키 반복은 무시한다. 입력 중이거나 메뉴가 열려 있으면 전역 스페이스 동작을 실행하지 않는다. 마우스로는 **정지·캡처 복사** 버튼을 사용한다. 이미 정지한 위치에서도 이 버튼으로 캡처할 수 있다.

실제 화면과 캡처에 동일한 Canvas 그림을 사용한다. SVG 원본은 SVG 이미지로 디코딩하며, 검수 화면 합성과 PNG 캡처는 화면 크기의 2배 해상도 Canvas에서 수행한다. 일반 연습 화면의 SVG 표시 방식은 유지한다. 정지 시 픽셀을 즉시 별도 canvas에 복제하여 비동기 PNG 생성 중 재생 위치가 달라져도 캡처가 바뀌지 않는다. 클립보드 쓰기는 사용자 키/클릭 이벤트 안에서 PNG Promise를 넘겨 요청한다.

클립보드가 차단되면 성공으로 표시하지 않는다. 같은 캡처를 **캡처 저장**으로 내려받아 대화에 첨부한다. 기존 PDF 페이지는 재렌더링하지 않는다.

이 모드는 시각 검수 도구이며 음표의 옳고 그름을 자동 판정하지 않는다. PDF 반복기호와 MusicXML에서 펼쳐 그린 마디처럼 의미는 같고 그림이 다른 경우도 있다.

<a id="score-review--오선-정렬"></a>

### 오선 정렬

검수 캔버스는 각 이미지 외곽 대신 오선 위치와 페이지별 오선 간격 중앙값을 기준으로 정렬한다. PDF의 회색 선과 음표에 가려진 선을 함께 처리한다. 마디는 셀 너비 전체를 사용하고 셀 사이 8px 여백을 제거한다. 진행선도 동일한 너비를 사용한다. 검수 악보 높이는 공통 조판 높이·배율로 계산하고 검출한 오선 및 위아래 표기 범위를 사용한다. 남는 화면 높이에 맞춰 늘리지 않는다. 원본 악보·MusicXML 데이터는 바꾸지 않는다.

PDF 오선은 페이지·y·높이가 같은 인쇄 줄의 좌우 영역을 합쳐 검출하고 같은 줄의 마디가 공유한다. SVG는 마디별 검출·페이지 중앙값 보정을 유지한다. 원본 PDF·XML·crop·박 위치·저장 형식을 변경하지 않는다. 검출 실패를 임의 좌표로 대체하지 않는다. 오류와 함께 형식·마디 ID·페이지·검사 crop·픽셀 크기·묶인 영역 수·예상 간격·검출 실패 상태를 로컬 진단에 남기며 로그 실패가 원래 오류를 덮지 않게 한다.

음표·쉼표·악기 표기는 [매핑](../score/notation.md#score-musicxml-osmd-mapping--악보의-musicxml--osmd-매핑-규칙)과 [SVG 정본](../score/rendering.md#svg-score-rules--svg-전체-악보-생성-규칙)을 따른다. 곡별 교정을 다른 악보의 공통 매핑으로 일반화하지 않는다.
