## 악보제작기 편집 화면

결정 근거: [ADR-0021](../../decisions/0021-contextual-help-and-shared-ui.md). 실행: [절차](../../how-to/verify.md#ui-review--화면악보재생-검수-절차).

<a id="score-workspace--편집-화면"></a>

### 편집 화면

설정 > 악보의 기존 편집 진입점에서 `editor-dialog`를 큰 별도 모달로 연다. 닫으면 원래 작업 위치로 돌아온다. 기본 곡 정보·악보 편집·가사와 기존 섹션 편집 탭을 유지하고 파일 작업은 곡 정보의 악보-음원 연결 영역으로 모은다. 별도 편집창과 파일 전용 탭은 제공하지 않는다.

파일 보유 칩은 최상단 편집 제목 우측, 곡 정보는 기존 입력값으로 표시하며 마디 수는 읽기 전용이다. 한국어 i18n·접근성 이름과 탭별 파랑/빨강/초록 계열 및 선택 본문 연결을 유지한다. 큰 창은 화면 높이를 넘지 않고 본문만 세로 스크롤하며 탭별 위치를 기억한다. 탭 이동으로 폼을 재생성하지 않고 기존 세션의 임시저장·저장·되돌리기·종료 확인을 공유한다. 전체 보기·업로드·내보내기는 기존 대화상자를 사용하고 닫으면 원래 탭으로 돌아온다.

<a id="score-workspace--곡-정보-시각-체계"></a>

### 곡 정보 시각 체계
- 공통 저장 상태/되돌리기/다시 실행/이력/저장은 최상단 도구막대로 이동한다.
- 넓은 화면은 제목·칩·탭·편집 도구·닫기 순서, 좁은 화면은 최상단 영역 안에서 행을 나눠 터치 영역을 유지한다.
- 곡 정보는 제목 우선의 밝은 카드와 템포/타이밍 카드로 구분한다. 입력은 48px 이상 높이, 일정한 라벨/필드 간격과 포커스 테두리를 사용한다.

- 웹 CSS 구현이며 네이티브 Liquid Glass API 사용을 뜻하지 않는다.

<a id="score-workspace--설정-진입-타일"></a>

### 설정 진입 타일

악보 편집·내 악보 목록·악보 추가를 같은 120×120 흰색 정사각형 타일로 배치한다. 아이콘 위·이름 아래, 왼쪽 정렬, 일정한 간격을 유지하며 공간이 좁으면 줄바꿈한다. 곡이 없을 때는 편집 타일만 숨긴다. 기존 홈의 목록·추가 동작을 재사용한다. 파란 강조는 선택된 설정 메뉴에 사용한다.

<a id="score-workspace--악보-편집-탭"></a>

### 악보 편집 탭

전체 보기 두 버튼과 페이지·마디 선택은 공통 도구막대에 둔다. 큰 악보 미리보기와 선택 마디 설정을 좌우로 분리하고 좁은 화면에서 세로로 배치한다. 내부 박 위치는 접기 영역에 보존하고 삭제는 별도로 둔다. 박 수와 분모는 공통 숫자 드래그 및 휠로 조절하며, 분모는 2·4·8·16만 순회한다. 이름과 0.001초 시각은 키보드 입력을 유지한다.

<a id="score-workspace--곡-정보와-저장"></a>

### 곡 정보와 저장

곡 정보 입력과 음원·악보 연결을 좌우에 배치하고 좁은 화면에서는 세로로 배치한다. 표시 제목·원제·가수·작사·작곡은 각각 한 행으로 표시하며 라벨은 좌측에 정렬한다. 중복 곡 정보 제목은 제거하고 마디 수는 연결 영역에 둔다. BPM은 기본 BPM으로 표시하며 드래그·휠을 지원한다. 첫 박 시각은 정밀 키보드 입력을 유지한다.

곡 정보 적용 버튼과 개별 처리 코드를 별도로 두지 않는다. 상단 저장의 기존 flushEditorForm → commit → persist 경로에서 입력 중인 제목·원제·가수·작사·작곡을 함께 저장한다. 템포/첫 박 변경은 기존 시간 보정에 영향을 주므로 전체 다시 맞추기 절차를 유지한다. 변경이 있는 상태의 닫기 확인, 임시저장·이력 동작도 유지한다.

<a id="score-workspace--파일-작업-통합"></a>

### 파일 작업 통합

파일 전용 탭은 두지 않는다. 섹션 편집은 [SVG 정본](../score/rendering.md#svg-score-rules--공통-xml-위치-계약)과 기존 편집 세션 경로를 따른다. 곡 정보의 `악보-음원 연결` 박스 상단에 악보 교체·음원 교체, 중간에 타이밍 조정, 하단 구분선 아래에 내보내기를 둔다. 기존 교체·내보내기 동작을 재사용한다. 가사 탭은 전체 너비를 유지한다.

제작기 홈은 공통 카탈로그를 사용하며 중복 목록 모달을 만들지 않는다. 목록 카드 삭제·설정의 전체 백업·새 곡 준비 창의 패키지 가져오기는 [구조 정본](../engineering/architecture.md#project-structure--프로젝트-구조)을 따른다.

<a id="score-review--pdf--musicxml-검수-계약"></a>

## PDF / MusicXML 검수 계약

결정 근거: [ADR-0005](../../decisions/0005-practice-layout-and-spacing.md). 실행: [절차](../../how-to/verify.md#ui-review--화면악보재생-검수-절차).

<a id="score-review--화면과-캡처"></a>

### 화면과 캡처

화면의 **PDF · MusicXML 검수**는 PDF와 MusicXML이 모두 있는 곡에 적용한다. 동일한 마디 ID와 박자표로 두 악보를 연결한다. 위아래 네 마디는 같은 구간이다. 각 악보의 박 위치 좌표에 따라 진행선을 별도로 그린다. 상단에 곡명, 가장 가까운 ¼박 위치와 실제 정지 시각을 표시한다.

재생 중 스페이스를 누르면 즉시 일시정지하고 두 악보를 PNG 한 장으로 복사한다. 다시 스페이스를 누르면 기존 연습 규칙대로 해당 마디 처음부터 재생한다. 키 반복은 무시한다. 입력 중이거나 메뉴가 열려 있으면 전역 스페이스 동작을 실행하지 않는다. 터치 사용자는 **정지·캡처 복사** 버튼을 사용한다. 이미 정지한 위치에서도 이 버튼으로 캡처할 수 있다.

실제 화면과 캡처에 동일한 Canvas 그림을 사용한다. SVG 원본은 SVG 이미지로 디코딩하며, 검수 화면 합성과 PNG 캡처는 화면 크기의 2배 해상도 Canvas에서 수행한다. 일반 연습 화면의 SVG 표시 방식은 유지한다. 정지 시 픽셀을 즉시 별도 canvas에 복제하여 비동기 PNG 생성 중 재생 위치가 달라져도 캡처가 바뀌지 않는다. 클립보드 쓰기는 사용자 키/클릭 이벤트 안에서 PNG Promise를 넘겨 요청한다.

클립보드가 차단되면 성공으로 표시하지 않는다. 같은 캡처를 **캡처 저장**으로 내려받아 대화에 첨부한다. 기존 PDF 페이지는 재렌더링하지 않는다.

이 모드는 시각 검수 도구이며 음표의 옳고 그름을 자동 판정하지 않는다. PDF 반복기호와 MusicXML에서 펼쳐 그린 마디처럼 의미는 같고 그림이 다른 경우도 있다.

<a id="score-review--오선-정렬"></a>

### 오선 정렬

검수 캔버스는 각 이미지 외곽 대신 오선 위치와 페이지별 오선 간격 중앙값을 기준으로 정렬한다. PDF의 회색 선과 음표에 가려진 선을 함께 처리한다. 마디는 셀 너비 전체를 사용하고 셀 사이 8px 여백을 제거한다. 진행선도 동일한 너비를 사용한다. 세로 화면에서 과도하게 늘어나지 않도록 오선 간격은 셀 너비로 제한한다. 원본 악보·MusicXML 데이터는 바꾸지 않는다.

PDF 오선은 페이지·y·높이가 같은 인쇄 줄의 좌우 영역을 합쳐 검출하고 같은 줄의 마디가 공유한다. SVG는 마디별 검출·페이지 중앙값 보정을 유지한다. 원본 PDF·XML·crop·박 위치·저장 형식을 변경하지 않는다. 검출 실패를 임의 좌표로 대체하지 않는다. 오류와 함께 형식·마디 ID·페이지·검사 crop·픽셀 크기·묶인 영역 수·예상 간격·검출 실패 상태를 로컬 진단에 남기며 로그 실패가 원래 오류를 덮지 않게 한다.

음표·쉼표·악기 표기는 [매핑](../score/notation.md#score-musicxml-osmd-mapping--악보의-musicxml--osmd-매핑-규칙)과 [SVG 정본](../score/rendering.md#svg-score-rules--svg-전체-악보-생성-규칙)을 따른다. 곡별 교정을 다른 악보의 공통 매핑으로 일반화하지 않는다.
