# 정지된 두 줄 악보의 세로 탐색

- 목표: 정지한 마디에서 PDF 전체 문서처럼 악보를 상하로 읽는다.
- 범위: 두 줄 표시의 정지 화면과 세로 휠/트랙패드/네이티브 터치 스크롤.
- 완료 조건: 전체 마디가 순서대로 이어지고 세로 탐색 시 재생 위치가 바뀌지 않는다. 재생 시 두 줄 따라가기로 복귀한다.
- 제외: 한 줄/검수 모드 재설계, 가사·악보 데이터 수정, 마커/반복 정책 변경.
- 검증: UI/제스처 회귀 테스트, Safari 스크롤 높이·위치 실측 및 전후 캡처, 빌드.

## 구현

정지 시 전체 마디를 4마디씩 행으로 배치한다. 첫 진입과 드래그·이동 컨트롤에 의한 재생 위치 변경 시 해당 마디 행으로 맞춘다. 정지 중 단일 탭 선택은 예외로, 재생 위치와 선택 표시만 바꾸고 현재 스크롤 위치는 유지한다. 이후 프레임에서는 스크롤 위치를 유지한다. 재생 시작 시 현재 마디가 포함된 행을 반드시 위쪽에 배치한다. 이후 그 행을 기준으로 위/아래 교대 진행을 유지한다. 좌우 드래그 중에는 두 줄 표시를 사용한다. 재생 위치와 세로 읽기 위치를 저장 데이터로 혼합하지 않는다. 곡/보기/창 크기가 바뀌면 레이아웃을 다시 맞춘다.

두 줄 정지 상태의 세로 wheel은 preventDefault/seek를 하지 않는다. 브라우저의 overflow-y:auto와 pan-y로 스크롤한다. 좌우 wheel/드래그와 탭·더블탭은 기존 동작을 유지한다.

## 검증

- 같은 Safari 1180×820, PDF 두 줄: 110마디, 표시 영역532px, 전체 스크롤 높이7504px.
- scrollTop 1330→1830(500px 이동), 음원56.410초/22마디와 정지 상태 유지. [이전](experiments/paused-scroll-before.png), [이후](experiments/paused-scroll-after.png).
- Safari의 실제 DOM 스크롤을 사용해 검증했다. 물리적 트랙패드/실기 iPad 터치 동작을 대행 검증했다고 주장하지 않는다.
- 자동 테스트는 세로 wheel 미소비·음원 위치 유지·프레임 후 스크롤 유지·좌우 wheel 이동·재생 복귀를 검사한다.

- SVG에서도 110마디와 scrollTop 1330→1830, 음원56.410초 유지 확인. [SVG 캡처](experiments/paused-scroll-svg.png).
- 전체51파일/211테스트 및 `npm run build` 통과. 기존 빌드 청크 크기 경고는 유지된다.
- 재생 시 8마디 따라가기 복귀는 자동 테스트로 확인했다. Safari 스크립트의 재생 클릭은 실제 재생으로 전환되지 않아 브라우저 재생 전환 검증은 미확인으로 남긴다.

## 두 줄 공통 간격 (2026-09-21)
- 재생/정지 모두 마디 너비에서 동일한 SVG 배율을 계산한다. stage 높이를 다시 배율 계산에 넣지 않는다.
- 상단/줄 사이/하단 여백은28 CSS px. 행 높이는 악보 실제 높이+가사30px, stage는 두 행+여백3개로 계산한다.
- 정지 상태에서도 같은 grid 행 높이/간격을 쓰며, 전체 악보 상하 스크롤은 유지한다.
- Safari 1180×820: stage439.875px. 재생/정지 crop147.9375px 동일, 두 번째 행234.9375/235.0625px(스크롤 소수점 반올림0.125px 차이). 기존534px에서 약94px 공간 확보.
- 실제 재생 캡처: experiments/compact-rows-playing.png. 전체223테스트 및 최종 빌드 통과.
