# iPad 연습 컨트롤 개편 검증

대상: `http://127.0.0.1:5173/`, `src/` 웹앱. 2026-09-20.
설계 정본: [IPAD-TOUCH-UX-PROPOSAL.md](IPAD-TOUCH-UX-PROPOSAL.md).

## 적용 범위

- 악보 한 번 탭 재생·정지 / 두 번 탭 마디 처음 이동 / 좌우 드래그 탐색. 정지 시 두 번째 탭을 기다리지 않는다.
- 정지 중 휠 탐색, 곡 진행률 숫자 드래그 탐색 및 탭으로 마커 열기.
- 모든 숫자 입력에 공통 좌우·상하 드래그 연결. BPM 변환은 손을 놓을 때 적용.
- 상단 연습 BPM, 메트로놈, 악보 목록, 설정. 하단 큰 재생 버튼, 되감기, 위치 복사, 진행률, 마커, 소리, 중심 반복.
- 현재 마디 앞뒤 1/2/3/4마디 반복. 최초 중심 유지, 다시 중심 잡기, 포함 끝 마디 방식, 선택적 박 단위 조정.
- 설정의 수동 전체화면 및 브라우저에 저장하는 자동 전체화면 옵션.
- 메트로놈 신호 강화와 음악·클릭 합산 피크 제한. 저장된 볼륨 값과 카운트인 음량은 유지.

## Ego 실제 포인터·휠 검사

일반 mouse wrapper가 각 단계마다 탭을 hidden→visible로 전환하는 현상을 이벤트 로그로 확인했다. 이때 앱은 의도한 화면 이탈 정책에 따라 드래그를 취소하고 시작 위치로 복원했다. 이를 앱 탐색 결함으로 처리하지 않고, 같은 Ego 페이지에서 CDP의 trusted 포인터 이벤트로 다시 검사했다. 해당 경로는 조작 중 visibility를 유지했다.

| 입력 | 관찰 결과 |
|---|---|
| 되감기 숫자 오른쪽 72px | 1→10, 최대 범위 적용 |
| 되감기 숫자 아래 48px / 위 24px | 10→4 / 4→7 |
| 진행률 오른쪽 64px | 1→9%, 26.72초로 이동, 마커 창 열리지 않음 |
| 진행률 위 32px | 9→13%, 38.59초로 이동 |
| 악보 왼쪽 200px / 오른쪽 100px | 38.59→39.93초 / 39.26초, 정지 유지 |
| 휠 아래 180 / 위 180 | 39.26→40.47초 / 39.26초, 정지 유지 |
| 검수 화면 세 번째 마디 두 번 클릭 | 해당 15마디 1박 36.13초로 이동, 정지 유지 |
| 진행률 한 번 클릭 | 마커 창 열림 |

근거: `docs/experiments/ipad-cdp-native-drag.json`, `ipad-cdp-gestures-qa.json`, `ipad-ego-visibility-trace.json`, `ipad-native-qa-final.json`, `IPAD-NATIVE-DRAG-QA-2026-09-20.md`. `isTrusted=true`인 데스크톱 마우스/휠 이벤트 검사이며 실제 손가락/트랙패드 기기 입력을 뜻하지 않는다. BPM 숫자 자체의 native 드래그는 별도 수행하지 않았으며 공통 숫자 컴포넌트 양축 검사와 Safari BPM 적용 검사를 구분한다.

## 메트로놈 실측

32kHz, 1kHz 비강세 클릭, 80ms 측정 창, 클릭 볼륨 1 기준:

| 항목 | 이전 | 변경 후 |
|---|---:|---:|
| 피크 | 0.213506 | 0.800000 |
| RMS | 0.035517 | 0.238170 |

피크 +11.47dB, RMS +16.53dB. 기본 클릭 생성 레벨을 0.22에서 0.8로 높이고 1ms 공격·10ms 유지·75ms 감쇠로 조절했다. 카운트인은 기존 독립 경로를 유지한다.

예제 곡 음악 0.8 + 클릭 1에서 제한 전 피크 1.660966. 제한 후 ±1 범위 유지. 박 주변 2,257,920개 샘플의 범위 초과 0개. 클릭 0.3에서는 출력 피크 0.997144. 이는 신호 측정이며 실제 iPad 스피커에서 음악 대비 들리는 정도의 청취 판정은 아니다.

재현: `docs/experiments/metronome-levels-20260920.py` / `.json`. 실제 음원 PCM에 합성 클릭과 연속 제한 공식을 적용한 계산이며 브라우저 OfflineAudioContext 렌더링이 아니다. 각 박 주변 80ms만 검사하며 파형 테이블 보간·기기 출력을 모델링하지 않는다. JSON에 입력/소스 해시와 ffmpeg 버전을 보존했다.

## 검증 경계

- 이번 GUI 검사는 macOS Safari와 Ego다. 실제 iPad 터치 하드웨어/스피커 및 Device Hub는 이번 검증에 포함하지 않았다.
- 자동 전체화면은 악보를 여는 사용자 동작에서 요청한다. 초기 HTML 자동 로딩 등 사용자 동작이 없는 경우 브라우저가 거절할 수 있다. 거절해도 악보 로딩은 계속한다. [Fullscreen API](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen).
- 휠 조작은 고정 악보 보기의 재생 위치 탐색이다. 전체 악보를 세로로 나열한 문서 보기로 바꾸지는 않는다.
- 악보 매핑, 음원/가사 정본, 기존 내보낸 HTML은 변경하지 않았다. 별도 HTML 재내보내기, 외부 배포, 원격 push 없음.
