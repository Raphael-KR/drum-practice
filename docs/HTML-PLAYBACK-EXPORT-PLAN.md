# 단일 곡 재생 HTML 내보내기 간소화 계획

작성: 2026-09-21 · 기준: main / 8d09129 / 0.3.0
상태: 사용자 승인 계획에 따른 구현·실행 검수 중. 계획 100점과 실제 제품 검수 통과는 별개다.

## 최신 승인 변경 — 2026-09-21

- SVG와 PDF가 모두 있는 곡은 두 렌더 결과를 한 HTML에 포함하고 실행 중 선택할 수 있게 한다. 음원은 한 번만 포함한다. 아래 초기 계획의 단일 형식 제한은 이 결정으로 대체한다.
- 전체 내부 데이터 추가 gzip은 동일 합본 파일로 실험한 결과 3.97%만 줄어 적용하지 않는다. 기존 SVG gzip은 유지한다. 상세 실측과 판단은 HTML-PLAYBACK-EXPORT-HISTORY.md에 기록한다.
- 정지 중 한 줄은 네이티브 좌우 스크롤, 두 줄은 악보가 손가락을 따라 이동하는 방식으로 수정한다. 실제 입력 검수 전에는 이 변경을 완료로 판정하지 않는다.

## 1. 목표와 이미 합의한 범위

- 목표: 한 곡의 악보·음원·가사를 인터넷 없이 재생하고 연습하는 가벼운 HTML 한 파일.
- 확정: HTML에서 곡 선택/초기화면과 설정 > 악보 전체를 제거한다. 편집·파일 관리·백업 복원 기능을 넣지 않는다.
- 확정: 보유한 SVG·PDF 렌더 결과를 한 HTML에 포함한다. 두 형식이 있으면 화면 설정에서 전환한다.
- 확정: 미사용 기능은 숨기거나 비활성화하지 않고, 해당 HTML·CSS·JavaScript·이벤트 핸들러·의존성·데이터를 최종 파일에 포함하지 않는다. 웹앱에 필요한 기능은 웹앱에 유지한다.
- 확정: 편집 초안·저장 이력·복구용 자료는 HTML에 포함하지 않는다. 전체 곡 백업은 웹앱의 내 악보 목록 하단 ‘백업 관리’에서 담당한다.
- 완료 조건: 실제 내보낸 파일에서 핵심 연습 기능이 작동하고, 제거 대상 UI·코드·데이터가 없으며, 웹앱과 전체 백업은 기존대로 동작한다.
- 제외: 음원 재인코딩/품질 저하, 신규 가사 추출, 다국어 가사 확장, 외부 호스팅, 네이티브 앱, 기존 HTML 파일 자동 수정.

기존 결정 정본: [SCORE-MANAGEMENT-PLAN.md](SCORE-MANAGEMENT-PLAN.md). 이번 문서는 HTML 부분의 실행 계획을 구체화한다.

## 2. 현재 구현에서 바꿀 부분

| 현재 근거 | 현재 상태 | 계획 |
|---|---|---|
| `scripts/build-portable.mjs` | `src/main.ts` 전체를 번들링하고 XML/PDF 렌더러를 오류용 대체 모듈로 바꿈 | 재생용 진입점으로 빌드하여 편집 코드를 의존성에서 제외 |
| `src/score-management.ts` | isPortable에서 보관함/편집 등의 요소를 hidden 처리 | 해당 화면의 마크업·스타일·생성 코드·이벤트 핸들러를 빌드에서 제외 |
| `src/portable.ts` | 원본 `pdf`, canonicalXML, otherScores와 렌더 페이지까지 직렬화 | 재생에 필요한 항목만 명시적으로 허용하는 별도 데이터 형식 |
| `src/main.ts` | save-html과 portableBlob 두 내보내기 경로 존재 | 웹앱의 통합 내보내기에서 하나의 공통 함수 사용 |
| `src/main.ts` | HTML 자체를 다시 저장하라는 안내와 관련 코드가 남음 | 재생 전용 HTML에서 재저장 기능/안내 제거 |
| 환경 설정 모듈 | localStorage 기반 웹앱 공통 설정 사용 | HTML 초기값과 변경 수명을 명확히 분리 |

현재 곡을 넣기 전 템플릿은 721,546 bytes이다. 음원/악보를 포함한 최종 파일 크기와 구분한다. 구현 전 같은 곡으로 기존 HTML의 전체 크기·실행 코드·데이터 항목별 용량을 측정해 비교 기준을 남긴다.

## 3. 승인된 화면 구성

파일을 열면 해당 곡의 악보 화면으로 바로 진입한다. 음악은 사용자가 재생을 누른 뒤 시작한다.

| 영역 | 유지 | 제거 |
|---|---|---|
| 상단 | 곡 제목, 연습 BPM, 메트로놈, 설정 | 내 악보 목록, 다른 곡 열기 |
| 악보 | 한 줄/두 줄 보기, 현재 마디 표시, 가사, 음표 따라가기 | 편집·검수 진입점 |
| 연주 조작 | 재생/정지, 마디 선택, 더블 탭 재생, 탐색 드래그, 정지 중 두 줄 상하 스크롤 | 파일 변경/추가 동작 |
| 하단 | 되감기, 현재 위치 %, 반복 범위/조정, 최근 3개 마커, 소리 | 곡 관리와 내보내기 |
| 설정 > 화면 | 악보 스타일, 해당 형식에서 가능한 크기 설정, MusicXML 음표 따라가기, PDF 전환, 전체화면 옵션 | PDF·MusicXML 동시 검수 |
| 설정 > 재생 | 마디 처음부터 다시 재생, 카운트오프 | 편집 관련 항목 |
| 설정 > 정보 | 드럼 연습실, 버전(소스 식별자), KST 빌드 시각, 포함 코드의 오픈소스 고지 | 편집 작업 기록 |
| 설정 > 악보 | 없음 | 메뉴와 하위 화면 전부 |

오류 메시지·로딩 표시·키보드 접근성은 유지한다. SVG/PDF 전체 보기와 전체 가사 보기처럼 현재 악보 관리 아래에 있는 별도 열람 화면은 이번 재생 전용 HTML에서 제외한다.

### 승인된 악보 형식 결정

단일 형식 제한은 사용자의 최신 결정으로 폐기했다. 보유한 MusicXML(SVG)과 PDF 표시 페이지를 함께 포함하며 음원은 한 번만 담는다. 현재 선택한 형식으로 열고 실행 중 설정에서 전환한다. 한 형식만 있으면 그 형식으로 열며 전환은 비활성화한다. 편집 원본과 관리 기능 제외는 유지한다.

### 승인된 초기 상태와 저장 수명

사용자의 계획 문서 전체 승인에 따라 다음 두 항목도 구현 기준으로 확정한다.

1. **처음부터 정지 상태:** 현재 재생 위치를 복사해 중간에서 시작하지 않고 1마디 정지 상태로 연다. 연습 BPM·음량·화면/카운트오프 설정과 마커는 내보내기 시점 값을 초기값으로 담는다. 반복 범위는 보존하되 반복은 꺼진 상태로 시작한다.
2. **HTML 내 변경은 이번 실행 동안만:** BPM·마커·반복·설정을 바꿀 수 있지만 원본 HTML이나 웹앱 보관함에 쓰지 않는다. 파일을 다시 열면 내보낸 초기값으로 돌아간다. localStorage 사용 가능 여부와 관계없이 작동하도록 한다. 이 동작은 내보내기 안내에 한 번 명확히 표시한다.

## 4. 재생 데이터와 실행 코드

### 데이터

새 형식 `PlaybackExportV2`(가칭)를 둔다. 기존 `PortableSong`을 무조건 축소해 다른 직렬화 경로를 깨뜨리지 않는다.

포함:
- 표시용 곡 제목/아티스트/기본 BPM 등 최소 메타데이터.
- 재생 시간표, 마디 박자와 영역, 박별 좌표, 재생용 가사 데이터.
- 보유한 악보 형식들의 렌더 페이지와 렌더에 필요한 메타데이터. SVG 음표 따라가기 표식·겹세로줄·기존 자산 라이선스 정보 보존.
- 음원 한 벌, 연습 설정 초기값과 마커, 파일 형식 버전.

제외:
- canonicalXML, 원본 XML/PDF 파일, 원본 소스가 포함된 otherScores(렌더 결과만 scores 허용 목록으로 변환).
- 편집 초안/저장 이력/복구용 가사 아카이브, 보관함 정보.
- 재생에 참조되지 않는 필드. 단, 필드 제거 전 `activate`/engine/좌표/가사 참조를 조사하고 필요한 값은 허용 목록에 명시한다.

악보 재생에 원본 XML/PDF를 다시 읽는 경로가 남아 있다면, 먼저 렌더 결과와 재생 메타데이터만으로 작동하도록 분리한다. 데이터를 먼저 버린 뒤 오류로 처리하지 않는다. 구형 SVG의 필요한 좌표/표식이 없으면 웹앱에서 렌더를 갱신한 후 내보낸다. 가사·음원·음표 위치는 압축 때문에 변형하지 않는다.

### 코드

미사용 기능의 **최종 산출물 미포함**은 필수 완료 조건이다. `hidden`, `display:none`, 비활성 버튼, 실행 시 분기, 오류 스텁으로 대체하지 않는다. 재생에 필요한 코드만 허용하는 진입점과 의존성 구조를 사용한다. 번들 메타파일로 미사용 모듈 제외를 확인하고, 최종 HTML의 마크업·스타일·실행 코드·데이터에서도 제외를 검증한다.

- `src/portable-player.ts`(신규 가칭): HTML 전용 시작점. 보관함·편집기·파일 업로드·전체 백업 모듈을 가져오지 않는다.
- 웹앱과 HTML이 엔진, 악보 표시, 제스처, 반복/마커, BPM/음량, 전체화면, 공통 설정 UI를 공유하도록 필요한 재생 부분만 추출한다. 웹앱 전체 재작성은 하지 않는다.
- HTML은 메모리 상태를 쓰고 웹앱은 기존 저장소를 쓰도록 저장 경계를 분리한다.
- OSMD/PDF.js 등 런타임 재렌더러와 편집 의존성이 번들에 없는지 메타파일로 확인한다. 실제 필요한 압축 해제·음원 처리 코드와 고지는 유지한다.
- HTML용 CSS도 필요한 화면 규칙만 포함하되 iPad 레이아웃·모달·전체화면 보정은 공유한다.
- build-portable의 `--demo` 경로도 공통 내보내기 함수를 사용하게 맞춰 오래된 예제 경로가 따로 남지 않게 한다.
- 구형 HTML은 자체 실행 코드를 포함하므로 그대로 둔다. 웹앱의 기존 백업/이전 형식 읽기는 회귀 검수하고 새 재생 DTO를 백업 DTO로 사용하지 않는다.

## 5. 실행 단계와 통과 조건

1. **기준선 확보:** 현재 동일 곡의 HTML 출력, 크기 구성, 화면/상태/네트워크 요청을 기록한다. 전체 백업과 공유하는 함수 사용처를 확인한다.
2. **재생 전용 데이터 도입:** 명시적 허용 목록·V2 검증기·선택 형식 렌더 캐시 준비. 음원/악보 바이트와 시간표/가사/마커를 대조한다. 편집 원본은 웹앱에 남는다.
3. **재생 실행 경로 분리:** HTML 진입점과 최소 화면을 만들고 공통 재생 코드를 추출한다. 단순 hidden 처리나 가져오기 오류 스텁으로 제거를 대신하지 않는다.
4. **통합 내보내기 연결:** 설정 > 악보 > 파일 > 내보내기의 HTML 항목을 새 경로로 연결한다. 선택한 형식과 실행 중 변경의 수명을 짧게 안내한다. 전체 백업 UI/데이터는 유지한다.
5. **파일 검수:** 실제 생성 HTML을 Safari와 Device Hub iPad mini에서 열어 확인한다. 발견 사항은 수정→재검수하며 아래 기준을 모두 통과해야 완료한다.
6. **기록:** 기존/신규 파일 크기, 실행환경, 캡처, 자동 테스트, 남은 플랫폼 제약을 보고한다. 커밋/버전업은 별도 요청에 따른다.

## 6. 검수 기준

| 구분 | 필수 확인 |
|---|---|
| 제거 범위 | 곡 선택·설정 > 악보·편집·업로드·백업·HTML 재저장 UI가 최종 HTML과 DOM에 없음. 관련 스타일·생성 코드·이벤트 핸들러도 없음 |
| 코드/데이터 | 편집기/원본 XML·PDF/초안/저장 이력 제외. 합본의 음원 중복이 없으며 동일 자산 기준 최종 크기와 압축 효율을 설명 |
| 기본 조작 | 재생/정지, BPM, 피치 유지 속도, 메트로놈·카운트오프, 음량, 되감기·퍼센트 탐색, 반복, 3슬롯 마커 |
| 악보 | 한 줄/두 줄, 합본 SVG/PDF 전환 각각, 가사, 음표 따라가기, 탭/더블 탭/드래그/정지 스크롤, 재생 재정렬 |
| iPad | mini 가로/세로, 설정에서 전체화면 전환 후 모달 유지, 닫기/재열기, 자르기/레이아웃 균형 |
| 자립성 | 네트워크 차단 후 외부 JS/CSS/폰트/음원 없이 실행. 출처 링크는 사용자가 눌렀을 때만 별도 접속. 브라우저 저장소 실패에도 재생 가능 |
| 초기 상태 | 1마디 정지·자동재생 없음, 내보낸 초기값 적용, 실행 중 수정이 웹앱과 원본 파일을 바꾸지 않음 |
| 호환/오류 | MusicXML만/PDF만/둘 다/가사 없음, 잘린 파일·지원하지 않는 버전은 이해할 수 있는 오류. 긴 곡·큰 음원 로딩 확인 |
| 회귀 | 웹앱 곡 관리·편집·백업 복원·일반 내보내기, 기존 파일 형식 테스트, 전체 테스트·TypeScript·빌드 |

Safari의 iframe 실행만으로 오프라인 파일 검수를 통과시키지 않는다. 실제 다운로드 파일을 여는 경로를 확인한다. iPad 파일 앱 미리보기가 JavaScript를 실행하지 않는 경우 이를 앱 코드 실패와 구분하고, 검증된 HTML 실행 경로와 안내를 기록한다. 브라우저가 자동 전체화면을 제한하면 첫 사용자 재생 동작에서 시도하고 실패해도 재생을 막지 않는다.

완료 보고는 구현·자동 테스트·실제 파일 실행·iPad 검수를 구분한다. 아직 확인하지 못한 환경을 통과로 기록하지 않는다.


## 7. 구현 책임과 산출물 계약

하나의 구현 작업에서 다음 책임을 순서대로 수행한다. 신규 경로는 가칭이며 기존 모듈 조사 결과에 따라 경로만 조정할 수 있다. 기능 범위와 검수 기준은 유지한다.

| 순서 | 소유 범위 | 완료 증거 |
|---|---|---|
| A | `src/portable.ts`, `src/library-backup.ts` 사용처 조사, 기존 출력 측정 | 공유 호출 목록, 기준 HTML 해시·크기, 백업 테스트 기준 결과 |
| B | 신규 `src/playback-export.ts`: 허용 목록 DTO와 검증·직렬화 | 입력→출력 필드 목록, 음원/렌더 바이트 SHA-256 일치, 타이밍/가사 대조 테스트 |
| C | 신규 `src/portable-player.ts`와 필요한 공유 재생 모듈, 전용 CSS | 웹앱 저장소를 불러오지 않는 실행 경로, 최소 DOM, 제스처/엔진 집중 검사 |
| D | `scripts/build-portable.mjs`: 전용 번들, 형식별 자산 및 라이선스 | 합본 esbuild metafile, 최종 HTML 검사 결과 |
| E | `src/main.ts`의 `save-html`/`portableBlob` 경로 통합 | 파일 내보내기와 demo가 같은 직렬화·조립 함수 사용, 중복 로직 제거 |
| F | 기존 portable/백업/재생 테스트 및 새 필수 검사 | 전체 테스트·타입·빌드 로그, 실제 파일·iPad 증거 |

### 재생 외 미사용 코드 제외

합본은 SVG/PDF 두 형식의 재생에 필요한 기능을 포함한다. 형식별 렌더 결과는 별도 보관하되 음원은 공유한다. OSMD/PDF.js 런타임, 편집기·업로드·곡 목록·백업·저장소 코드는 여전히 제외한다. 두 형식 중 하나만 선택하도록 사용자를 강제하여 크기를 줄이지 않는다. 라이선스 고지와 실행 코드 포함 여부는 구분한다.

### 데이터 완전성과 실패 처리

- DTO 필드는 넓은 `Song`/`RecordData` 객체 복사로 채우지 않는다. 각 필드의 타입·소비자·필수 여부를 허용 목록에 적는다. 중첩 데이터도 같은 규칙을 적용한다.
- 내보내기는 한 곡·보유한 두 형식의 일관된 스냅샷에서 생성한다. 내보내는 중 곡 전환/편집이 발생하면 스냅샷을 유지하거나 결과 다운로드 전에 명확히 취소한다. 서로 다른 버전을 섞지 않는다.
- 페이지와 마디 참조, 유한한 좌표·시간, 양수 BPM, 음원 길이와 재생 범위, 마커 범위를 검증한다. 누락 필수 데이터는 내보내기를 중단하고 원인·복구 방법을 표시한다.
- 선택 형식의 렌더 캐시가 없거나 오래되었으면 웹앱에서 갱신한다. 실패 시 다른 형식을 몰래 내보내지 않는다.
- 음원 없는 곡은 이번 오디오 동기 연습 HTML의 내보내기를 비활성화하고 ‘음원을 추가한 뒤 내보내세요’를 표시한다. 새 무음 연습 모드는 추가하지 않는다.
- SVG 압축 데이터와 PDF 페이지 이미지는 원본 렌더 바이트를 보존한다. PDF 이미지 재압축·음원 재인코딩을 하지 않는다.
- JSON과 HTML 경계를 안전하게 직렬화한다. 제목/가사에 `</script>`, 따옴표, `<`, `&`, 유니코드가 있어도 실행 코드가 되지 않고 원문 텍스트로 표시되어야 한다. SVG의 스크립트·외부 참조도 검증한다.
- 내보내기 연속 클릭은 하나의 작업만 실행한다. 취소/실패 시 부분 파일을 다운로드하지 않고 버튼을 복구한다. 생성 URL·오디오/이벤트 자원은 종료·실패 시 정리한다.
- 라이선스는 실제 포함한 런타임·폰트·악보 자산의 고지 의무와 대조한다. 제거 모듈 판정 때문에 필요한 저작권 고지를 삭제하지 않는다.

## 9. 측정·검수 반복과 종료

### 고정 기준선

- A단계에서 자료 이름·SHA-256, 소스 HEAD, 의존성 lock 해시, 기기/OS/브라우저, 출력 형식·설정, 테스트 명령을 기록한다. 비교 시 동일 자료와 조건을 유지한다.
- 기존/신규의 템플릿, 실행 JS/CSS, 악보, 음원, 총 HTML bytes를 분리한다. 합본 전환 승인을 반영하여 이전 단일 형식과의 크기 차이를 따로 보고하며, 추가 gzip은 합본끼리 비교한다. 음원·페이지 바이트가 같음을 검증해 품질 저하에 따른 감소를 배제한다.
- 시작시간은 문서 탐색 시작부터 악보 첫 화면 표시·음원 디코딩 완료·재생 버튼 활성화가 모두 충족된 시점까지 측정한다. 기준판에 계측이 없으면 같은 조건의 외부 계측을 두 판에 적용한다. 준비 상태에서 벗어나지 못하면 측정 성공으로 취급하지 않는다.
- 같은 기기에서 기준/후보를 각각 5회 새로 열어 최초 조작 가능 시점의 중앙값을 기록한다. 후보가 기준보다 `max(기준의 10%, 100ms)` 이상 느리면 실패로 분석·수정한다. 이 수치는 QA 회귀 허용치이며 속도 개선을 보장하는 표현이 아니다.
- 기존 기준선 실행 자체가 불가능하면 이를 먼저 복구하거나 측정 차단으로 남긴다. 근거 없는 이전 점수·시간으로 대체하지 않는다.
- 실행 명령: 관련 Vitest 파일 집중 실행 후 `npm test`, `npm run build`(portable 생성·TypeScript·Vite 포함). 백업 회귀는 별도 시험 보관함에서 export→import→필드/자산 대조하며 사용자 보관함에 덮어쓰지 않는다.

### 기록과 loop

- 고정 채점 기준: [HTML-PLAYBACK-EXPORT-QA.md](HTML-PLAYBACK-EXPORT-QA.md).
- 실험·실패·수정·재검수 기록: [HTML-PLAYBACK-EXPORT-HISTORY.md](HTML-PLAYBACK-EXPORT-HISTORY.md). 계획 정본에는 최종 결정과 실행 방법만 남긴다.

## 10. 구현 상태와 실행 환경 결정 (2026-09-21)

- 재생 전용 `src/portable-player.ts`와 SVG/PDF 합본 빌드로 전환했다. `src/main.ts`의 HTML 내보내기는 `src/playback-export.ts`의 명시적 허용 목록을 사용한다. 관리 코드는 숨기지 않고 번들에서 제외한다.
- `audio-core.ts`는 저장소 없는 공통 엔진이며 기존 웹앱은 `audio.ts` 래퍼로 설정 저장을 유지한다. HTML 설정은 메모리에만 있다.
- 최종 산출물 검사는 `node scripts/check-playback-build.mjs`로 수행한다. 에셋 라이선스 고지는 실행 의존성 유무와 별개로 보존한다.
- 사용자 추가 결정: 오프라인 단일 파일을 유지하고 **iPad 실행 앱은 Edge**로 지정한다. Edge 실기기에서 로컬 파일의 JavaScript, Web Audio, Blob Worker, 전체화면과 설정을 검증해야 한다. Mac Edge/Safari 또는 iPad Safari의 HTTP 실행으로 대신 판정하지 않는다.
- 연결된 iPad mini 시뮬레이터에는 Edge가 없다. 실기기의 Edge 실행 경로 확보 전 R08은 차단이다. 지원 범위나 기존 기준을 낮추지 않는다.
- Safari 실행 검사는 `document.visibilityState === "visible"`을 선행 확인한다. 합성 pointer 이벤트는 브라우저의 실제 pointer capture 검증을 대신하지 못하므로 드래그는 실제 입력으로 별도 확인한다.

## 11. 기존 앱의 화면 유지 (2026-09-21 사용자 정정)

재생 전용 분리는 기능·코드 포함 범위만 줄인다. 남는 기능의 버튼 배치·아이콘·크기·간격·색상·설정 화면을 별도로 재설계하지 않는다. 앱의 중앙 재생 버튼, 좌측 처음/되감기/위치, 우측 진행률/마커/소리, 하단 좌측 반복과 우측 세 마커 슬롯을 기준으로 한다. 관리 기능 제거로 빈 자리가 생겨도 남은 재생 컨트롤의 계층을 바꾸지 않는다. R07 화면 검수에는 기존 앱과 동일 폭에서 비교하는 항목을 추가한다.

## 2026-09-21 최신 결정: 두 줄 고정 보기

두 줄 모드는 각 행에 4마디를 고정한다. 재생/정지 모두 악보의 좌우 드래그·좌우 휠 탐색을 사용하지 않는다. 정지 상태의 상하 스크롤, 한 번 탭 선택, 두 번 탭 재생과 재생 중 한 번 탭 정지는 유지한다. 한 줄 모드의 좌우 탐색과 진행률 컨트롤은 유지한다. 웹앱과 HTML 내보내기 모두 적용하며 이전 두 줄 가로 이동 규칙을 대체한다.
