2026-10-03. 원칙 승인, 수치는 검토 후보. 이번 작업은 문서와 코드 읽기이며 구현/배포 변경 없음.

- 범위: MusicXML 한 줄 재생 보기. PDF는 사용자 제공 비교 기준이며 PDF 조판을 그대로 복사하지 않는다.
- 완료 조건: 승인 원칙, 측정 단위, 후보 수치, 충돌 조건과 후속 검증을 구분해 기록한다.

- 검증: 현재 간격 산정 코드와 기존 측정 자료 대조. 수치의 편안함은 후속 iPad mini Safari 사용자 검수 필요.

## 승인 원칙

음표는 읽을 수 있게 유지하고 가로 간격은 적절히 줄인다. 같은 음가는 같은 거리로 놓고 BPM은 이동 속도만 바꾼다. 진행선 앞에 여러 마디를 보여 준비할 시간을 확보한다. 스크롤을 음원보다 늦춰 맞추지 않는다. 정본은 `SVG-SCORE-RULES.md`의 최신 가독성 절이다.

## 현재 근거

사용자 비교 캡처에서는 MusicXML5마디 한 개가 화면 대부분을 차지하고 PDF는 약5마디를 보여 준다. 캡처는 크기 조정된 이미지이므로 이미지 픽셀을 CSS px 실측값으로 사용하지 않는다.

`src/ribbon-engraving.ts:ribbonSpacing`은 기본100 조판 단위에서 시작하고, 인접 음표 metrics와12단위 여유, 마디 끝 offset을 검사하여 곡 전체 최대 quarter 간격을 선택한다. 짧은 음가/끝 여백이 전체 폭을 키울 수 있다. `playback-screen.ts:widthOf`는 그 결과를 공통 measureWidth에 전달한다. 특정 기호가 최대값을 만든다는 진단은 항목별 실측 전에는 확정하지 않는다.

기존 로컬 audit.json의 quarterPixels는 Loveholic192.289, Real Paradis343.902였다. 이는 당시 렌더 조건의 측정이며 현재 캡처의 CSS 간격이라는 뜻은 아니다. 정확한 음가 비율만 검사하고 충분히 미리 보이는지 평가하지 않은 것이 이전 검수의 공백이다.

## 측정 단위와 계산식

모든 화면 거리는 CSS px로 기록한다. Retina 배율/스크린샷 픽셀과 혼용하지 않는다.

- W: 악보 표시 영역의 실제 너비.
- P: 표시 영역 왼쪽에서 진행선까지의 거리.
- Q: 4분음표 하나의 가로 거리.
- B: 4분음표 기준 실효 BPM. 다른 박 단위는 4분음표로 환산하고 연습 배속을 곱한다.
- 화면 박 수 N = W / Q. 4/4 환산 마디 수 = N / 4.
- 진행선 앞의 박 수 A = (W − P) / Q.
- 이동 속도 V = Q × B / 60 (CSS px/초).
- 화면 너비 대비 이동 속도 U = V / W (화면/초).
- 앞으로 읽을 수 있는 시간 T = A × 60 / B (초).

변박에서는 ‘마디 수’ 대신 4분음표 환산 길이로 비교한다. 실제 시간 보정/템포 변화가 있는 곡은 V = Q × 실제 4분음표 진행률로 측정하고, T는 현재 위치부터 오른쪽 경계까지의 실제 타임라인 차이로 계산한다. 명목 BPM 계산을 실제 동기화의 증거로 대신하지 않는다.

| 항목 | 후보 | 의미 |
| --- | --- | --- |
| 기본 밀도 | N=16, 허용 비교 범위12–20 | 4/4 환산3–5마디, 중심 목표4마디 |
| 진행선 | 현재 위치 유지, 예시는 P=W/3 | 밀도 개선을 위해 진행선을 갑자기 이동하지 않음 |

## 피할 수 없는 제약과 해결 순서

화면 폭이 좁거나 음표가 매우 조밀하면 큰 음표·많은 선행 마디·균일 간격·충돌0을 동시에 충족하지 못할 수 있다. N=16을 억지로 맞추기 위해 음표를 찌그러뜨리지 않는다.

1. 최대 Q를 결정한 마디/음가/기호/끝 여백을 계측한다.
2. 불필요한 마디 끝 offset과 중복 여백을 제거할 수 있는지 확인한다.
3. 악기·주법 의미와 native glyph 크기를 보존하면서 기호의 상하 배치 등을 검토한다. 승인되지 않은 대체 기호는 쓰지 않는다.
4. 실제 최소 간격 Qmin과 목표 W/16을 비교한다. Qmin이 더 크면 가독성 목표 미달을 보고하고 해결안을 검토한다. 특정 마디만 넓혀 이동 속도가 출렁이는 방식은 기본 해법으로 삼지 않는다.
5. 좁은 세로 화면에서는 같은 글리프 크기에서 보이는 박 수 감소를 별도 평가한다. 모든 화면에4마디를 강제하지 않는다.

## 후속 검증 방법

- Loveholic과 Real Paradis에서 W/P/Q/N/A/V/T, 오선 간격, 음표머리 크기, 최대 간격의 원인 마디를 기록한다.
- iPad mini Safari 가로/세로, 기본 확대율에서 검수한다. Loveholic2/5/10/120–123, 변박·꾸밈음·주법 밀집 구간을 포함한다.
- 밀도12/16/20박 후보는 같은 음표 크기로 비교한다. 숫자 달성만으로 통과하지 않고 사용자가 PDF와 나란히 보고 연주 준비가 편한지 판단한다.
- 동일 BPM에서 마디 경계 전후 이동 속도 불연속이 없는지 측정한다. 원래 음원 템포 변화와 표시 좌표의 결함을 구분한다.
- 재생 중 새 조판0회, 현재 마디·박/반복 유지, 회전 후 가로 넘침0을 회귀 검사한다.
- 수치 선택 후 캐시 정책 버전과 공통 렌더링 규칙을 함께 갱신한다. 현재 배포본은 아직 이 밀도 개선을 포함하지 않는다.


### 2026-10-03 구현 기준 확정

- 기존 Loveholic quarter208/offset24, Real Paradis quarter372/offset34 조판 단위. Real Paradis72·100마디 마지막6연음 간격1/6박에 `(global offset + note width + padding) / duration`을 적용하면서 최대371.18→372가 곡 전체에 전파됐다.

- 50%의 Q=W/16, 다른 확대율의 Q=(W/16)×(zoom/0.5). native quarter/오선 비율에서 동일 XY배율을 구한다. 따라서 100%는 약2마디,200%는 약1마디다. BPM 변경은 이 계산에 참여하지 않는다. 곡 시작/끝에는 내용이 없는 부분이 있어 실제 보이는 완전한 마디 수는 줄어들 수 있다.

### 실패·해결 및 남은 한계

1. 첫 화면 검수에서 고정 stage 높이가 새 음표 배치 높이를 수용하지 못해 가사가 아래에서 잘렸다. 실제 crop 높이도 stage 높이에 반영해 수정하고 캡처로 재확인했다.
2. 끝구간 온마디 쉼표가 왼쪽에 붙었다. 네이티브 한 줄 조판에서 완전히 쉰 마디의 쉼표를 중앙에 배치했다. 첫 수정에서 다성부 마디까지 영향을 주는 사례가 자동 대조에 잡혔으며, 모든 음이 실제 쉼표인 경우로 제한해 이상값0을 확인했다. 일반 GraphicalMeasure의 타입에는 getVFStave가 없으므로 OSMD adapter의 명시적 형태로 좁혀 빌드 오류도 해결했다.
3. HMR/비활성 탭이 QA 보고서를 덮어써 빈 position을 남긴 경우는 위치 유지 증거에서 제외한다. 활성 시뮬레이터 화면 캡처와 유효한 최종120마디 보고서를 대조했다.
4. 좁은 세로 화면의50%는 작은 음표를 보인다. 편안함의 보편적 보장은 하지 않으며 사용자가 확대하면 자연스럽게 보이는 마디 수가 줄어든다. 매우 복잡한 다른 악보의 조밀도/꾸밈음/기호는 추가 검수가 필요하다.
5. 병행 제작 세션이 Loveholic 로컬 패키지를269개 위치 가사로 교체했다. 그 자료를 보존했고 본 작업은 원본 PDF/MusicXML이나 가사 데이터를 수정하지 않았다. 가사 내용의 전수 검수는 해당 제작 세션 책임이다.
