# SVG 한 줄 보기: 시간 기준 배치

2026-10-03 사용자 승인. 기존 SVG 재생 여백/높이 수정에 이어 적용한다.

## 확정 요구
- 같은 음악적 박 길이는 같은 가로 거리로 표시한다. 4분음표 단위로 환산하며 16분음표는 1/4 간격이다.
- BPM/재생 속도 변경은 스크롤 속도만 바꾸고 악보 배치를 다시 흔들지 않는다.
- 음표·오선·기호의 크기는 유지하고, 음표 사이 간격을 재배치한다. 이미지 전체 가로 압축으로 대체하지 않는다.
- 마디 경계에서도 일정한 이동을 유지하고 진행선·음표 강조·가사를 동일한 좌표에 연결한다.
- 조밀한 마디 하나만 넓히지 않는다. 곡 전체에 필요한 공통 박 간격을 확보한다. 꾸밈음은 시간을 늘리지 않고 본음 주변에 배치한다.
- 적용 범위: SVG 한 줄 보기. 원본 MusicXML/PDF, 전체 SVG의 페이지/줄 구성, 두 줄 보기 4마디 구성 및 PDF 보기는 유지한다.
- 공통 재생 구현을 사용한다. 독립 HTML 재생 파일 생성·저장은 하지 않는다.

## 구현/검증 순서
1. 현재 SVG의 음표·쉼표·빔·붙임줄·기호 및 음악적 시간 정보 계약을 확인한다.
2. 원본과 분리한 시간 기준 표시 데이터를 준비하고 공통 렌더/이동/탐색에 연결한다.
3. m2/m10, 온쉼표, 변박, 셋잇단음표, 꾸밈음, 마디 경계, 마지막 마디를 검증한다.
4. 전 마디 박당 이동거리·글리프 크기·진행선 일치 및 기존 PDF/두 줄 보기 회귀를 확인한다.
5. 실제 Safari 화면과 실행 결과를 기록한다. 미검증·미지원 표기는 완료로 처리하지 않는다.

## 현재 상태
- 승인안 구현 및 로컬 실행 검증 완료. Sites 배포와 독립 HTML 생성은 하지 않음.

## 구현 결과

- `ribbon-engraving.ts`: 원본과 분리한 OSMD 재조판, 공통 박 너비 계산, native 음표/빔/붙임줄 조판 유지.
- `ribbon-timeline.ts`: 버전·좌표 계약과 입력 검증. 잘못된 캐시를 이미지 자원 할당 전에 거부한다.
- `musicxml.ts`: 인쇄용 원본 배치를 유지하고 재생용 캐시를 비표시 metadata에 포함한다.
- `playback-assets.ts`, `playback-screen.ts`: 모든 호스트가 같은 자산과 선형 시간 좌표 사용. PDF/두 줄은 기존 인쇄 배치 사용.
- 기존 두 bundled 패키지는 첫 SVG 페이지에 metadata만 추가했다. 원본 XML/PDF/음원, 두 번째 이후 SVG, song 데이터·기존 crop geometry는 바이트/객체 대조로 보존했다. 이전 패키지는 실험 폴더에 백업했다.

## 막힘과 해결 기록

1. 전체 SVG crop의 width만 맞추는 안: 기호가 변형되고 박 내부 간격이 남으므로 채택하지 않음. native 조판 전 tick context 이동으로 해결.
2. 초기 실험에서 첫 음표 좌표가 덮어써짐: 원본의 별도 가사 성부까지 실험 OSMD에 넣어 공유 tick context를 두 번 옮긴 원인. 실제 `parseMusicXML`의 선택 파트 경로로 실험/구현을 통일하여 해결. 다른 성부의 시간 축을 임의로 움직이지 않음.
3. 정확한 오선 좌표를 써도 특정 페이지의 박 폭에0.0388px 차이가 남음: SVG viewBox 높이가 소수인데 `Image.naturalHeight`가 정수로 반올림됨. SVG viewBox 비율로 바꿔 해결.
4. 음표 크기 히스토그램을0.001단위로 비교하면11.400/11.401로 분리됨: getBBox의 부동소수 좌표 오차. 실제 머리 크기 축소가 아님을 확인하고0.01단위 분포 및 화면 검수를 함께 사용.
5. 개발 중 다른 파일 변경의 HMR로 페이지가 바뀌어 UID가 무효화됨. 현재 화면을 다시 읽고 같은 BPM 검사를 재실행하여 통과. `$uid` 실행 매크로 실패 시 확인된 DOM id와 같은 change handler로 검사.

최종 자동 검증: 73파일347테스트, TypeScript 검사, editor/player 빌드 및 player renderer-free 경계 검사 통과. 소스 변경 이후 저장된 두 패키지를 다시 로드하여123/110마디 캐시 준비를 재확인했다.
