# 최종 가사 묶음을 정본에 저장하고 원음절 자료는 작업 파일에 보존한다

## Context and Problem Statement

두 앱의 모든 MusicXML 화면에 기존 균등식을 공통 시간 비례 조판으로 적용하면서, 가까운 음절의 글자 영역이 겹치는 경우를 처리해야 했다. 사용자는 원음절별 표시를 위해 악보 폭을 사전 확장하는 방식 대신, 겹치는 가사를 첫 시작점 기준으로 묶는 계획을 승인했다.

사용자는 2026-11-13 웹앱 개발 채팅에서 보완 계획의 구현과 악보제작자의 정본 전환을 명시했다. 묶기 전 전체 원문·음절별 시간은 작업 파일에 보존하고 정본에는 최종 묶음만 남기기로 했다. 구형 앱 저장 파일 지원은 종료하되 원본·제작 자료·기록은 보존한다. 이번 구현 검증은 정적 검사로 제한하며 커밋·푸시·발행은 하지 않는다.

## Considered Options

- 원음절을 계속 정본에 저장하고 화면마다 임시로 묶는다.
- 글자 폭에 맞춰 시간 비례 간격을 넓힌다.
- 제작 단계에서 공통 함수로 표시 묶음을 확정하고 원음절 자료와 분리한다.

## Decision Outcome

세 번째 방식을 선택한다. 현행 계약은 [MusicXML 최종 가사 묶음](../reference/score/musicxml.md#musicxml-canonical--최종-가사-묶음), 절차는 [가사 제작·전환](../how-to/correct-lyrics.md#final-lyric-groups)에 둔다.

- 같은 보표의 소유 가사 성부와 `noteId, voice, id, confirmed` 구조를 재사용한다. 항목의 의미는 최종 표시 묶음으로 바뀌며 manifest는 v3다.
- 원래 텍스트 박스의 겹침만 계산한다. 묶은 뒤 커진 문자열로 다음 묶음까지 연쇄 병합하지 않는다.
- 줄 끝·줄 경계·다음 묶음 침범을 미리 금지하지 않고 사전 최소 폭을 추가하지 않는다. 실제 사례를 확인한 뒤 공통 처리 또는 구간 예외를 결정한다.
- 원문·원음절 시간·이전 정본·음절→묶음 대응표는 제작 작업 파일에 남긴다. 정본은 최종 문구·첫 위치·필요 음가를 사용한다.
- 구형 앱 데이터·패키지·캐시 정리는 앱 담당, 정본 전환과 제작 근거는 악보제작자가 맡는다.

### Consequences

- 두 앱은 같은 문구와 시작점으로 재생성할 수 있다. 원음절 편집으로 돌아가려면 작업 파일이 필요하다.
- 묶음 수 감소는 가사 삭제나 원본 판독 정확도 향상을 뜻하지 않는다. 미확정 음절을 포함한 묶음은 미확정으로 유지한다.
- 화면 침범이 모두 해소됐다는 보장은 없다. 정적 규격·보존 검사와 실제 표시 검증을 구분한다.
