# 원본 줄 구성과 연습용 자르기의 범위를 구분한다

## Context and Problem Statement

전체 출력의 원본 줄 구성, 두 줄 재생의 4마디 배치, PDF 줄 앞 자르기가 혼동되었다. 2026-10-03 최종 정정은 이 세 범위를 구분한다.

## Considered Options

* 전체 출력과 두 줄 재생에 같은 줄별 마디 수를 적용한다.
* 전체 출력은 원본 줄 구성, 두 줄 재생은 4마디, 줄 앞 여백은 별도 crop으로 처리한다.

## Decision Outcome

후자를 채택한다. 줄 앞 타악기 표시 자르기 과정의 인쇄 가사·마디 숫자 손실은 허용하며 원본 파일과 실제 음악 좌표는 보존한다.

### Consequences

상하 내용 보존과 가로 prefix 자르기는 별개다. 특정 곡의 좌표표·페이지 구성을 다른 곡에 적용하지 않는다.

### Confirmation

현재 기준은 [SVG 규칙](../reference/score/rendering.md#svg-score-rules--svg-전체-악보-생성-규칙)을 따른다. 아래 검증·버전·수치는 당시 기록이며 이번 문서 이관에서 시험을 재실행한 결과가 아니다.

## More Information

아래는 분리 전 혼합 문서에서 옮긴 원문이다. 원문의 날짜·버전 순서와 위 Decision Outcome을 함께 읽는다. 과거의 ‘현재’, ‘미구현’, 초안 수치와 PASS는 당시 범위에만 적용한다.

#### 줄 간격과 페이지 나눔의 정본

- 곡별 MusicXML의 `system-layout/system-distance`, `top-system-distance`, `print new-system`, `print new-page`가 배치 의도의 정본이다.
- 새로 만드는 악보의 공통 간격은 XML 작성 초기값이다. 각 악보에서 따로 지정할 수 있으며 기존 XML의 값을 공통값으로 덮어쓰지 않는다.
- SVG 전체 보기에는 독립적인 줄 간격 설정을 두지 않는다. 렌더 복제본에서도 XML 간격 정보를 삭제하지 않는다.
- OSMD의 XML 줄/페이지 나눔 적용을 켠다.
- 현재 한계: OSMD 2.1.2 소스에는 `system-distance`를 읽어 시스템 간격에 적용하는 처리가 없다. `top-system-distance`의 일부 읽기 처리만 있다. 따라서 XML 간격의 정확한 출력 지원은 아직 미완료다. 렌더러의 상수 간격 강제로 이 지원을 대신했다고 보고하지 않는다.
- 곡별 검증 사례: 「風と丘のバラード」(Real Paradis, 110마디)는 2026-09-21에 PDF와 같은 1–36 / 37–76 / 77–110마디의 3페이지로 검증했다. XML 페이지 경계는 유지하고 PDF 줄 시작에 new-system을 기록한다. 마지막 두 줄은 105–106 / 107–110마디다. 1500px 조판 폭에서 OSMD 자동 넘침 없이 이 구성을 확인했다. RenderXMeasuresPerLineAkaSystem=0으로 고정 마디 수를 강제하지 않는다. XML system-distance의 정확한 지원과는 별개이며 다른 곡의 페이지 경계를 이 값으로 강제하지 않는다.
- Loveholic(123마디)은 별도 [제작 기록](../records/songs/loveholic.md#loveholic-conversion--loveholic-pdf--musicxml-작업)의 1–36 / 37–79 / 80–123마디 3페이지 검증을 따른다. 곡별 배치 증거와 공통 SVG 규칙을 구분한다.

### 3. 타악기 음자리표와 세로줄

- 타악기 음자리표 `||`는 첫 마디와 시스템 시작을 포함해 앱 생성 SVG에서 숨긴다.
- 원본 MusicXML의 `<clef><sign>percussion</sign></clef>`와 악기 정보는 유지한다.
- 실제 세로줄·겹세로줄·마침줄·도돌이표는 유지한다. 모양이 비슷하다고 지우지 않는다.
- 현재 구현은 렌더 문서의 모든 명시된 clef가 percussion일 때 `.vf-clef` 그룹만 제거한다. 혼합 음자리표 파트의 선택적 제거는 아직 구현되지 않았으므로 일반 음자리표를 함께 제거하지 않는다.

#### 줄 앞 타악기 표시 자르기 — 최신 확정 결정 (2026-10-03)

> 타악기 표시 자르기를 하고, 그걸 하면서 가사나 숫자가 잘려도 괜찮다.

- PDF 연습 화면의 줄 앞 타악기 표기·여백을 표시 영역에서 잘라 다른 마디와 길이를 맞춘다. 이 과정에서 인쇄 가사·마디 숫자가 잘리는 것은 허용한다.
- 이 자르기에 대해서는 과거의 “마디 번호 유지” 조건보다 위 최신 결정이 우선한다. 가사·숫자 보존 때문에 타악기 표시를 남기는 예외를 두지 않는다.
- 원본 PDF와 MusicXML은 보존한다. 첫 음표·박자표·실제 마디선과 진행선 좌표는 보존·대조한다. 줄 전체의 상하 내용 자르기는 별도 규칙을 따른다.
- [결정 대조 기록](../records/songs/loveholic.md#musicxml-troubleshooting--줄별-마디-구성과-줄-앞-타악기-표기의-과거-결정-대조)에 승인 이력을 남긴다. 결정 기록과 현재 곡의 구현·검증 완료를 구분한다.

#### 현재 곡의 PDF 페이지별 줄 시작 마디

- 1쪽: 1, 5, 9, 13, 17, 21, 25, 29, 33
- 2쪽: 37, 41, 45, 49, 53, 57, 61, 65, 69, 73
- 3쪽: 77, 81, 85, 89, 93, 97, 101, 105, 107
- 참조: data/reference/geometry.json. 다른 곡에 이 번호표를 적용하지 않는다. 페이지 경계·줄 시작·줄별 마디 목록을 모두 PDF와 대조한다.

#### 연습 화면 Trim
- 마디 crop은 같은 시스템의 실제 SVG 음표·쉼표·구간 표시 bounding box에 상하 5 SVG 단위만 더한다. 고정 하단 9.5칸으로 다음 줄을 포함하지 않는다.
- 제목은 전체 SVG에 보존하며 연습용 페이지 복제본에서만 제거한다.
- 두 줄 보기의 공통 높이/정렬은 유지하되 원본 시스템 경계 밖의 잉크는 clip-path로 가린다.

### 두 줄 고정 보기 — 2026-10-03 재확정

두 줄 모드는 각 행에 4마디를 고정한다. 재생/정지 모두 악보의 좌우 드래그·좌우 휠 탐색을 사용하지 않는다. 정지 상태의 상하 스크롤, 한 번 탭 선택, 두 번 탭 재생과 재생 중 한 번 탭 정지는 유지한다. 한 줄 모드의 좌우 탐색과 진행률 컨트롤은 유지한다. 악보제작기와 드럼연습실 모두 적용하며 이전 두 줄 가로 이동 규칙을 대체한다.

2026-10-03 최종 사용자 정정: 두 줄 보기는 4마디, 전체 SVG 출력은 원본 줄별 마디 구성, PDF 보기는 줄 앞 타악기 표시·여백을 스킵(그 과정의 인쇄 가사·마디 번호 잘림 허용), 원본 PDF와 MusicXML 보존. 앞서 두 줄 재생도 원본 줄 구성을 따른다고 기록한 것은 잘못된 해석이며 철회한다.

### 2026-10-03 PDF 재생 오선 정렬

SVG의 기존15간격 프레임은 유지한다. 공통 재생 경로에서 PDF도 오선을 검출해 줄 간 배율과 기준선을 맞춘다. PDF 인쇄 가사까지 보존하도록 모든 crop을 포함하는 공통 상하 프레임을 구하며, 검출 불가 PDF는 전체를 종전 crop 표시로 유지한다. 원본 PDF·SVG·마디/박 위치는 수정하지 않는다. 래스터 선의 반올림은 오선 전체 길이로 간격을 추정하고 같은 줄은 한 번 검출한다. 근거: LOVEHOLIC-REVIEW.md.

이 상하 프레임의 내용 보존 검증은 §3의 줄 앞 타악기 표기·여백을 가로로 자르는 사용자 허용을 취소하지 않는다. 두 자르기의 방향·목적·검증 범위를 구분한다.

#### SVG 재생 화면의 줄 시작 여백 (2026-10-03)

- Loveholic의 검증된 SVG에서 첫 마디를 제외한 31개 시스템 시작에 남은 타악기 음자리표 슬롯 26 SVG 단위를 재생 영역에서 제외한다. 첫 박 앵커 앞 여백은 49.00912 → 23.00912 단위로 일반 마디와 같아진다.
- `src/content/svg-display-crops.json`의 곡 ID·영역 좌표·박 앵커가 일치할 때만 `displayRegion`에서 적용한다. 다른 곡이나 재조판된 좌표에는 추측 적용하지 않는다.
- 마디 오른쪽 경계와 음표/박의 원본 절대 좌표를 유지한다. 구간 표시의 글자·테두리는 재생용 SVG 복제본에서 같은 양만큼 오른쪽으로 이동하여 잘림을 방지한다.
- 원본 MusicXML·전체 SVG·PDF는 유지한다. 공통 재생 구현을 사용하는 화면에 적용하며 별도 HTML 재생 파일은 만들지 않는다.

### 2026-10-21 PDF/MusicXML 검수의 PDF 오선 검출

검수의 PDF 오선 위치도 같은 페이지·y·높이에 속한 인쇄 줄 전체에서 검출하여 마디마다 공유한다. 밀집된 빔/음표로 단일 마디 검출이 실패하는 경우를 해결한다. 실제 표시 crop과 박 좌표는 유지하고, SVG 검출·표시 규칙은 바꾸지 않는다. 오선 없는 영역은 검수 오류로 남긴다. 근거: [검수 수정 기록](0005-practice-layout-and-spacing.md#이관-원문--score-reviewmd--9).

### MusicXML 입력 매핑·정본 계약에서 옮긴 근거 — 2026-10-23 이관

아래 원문은 당시 문맥·승인/검증 범위를 보존한다. 과거의 미확인·보류·HTML·시안 수치를 현재 지원이나 새 실행으로 해석하지 않는다. 현행 규칙은 입력 매핑·정본 계약·SVG Rule에서 확인한다.

##### 앱 표시 예외: 타악기 음자리표 숨김 (2026-09-21 사용자 확정)
- MusicXML의 percussion 음자리표·악기 정보는 유지한다.
- 이 프로그램이 생성하는 SVG에서는 타악기 음자리표 글리프를 제거한다. 첫 마디/시스템 시작의 반복 표시도 숨긴다.
- 겹세로줄·마침줄·도돌이표는 음자리표가 아니므로 유지한다. PDF 원본은 변경하지 않는다.
