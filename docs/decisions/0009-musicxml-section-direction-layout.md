# 섹션과 연주 지시를 분리하고 XML로 배치 의도를 보존한다

## Context and Problem Statement

2026-10-23 섹션과 연주 지시가 겹쳤다. 합친 이름·SVG 후처리·다음 음표 기준 시안·XML offset 비교를 거쳐 최종7원칙을 확정했다.

## Considered Options

* 표제와 지시를 합치거나 SVG 좌표표로 후처리한다.
* rehearsal과 words를 분리하고 XML 위치 속성·공통 조판을 사용한다.

## Decision Outcome

후자를 채택한다. 섹션 바깥선은 자기 마디 오선 시작에 정렬하고 적용 박을 유지한다.0.0625박 최소 표시 offset·오선 간격¼ 여백·같은 줄 제한·XML 높이 분리·원본 표제만 사용의7원칙은 규칙 §4에 정의한다.

### Consequences

v2 음표 순차 이동/8 SVG 여백과 v8/v10 여백0·같은 마디 탐색은 최종 기준을 대신하지 않는다. 당시 결과와 후속 붉은 노을 재제작의 검증 범위를 구분한다.

### Confirmation

현재 기준은 [SVG 규칙](../reference/score/rendering.md#svg-score-rules--svg-전체-악보-생성-규칙)을 따른다. 아래 검증·버전·수치는 당시 기록이며 이번 문서 이관에서 시험을 재실행한 결과가 아니다.

## More Information

아래는 분리 전 혼합 문서에서 옮긴 원문이다. 원문의 날짜·버전 순서와 위 Decision Outcome을 함께 읽는다. 과거의 ‘현재’, ‘미구현’, 초안 수치와 PASS는 당시 범위에만 적용한다.

### 4. 구간 시작 표시

#### 섹션·연주 지시 7가지 최종 원칙 — 사용자 확정 2026-10-23

아래 7가지가 현재 제작 기준이다. 뒤의 구현·검증 기록과 과거 시안은 이 원칙의 구현 완료를 대신하지 않는다.

1. **섹션 테두리를 해당 마디의 오선 시작점에 좌측 정렬한다.**
   줄 중간의 섹션도 해당 마디 시작점을 기준으로 한다. 테두리 여백과 선 두께를 포함한 **바깥선의 왼쪽**을 맞춘다.

2. **연주 지시의 음악적 적용 박은 원본과 동일하게 유지한다.**
   표시 위치도 기본적으로 원래 적용 박을 따른다. 표시를 옮겨도 연주·재생의 적용 시점은 바꾸지 않는다.

3. **섹션과 겹치거나 최소 여백이 부족하면 표시 위치만 뒤로 이동한다.**
   사분음표를 1박으로 하여 **0.0625박씩** 탐색하고, 조건을 만족하는 가장 작은 offset을 선택한다. 최소 여백은 **인접한 오선 두 선 사이 간격의 ¼**로 한다. 테두리 선 두께와 실제 글자 경계를 포함해 판정한다.

4. **모든 배치 의도를 MusicXML에 기록한다.**
   섹션은 `rehearsal`, 연주 지시는 별도 `words`로 저장한다. 섹션 위치·정렬과 지시문의 표시 offset을 XML에 기록하며, 표시 이동에는 **`<offset sound="no">`**를 사용한다. 해당 `words`에는 offset을 무효화하는 `default-x`를 병용하지 않는다. 별도 좌표표나 수정된 SVG 없이 재생성할 수 있어야 한다.

5. **미지원 속성은 최신 안정판에서 먼저 확인하고 공통 조판 단계에서 보완한다.**
   호환성 검증 후 필요한 업데이트를 적용한다. 여전히 미지원이면 제작기·재생기가 공유하는 조판 단계에서 XML 속성을 반영한다. 재현 기준은 **동일한 공통 조판기·Pretendard·조판 폭**으로 한다.

6. **가로 이동은 같은 줄 안으로 제한하고, 공간이 없으면 높이를 분리한다.**
   지시문 전체가 같은 줄 안에 들어가야 한다. 배치할 공간이 없으면 추가 표시 offset을 **0으로 되돌려 원래 적용 박 위에 놓고**, 별도 높이에 배치한다. 세로 이동도 `words`의 `relative-y` 등으로 MusicXML에 기록한다. 최종 배치는 섹션·음표·다른 지시문·인접 줄과 겹치지 않고 최소 여백을 확보해야 한다.

7. **섹션 표제는 원본에 명시된 것만 사용한다.**
   원본의 섹션 이름·순서·적용 마디를 보존한다. 제작자의 해석이나 설명을 새로운 섹션 표제로 추가하지 않으며, 원본에 없는 임의 표제는 제거한다.

기술 단위: MusicXML의 divisions는 사분음표 기준이다. divisions96에서는 0.0625박=6divisions이며, 오선 한 간격10tenths의 ¼은2.5tenths다. [offset 규격](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/offset/)은 `sound="no"`의 적용 위치 보존과 `default-x` 우선순위를 정의하고, [words 규격](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/words/)은 세로 위치 속성을 정의한다.

#### 원칙 확정 직후 상태와 후속 재제작 (2026-10-23)

- 원칙 확정 직후에는 문서·제작 스킬만 수정했고 v10/기존 패키지는 유지했다. 당시 도구는 여백0·같은 마디 탐색이었으므로 그 결과를 새7원칙 전체의 통과로 사용하지 않는다.
- 후속 `common/direction-offset.mjs`는 실제 잉크와 stroke, 오선 한 간격¼ 여백, 같은 줄 탐색·공간 부족 시 offset0/relative-y 높이 분리를 구현했다. 세로 위치는 아래 공통 native words 지원에서 해석하며 완성 SVG를 움직이지 않는다. 원래 박의 native 글자 정렬/작은 왼쪽 돌출과 섹션 테두리의 오선 시작 정렬을 구별한다.
- [붉은 노을 최신 재제작](../records/songs/red-sunset.md#red-sunset-rebuild-20261023--붉은-노을--최신-제작-원칙-전곡-재제작)은 원본 높이를 default-y로 기록하고14원본 표제·16지시·O+와 전곡7원칙을 검증했다. 이번 최종 입력은 모두 가로 배치가 가능해 세로 분기를 쓰지 않았다. `기보된 카운트` 표제만 제거하고 원래 첫 마디4타격을 유지했다. 검증 기준은 해당 인쇄 폭1500이며 다른 곡/폭·실제 수록 교체를 완료한 것으로 확대하지 않는다. [v10](../records/archive/rendering-experiments.md#section-direction-final-20261023--갑자기붉은-노을-전체-재조판)과 [추가 경위](../records/songs/red-sunset.md#red-sunset-production--원본에-없는-시작-표제--2026-10-23-경위-확인)는 과거 상태로 보존한다.

#### words XML 세로 위치 지원 — 공통 조판 (2026-10-23)

- 일반 연주 지시 words의 `default-y`·`relative-y`를 native 라벨·skyline 계산 단계에서 반영한다. 값은 tenths이며 양수가 위쪽이다. `default-y`는 오선 위 선 기준이고, `relative-y`는 native 기본 위치 또는 지정된 `default-y`에서 추가 이동한다.
- 위치 지정된 지시의 실제 글자 경계를 시스템 crop에 포함한다. 완성 SVG 좌표 이동·곡별 좌표표를 사용하지 않는다. 위치 미지정 지시·음표·주법·섹션의 기존 배치와 적용 박은 유지한다.
- native가 템포로 분류하거나 서로 다른 Y를 한 라벨에 합쳐 개별 적용할 수 없는 경우는 해당 라벨의 기존 배치를 보존하고 진단 경고한다. 악보 전체를 거부하지 않으며 미지원 라벨을 지원 완료로 보고하지 않는다.
- 세부 지원 경계·실제 입력·네 경로 회귀와 한계는 [words 위치 검증 기록](../records/archive/rendering-experiments.md#words-position-20261023--연주-지시-words-세로-위치-지원--2026-10-23)을 따른다. 캐시는 `v28-words-position`으로 갱신한다.

#### XML 가로 위치 지원의 배경

`<rehearsal>`의 `default-x`·`relative-x`·`halign`·`justify`를 정본 입력으로 삼는다. 설치 OSMD 2.1.2 reader의 속성 누락은 [v6 재현·개발 인계](../records/archive/rendering-experiments.md#section-direction-layout-review--xml-위치-속성-입력과-조판기-미지원-재현--v6)에 보존하고, 앱은 아래 공통 native 조판으로 지원한다. v2/v5의 곡별 SVG 섹션 보정은 과거 검토 시안이다.

#### XML 가로 위치 지원 — 공통 조판 (2026-10-23)

- `rehearsal-layout.ts`는 선택 파트의 마디 순서로 XML 속성을 연결한다. OSMD 계산기 인스턴스가 만든 native VexFlow StaveSection의 그리기 인자를 SVG 생성 전에 계산한다. 원본 XML·완성 SVG 노드의 X좌표·native 글꼴/테두리/음표 좌표는 바꾸지 않는다. 위치 속성이 없는 과거 악보는 기존 경로를 유지한다.
- `default-x`의 원점은 해당 마디의 오선 전체 시작점이다. 음표 시작점이나 음자리표·박자표 뒤가 아니다. `relative-x`를 더하고 native 오선 간격/10으로 tenths를 환산한다. `halign`이 우선하며 생략하면 `justify`, 둘 다 없으면 left다. 현재 native 단일행 rehearsal 범위이며 여러 줄 내부 정렬 지원을 의미하지 않는다.
- MusicXML 표준의 텍스트 위치 속성과 앱의 테두리 여백 정책은 구분한다. 사용자가 지정한 섹션 기준은 **테두리 바깥선**이므로 native 글자 폭·padding·2단위 stroke를 포함한 왼쪽/가운데/오른쪽을 앵커에 맞춘다. left·default-x0이면 바깥선=마디 오선 시작, rect 경로는 그보다1단위 오른쪽이다.
- 기존 공통 SVG Y 보정과 과거 표시 영역의 prefix crop 처리는 유지한다. XML 가로 배치 자체는 곡별 좌표표·SVG 후처리 없이 재생성한다. 당시 words는 MusicXML offset과 기존 native 정렬을 유지했으며 새 충돌 회피 엔진은 구현하지 않았다. 현재 제작 기준은 위 7원칙을 따른다.
- 실제 갑자기12개·붉은 노을15개 섹션은 print/timeline/rows/grid의108개 위치에서 오차0을 확인했다. 붉은 노을26·134마디의 default-x0→100은 바깥선50→150으로 이동했다. print6쪽은 섹션 쌍의 X좌표를 제외한 SVG가 기존 코드와 같았다. 근거는 로컬 `.tmp/rehearsal-results.json`과 Safari 캡처다.
- 렌더 정책은 `v24-rehearsal-position`으로 갱신하며 기존 v23 다중 마디 wedge 지원을 포함한다. 저장/XML/타임라인 메타데이터 스키마는 유지한다. 기존 패키지 파일 교체나 보관함의 곡 수정은 별도 작업이다.
- 현행 OSMD는 2.2.1이다(2026-10-23). 위 공통 XML 보완을 유지한 상태에서 실제 Safari 228위치, default-x100 이동, 0.0625박 words offset과 여러 마디 wedge를 재확인했다. 패키지 버전은 캐시 키에 자동 포함된다. 범위·한계·개발 서버 캐시 해결은 [업데이트 기록](../records/archive/rendering-experiments.md#osmd-upgrade-20261023--osmd-221-업데이트)을 따른다. 앞선 2.1.2 미지원 기록은 당시 재현 근거로 보존한다.

#### 과거 섹션 표시와 배치 시안 — 아래는 현재 제작 기준이 아닌 이력

- v8/v10 제작 당시에는 추가 고정 여백 없이 겹침만 피하는0.0625박 최소 표시 offset을 탐색했다. 적용 cursor는 유지했다. 당시 결과는 [제작 기록](../records/archive/rendering-experiments.md#section-direction-final-20261023--갑자기붉은-노을-전체-재조판)에 보존하며 위 최종 7원칙의 여백/줄 경계/높이 분리 검증으로 대신하지 않는다. 아래 v2~v7 시안·표본값도 과거 검토 이력이다.

- 후속 검토(2026-10-23): 사용자는 더 나은 표준 방식이 있으면 아래 ‘음표에서 글자 왼쪽 시작’ 아이디어를 철회할 수 있다고 했다. 현재 대표 마디에서는 이를 합격 조건으로 강제하지 않고 MusicXML `offset sound="no"`와 공통 조판기의 기본 정렬을 비교한다. [대표 마디 v3](../records/archive/rendering-experiments.md#section-direction-layout-review--대표-마디-v3--xml-offset과-현재-기본-정렬-비교)는 검토본이며, 표본 offset 값을 전곡 공통값으로 확정하거나 기존 SVG 후처리를 XML 단독 재현으로 간주하지 않는다.

- Intro, A, 후렴, C, Interlude, Ending 등 rehearsal 표시의 내용은 유지한다. 임의 번역하지 않는다.
- 사용자 결정(2026-10-23): 구간 표시 테두리의 왼쪽을 해당 마디의 왼쪽 오선 시작점에 맞춘다. 줄 첫머리에서는 오선 전체의 시작점, 줄 중간 섹션은 해당 마디 왼쪽 경계다. text와 테두리를 함께 이동하며 테두리 크기는 유지한다. 과거 X좌표 유지 규칙은 이 결정으로 대체한다.
- 사용자 재확인(2026-10-23): 연주 지시의 XML offset·기본 정렬 비교에서도 **섹션 좌측 정렬은 계속 적용한다**. 지시문 정렬의 재검토는 섹션 정렬을 철회한 것이 아니다. 현재 조판기의 기본 출력을 비교한다는 이유로 섹션 좌측 정렬을 빠뜨리지 않는다.
- 오선 제5선 위로 5칸에 해당하는 여유 영역을 사용한다.
- 테두리 상단은 제5선 Y좌표 − 70 SVG 단위로 맞춘다. 선 두께를 포함해 화면 상단에 약 1 SVG 단위 여유가 남는다.
- text와 해당 테두리를 함께 이동한다. VexFlow가 사이에 생성한 빈 path는 건너뛴다.
- 시스템 시작 여부 때문에 표시 높이가 달라지지 않게 한다. 이름이 길어도 텍스트를 잘라 숨기지 않는다.
- 연주 지시의 시작 X좌표는 적용 대상 음표의 머리 중심이다. 섹션과 최소 여백을 확보하지 못하면 같은 줄의 다음 음표들을 음악적 순서대로 확인하여 처음으로 겹치지 않는 음표 위에 놓는다. XML의 적용 마디·박·offset은 그대로 보존하며 표시 위치만 바꾼다. 같은 줄에 자리가 없으면 기준 음표 X를 유지한 별도 높이를 사용한다.
- 과거 v2 제작 시안은 실제 글자/테두리 경계를 기준으로 8 SVG 단위의 최소 여백을 사용했다. 최신 XML offset 탐색은 이 고정 여백을 사용하지 않는다. 섹션·다른 연주 지시·페이지 경계와의 충돌을 확인한다. 이 수치는 조판 초기값이며 음악적 위치가 아니다.

#### 섹션 표제·연주 지시 분리의 승인·적용 이력 (2026-10-23)

- MusicXML 입력 의미는 [매핑 정본](../reference/score/notation.md#score-musicxml-osmd-mapping--섹션-표제와-연주-지시)에 따라 rehearsal과 별도 words로 구분한다. SVG 충돌을 피하려고 원본의 두 내용을 합쳐 섹션 이름을 바꾸지 않는다.
- 출력에서도 섹션 테두리와 연주 지시를 구분해 읽을 수 있어야 한다. 아래 내용은 v2 시안 당시 구현 기록이다. 당시 좌측 정렬·음표 순차 탐색 원칙을 두 곡의 전체 SVG에 적용했다. 제작용 `tools/score-production/musicxml/common/direction-layout.mjs`의 SVG 후처리이며, 앱의 공통 renderer에 통합된 상태는 아니다.
- [비교할 기존 SVG 목록](../records/archive/rendering-experiments.md#section-direction-layout-review--섹션-표제연주-지시의-svg-공동-검토)은 겹침을 보였던 과거판·당시 합쳐진 판·추가 의미 검토 후보의 이력이다. 이후 분리한 v10과 기존 수록 패키지 반영 상태는 구분하며, 새 제작·교정에는 위 최종 7원칙을 적용한다.

#### 섹션 표제와 연주 지시 — 사용자 결정 2026-10-23

현재 제작·표시 기준은 [섹션·연주 지시 7가지 최종 원칙](../reference/score/rendering.md#svg-score-rules--4-구간-시작-표시)이다. 원본의 섹션 이름·순서·적용 마디만 인코딩하고, 제작자의 해석으로 임의 표제를 추가하지 않는다. 기존에 추가한 표제는 제거하되 원래 마디·음표는 보존한다.

- 최신 요구: 섹션 위치·정렬도 MusicXML에 명시하고 XML만으로 재생성한다. 마디 시작 기준 위치는 rehearsal의 `default-x`, 텍스트 정렬은 `halign`/`justify`로 기록한다. 표준 속성 존재와 현재 OSMD의 지원 여부를 구분하며, 무시되는 속성을 입력했다는 사실만으로 좌측 정렬 완료라 보고하지 않는다. 테두리 여백과 외곽 기준 정렬은 조판 단계에서 검증한다. SVG만 바꾸거나 곡별 외부 좌표를 정본으로 삼지 않는다.
- 섹션 표제는 MusicXML `direction/direction-type/rehearsal`, 텍스트 연주 지시는 별도 `direction/direction-type/words`로 저장한다. 예: 섹션 `A`와 연주 지시 `Closed H.H →`.
- 같은 마디에 있다는 이유나 SVG 겹침을 피하기 위해 둘을 하나의 rehearsal 문자열로 합치지 않는다. 원본의 섹션 이름·연주 지시·음악적 위치를 각각 보존한다.
- 실제 악기 주법의 전용 MusicXML 인코딩은 아래 확정 범례를 그대로 따른다. 이 절은 텍스트 연주 지시와 섹션 표제의 구분이다.
- 조판 충돌·최소 여백·같은 줄 탐색/높이 분리는 위 최종 7원칙을 따른다. 높이 분리도 words의 relative-y 등으로 XML에 기록하고, 표시 offset을 사용하는 words에는 default-x를 병용하지 않는다. [공동 검토 목록](../records/archive/rendering-experiments.md#section-direction-layout-review--섹션-표제연주-지시의-svg-공동-검토)은 과거 시안이며, 현재 코드/기존 산출물의 충족 상태는 [제작 기록](../records/archive/rendering-experiments.md#section-direction-final-20261023--갑자기붉은-노을-전체-재조판)과 구분한다.
