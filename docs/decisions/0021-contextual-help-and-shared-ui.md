# 공통 UI와 맥락형 도움말로 반복 조작 부담을 줄인다

## Context and Problem Statement

목록·설정·도움말이 중복되고, 페이지 안내와 모달 닫기 방식이 여러 차례 바뀌었다. 원래 결정 시기는 2026-09-21~10-22이며, YAML 날짜는 이번 문서 정리일이다.

## Considered Options

* 별도 목록·페이지 튜토리얼·모달별 도움말 버튼을 유지한다.
* 공통 카탈로그와 UI를 재사용하고 선택한 대상의 설명 하나를 제공한다.

## Decision Outcome

후자를 채택한다. 메인 화면 [?], 모달·팝업 공통 X, 650ms 길게 누르기 설명을 사용한다. 저장 구간의 손 뗀 뒤 유지·삭제는 ADR-0006의 예외다. 두 앱은 공통 목록과 앱별 테마를 사용한다.

### Consequences

사용자 핵심 행동은 도움말 없이 이해되어야 한다. 잠정 문구와 미확인 기기 상태는 확정·검증으로 올리지 않는다. 새 기능·삭제·전송·배포 승인을 추가하지 않는다.

### Confirmation

현행 계약과 실행 절차는 [UX Rule](../reference/product/ux.md#ux-principles--팀-ux-원칙과-맥락형-도움말), [설정](../reference/product/playback.md#settings-playback--설정과-재생-정책), [검수 절차](../how-to/verify.md#ui-review--화면악보재생-검수-절차)에서 확인한다. 아래 당시 검증 수치·실패·미확인은 해당 환경의 기록이며 이번 작업에서 앱·악보 검증을 다시 수행한 결과가 아니다.

#### 통합 악보 화면

설정 > 악보에는 곡 제목·아티스트·마디 수·BPM과 보유 상태 칩을 표시한다. 그 아래의 정사각형 악보 편집 버튼을 누르면 기존 editor-dialog를 화면을 크게 채우는 별도 모달 레이어로 연다. 새 편집창을 만들지 않는다. 닫으면 아래의 설정으로 돌아간다.

별도 상단 공통영역은 두지 않는다. 파일 보유 칩은 최상단 편집 제목 우측에 표시한다. 곡 제목·아티스트·BPM은 곡 정보의 기존 입력값으로만 표시하고, 마디 수는 곡 정보에 읽기 전용으로 표시한다.
최상단 제목/닫기와 같은 바에서 곡 정보, 악보 편집, 가사, 파일을 글자 탭으로 전환한다.
각 탭은 파랑/빨강/초록/노랑 색으로 구분하고 내용 배경도 같은 계열로 표시한다.
탭에는 한국어 i18n 이름과 접근성 이름을 제공한다. 선택된 탭은 높게 올라오고 같은 색의 본문과 이어진다.

모달은 화면 높이를 넘지 않는다. 큰 창의 본문 영역만 세로 스크롤하며 탭별 위치를 기억한다.
탭 이동은 입력 폼을 재생성하지 않는다. 기존 편집 세션의 임시저장/저장/되돌리기/종료 확인을 공유한다.
전체 악보 보기와 업로드·내보내기는 별도 대화상자로 열고 닫으면 원래 탭으로 돌아온다.
파일 탭의 현재 곡 악보 추가·교체는 한 항목이며, 새 곡 추가는 보관함에 둔다.

##### 목적과 적용 범위

반복 사용의 수고를 줄이고, 행동의 결과를 예측할 수 있게 만든다. 드럼연습실과 악보제작기의 화면 설계·구현·리뷰에 적용한다.

악보 선택 목록은 두 앱의 공통 카탈로그를 사용한다(2026-10-21). 제작기에도 기본 연습곡과 내 악보를 모두 표시한다. 저장 전에는 ‘악보 불러오기’, 저장 후에는 ‘편집 열기’로 연결하며, 다운로드 뒤에는 편집창까지 연다. 음원 전용 항목은 연습실에서 관리한다.

두 앱의 목록 카드·즐겨찾기·곡명/가수 배치·간격은 공통 UI를 사용한다(2026-10-21). 드럼연습실은 블루, 악보제작기는 오렌지 테마로 구분한다. 앱별 CSS 색상 변수로 제목 바·주요 버튼·선택 상태·배경만 바꾸고, 악보의 마커·반복 구간 등 의미 색상은 유지한다. 제작기의 새 악보 만들기는 목록 상단에 둔다. ‘내 악보 목록’은 재생을 멈추고 작업 내용을 저장한 뒤 이 공통 홈으로 돌아간다. 중복 목록 팝업을 만들지 않는다.

‘깔끔함’은 구별이 선명하고, 공간을 효율적으로 쓰며, 눌렀을 때 결과를 예상할 수 있는 화면을 뜻한다. 흐릿한 색이나 넓은 여백 자체를 목표로 삼지 않는다. 첫인상보다 실제 반복 사용 중 수고와 혼란 감소를 우선한다.

| 원칙 | 적용 지침과 사례 |
| --- | --- |
| 조작 단계 최소화 | 자주 쓰는 기능은 직접 접근하게 한다. 드문 기능까지 모두 노출하지 않으며, 백업 관리처럼 빈도가 낮은 기능은 우선순위를 낮춘다. |
| 불필요한 인지·판단 부담 감소 | 사용자의 행동에 도움이 되지 않으면서 주의를 끌거나 해석·선택을 요구하는 정보는 제거한다. 버튼명을 되풀이하는 설명, 중복 제목·정보, 불필요한 상태 문구를 줄인다. 정보 삭제보다 부담 감소가 목표이므로, 삭제·교체의 결과나 복구 방법처럼 판단에 필요한 정보는 제공한다. |
| 관련 기능 그룹화 | 재생1바·재생2바를 재생바 그룹으로 묶고, 곡 관리 기능은 편집창의 탭으로 묶는다. 작업 흐름을 기준으로 배치한다. |
| 모양으로 관계 표현 | 선택된 탭과 본문은 시각적으로 이어지게 한다. 영역은 색으로 구분하되 색만으로 상태를 전달하지 않는다. 모든 요소를 동시에 강조하지 않는다. |
| 목적에 맞는 아이콘과 글자 | 재생·닫기처럼 익숙한 행동은 픽토그램, 탭처럼 이름이 더 명확한 곳은 글자를 쓴다. 아이콘 사용을 강제하지 않는다. |
| iPad 터치 최적화 | 충분한 터치 영역과 자연스러운 스크롤을 제공한다. 조작 중 화면이 갑자기 이동하거나 재정렬되지 않게 한다. |
| 상태 기반 노출과 위치 안정성 | 가사가 없으면 업로드, 곡이 없으면 목록·추가처럼 현재 가능한 행동을 제시한다. 상태 변화로 조작 위치가 갑자기 바뀌지 않게 한다. 기능을 알려둘 필요가 있지만 일시적으로 실행할 수 없다면 비활성과 짧은 이유 표시를 검토한다. |
| 기존 동작 재사용 | 이미 있는 창·기능과 동작 경로를 활용한다. 같은 기능으로 가는 중복 메뉴를 줄이고, 필요한 진입점에서는 동일한 기존 동작을 연결한다. |

###### 잠정 유지하는 표현

**“표현은 목적에 맞게, 동작은 일관되게.”**

아이콘과 글자의 선택은 목적에 맞게 달라도 된다. 같은 의미의 조작이 화면마다 예상 밖의 다른 결과를 내서는 안 된다. 이 문구는 최종 표현으로 확정하지 않고 실제 사례를 보며 다듬는다.

###### 동작과 구성

- 진입점은 메인 화면 제목줄의 공통 `[?]`로 유지한다. 모든 모달·팝업에는 `[?]` 없이 공통 닫기 `×`만 둔다. 모달·팝업 안의 설명은 버튼을 길게 누르고 있는 동안 말풍선으로 제공한다.
- 현재 활성 화면과 상태를 기준으로 관련 도움말을 선택한다. 아래에 가려진 재생 화면보다 현재 편집창 등 사용 중인 화면을 우선한다.
- 실제 버튼 위치를 기준으로 설명을 배치하는 반투명 오버레이를 사용한다. 고정 스크린샷으로 위치를 대신하지 않는다. 회전·해상도·번역에 따라 위치를 갱신한다.
- 도움말을 열면 공통 명칭표의 컴포넌트 이름을 해당 영역의 테두리 위에 표시한다. 버튼을 선택하면 영역 이름을 숨기고 버튼의 명칭(종류)과 설명을 표시한다. 숫자·곡 구간명 등 현재 값만으로 버튼 명칭을 대신하지 않는다. 빈 곳을 누르면 영역 이름으로 돌아간다. 평소 화면에는 영역 테두리를 추가하지 않는다(2026-10-21).
- **페이지를 나누지 않는다.** 하단 안내 하나를 두고, 실제 버튼을 가리키거나 선택하거나 키보드 포커스를 옮기면 해당 말풍선 하나만 표시한다.
- 평소에도 모든 버튼을650ms 이상 길게 누르고 있는 동안 말풍선을 표시한다. 떼거나 스크롤·드래그·취소하면 숨긴다. 저장 반복 구간은 삭제 버튼 조작을 위해 손을 떼어도 유지하는 예외다(2026-10-22). 동적으로 추가된 버튼에도 공통으로 적용한다.
- 사용 환경에 맞춰 터치 조작 또는 키보드 단축키를 안내한다. 현재 화면과 무관한 내용을 채워 넣지 않는다.
- `×` 또는 Esc로 닫는다. 도움말을 보는 동안 실제 기능 실행을 차단하되 스크롤과 버튼 포커스 이동은 허용하고, 닫으면 원래 작업 위치와 키보드 포커스로 돌아간다.
- 도움말 문구는 공통 i18n 정의를 사용한다. 색상 외의 구분, 읽을 수 있는 대비, 접근 가능한 이름과 키보드 이동을 함께 제공한다.
