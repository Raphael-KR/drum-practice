# 연습 배치는 native 비율과 보기별 간격 정책을 사용한다

## Context and Problem Statement

2026-10-03~04에 두 줄 음표 크기·높이·확대 기준과 균등 모드를 여러 차례 정정했다. 초안의 50% 기준·높이에 맞춘 폭 축소·가변 줄바꿈을 최종 기준과 구분해야 한다.

## Considered Options

* 인쇄 마디를 셀에 비균등 확대하거나 남은 높이에 맞춰 폭을 줄인다.
* native 종횡비와 폭 기준 높이를 유지하고 row/grid를 구분한다.

## Decision Outcome

후자를 채택한다. 확대 중앙은100%, 한 줄 확대 범위는50~300%다. 일반 row와 고정 폭 grid를 구분하며 현재 두 줄은4마디다. 세부값은 규칙 §8을 따른다.

### Consequences

50%에16박을 맞추던 초안, 두 줄에서 한 줄 자산을 무조건 재사용하던 v10, 서랍 높이에 맞춘 폭 축소, 균등 모드의 가변 줄바꿈은 대체된 결정이다. 아래 원문은 적용 순서를 보존한다.

### Confirmation

현재 기준은 [SVG 규칙](../reference/score/rendering.md#svg-score-rules--svg-전체-악보-생성-규칙)을 따른다. 아래 검증·버전·수치는 당시 기록이며 이번 문서 이관에서 시험을 재실행한 결과가 아니다.

## More Information

아래는 분리 전 혼합 문서에서 옮긴 원문이다. 원문의 날짜·버전 순서와 위 Decision Outcome을 함께 읽는다. 과거의 ‘현재’, ‘미구현’, 초안 수치와 PASS는 당시 범위에만 적용한다.

### 8. 연습 화면 전용 배치

- 전체 페이지 SVG와 마디별 연습 화면을 구별한다. 전체 페이지에 연습 화면 크기/배경/버튼을 굽지 않는다.
- 두 줄 재생 보기의 최종 사용자 기준(2026-10-03): 각 행은 4마디로 표기한다. 원본 줄별 마디 구성을 따르는 것은 전체 SVG 출력이며 두 줄 재생 배치에 적용하지 않는다. 가로 틈0, 상단·행 사이·하단 여백28 CSS px.
- MusicXML 음표 크기는 마디 너비×0.52를100~180px로 제한한 budget으로 계산한다. 오선 간격은 budget/15과 마디 너비/25 중 작은 값이다.
- crop 높이는 오선 간격×15, 제5선은 crop 상단에서7칸 아래. 가사는 crop 아래6px에 배치한다.
- 공통 행 높이는 실제 최대 crop 높이+가사 영역30px. stage 높이는 두 행+28px 여백3개다.
- 마지막 행이 4마디 미만이면 남은 칸을 빈 칸으로 유지한다. 다음 행의 마디가 빈 칸으로 당겨져 올라오지 않게 하며, 정지 시 행 위치 판정에도 빈 칸을 포함한다.
- 재생·정지 모두 같은 음표 배율·행 높이·간격을 사용한다. 정지 상태에서 전체 악보 상하 스크롤을 허용한다.
- 한 줄 보기와 비교 검수 화면의 개별 레이아웃은 전체 SVG 파일의 형상을 변경하지 않는다.

#### 2026-09-21 캡처 검수 보정

- 한 줄 보기에서도 마디 crop 높이가 아닌 오선 간격을 기준으로 배율을 정한다. 온마디쉼표에서 일반 음표 마디로 넘어가도 오선 높이와 간격이 이어진다.
- 연습 화면 공통 프레임은 오선 간격 15개 높이이며 제5선 위에 7개 간격을 확보한다. 구간 표시는 음표 연결선 위에 배치한다.
- 전체 SVG 모달의 고정 헤더 위로 스크롤된 악보가 비치지 않게 가린다. 정지 두 줄 보기의 아래쪽 여백에는 다음 줄 마디 번호가 비치지 않게 한다.

#### 한 줄 보기의 좁은 마디 배율 (2026-10-03)

- 한 줄 보기에서는 마디 폭과 무관하게 오선 간격과 세로 기준선을 유지한다. 짧은 마지막 마디·온쉼표 마디 때문에 세로로 축소하지 않는다.
- 고정 셀 폭에 따른 높이 제한은 두 줄 보기에만 적용한다. 원본 SVG·MusicXML과 전체 악보 조판은 변경하지 않는다.
- 회귀 검증에는 곡의 끝까지 모든 마디의 표시 오선 간격과 기준선 대조를 포함한다.

### SVG 한 줄 보기의 시간 비례 배치 — 2026-10-03 승인·구현

- SVG 한 줄 재생 보기에서는 **같은 4분음표 시간 = 같은 가로 거리**다. 8분·16분·셋잇단음표는 음악적 길이의 비율대로 배치한다. 5/4 마디의 폭은 4/4의 5/4배다.
- 곡 전체의 가장 조밀한 음표·꾸밈음·기호가 들어갈 공통 박 간격을 구한다. 한 마디만 늘리지 않는다. BPM/연습 속도는 시간당 이동량만 바꾸며 악보 너비는 바꾸지 않는다.
- VexFlow tick context를 native 조판 단계에서 이동한다. 음표·오선 이미지를 가로로 압축하지 않는다. 빔·붙임줄·꾸밈음의 조판은 렌더러를 사용한다. 꾸밈음은 본음 앞에 붙으며 시간 축을 늘리지 않는다. 온마디 쉼표는 마디 중앙을 유지한다.
- 재생 전용 캐시는 전체 SVG 첫 페이지의 비표시 `metadata[data-ribbon-timeline]`에 저장한다. 원본 MusicXML/PDF와 전체 SVG의 인쇄 배치, 두 줄 보기의 4마디 구성은 별도 규칙 그대로다. 재생용 캐시의 내부 페이지 나눔은 원본 페이지 나눔이 아니다.
- 공통 `preparePlaybackAssets`와 `playback-screen`이 악보제작기·드럼연습실에서 같은 캐시/동작을 사용한다. player에 OSMD를 추가하지 않는다. 제작앱이 캐시를 생성하며 이전 캐시는 제작앱에서 열 때 갱신한다. 캐시가 없는 기존 완성 파일은 기존 표시를 유지하며 새 기능 적용에는 제작앱에서 재저장이 필요하다.
- SVG `viewBox`와 렌더러의 오선 좌표를 사용한다. 이미지 naturalHeight 정수 반올림이나 픽셀 검출 오차를 박 간격에 전파하지 않는다.

### 한 줄 보기의 읽기 편한 밀도·이동 (2026-10-03 사용자 승인)

목적은 악보를 쫓는 반응 게임이 아니라 다음 연주를 미리 준비하는 드럼 연습이다. 동일 음가·동일 거리만으로 사용성 통과를 판정하지 않는다.

- 음표와 오선은 읽을 수 있는 크기를 유지하고, 불필요한 가로 간격을 줄인다. SVG 전체를 가로 압축하거나 글리프까지 축소하는 방식으로 해결하지 않는다.
- 진행선 앞에 여러 마디가 보여 다음 연주를 준비할 여유를 제공한다.
- 동일 표시 조건에서 동일 음가는 동일 거리다. BPM/연습 배속은 이동 속도만 변경하며 음표 간격을 자동 변경하지 않는다.
- 빠른 곡에서 불필요한 여백 때문에 이동이 과도하게 빨라지지 않게 한다. 음원과 어긋나도록 스크롤 속도만 제한하지 않는다.
- 확대율·회전·보기 전환 시 연습 위치와 반복 구간을 보존한다. 재생 도중 마디별 밀도를 자동 변경하지 않는다.
- 기존의 ‘곡 전체 최대 필요 간격’ 방식은 충돌 방지 수단이지 사용성 목표가 아니다. 이 방식 때문에 밀도 기준을 충족하지 못하면 원인을 개선해야 하며, 곡 전체를 계속 늘려 해결됐다고 판단하지 않는다.

정량화 후보·계산식·검증 계획은 [한 줄 가독성 정량 검토](../product/RIBBON-READABILITY.md)를 따른다. 원칙은 승인됐으나 수치 후보는 사용자 검토/실행 검증 전이며 아직 코드에 적용하지 않았다. 두 줄4마디·인쇄 배치·PDF 보존 규칙은 그대로다.

#### 2026-10-03 구현 기준 확정
사용자 승인: 한 줄 MusicXML 보기에서 악보 크기50%는 표시 영역 전체16개의4분음표(4/4환산4마디)를 기준으로 한다. 다른 크기는50%를 기준으로 선형 확대·축소한다. BPM/배속은 배치에 영향을 주지 않는다. native 글리프의 가로/세로 비율을 동일하게 유지한다. 숫자 충족과 실제 가독성/충돌 검증은 별도로 기록한다. 이전 미확정16박 후보는 이 결정으로 확정한다.

### 두 줄 보기의 음표 비율과 기둥 (2026-10-03, v10 초안·아래 v11로 보완)
- 두 줄 보기에서도 공통 재생용 원생 조판을 사용한다. 인쇄 마디를 각 셀에 맞춰 가로로 늘이거나 누르지 않는다. 한 줄 4개 셀은 유지한다.
- 같은 박자 길이의 곡은 한 줄용 조판 자산을 재사용한다. 박자 길이가 섞이면 가장 긴 마디를 기준으로 같은 원생 마디 너비를 확보하고, 짧은 마디의 음표 간격을 조판 단계에서 재배치한다. 음표/기둥/기호의 도형을 변형하지 않는다.
- 화면 배치는 원생 페이지 종횡비대로 동일 배율을 두 축에 적용한다. 음표 강조도 같은 조판 좌표를 사용한다.
- 기둥은 EngravingRules.StemWidth=0.1(원생 SVG 1단위, 기존 1.5단위)로 한다. 보통 머리 너비 약12단위 대비 약8%이다. 머리·꼬리 도형은 유지하며 오선·연결선을 일괄 가늘게 만들지 않는다.
- 파생 캐시 정책 v10-uniform-rows-stems. 원본 XML/PDF 및 인쇄 페이지·줄별 마디 구성은 보존한다.
- 전곡 동일 음표 크기와 4마디를 함께 유지하므로 밀집 음형이 있는 곡의 음표는 작아질 수 있다. 읽기 편한 최소 크기를 무조건 충족한다고 보증하지 않는다.

### 두 줄 가독성 보완 v11 (2026-10-03)
- v10의 한 줄 조판 자산 재사용은 균등 배율은 보장했으나, 짧은 음가 하나 때문에 전곡 음표가 지나치게 작아졌다. 두 줄용 간격 조판을 별도로 생성한다. 공통 조판 엔진과 음표 도형은 그대로 공유한다.
- 원생 마디 너비는 최소320단위이며, 전곡에서 필요한 머리·주법·장식음 간격 합계보다 작지 않게 한다. 각 마디에서 필요한 최소 간격을 먼저 확보하고 남는 폭을 음가에 따라 배분한다. 이 시간 비선형 간격은 두 줄 보기에만 적용한다. 재생선은 해당 조판의 beatXs를 따른다.
- 한 줄 보기는 종전대로 같은 음가 같은 거리, 50%에16분음표가 아닌16개의4분음표(4/4 네 마디) 기준을 유지한다.
- 악보 크기 슬라이더는 실제50~200% 범위이고 중간 위치는50%가 아니다. 현재 수치를 output으로 항상 표시한다. 저장된 배율을 임의로 초기화하지 않는다.
- 홈 본문18px·곡 제목20px. 재생 화면 전체 글꼴에 영향을 주는 전역 변경은 하지 않는다.

### 배율 중앙 기준 정정 (2026-10-03 사용자 최신 결정)
- 앞선 '50%'는 배율50%가 아니라 슬라이더 이동 구간의 중앙이라는 사용자 정정에 따른다. 기존50% 기준은 폐기하고, 중앙=100%에서 한 줄 전체에4/4 약4마디(16quarter)가 보이게 한다.
- 기존 배율 범위50~200%는 유지한다. 눈금은50/75/100/150/200%, 중앙100%. 좌우 구간의 변환율은 다르며 표기된 배율이 실제 확대 배율이다.
- 현재 퍼센트와 눈금을 함께 표시. 포인터 드래그는 눈금에서 슬라이더 구간3% 이내이면 흡착하고, 밖으로 움직이면 해제. 키보드 미세조정에는 흡착을 적용하지 않는다.
- 화면 크기·BPM·배속 및 두 줄 보기 조판에는 영향을 주지 않는다. 이는 화면 확대 기준 변경이므로 MusicXML조판 캐시를 다시 생성할 필요가 없다.

#### 2026-10-04 서랍과 두 줄 악보 높이 (이전 방식; 아래 폭 기준 정책으로 대체)
- 하단 서랍이 열린 iPad 가로 화면에서 악보가 잘리지 않도록 남은 stage 높이에 맞춰 공통 마디 폭을 축소한다. SVG 종횡비는 유지하고 줄은 가운데에 배치한다.
- 렌더링·가사·히트 영역에 같은 마디 폭을 전달한다. 정지 중 세로 탐색은 유지한다. 음표 표준이나 원본 악보 데이터는 변경하지 않는다.
- 서랍이 닫혀도 공간을 확보하므로 악보 높이와 배율은 그대로다. 두 줄 모드에서는 정지 중에도 두 행이 화면 높이를 나눠 사용한다. 상하 탐색은 유지하되 스크롤 종료 시 행 경계에 맞추고, 화면 폭 변경 시 현재 마디 행으로 다시 정렬한다.

### 두 줄 재생 영역 여백 (2026-10-04)
두 줄 맞춤 계산은 상단 마디 표시28px와 줄 사이28px, 각 줄 가사30px를 확보한다. 하단에 추가28px 빈 공간을 예약하지 않는다. 원본 종횡비와 두 줄 제한, 조작판 고정 높이는 유지한다.

두 줄 보기의 UI 마디 구분선은 마디 사이에만 표시한다. 각 줄 네 번째 칸의 오른쪽 테두리는 투명하게 하며, 원본 악보의 세로줄과 선택 강조선에는 적용하지 않는다.

### 두 줄 폭 기준 고정 높이 (2026-10-04)
현재 정책은 악보 영역의 전체 내부 폭을 4마디에 나눠 쓰고, 그 폭에서의 SVG 종횡비로 필요한 두 줄 높이를 먼저 계산하여 고정하는 것이다. 남은 세로 공간 때문에 마디 폭을 축소하지 않는다. 곡 전체에서 필요한 최대 악보 높이를 사용하여 마디 이동에 따른 높이 변화를 막는다. 상단28px·줄 사이28px·각 줄 가사30px와 외곽선2px를 확보한다.
두 줄 모드에서 제목줄 아래 외부 여백은0, 재생바와의 간격은2px로 둔다. 조작판의 기존 고정 높이는 유지한다. 작은 창에서 전체 높이가 부족하면 바깥 영역에서 세로 접근을 허용하며 조작판 내부 스크롤은 만들지 않는다. 한 줄 모드의 배치는 유지한다.

#### 두 줄 보기의 마지막 줄 (2026-10-04)

#### 한 줄 보기 100% 크기 기준 (2026-10-04)

#### 한 줄/두 줄 동일 SVG 사용 (2026-10-04, 위 세로 배율 보정 대체)
세로 크기만 맞추면 별도 시간축 SVG의 가로 압축이 남는다. 두 모드 모두 row SVG 마디 그림을 사용하고 nativePageRatio를 보존하여 균등 확대한다. 한 줄의 마디 폭 계산은 기존 값을 유지하며, 음표 강조 위치 계산은 공유된 그림의 beatXs를 사용한다. 한 줄 진행선은 아래 등속 시간축 규칙을 따른다. 가로·세로 배율을 함께 검증하며 crop 높이만으로 도형 일치를 판정하지 않는다.

#### 균등 모드 최종 정정: 고정 마디·32분 격자 (2026-10-04)
앞선 마디 폭 확장·가변 줄바꿈 정책은 폐기한다. 모든 마디 폭은 같고, 두 줄 보기는 기존 4마디씩 유지한다. 기존 row 조판과 동일한 native rowWidth를 사용해 음표 크기·오선 간격을 유지한다.
- 별도 grid SVG는 고정 좌우 여백 없이 마디 전체 폭에 시간 격자를 둔다. 양 끝은 격자 반 칸씩으로, 음표 중심은 (quarterOffset×8+0.5)×마디폭/격자수에 놓는다. 마디선은 앞마디 마지막 격자와 다음 마디 첫 격자의 정중앙이다. 4/4는32칸이며 quarterOffset×8을 격자 좌표로 삼는다. 음표와 쉼표가 적어도 격자 공간은 유지한다. 셋잇단·더 짧은 음가는 반올림하지 않고 분수 위치를 보존한다.
- 조판 단계에서 tick context의 가로 위치만 변경하고 beam·stem·rest·가사 앵커는 해당 조판 좌표를 사용한다. 도형 가로 압축/세로 확대는 하지 않는다. 전체마디 쉼표는 시간 격자 첫 칸에 배치하지 않고 마디 중앙에 표시한다. VexFlow 쉼표 오프셋으로 crop 밖에 나가지 않도록 렌더 후 중앙 보정을 적용한다.

- 균등 모드 진행선도 같은 격자 식을 사용한다. Region beatXs의 마지막 값은 저장 계약상1로 유지하되, 실제 진행선은 이를 보간하지 않아 마지막 박에서 감속하지 않는다. 같은 박자·템포의 인접 마디 경계에서도 좌표와 속도가 이어진다.

##### 측정 단위와 계산식

모든 화면 거리는 CSS px로 기록한다. Retina 배율/스크린샷 픽셀과 혼용하지 않는다.

- W: 악보 표시 영역의 실제 너비.
- P: 표시 영역 왼쪽에서 진행선까지의 거리.
- Q: 4분음표 하나의 가로 거리.
- B: 4분음표 기준 실효 BPM. 다른 박 단위는 4분음표로 환산하고 연습 배속을 곱한다.
- 화면 박 수 N = W / Q. 4/4 환산 마디 수 = N / 4.
- 진행선 앞의 박 수 A = (W − P) / Q.
- 이동 속도 V = Q × B / 60 (CSS px/초).
- 화면 너비 대비 이동 속도 U = V / W (화면/초).
- 앞으로 읽을 수 있는 시간 T = A × 60 / B (초).

변박에서는 ‘마디 수’ 대신 4분음표 환산 길이로 비교한다. 실제 시간 보정/템포 변화가 있는 곡은 V = Q × 실제 4분음표 진행률로 측정하고, T는 현재 위치부터 오른쪽 경계까지의 실제 타임라인 차이로 계산한다. 명목 BPM 계산을 실제 동기화의 증거로 대신하지 않는다.

##### 사용

곡에 PDF와 MusicXML을 모두 추가한 뒤 **화면 → PDF · MusicXML 검수**를 선택한다. 동일한 마디 ID와 박자표로 두 악보를 연결한다. 위아래 네 마디는 같은 구간이다. 각 악보의 박 위치 좌표에 따라 진행선을 별도로 그린다. 상단에 곡명, 가장 가까운 ¼박 위치와 실제 정지 시각을 표시한다.

재생 중 스페이스를 누르면 즉시 일시정지하고 두 악보를 PNG 한 장으로 복사한다. 다시 스페이스를 누르면 기존 연습 규칙대로 해당 마디 처음부터 재생한다. 키 반복은 무시한다. 입력 중이거나 메뉴가 열려 있으면 전역 스페이스 동작을 실행하지 않는다. 터치 사용자는 **정지·캡처 복사** 버튼을 사용한다. 이미 정지한 위치에서도 이 버튼으로 캡처할 수 있다.

실제 화면과 캡처에 동일한 Canvas 그림을 사용한다. SVG 원본은 SVG 이미지로 디코딩하며, 검수 화면 합성과 PNG 캡처는 화면 크기의 2배 해상도 Canvas에서 수행한다. 일반 연습 화면의 SVG 표시 방식은 유지한다. 정지 시 픽셀을 즉시 별도 canvas에 복제하여 비동기 PNG 생성 중 재생 위치가 달라져도 캡처가 바뀌지 않는다. 클립보드 쓰기는 사용자 키/클릭 이벤트 안에서 PNG Promise를 넘겨 요청한다.

클립보드가 차단되면 성공으로 표시하지 않는다. 같은 캡처를 **캡처 저장**으로 내려받아 대화에 첨부한다. 이전 HTML에 SVG 캐시가 없으면 웹앱에서 검수 모드를 열어 갱신한 뒤 HTML을 다시 저장한다. 기존 PDF 페이지는 재렌더링하지 않는다.

이 모드는 시각 검수 도구이며 음표의 옳고 그름을 자동 판정하지 않는다. PDF 반복기호와 MusicXML에서 펼쳐 그린 마디처럼 의미는 같고 그림이 다른 경우도 있다.
