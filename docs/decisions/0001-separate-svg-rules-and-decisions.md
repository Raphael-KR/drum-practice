# SVG 현행 규칙과 결정 이력을 분리한다

## Context and Problem Statement

현행 규칙과 폐기된 시안·곡별 검증이 한 파일에 누적되어 과거 값을 현재 기준으로 읽을 수 있었다. 사용자가 2026-10-23에 Rule과 결정 이력의 분리를 요청했다.

## Considered Options

* 기존 혼합 문서를 계속 누적한다.
* 기존 규칙 경로를 유지하고 결정별 MADR을 별도 파일에 둔다.

## Decision Outcome

후자를 채택한다. SVG-SCORE-RULES.md는 현재 유효한 규범 문서로 유지하고, 결정은 docs/decisions/NNNN-title-with-dashes.md에 기록한다.

### Consequences

현재 규칙을 읽는 비용을 줄인다. 이미 대체된 결정·원문·검증 근거는 이관 기록에서 보존하며 새 기능이나 정책 승인을 만들어내지 않는다.

### Confirmation

현재 기준은 [SVG 규칙](../reference/score/rendering.md#svg-score-rules--svg-전체-악보-생성-규칙)을 따른다. 아래 검증·버전·수치는 당시 기록이며 이번 문서 이관에서 시험을 재실행한 결과가 아니다.

## More Information

* [MADR 공식 안내](https://adr.github.io/madr/)와 [4.0.0 템플릿](https://github.com/adr/madr/blob/4.0.0/template/adr-template.md)을 따른다. Markdown·일련번호/소문자 하이픈 파일명·YAML 상태/날짜·Context/Options/Outcome/Consequences 구조를 사용한다.
* 문서 관리 방식의 선택이며 별도 ISO 강제 규격을 주장하지 않는다. 전역 지침에는 ADR 파일 형식 지정이 없었다.
* 원래 결정일이 아닌 기록의 마지막 갱신일을 YAML date로 쓴다. 원래 날짜·버전·대체 관계는 각 기록 본문에 남긴다.
* 미래의 실질적 결정 변경은 새 ADR로 기록하고 이전 ADR을 superseded로 연결한다. 이번 최초 이관은 주제별 최종 결정을 accepted로 정리하며 그 안에 포함된 과거 시안을 다시 승인하지 않는다.
* 현행 규칙의 §1~11과 기존 참조 앵커를 유지한다. 코드·악보·산출물·앱 버전·배포는 변경하지 않는다.

### 후속 적용 범위 — 2026-10-23

사용자는 MusicXML 매핑 정본과 정본 계약에도 같은 분리를 명시적으로 요청했다. 두 현행 문서의 경로·규칙·참조 링크를 유지하고 기존 ADR-0003/0004/0007/0009/0011에 해당 근거를 추가했다. 정본 원천·가사·메타정보·음원 템포/박별 연결의 기존 결정은 ADR-0012~0016에 분리한다. 초기 SVG 이관의 문맥·검증 결과를 변경하거나 새 정책 승인을 만들지 않는다.

### 프로젝트 전체로 적용 범위 확장 — 2026-10-23

사용자가 프로젝트 전체 Rule 목록과 혼합 문서의 Rule·실행 절차·MADR 4.0 분리를 요청했다. [전체 목록](../RULES-INDEX.md)을 진입점으로 두고 기존 정본 경로·기존 ADR을 재사용한다. 명령·입력·완료 확인은 실행 절차, 선택 이유·대체 경로는 ADR, 배포·측정·검수의 사실은 records 또는 기존 곡별 기록으로 구분한다. 사실 기록을 새 승인 결정으로 만들지 않는다. 앱 코드와 악보는 이번 정리 범위에서 제외한다.


### Rule 재점검 원문 — DOCUMENTATION-RULES.md / 1

출처: [docs/DOCUMENTATION-RULES.md](../reference/engineering/documentation.md#documentation-rules--프로젝트-문서-관리-rule). 2026-10-23 재점검에서 분리한 변경 전 문구다. 당시 문맥·후보·검증 한계의 보존이며 새 승인이나 새 실행 결과가 아니다. 현행 계약은 출처 Rule을 따른다.

> - 현행 동작을 바꾸면 해당 정본과 `history.md`를 함께 갱신한다. 같은 규칙을 다른 문서에 복제하기보다 정본을 연결한다.
> - 혼합 문서는 현행 요구를 먼저 구분하고 실행 순서·이유·실측을 각 역할로 옮긴다. 곡별 예외나 검토 후보를 승인된 공통 Rule로 승격하지 않는다.
> - 같은 결정은 기존 ADR을 재사용한다. 실제 새 결정이 이전 결정을 대체하면 새 ADR과 대체 링크/상태를 남긴다. 이번 최초 이관은 확인된 기존 결정을 기록하며 새 승인을 만들지 않는다.
> - ADR의 YAML status는 결정 상태, date는 마지막 갱신일이다. 원래 날짜·버전·승인 범위·대체 전 시안은 본문에 보존한다. `accepted`는 구현·모든 기기 검증·배포 완료와 다르다.
> - 원문·식별자·수치·검증 한계와 기존 파일 경로를 보존한다. 옮긴 문단의 기존 앵커는 현행 문서의 대응 내용이나 이관 안내로 유지하고 상대 링크를 새 위치에서 다시 계산한다.
> - 사용자 원본·악보·미디어·Git 제외 자료는 별도 보존 정책을 따른다. 과거 삭제된 증거를 필수 입력으로 안내하거나 존재를 가정하지 않는다. 당시 경로와 삭제/미확인 상태는 기록으로 남긴다.
> - UI 컴포넌트 문서 등 생성물은 정본/생성 스크립트와 일치시킨다. 앱 코드 변경이 금지된 문서 정리에서 생성 코드를 수정해 검사를 우회하지 않는다.

### 주제별 정본과 작업별 절차로 통합 — 2026-10-23

사용자가 [문서 통합 계획](../records/archive/documentation-reorganization.md#documentation-consolidation--프로젝트-문서-구조-통합-실행-계획)에 따른 실행을 요청했다. 최초 분리의 “기존 경로 유지”는 이제 기존 주소 안내를 보존한다는 뜻이며, 현행 본문은 `reference/`의 18개 주제와 루트 AGENTS·PRD로 통합한다. 실행은 `how-to/`, 곡별 사실은 `records/songs/`, 완료 계획·과거 시안은 `records/archive/`로 찾는다. 20개는 주 진입점 수이며 강제 파일 상한이 아니다.

선택지는 기존 분리 문서에 목록만 추가하는 방식과, 주제별 본문을 통합하며 기존 주소를 안내로 남기는 방식이었다. 사용자는 후자를 선택했다. 파일별 반복 탐색을 줄이고 Rule·절차·결정·실측의 역할을 유지한다. 표의 저장 형식·수치·권한·지원 한계와 후보/승인 구분은 바꾸지 않는다.

검사 코드가 읽는 `docs/plans/PLAYBACK-SCREEN-INVENTORY.md`와 생성 UI·범례·폰트 배치 경로는 유지한다. 코드/설정의 기존 참조도 문서 안내를 통해 연결하며 이번 작업에서 소비 코드를 바꾸지 않는다. 기존 27개 ADR의 식별자·상태·원래 날짜·결정 의미와 과거 증거 경로는 보존한다. 이 통합은 앱·악보·런타임·버전·배포 변경 승인이 아니다. 결과는 [문서 기록](../records/documentation.md), 출처는 [이전표](../records/documentation-migration.md)를 따른다.

### 통합 후 이전 주소 안내 정리 — 2026-10-23

사용자가 청소를 요청했고, 이전 주소 안내 98개를 삭제하면 과거 대화 링크가 끊긴다는 설명을 확인한 뒤 “이전 주소 안내 파일도 정리”를 승인했다. 통합 당시 모든 이전 주소를 남기는 방식 대신, 내부 링크와 원문 이전표를 새 목적지로 연결하고 불필요한 안내를 제거한다. 이는 이 문서의 통합 당시 경로 유지 방식을 수정하는 후속 결정이다.

코드·인계 JSON이 참조하는 6개 안내는 소비 코드를 변경하지 않는 범위에 맞춰 유지한다. 나머지 92개 안내와 일회성 이관 스크립트·검색 출력 8개를 정리한다. 통합 전부터 있던 별도 이력 진입점 7개는 이번 98개 대상에 포함하지 않았다. 원문 스냅샷·이전표·검증 근거와 기존 ADR은 보존한다. 과거 대화·외부 링크의 단절은 승인된 결과이며, 내부 문서 링크의 단절은 허용하지 않는다. [실행·검증 기록](../records/documentation.md#이전-주소-안내와-임시파일-정리--2026-10-23)을 따른다.
