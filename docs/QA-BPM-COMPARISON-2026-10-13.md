# BPM 분석기 16곡 비교 (2026-10-13)

- 목표: 현재 구현, Essentia.js, web-audio-beat-detector의 BPM·박 위치·분석 시간을 같은 16개 MP3로 비교한다.
- 범위: 승인된 로컬 음원, 별도 로컬 브라우저 시험 페이지와 격리된 의존성.
- 완료 조건: 16곡 × 3분석기 × 3회 결과와 독립 기준이 있는 곡의 오차를 기록한다.
- 제외: 앱 분석기 교체, 음원 서버 전송, 캐시 변경, 커밋·푸시·배포.
- 검증: 파일 해시 보존, 인쇄 악보 BPM 대조, 기존 2곡의 녹음 기준 격자 대조, 반복 시간 측정.

## 결론

이번 표본에서는 Essentia.js가 가장 유력하다. 악보·기존 설정의 BPM과 ±2% 이내로 일치한 곡은 현재 구현 7/9, Essentia 9/9, web-audio-beat-detector 기본 설정 6/9다. 이는 16곡 전체의 정답률이 아니다. 7곡은 독립 기준이 없으며, 인쇄 악보 BPM도 해당 녹음의 정밀 실측값은 아니다.
Essentia의 박 시각 목록은 기존 두 곡의 기준 격자와 잘 맞았다. 그러나 첫 tick부터 일정 간격을 이어 붙이면 두 곡 모두 시작 위상이 어긋났다. 앱 적용 시 안정 구간 ticks로 BPM과 시작 위상을 함께 추정해야 한다. 첫 tick은 첫 마디의 1박이라는 보장이 없다.

## 조건

- Apple M4 Pro / arm64, macOS, Ego Chromium 152.0.0.0. iPhone·iPad Safari 실측은 아니다.
- Essentia.js 0.1.3 / 내장 Essentia 2.1-beta6-dev, RhythmExtractor2013 multifeature. web-audio-beat-detector 8.2.39의 guess 사용.
- 모든 분석기에 같은 MP3의 첫 90초, 공통 44.1kHz 디코딩을 사용했다. 곡 전체가 90초보다 길다. Essentia의 요구 샘플레이트를 따른다.
- 현재 구현은 실제 앱처럼 스테레오 RMS 에너지로 합성한다. Essentia는 signed mono 평균, web-audio-beat-detector는 라이브러리 자체 전처리를 사용한다.
- 본 비교의 후보 범위는 40–240BPM. 현재 구현의 원래 후보 범위를 유지하고 다른 두 라이브러리에 같은 범위를 설정했다. 알고리즘의 prior까지 같지는 않다.
- web-audio-beat-detector는 범위 영향이 커 기본 90–180BPM에서도 16곡 × 3회를 별도로 측정했다. 곡별 정답을 보고 옵션을 바꾸지 않았다.
- 각 곡을 3회 분석하고 실행 순서를 current→essentia→webAudio, essentia→webAudio→current, webAudio→current→essentia로 바꿨다. 표의 시간은 곡별 중앙값이다.
- 최초 실제 곡으로 워밍업했다. 분석 시간에는 채널 합성·벡터 변환·출력 복사·벡터 해제가 포함되며, MP3 디코딩·파일 읽기·모듈 다운로드/초기화·자동화 도구 왕복은 제외한다.
- 공통 MP3 디코딩/90초 버퍼 준비 중앙값은 201.3ms였다. 전체 파일을 디코딩한 뒤 첫 90초를 분석했다. 브라우저 안에서 관측한 Essentia init 호출은 5ms였으나 번들 로드 중 초기화 시간까지 포함한 cold-start 수치는 아니다.
- 현재 앱의 32kHz 경로도 각 곡 한 번 확인했다. 15곡의 BPM은 공통 조건과 같고 사랑의 바보만 117.7→117.6이었다. 첫 박은 일부 10ms 차이. 주 비교의 시간에는 이 보조 실행을 섞지 않았다.

3회 반복에서 각 파일/분석기의 BPM은 동일했다. 현재 구현보다 Essentia의 중앙 분석 시간은 약 90배 길지만, 이 Mac에서는 90초 음원을 약 1.82초에 처리했다. 모바일 소요 시간으로 환산하지 않는다.
현재 구현은 혼자가 아닌 나를 80BPM으로 잡아 악보 120과 크게 달랐다. WAB 기본 설정은 흰수염고래 177.10(악보 88), Loveholic 90.77(악보 136), 붉은 노을 92.17(악보 134)로 다른 주기를 선택했다. 공통 범위에서는 여러 곡이 1/2 또는 다른 세분 주기로 내려갔다.
붉은 노을의 134BPM 악보는 Lv2 편곡본이므로 해당 녹음과의 정확한 일치가 확인되지 않았다. 이 곡을 제외하면 현재 7/8, Essentia 8/8, WAB 기본 6/8이다. Essentia가 134에 가까웠다는 사실만으로 해당 녹음에서 더 정확하다고 단정하지 않는다.

## 박 위치 비교

엄밀한 수작업 beat annotation이 없어 아래는 **기존 앱 격자와의 일치도**다. 음악적 정답률로 부르지 않는다. 바람과 언덕의 발라드: 94BPM / 0.388971초, Loveholic: 녹음 추정 136.232BPM / 0.193초. 후자는 소스에도 청취 검증 전 신호 분석 추정이라고 표시되어 있다. 앞선 ID3 변경 전 MP3 해시와 패키지 해시가 일치하고 오디오 데이터는 보존되었다.
5–85초 구간에서 기준 박과 예측 박을 ±70ms 이내 1:1로 대응시켜 precision/recall의 F1을 계산했다. 현재/WAB는 BPM+offset의 고정 격자, Essentia는 실제 ticks와 첫 tick 기반 고정 격자를 별도 평가했다. nearest 오차는 예측 박에서 가장 가까운 기준 박까지의 거리다. 반 속도 결과는 nearest 오차가 작아도 recall이 낮을 수 있다.

| 곡 | 출력 방식 | ±70ms F1 | nearest 오차 중앙값 |
|---|---|---:|---:|
| 風と丘のバラード | 현재 고정 격자 | 100.0% | 21.4ms |
| 風と丘のバラード | Essentia ticks | 100.0% | 27.7ms |
| 風と丘のバラード | WAB 공통 고정 격자 | 0.0% | 303.2ms |
| 風と丘のバラード | WAB 기본 고정 격자 | 0.0% | 303.0ms |
| 風と丘のバラード | Essentia 첫 tick 기반 고정 격자 | 0.0% | 193.3ms |
| Loveholic | 현재 고정 격자 | 82.4% | 38.1ms |
| Loveholic | Essentia ticks | 100.0% | 18.3ms |
| Loveholic | WAB 공통 고정 격자 | 66.7% | 19.7ms |
| Loveholic | WAB 기본 고정 격자 | 0.0% | 110.0ms |
| Loveholic | Essentia 첫 tick 기반 고정 격자 | 0.0% | 166.4ms |

Essentia ticks는 두 곡 모두 이 격자 기준에서 F1 100%였다. 반면 첫 tick 기반 고정 격자는 두 곡 모두 F1 0%였고, 중앙 위상 오차는 약 193ms/166ms였다. 반환 첫 tick을 그대로 firstBeat로 저장하는 단순 교체는 부적절하다.
이번 호출의 세 분석기 모두 3/4·4/4 박자표 또는 마디 첫 박(downbeat)을 판별하지 않는다. BPM·박 간격이 맞는 것과 마디 시작이 맞는 것은 별개다. 앱은 현재 4/4를 기본값으로 저장하므로 변박곡 검증은 별도다.

## 권고와 한계

1. Essentia를 차기 분석기 후보로 선택한다. 본 표본에서 큰 BPM 오류를 줄였고 ticks를 얻을 수 있다. 라이선스/번들 크기/모바일 메모리와 실기기 시간 확인 후 도입 여부를 확정한다.
2. 도입 시험은 Web Worker에서 수행하고, 안정적인 ticks 구간으로 고정 메트로놈의 BPM·위상을 함께 맞춘다. 첫 tick을 첫 마디로 간주하지 않는다. 이 후처리는 이번 벤치마크에 넣지 않았다.
3. BPM 정답 기준이 없는 7곡과 첫 박 기준이 없는 14곡은 청취·탭 또는 별도 정밀 주석이 필요하다. 세 분석기 일치만으로 정확하다고 판정하지 않았다.
4. 첫 90초만 분석했으므로 곡 후반 템포 변화·전체 길이 누적 오차·변박 추종은 검증하지 않았다. 별도 BPM과 위상 기준이 없는 곡의 박 정확도 수치는 만들지 않았다.
5. 파일 전체 SHA-256 16개가 ID3 업데이트 직후 기록과 모두 일치했다. 원본 파일·앱 코드·실제 사용자 데이터·공개 캐시는 변경하지 않았다. 루트 package.json/lock에도 의존성을 추가하지 않았다.
6. 합성 클릭 워밍업에서는 WAB가 detectable beats 없음 오류를 냈다. 실제 MP3 워밍업과 192회 본/기본범위 분석에서는 오류가 없었다. 순수 클릭 신호 실패를 실제 16곡 실패로 집계하지 않았다.
