# 악보 관리 승인 목업 구현 검증 — 2026-09-20

정본: [SCORE-MANAGEMENT-PLAN.md](SCORE-MANAGEMENT-PLAN.md). 로컬 개발 앱 `http://127.0.0.1:5173/`, Safari MCP. 실제 자료 `real-paradis`를 복제한 `management-qa`에서 변경 수행. 원본 곡은 편집하지 않았다.

## 검증 결과

- 설정 > 악보: 요약 + MusicXML/PDF/가사/음원 상태 칩 + 편집/파일. 홈에서 곡 미선택은 비활성화.
- 파일: 승인 명칭 및 동일 행 간격, 내보내기 우측 화살표 없음. 실제 화면 확인.
- 편집 3탭, 마디 탐색만 한 뒤 닫기: 저장 확인 없이 원래 설정 복귀.
- 제목 입력 중 IndexedDB: 확정 제목 유지, 별도 초안 폼에 입력값 저장. 닫기 저장 확인 후 저장: 초안 제거, 이전 저장본 생성. 버리기: 확정 제목 보존.
- 새로고침 후 초안 이어서 편집 확인: 입력 중이던 제목 복원 및 저장 성공.
- 이전 저장본 복원, undo, redo: 각각 기대 제목으로 돌아옴. 실제 Safari 확인.
- 다중 내보내기: MusicXML/PDF/HTML 3개 선택 → ZIP 파일 3개 확인. HTML의 draft/revisions/lyricArchive 없음.
- 내보낸 HTML을 Safari iframe에서 실행: 곡 로드 성공, 곡 선택·악보 설정·편집 숨김 확인. 별도 파일 앱에서의 실행은 확인하지 않음.
- 전체 백업 실제 버튼: 전체 2곡, ID 2개, QA 저장 이력 3개 복호화 확인. QA 곡만 포함한 백업을 파일 입력으로 복원하고 ID 충돌 확인 후 실행.
- 저장소: 일괄 복원 중 한 미디어 읽기 실패 시 기존 곡 보존, 연속 저장 순서 보존 자동 테스트.
- 51개 테스트 파일 / 207개 테스트 통과, TypeScript 및 프로덕션/portable 빌드 통과. 기존 대형 번들 경고 유지. 마지막 제목 표시 보정 후 집중 29테스트와 빌드도 재통과.

## 증거 및 범위

실험 출력은 로컬 `docs/experiments/management-*`에 보존하고 Git에서는 제외한다. Safari 화면 캡처와 함수/DOM·IndexedDB 상태를 함께 확인했다. 화면 폭 744px에서 내보내기 창의 가로 넘침 없음. Safari 창 높이는 666px로 제한되어 실제 744×1133 세로 iPad 검증으로 간주하지 않는다. 실물 iPad의 파일 선택·다운로드 및 메모리 제한은 미검증.

저장 이력은 편집 데이터의 최근 10개이다. 교체 전 다른 파일명을 참조하는 저장본은 현재 미디어와 섞어 적용하지 않고 전체 백업 복원을 안내한다. 대형 전체 백업 ZIP은 메모리에서 생성한다.
