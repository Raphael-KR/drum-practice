# 팀 UX 원칙과 맥락형 도움말 설계 지침

합의일: 2026-09-21. 상태: 사용자 승인 기준. 문구 하나는 아래와 같이 잠정 유지한다.

## 목적과 적용 범위

반복 사용의 수고를 줄이고, 행동의 결과를 예측할 수 있게 만든다. 드럼 연습실의 화면 설계·구현·리뷰에 적용하며, 내보내기 HTML에도 해당 기능 범위에서 같은 원칙을 적용한다.

‘깔끔함’은 구별이 선명하고, 공간을 효율적으로 쓰며, 눌렀을 때 결과를 예상할 수 있는 화면을 뜻한다. 흐릿한 색이나 넓은 여백 자체를 목표로 삼지 않는다. 첫인상보다 실제 반복 사용 중 수고와 혼란 감소를 우선한다.

## 선호 원칙 8가지

| 원칙 | 적용 지침과 사례 |
| --- | --- |
| 조작 단계 최소화 | 자주 쓰는 기능은 직접 접근하게 한다. 드문 기능까지 모두 노출하지 않으며, 백업 관리처럼 빈도가 낮은 기능은 우선순위를 낮춘다. |
| 불필요한 인지·판단 부담 감소 | 사용자의 행동에 도움이 되지 않으면서 주의를 끌거나 해석·선택을 요구하는 정보는 제거한다. 버튼명을 되풀이하는 설명, 중복 제목·정보, 불필요한 상태 문구를 줄인다. 정보 삭제보다 부담 감소가 목표이므로, 삭제·교체의 결과나 복구 방법처럼 판단에 필요한 정보는 제공한다. |
| 관련 기능 그룹화 | 재생1바·재생2바를 재생바 그룹으로 묶고, 곡 관리 기능은 편집창의 탭으로 묶는다. 작업 흐름을 기준으로 배치한다. |
| 모양으로 관계 표현 | 선택된 탭과 본문은 시각적으로 이어지게 한다. 영역은 색으로 구분하되 색만으로 상태를 전달하지 않는다. 모든 요소를 동시에 강조하지 않는다. |
| 목적에 맞는 아이콘과 글자 | 재생·닫기처럼 익숙한 행동은 픽토그램, 탭처럼 이름이 더 명확한 곳은 글자를 쓴다. 아이콘 사용을 강제하지 않는다. |
| iPad 터치 최적화 | 충분한 터치 영역과 자연스러운 스크롤을 제공한다. 조작 중 화면이 갑자기 이동하거나 재정렬되지 않게 한다. |
| 상태 기반 노출과 위치 안정성 | 가사가 없으면 업로드, 곡이 없으면 목록·추가처럼 현재 가능한 행동을 제시한다. 상태 변화로 조작 위치가 갑자기 바뀌지 않게 한다. 기능을 알려둘 필요가 있지만 일시적으로 실행할 수 없다면 비활성과 짧은 이유 표시를 검토한다. |
| 기존 동작 재사용 | 이미 있는 창·기능과 동작 경로를 활용한다. 같은 기능으로 가는 중복 메뉴를 줄이고, 필요한 진입점에서는 동일한 기존 동작을 연결한다. |

### 잠정 유지하는 표현

**“표현은 목적에 맞게, 동작은 일관되게.”**

아이콘과 글자의 선택은 목적에 맞게 달라도 된다. 같은 의미의 조작이 화면마다 예상 밖의 다른 결과를 내서는 안 된다. 이 문구는 최종 표현으로 확정하지 않고 실제 사례를 보며 다듬는다.

## 설계와 리뷰의 태도

실제 불편에서 출발한다. 작은 정지 버튼, 깊은 메뉴, 갑자기 움직이는 악보처럼 연습을 방해하는 요소를 우선 해결한다. 형식을 고집하기보다 작업 목적과 화면 사이의 관계를 살핀다.

취향을 희석하는 대신 간결함이 정보 부족으로, 직접 접근이 화면 복잡함으로 넘어가는 경계를 검토한다. 사용자 지시라도 사용성·접근성에 불리한 결과가 예상되면 구체적인 이유와 대안을 제시한다. 제작자에게 익숙한 화면이 초행자에게도 명확한지는 별도로 검수한다.

## 적용 사례: [?] 맥락형 도움말

### 역할

필요한 사람이 필요한 순간에 여는 보완 수단이다. 강제로 진행하는 튜토리얼로 만들지 않는다. 핵심 행동은 도움말 없이 이해되도록 기본 화면을 설계하고, 도움말에서도 당연한 조작을 반복 설명하지 않는다.

온보딩은 첫 곡 열기·재생·구간 반복 등 첫 사용의 성공 과정 전체를 포함한다. 이 기능의 명칭은 온보딩 슬라이더가 아니라 **맥락형 도움말**이다.

### 동작과 구성

- 진입점은 모든 화면에서 우하단의 `[?]`로 유지한다. 전체화면과 편집 모달에서도 접근할 수 있어야 하며, 주요 조작이나 콘텐츠를 가리지 않게 한다.
- 현재 활성 화면과 상태를 기준으로 관련 도움말을 선택한다. 아래에 가려진 재생 화면보다 현재 편집창 등 사용 중인 화면을 우선한다.
- 실제 버튼 위치를 기준으로 설명을 배치하는 반투명 오버레이를 사용한다. 고정 스크린샷으로 위치를 대신하지 않는다. 회전·해상도·번역에 따라 위치를 갱신한다.
- **한 페이지가 기본이다.** 화면 설명과 필요한 조작·단축키를 함께 담는다. 읽기 좋은 크기와 간격으로 담기 어려울 때만 페이지 수를 늘린다. 한 페이지에 억지로 맞추려고 글자를 작게 만들지 않는다.
- 여러 페이지일 때 좌우 스와이프와 점·화살표로 이동한다. 마우스와 키보드로도 조작할 수 있어야 한다. 한 페이지일 때 불필요한 페이지 이동 장치를 표시하지 않는다.
- 사용 환경에 맞춰 터치 조작 또는 키보드 단축키를 안내한다. 현재 화면과 무관한 내용을 채워 넣지 않는다.
- `×` 또는 Esc로 닫는다. 도움말을 보는 동안 배경 조작을 차단하고, 닫으면 원래 작업 위치와 키보드 포커스로 돌아간다.
- 도움말 문구는 공통 i18n 정의를 사용한다. 색상 외의 구분, 읽을 수 있는 대비, 접근 가능한 이름과 키보드 이동을 함께 제공한다.

### 설계의 이유

공통 위치는 찾는 수고를 줄이고, 맥락별 내용은 무관한 정보의 해석 부담을 줄인다. 실제 위치 기반 오버레이는 안내 대상과 설명의 관계를 보여준다. 한 페이지 기본 구성은 불필요한 탐색을 줄이되, 정보량에 따라 확장할 수 있게 한다.

### 구현 상태와 설계의 구분

2026-10-03: 공통 `[?]`에서 현재 화면의 맥락형 도움말을 연다. 실제 요소의 위치를 반투명 테두리·번호와 설명으로 연결한다. 재생·목록·설정·편집 탭에 맞는 내용을 공통 i18n에서 읽는다. 기본 한 페이지이며 좁거나 낮은 화면은 분할하고 화살표·키보드·스와이프로 이동한다. Esc/닫기 후 기존 창과 포커스를 유지한다. 재생 화면 하단의 상시 조작 안내는 제거하고 도움말에 통합했다.

로컬 Safari에서 재생·설정·제작실 편집창 및 Esc/포커스 복원을 확인했다. 좁은 화면 페이지 전환은 자동 테스트로 확인했으며 실제 iPad 터치 스와이프·회전과 전체화면 전환 검증은 별도 미확인이다. 공개 Sites 배포와 독립 HTML 재생 파일 생성은 하지 않았다.

## 공통 검수 질문

1. **처음 보는 사람도 도움말 없이 핵심 행동을 시작할 수 있는가?**
2. **익숙해진 사람은 설명과 불필요한 단계를 건너뛰고 반복 작업을 할 수 있는가?**
3. **잘못 눌렀을 때 무슨 일이 일어났는지 알고, 되돌아올 수 있는가?**

검수 기록에는 대상 화면·사용 상태·수행한 행동·관찰 결과를 남긴다. 실제 확인하지 않은 항목은 통과로 표시하지 않는다. 이 세 질문으로 시작하고, 실제 사용에서 발견한 문제를 근거로 기준을 보완한다.

## 악보를 미리 읽을 여유 (2026-10-03 승인)

드럼연습실은 반응 속도를 겨루는 화면이 아니다. 음표의 읽기 좋은 크기를 유지하면서 불필요한 가로 간격을 줄이고, 앞으로 연주할 여러 마디를 볼 수 있게 한다. 동일 음가·동일 거리의 정확성뿐 아니라 선행 박 수와 선행 시간도 검수한다. 정량 후보는 [RIBBON-READABILITY.md](RIBBON-READABILITY.md)에 있으며 확정 수치와 구분한다.

## 설정 화면의 연속 탐색 (2026-10-03 승인·구현)
- 설정은 화면·재생·정보·악보 등 사용 가능한 섹션을 한 스크롤 영역에 모두 표시한다. 각 섹션은 제목과 서로 다른 옅은 배경색으로 구분한다.
- 좌측 메뉴는 화면 전환 대신 섹션으로 이동하는 바로가기다. 직접 스크롤할 때도 현재 섹션을 강조한다. 좌측 메뉴와 닫기 버튼은 내용 스크롤에 함께 사라지지 않는다.
- 좌측 버튼은 공통 CSS와 같은 너비를 사용한다. 기존 왼쪽 padding12px를 보존하고 오른쪽도12px로 맞춰 남는 폭을 줄인다. 좁은 화면에서는 기존 가로 메뉴 배치를 유지한다.

### 화면 설정의 선택 버튼 (2026-10-03)
- 보기 방식(한 줄/두 줄)과 악보 형식(PDF 원본/MusicXML)을 위쪽 두 행의 선택 버튼으로 표시한다. 네 버튼은 공통 CSS로 같은 너비·높이를 사용하고 설명 캡션은 오른쪽에 둔다. 좁은 화면에서는 캡션만 다음 줄로 배치한다.
- 음표 따라가기와 전체화면 스위치는 아래에 기존 스타일로 유지한다. 한 줄 보기에서 악보 크기 조절도 유지한다. 제작실의 검수 보기 기능은 추가 선택으로 보존한다.

### 2026-10-03 도움말 공통 범례
- 모든 맥락형 도움말의 닫기 버튼 왼쪽에 **[범례]** 버튼을 둔다. 본문 레이아웃과 분리된 너비 100vw·높이 100dvh Liquid Glass를 참고한 웹 반투명 모달(28px 배경 흐림·145% 채도·다층 하이라이트)에서 공통 범례를 보여 준다. 중복 제목과 상단 설명 두 줄은 표시하지 않는다. 가로 화면은 3열, 세로 화면은 2열과 하단 주법 영역으로 배치해 27개를 한 화면에 보여 준다. 드럼·킥 9개는 오선 위 위치를 SVG 그림으로 함께 표시한다. 범례가 열리면 뒤의 도움말은 숨긴다. 닫으면 도움말 상태를 유지하고 범례 버튼으로 초점을 돌린다.
- `docs/SCORE-MUSICXML-OSMD-MAPPING.md`의 확정 항목 27개를 하이햇·심벌, 드럼·킥, 주법·손 지시로 분류한다. 표기 위치·모양·의미를 설명하며 악보마다 성부·기둥·연결선을 유지하는 적용 범위를 명시한다.
- 구현은 `src/help-legend.ts`와 공통 도움말을 사용한다. 문자 기호는 모양 안내이며 실제 악보 조판 예제가 아니다. 버즈 롤 등 상세 모양을 문자로 정확히 표현할 수 없는 항목은 설명을 제공한다.
- 승인 범례 변경 시 도움말 번역 문구와 항목도 함께 대조한다. 범례 안내가 모든 주법의 음향 합성 지원을 의미하지 않는다.

### 2026-10-04 도움말 하단 조작부
- 도움말·범례·닫기 조작부는 우측 하단에 고정한다. 원래 ? 버튼과 가까운 위치이며 safe-area 하단 여백을 반영한다.
- 설명 패널은 조작부 위에 배치한다. 좁은 화면의 설명 패널도 조작부를 덮지 않는다.
- 설명 패널과 조작부는 범례 모달과 같은 반투명 그라디언트·28px blur·145% 채도 재질을 공유한다. 투명도 감소·대비 증가 및 미지원 환경은 불투명 배경으로 대체한다.

### 2026-10-04 4줄 SVG 범례 적용
- 범례 모달은 승인된 오선 4줄 SVG를 비율 유지(contain)로 표시한다. 과거 3열 텍스트/개별 오선 배치는 대체한다.
- SVG 내부 배경에 굴절·반투명 면·반사를 적용하고, 음표·텍스트는 왜곡하지 않는다. 모달은 뒤 화면 흐림을 담당한다.
- 공통 src/help-legend.ts가 생성된 src/vendor/score-legend-svg.ts를 호출한다. 글리프 OFL은 src/vendor/Bravura-OFL.txt에 보존한다. 생성기는 docs/design/legend-diagram/draw-four-staves.py이다.
- 모든 SVG CSS는 score-legend-illustration 아래에 한정해 실제 악보 스타일에 영향을 주지 않는다. 화면 읽기용 27항목 설명은 별도로 보존한다.

### 2026-10-04 버튼 ↔ 도움말·범례 모달 전환

### 모달 애니메이션 정정
- 버튼 자체는 전환 대상으로 지정하지 않는다. 버튼의 현재 사각형을 기준점으로 삼아 모달 스냅샷만 확대/축소한다.
- 과거 버튼↔모달 view-transition-name 교환 방식은 폐기. 도움말과 범례에 동일한 모달 전용 expand/collapse 규칙을 적용한다.

- Safari의 범례 확대 프레임 지연을 방지하도록 모달 전환 중에만 SVG 배경 굴절 필터를 끈다. 정적 유리 면과 반사는 유지하며 전환 종료 후 굴절을 복원한다. 음표·텍스트와 버튼에는 확대 필터를 적용하지 않는다.

### 2026-10-04 재생바와 하단 서랍
- 승인 명세: `docs/plans/PLAYBACK-DRAWER.md`. 가로는 한 줄, 세로는 두 줄이며 서랍 상태는 회전해도 유지한다.
