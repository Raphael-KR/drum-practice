# 음표 따라가기

- 설정: 설정 > 화면 > **음표 따라가기**. 기본값 켜짐, 앱 공통 설정으로 저장. 곡을 바꾸거나 앱을 다시 열어도 유지하며, 토글 변경은 현재 화면에 즉시 반영한다. 홈에서도 변경 가능하며 선호값은 PDF 선택 여부와 독립적으로 기억한다. 단, 현재 화면이 PDF/검수이면 토글은 꺼진 비활성 상태로 표시하고 사용 불가 이유와 전환 방법을 안내한다. MusicXML 연습 화면으로 돌아오면 저장된 선호값을 복구한다. 저장이 차단되면 현재 세션에서 유지한다.
- 목표: MusicXML/SVG의 음표는 실제 시작 박자에 흰 중심과 청록색 광륜으로 점등하고, 빔은 현재 진행 부분에 짧은 빛이 연속적으로 지나간다.
- 범위: 한 줄/두 줄 MusicXML 연습 화면. PDF 원본과 비교 검수의 원본 도형은 변경하지 않는다.
- 기준: 픽셀 위치를 박자로 추정하지 않고 OSMD 음표의 악보 내 timestamp를 사용한다. 동시 타격은 동시에 전환한다. 오선과 가사에는 음표 색을 적용하지 않는다.
- 표시: 음표 시작에 밝게 켜지고 약 140ms 뒤 꺼진다(최대 ¼박, 다음 음표 시작 전까지). 지나간 음표에 색을 누적하지 않는다. 빔도 짧은 이동 구간만 강조한다. 일시정지는 그 위치를 유지하고, 탐색/반복은 현재 재생 위치에서 다시 계산한다. 카운트오프 중에는 강조하지 않는다.
- 저장: 원본 MusicXML의 색/음가를 바꾸지 않고 SVG 렌더 캐시에 타이밍 메타데이터를 추가한다. 기존 캐시는 자동 갱신한다.
- 검증: 음표 시작 전/정확한 시작/동시음, 빔 중간/끝, 되감기, 캐시 갱신, 전체 테스트와 빌드, Safari 실제 SVG 확인.

## 2026-09-21 검증 결과

- 캐시 버전2. 110마디 예제에서 음표머리/기둥 2,508개 표시 그룹, 빔600개를 실제 SVG 도형과 연결했다. 동시음은 각 그룹이 같은 timestamp를 사용한다.
- Safari 1180×820에서 22마디 두 번째 8분음표의 시작1ms 전: 4개 도형 모두 hidden → 정확한 시작: 모두 visible → 되감기: 모두 hidden 확인. 경계 측정 시 테스트용 seek 입력만 step=any로 바꾼 뒤 원복했다.
- Safari 실제 재생60.71→60.83초에서 음표 그룹23개는 그대로 유지되면서, 진행 중 빔 클립은100956.324→100971.503으로 연속 증가했다. 첫 검수의 CSS 클리핑 문제를 SVG userSpaceOnUse clipPath로 수정 후 재확인했다.
- 두 줄 [캡처](experiments/note-highlight-final-beam.png), 한 줄 [캡처](experiments/note-highlight-ribbon.png). 원본 오선/쉼표/가사 색은 유지된다.
- 전체52파일/217테스트 및 빌드 통과. 음표 시작/동시음/셋잇단음표 보간/성부별 빔/되감기/마디 전환/카운트오프 숨김/안전한 도형 추출/기존 캐시 갱신 검사 포함.
- 박자 판정은 기존 음원↔마디 타이밍과 MusicXML 음가를 따른다. 실제 음원과 XML 음가가 틀리면 그 오차를 별도로 교정해야 한다. 화면 갱신은 브라우저 프레임 단위이며 실제 iPad 기기의 오디오 출력 지연까지 측정한 것은 아니다.
- PDF와 PDF·MusicXML 검수 캔버스에는 이번 강조를 적용하지 않는다. 원본 비교에 재생 장식을 섞지 않는다.

## PDF 보기에서 켜짐으로 오인한 문제 수정

- 실제 사용자 화면: PDF=true, 음표 따라가기=true, 표시층0개. 이전 QA 후 PDF 보기를 복원하면서 사용 불가 상태를 알리지 않은 것이 원인이었다.
- PDF에서는 토글 disabled=true/checked=false와 MusicXML 전환 안내를 표시한다. 내부 공통 선호값은 삭제하지 않는다.
- Safari에서 MusicXML로 전환 후 실제 재생85.85→86.02초: 강조 도형14→16개, 다음 빔 클립0→100458.602 확인. [34마디 재생](experiments/note-follow-live-1.png), [37마디 재생](experiments/note-follow-live-2.png)을 직접 열어 색 변화를 검수했다.
- 검증 후 MusicXML 보기/기능 켜짐을 유지하고, 재생 위치는 시작 시77.82초로 되돌려 정지했다. 전체53파일/221테스트와 빌드 통과.

## 순간 점등 방식으로 변경

- 사용자 요청에 따라 리듬게임처럼 순간 점등 후 검정색으로 복귀. 형광 연두색에 작은 발광 효과를 적용했다.
- Safari 실제 재생 70.03~70.81초를 50ms 간격으로 측정: 1박 그룹 켜짐 → 꺼짐 → 1.5박 그룹 켜짐 → 꺼짐 → 2박 동시음 4개 켜짐 → 꺼짐 확인. 이전 음표는 누적되지 않는다.
- [점등 화면](experiments/note-pulse-on.png), [실제 재생 화면](experiments/note-pulse-live.png)을 직접 확인했다. 검수 후 MusicXML/켜짐 유지, 77.82초에서 정지.
- 53파일/223테스트와 프로덕션 빌드 통과. 빠른 연속음, 동시음, 이동 빔 종료, 속도별 점등 길이, 토글/카운트오프 검증 포함.

## 흰 중심과 청록 광륜

- 첨부 참고 이미지에 맞춰 평면 연두색을 흰빛 중심, 청록색 테두리와 다중 번짐으로 변경. 음표 머리에는 추가 광륜, 기둥/연결선에는 약한 빛을 적용한다. 악보 전체 배경은 유지한다.
- 점등 순간이 가장 밝고 기존 약140ms 창 안에서 밝기를 낮추며 소등한다. 원본 MusicXML에는 영향을 주지 않는다.
- YouTube 링크는 접근 제한으로 영상 재생 확인하지 못함. 첨부 이미지의 시각 특성을 참고한 2D 발광 효과이며 실제 3D 장면은 아님.
- Safari 실제 SVG에서 음표 머리1488개를 분리했고 실제 재생과 [점등 캡처](experiments/note-light-cyan.png)를 확인. 223테스트와 빌드 통과.
