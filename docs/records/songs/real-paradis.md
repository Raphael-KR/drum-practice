<a id="musicxml-conversion--입력과-방법"></a>

### 입력과 방법

원본 3쪽 PDF와 기존 `data/reference/geometry.json`의 시스템/마디 경계를 읽는다. 기존 beatXs는 음가 인식 근거로 사용하지 않는다. 원본 파일과 분석 결과는 Git 제외 경로에 둔다.

MusicXML 4.0의 `unpitched`, `instrument`, MIDI channel 10을 사용한다. 반복기호는 각 마디의 실제 이벤트를 복사하고 `measure-repeat`로 표기한다. 1–4마디는 실제 네 개의 쉼표 마디와 `multiple-rest`로 표현한다.

공식 계약: [Percussion](https://www.w3.org/2021/06/musicxml40/tutorial/percussion/), [measure-repeat](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/measure-repeat/), [Verovio](https://book.verovio.org/toolkit-reference/toolkit-methods.html).

Apple 도구 검토: STT는 인쇄된 리듬·드럼 악기·빔 판독에 직접적인 근거를 제공하지 않는다. 기존 AFM 텍스트 비교 계약도 음악 기호의 이미지 판독을 보증하지 않는다. 이 변환에서는 벡터 분석과 원본 시각 대조를 사용한다.

<a id="musicxml-conversion--음가-복원과-예외"></a>

#### 음가 복원과 예외

글리프의 모양·오선 위치, 줄기의 방향/연결, 직선으로 닫힌 빔 사각형을 읽는다. 빔 위치는 해당 줄기 끝의 방향을 제한해 다음 시스템의 빔과 혼동하지 않는다. 곡선 붙임줄은 빔 개수에서 제외한다. 음가를 마디 총합에 맞추기 위해 임의 조정하는 규칙은 없다.

| 대상 | 원본에서 확인한 처리 |
|---|---|
| 1–4 | 4개 실제 쉼표 마디 + `multiple-rest=4` |
| 6, 43, 44, 47, 51, 103 | 직전 마디 실제 이벤트 복사 + `measure-repeat`; 44는 43을 거쳐 42의 패턴 |
| 7 | 점4분 크래시의 3획 트레몰로, 다음 8분음표와 붙임줄, 스네어 앞 작은 슬래시 장식음 |
| 8 | 첫 8분쉼표를 두 성부가 공유; 아래 성부에 숨긴 동등한 쉼표 기록 |
| 72, 100 | 마지막 16분음표 6개에 인쇄된 `6`; 6:4 비율, 각 1/6박 |
| 84 | 5/4, 마지막 4분쉼표 공유; 두 성부 모두 5박 |
| 94, 96 | 깃발 옆 멀리 배치된 점을 같은 코드의 점8분음표로 연결 |
| 107–109 | 아래 성부의 생략된 공유 쉼표를 보충; 보이는 원본 쉼표는 유지 |
| 110 | 온마디 쉼표와 종지선 |

<a id="musicxml-conversion--악기-매핑과-확정-범위"></a>

#### 악기 매핑과 확정 범위

표의 위치는 원본 오선의 가장 위 F5선을 0으로 하는 온음계 칸이다. MIDI 번호는 GM의 0–127 번호이며 MusicXML에는 규격대로 1을 더해 쓴다.

| 기호/칸 | 표시 위치 | 후보 악기 | GM MIDI |
|---|---|---|---:|
| œ / 7 | F4 | Bass drum | 36 |
| œ / 3 | C5 | Snare | 38 |
| œ / 1, 2, 5 | E5, D5, A4 | High / Mid / Low tom | 50 / 47 / 43 |
| x / -1 | G5 | Closed hi-hat | 42 |
| o / -1 | G5 | Open hi-hat | 46 |
| x / 0 | F5 | Ride | 51 |
| x / -2 | A5 | Crash | 49 |
| x / 3 | C5 | Cross stick | 37 |

**원본에는 악기 범례가 없다.** 악보의 기호·오선 위치 보존과 실제 악기 이름/GM 음색의 확정은 별개다. 악기명이 정답이라고 확정하지 않았으며 음표가 있는 각 마디의 `audit.json`에 미확정 상태를 기록했다. 특히 x/F5, x/C5와 탐의 실제 튜닝/종류는 연주자 확인이 필요하다. 오선 위치와 기호가 남아 있어 매핑만 변경할 수 있다.

7마디의 장식음 재생 시점과 트레몰로 타격 속도는 원본에 수치로 지정되어 있지 않다. 기호를 보존했으며 임의의 MIDI 연타로 바꾸지 않았다. 전체 음원과의 청취 검증, 다른 악보 프로그램의 드럼 음색 재생 검증은 수행하지 않았다.

검토 수준도 구분했다. 9·12·84는 세부 수동 fixture와 렌더 대조, 7·72·100은 예외 기호 집중 대조, 나머지는 전수 구조 검사와 3쪽 전체 시각 대조다. 모든 마디를 별도 수작업으로 재전사해 이중 검증한 것은 아니다.

<a id="musicxml-conversion--렌더링-한계"></a>

#### 렌더링 한계

MusicXML은 실제 반복 음표를 갖지만 Verovio는 반복기호 마디 폭을 좁게 조판하고 2/3 같은 반복 회수 숫자를 추가한다. 빈 원본 마디 폭과 같지 않다. 원본의 둥근 o 머리는 비어 있는 일반 머리로 표현한다. 빔 기울기, 기본 음표 간격, 제목/첫 Intro의 표시도 원본과 다르다. 원본 제목·구간명은 XML에 보존되어 있으나 Verovio의 다중마디 쉼표 처리에서 첫 Intro가 렌더링되지 않는다. BPM은 XML 1마디에 있으며 렌더에서 읽을 수 있도록 5마디에도 표시한다.

SVG의 텍스트 글꼴만 `YuMincho`로 지정하고 `サビ`를 기존 프레임에 맞게 줄여 Cairo의 일본어 네모 표시를 해결했다. 음악 글리프 경로는 수정하지 않았다. 이 결과는 음악 데이터 검토용이며 원본과 픽셀이 같은 복제 PDF가 아니다.

<a id="musicxml-conversion--재현"></a>

### 재현

통합된 프로젝트 루트에서 실행한다. 원본 PDF는 읽기만 한다. 이 코드는 해당 PDF 해시에 결합한 전용 변환기이며 다른 곡에 수동 예외를 적용하지 않는다. Python/Cairo와 YuMincho가 있는 현재 macOS 환경 기준이다.

```sh
python3 -m venv docs/experiments/musicxml/venv
docs/experiments/musicxml/venv/bin/pip install -r tools/score-production/musicxml/requirements.txt
cp /Users/raphael/Playground/drum-practice/data/reference/geometry.json data/reference/musicxml/geometry.json
mkdir -p docs/experiments/musicxml/schema
curl -fsSL https://raw.githubusercontent.com/w3c/musicxml/v4.0/schema/musicxml.xsd -o data/reference/musicxml/schema/musicxml.xsd
curl -fsSL https://raw.githubusercontent.com/w3c/musicxml/v4.0/schema/xml.xsd -o data/reference/musicxml/schema/xml.xsd
curl -fsSL https://raw.githubusercontent.com/w3c/musicxml/v4.0/schema/xlink.xsd -o data/reference/musicxml/schema/xlink.xsd
```

이하 `PY`는 위 가상환경 Python 경로, `OUT`은 산출물 경로다. 임의의 사용자 파일이 있는 디렉터리를 OUT으로 지정하지 않는다.

```sh
PY=docs/experiments/musicxml/venv/bin/python
OUT=docs/experiments/musicxml
SCORE_PDF='/Users/raphael/Documents/드럼 악보/Real paradis-風と丘のバラード.pdf'
"$PY" tools/score-production/musicxml/convert.py --pdf "$SCORE_PDF" --geometry "$OUT/geometry.json" --out "$OUT"
"$PY" tools/score-production/musicxml/export.py --input "$OUT/extracted.json" --out "$OUT/representatives.musicxml" --representatives
"$PY" tools/score-production/musicxml/verify.py --xml "$OUT/representatives.musicxml" --ir "$OUT/extracted.json" --schema "$OUT/schema" --out "$OUT/representatives-audit.json"
"$PY" tools/score-production/musicxml/render.py "$OUT/representatives.musicxml" --out "$OUT/representatives-render"
"$PY" tools/score-production/musicxml/export.py --input "$OUT/extracted.json" --out "$OUT/real-paradis-110-candidate.musicxml"
"$PY" tools/score-production/musicxml/verify.py --xml "$OUT/real-paradis-110-candidate.musicxml" --ir "$OUT/extracted.json" --schema "$OUT/schema" --out "$OUT/audit.json"
"$PY" tools/score-production/musicxml/test_verification.py
"$PY" tools/score-production/musicxml/render.py "$OUT/real-paradis-110-candidate.musicxml" --out "$OUT/full-render"
"$PY" tools/score-production/musicxml/review.py --pdf "$SCORE_PDF" --out "$OUT"
```

<a id="musicxml-conversion--2026-09-19-사용자-제공-제작자제목-정보-반영"></a>

### 2026-09-19 사용자 제공 제작자·제목 정보 반영

`tools/score-production/musicxml/song-metadata.json`을 재생성 메타데이터 정본으로 추가했다. 사용자가 직접 제공한 정보이며 링크의 내용을 별도로 검증한 결과로 표시하지 않는다.

- 원제(`work-title`): 風と丘のバラード
- 표시 제목(`movement-title`, title credit): 바람과 언덕의 발라드
- 노래(`creator type="artist"`): Real Paradis with のだめオーケストラ
- 작사(`creator type="lyricist"`): Jane Su
- 작곡(`creator type="composer"`): 野村陽一郎
- 제공된 노래·작사 링크는 `miscellaneous-field`로 보존했다.

### 결론

요청된 전 음절 청취 검증은 수행하지 못했다. 현재 도구에는 원음을 모델의 청각 입력으로 전달해 발음 시작을 직접 판정할 경로가 없다. Apple STT/Whisper의 숫자와 텍스트는 직접 청취 정답이 아니다. 청취로 확인된 정답 시각이0개이므로 현재 정확도, 평균 절대 오차, 보정 전후 정확도 개선율은 산출할 수 없다.

### 실제 정확도 평가에 필요한 자료

556개 음절 각각의 독립적인 청취 시작시각, 확인자, 애매한 발음의 허용 구간이 필요하다. 이후 동일한 정답에 대해 보정 전/후 평균·중앙·95백분위 절대오차, ±100ms 내 비율과 악화된 음절 수를 비교할 수 있다. 이 허용범위는 향후 평가 기준 예시이며 실제 정확도 수치가 아니다.

로컬 `docs/experiments/syllable-sync/listening-review.csv`에556개 행과 수정 전/후 시각을 준비했다. 청취 시각·확인자 칸은 빈 상태로 남겼다. 측정하지 않은 값을 채우지 않았다. 정량 감사 결과는 같은 폴더의 accuracy-limit-review.json에 있다. 이 검토에서는 앱 시각을 추가 변경하거나 되돌리지 않았다.

### 확인된 방법과 한계

기존 자료는 보컬 분리 음원에 MLX Whisper 강제 정렬을 수행한 뒤, 일본어 토큰을 한글 발음으로 대응시켰다. 여러 한글 음절이 한 토큰에 대응하면 그 토큰 구간을 균등 분배했다. 일부 문장 시작은 별도 파형 기준 보정, 후렴 시작은 공통 리듬 틀을 적용했다. 전 음절을 사람이 듣고 확인한 결과가 아니다.

- 전체 표시 음절: 556개
- 여러 음절을 포함한 토큰: 140개 / 그 안의 음절 306개
- 토큰 확률0.5미만: 56개 (이 확률은 시간 정확도의 확률이 아님)
- 전 음절 청취 검증: 미수행. 현재 세션에는 직접 청취·발음 경계를 판정할 오디오 입력 도구가 없다.
- 이번 조사에서 실제 앱 가사 시각은 변경하지 않았다. 기존 confirmed=false 유지.

<a id="lyric-sync-correction--판단과-근거"></a>

### 판단과 근거

Apple 로컬 STT와 AFM 워크플로우의 기존 원시 결과를 참조했다. AFM은 음절 시각을 만들거나 최종 변경을 결정하지 않았다. STT는 일부 한자·음절을 묶어 반환하므로, 이 문제에는 기존 로컬 MLX Whisper 모델의 강제 정렬을 추가했다. 네트워크 전송은 없다.

- 보컬 분리 음원: 원래 구간, 시작을0.6초 앞당긴 구간의 두 실행.
- 원곡 믹스: 동일 가나로 별도 실행.
- 보컬 분리 음원:8음절마다 앞뒤 문맥을 붙인 짧은 창으로 별도 실행.
- 일반 후보 조건: 긴 문맥의 보컬2회와 원곡 결과의 최대–최소가0.1초 이내이고, 짧은 창은 해당 중앙값에서0.1초 이내이며, 음절 길이0.06초 이상 및 토큰 확률0.1 이상, 기존과0.08~0.7초 차이. 영어 표기 후보와 인접 순서를 뒤집는 변경은 제외.
- 48마디 ‘테’는 믹스의 토큰 확률이 낮아 일반조건에서 제외됐다. 보컬 두 실행122.44초, 짧은 창122.47초, 믹스122.42초, Apple의 명시적 `て` 시작122.48초를 비교하고122.44초로 보정했다.
- 48마디120~123초의 보컬 파형도 생성·시각 점검했다. 파형만으로 음절 정체를 확인했다고 해석하지 않는다.

동일 모델의 여러 결과 일치는 독립적인 청취 정답이 아니다. 토큰 확률도 시각 정확도의 확률이 아니다. 이번 변경은 균등 분배 방식보다 세분화된 음원 기반 추정 보정이며, 100% 정확성 보증이 아니다.

### 15마디 사용자 기준으로 다시 시험한 결과

2026-09-19 사용자 기준은 ‘코’가 네 번째 팔분음표,37.090228초다. 같은 Apple STT에 원곡/보컬 분리 각각34–40초와36.4–39.5초를 넣었다. 긴 창의こ 시작은 둘 다36.16초, 짧은 창은 둘 다37.12초로 변했다. 짧은 창은 사용자 기준보다 약29.8ms 늦다. 이를 다른 모든 음절의 정확성으로 일반화하지 않는다.

보컬 RMS는36.25–36.75초에도 다음 코 구간 대비 약-1.1dB였고37.0–37.1초에-16.8dB로 떨어졌다. 따라서 앞 구간 전체가 무음이라고 설명할 수 없다. 앞 발음의 지속/여운을 포함하는 경계 구간을 다음 글자의 STT 시간에 할당했을 가능성이 크지만, 직접 청취로 해당 소리의 정체를 판정한 것은 아니다.

이 사례의 약0.870초 차이는 현재 박자망에서 팔분음표 약2.73개다. 주요 문제는 인식된 글자구간 시작을 실제 발음 시작으로 간주한 것과 문맥 의존 경계가 반복 실행에도 안정적으로 보일 수 있다는 점이다. 기존コ 후보는 낮은 모델 토큰확률 때문에 보정에서 제외되어 오래된36.22초가 유지됐었다.

개선 방향: 긴 한 음절 구간/국소 에너지 경계를 의심 표시하고, 앞 구절을 제외한 짧은 창과 중첩창으로 재전사하여 사용자 확인 앵커와 대조한다. 나머지 음절을 모두 같은 양으로 밀거나 가장 늦은 추정치를 일괄 채택하지 않는다. 다음 노 등 이웃도 따로 검증해야 한다. 현재 사용자 확인 코37.090228초는 유지했다. 원시 결과는 docs/experiments/bar15-boundary/에 있다.

### 현재 앱의 한글 발음과 실제로 다른 내용

1. ‘쿄 데테이쿠’ → ‘쿄- 데테이쿠와’: 종결 ‘わ’ 음절 추가가 필요하다. 새 일본어로 확인한 텍스트 차이이며, 추가할 ‘와’의 시각은 음원에서 별도 정렬해야 한다.
2. ‘코마라테타히’ → ‘코마라세타히’: 困らせた日의 せ에 대응하는 발음. 기존 한글의 테를 세로 교체할 부분이다.
3. ‘미타코토노나이’ → ‘미타코토모나이’: 見たこともない의 も에 대응하는 모. 노를 모로 교체할 부분이다.

장음 표기(쿄-/키보-/소-/무코-/요-니/타이요-/스-츠케-스 등)는 별도 통일할 수 있지만 장음 기호마다 새 발음 시작이나 새 타임스탬프를 만들면 안 된다. ‘나앗/타앗/후웃’은 기존 v2에서 앞 음절과 묶은 촉음 표현으로 처리한다.

### 이번 자료만으로 바꾸지 않을 내용

- 空のスーツケース는 일본어 글자가 동일하다. ‘空’ 한자만으로 소라/카라의 읽기를 확정하지 않는다. 사용자 한글 ‘카라’와 기존 STT의 か/ら 결과는 카라를 뒷받침하며, 새 본문 때문에 소라로 되돌릴 이유는 없다.
- always blight는 이번 본문에도 같다. 영어 의미를 근거로 임의로 bright로 교정하지 않는다. 표기 출처와 실제 가창 발음은 별개다.
- 이 대조는 가사 본문 검증이다. 새 싱크 정확도를 검증하거나 의심 목록의 음절을 자동으로 청취 확정하지 않는다.
