# OSMD 기본 가사 출력 전환 검토 — 2026-11-10

상태: **SVG 전체 보기 전환 구현·정적 검사와 후속 로컬 CLI 오류 회귀검증 완료**. 아래 검토 기록은 구현 전 조사다. 후속 사용자 승인에 따른 구현 범위·결과·미검증 항목은 마지막 절에서 구분한다. 현재 계약은 [현행 출력 규칙](../../reference/score/rendering.md#svg-score-rules--전체-보기-가사)을 따른다.

후속 사용자 요청으로 진행한 [갑자기의 같은 보표 가사 성부 시험](suddenly-lyric-voice-trial-20261110.md)은 별도 기록이다. 이 문서의 운영 구현과 시험본의 저장 구조를 구분한다.

- 목표: SVG 전체 보기에서 가사를 섹션·지시문과 같은 크기로 표시하고 악보와 함께 확대·축소할 수 있는 기본 기능 경로를 찾는다.
- 범위: 설치된 OSMD 2.3.0, 공통 렌더러·전체 보기·가사 저장 계약, 수록 패키지 6개와 초기 Git 기록을 읽는다.
- 완료 조건: 지원 기능, 현재 연결의 차이, 보존할 데이터, 구현 후보와 실제 출력 확인이 필요한 항목을 구분한다.
- 제외: 앱·악보·저장 데이터·의존성·버전 변경, 렌더링 실행·화면 검사·테스트·빌드·커밋·푸시·발행.
- 검증: 원본 패키지 XML/Song의 정적 대조, 설치 코드·공식 API·기록 비교, 문서·링크·앵커 검사와 대상 보존 확인.

## 왜 별도 표시를 만들었는가

2026-09-19의 MusicXML 도입 커밋 `29d5aa6`에 있는 PRD는 PDF·음원·별도 가사를 입력으로 삼고, 악보 아래에 음절을 배치하며 시간·글자를 편집하도록 규정했다. PDF 아래의 가사 표시는 별도 구현이 필요한 구조였다. 이 커밋의 `src/musicxml.ts`는 이미 `drawLyrics: false`를 사용한다. 뒤이은 `6b625ff`는 가사 리듬과 곡의 정본을 MusicXML로 옮겼다.

2026-11-09 SVG 전체 보기 변경은 연주 화면의 공통 데이터·HTML 배치를 재사용하며 OSMD 가사 출력 변경을 제외했다. 당시 기록은 [history.md](../../../history.md#2026-11-09--svg-전체-보기의-공통-가사-표시)에 있다.

이 순서는 PDF용 별도 표시가 MusicXML·전체 보기에도 유지됐음을 보여준다. 확인한 Git·ADR·history에는 **OSMD 기본 가사를 비교 검증한 뒤 기술적 한계 때문에 배제했다는 근거가 없다.** 당시 작성자의 모든 의도를 단정할 수는 없지만, SVG 전체 보기를 추가할 때 기본 출력과 기존 구현을 비교한 근거가 부족했다. 기존 코드 재사용만으로 이 선택이 최선이었다고 판단하지 않는다.

## 기본 기능과 현재 앱의 차이

| 항목 | 확인한 사실 |
| --- | --- |
| 기본 출력 | OSMD `drawLyrics`는 가사·연장선·연결 대시를 출력한다. SVG backend에서 가사도 SVG 요소로 그린다. |
| 크기 | `EngravingRules.LyricsHeight`가 있다. 현재 기본값은 2 engraving units다. 섹션 10pt와 같은 크기로 맞추려면 기존 지시문과 같은 변환식 `RehearsalMarkFontSize × (96/72) ÷ 10`을 공유할 수 있다. 실제 출력 크기 일치는 아직 확인하지 않았다. |
| 글꼴 | 기존 `score-text-font`의 Pretendard 로딩·SVG 글꼴 내장을 재사용할 수 있다. HTML 가사용 별도 화면 픽셀 크기를 SVG 출력에 적용할 필요는 없다. |
| 앱 입력 | `musicxml-parse`는 선택한 드럼 파트 이외의 파트를 OSMD용 문서에서 제거한다. `musicxml-engine`은 `drawLyrics: false`다. |
| 가사 저장 | 표준 음절 가사는 `DrumPracticeLyrics`의 숨긴 음표와 `<lyric>`에 있다. 현재 수록 패키지의 P1에는 `<lyric>`이 없다. |
| 현재 전체 보기 | `full-score-view`가 SVG를 표시 구간으로 나누고 HTML 가사 행을 추가한다. 크기·충돌·행 높이는 HTML에서 별도로 계산한다. |

근거: [OSMD 옵션](https://opensheetmusicdisplay.github.io/classdoc/interfaces/IOSMDOptions.html), [조판 규칙 API](https://opensheetmusicdisplay.github.io/classdoc/classes/EngravingRules.html), 설치된 2.3.0의 타입 선언·배포 코드, [렌더러 설정](../../../src/modules/score/musicxml-engine.ts), [파트 선택](../../../src/modules/score/musicxml-parse.ts), [공통 글꼴](../../../src/modules/score/score-text-font.ts), [전체 보기](../../../src/modules/score/full-score-view.ts).

## 실제 가사 데이터에서 확인한 제약

패키지 원본을 읽고 `Song.lyrics[].scorePosition.quarterOffset`과 P1의 `divisions/duration/backup/forward/chord`를 사분음표 단위로 대조했다. 아래 수는 가사 항목 수이며 화면에서 누락된 수가 아니다.

| 수록 패키지 | 음절 가사 | 마디 중앙 문구 | 같은 시작 위치에 드럼 음표 없음 | 음표·쉼표 모두 없음 |
| --- | ---: | ---: | ---: | ---: |
| 갑자기 | 301 | 7 | 0 | 0 |
| Loveholic | 269 | 0 | 6 | 4 |
| 바람과 언덕의 발라드 | 515 | 0 | 178 | 174 |
| 붉은 노을·기본 연습곡 2개 | 0 | 0 | 0 | 0 |

- 가사를 가까운 드럼 음표에 옮겨 붙이는 방법은 채택하지 않는다. 독립 가사 리듬은 오류가 아니며 시작 위치·음가·마디를 넘는 연장을 그대로 보존해야 한다.
- OSMD의 `RenderLyricsOfHiddenVoices`는 **같은 보표 안의 숨긴 voice**를 다룬다. 별도 part를 드럼 보표 아래로 자동 합치는 옵션으로 해석하지 않는다. `HiddenVoicesKeepLayout`을 끄면 보이는 음표가 없는 시각의 가사가 빠질 수 있다는 조건이 공식 설명에 있다.
- `Song.measureLyrics` 7개는 박·음가가 없는 마디 문구다. MusicXML 확장 manifest에 저장되며 표준 `<lyric>`과 다르다. OSMD 가사 옵션이 이를 자동 해석하지 않으며, 출력 편의를 위해 가짜 음절 위치나 음표를 만들어서는 안 된다.

저장 계약은 [정본 가사](../../reference/score/musicxml.md#musicxml-canonical--저장-계약)와 [마디 가사](../../reference/score/musicxml.md#measure-lyrics--데이터)를 따른다. 읽기 결과와 패키지 SHA-256은 `.tmp/osmd-native-lyrics-review-20261110/inspection.json`에 있다.

## 권장 순서와 전환 조건

**SVG 전체 보기부터 기본 출력의 적합성을 확인한다.** 기존 저장 형식을 바꾸거나 연주 화면까지 동시에 교체하지 않는다.

1. 드럼 파트와 독립 가사 파트를 함께 OSMD에 전달하는 후보부터 확인한다. 숨긴 음표의 리듬·가사 연장은 유지하고 가사 파트의 빈 보표·음자리표·반복 박자표가 추가되지 않아야 한다. 설치 코드에는 `Staff.StafflineCount`와 `<staff-lines>` 처리가 있지만, 선 수를 0으로 하는 것만으로 원하는 배치·여백이 나오는지는 미검증이다. `Instrument.Visible=false`로 파트 전체를 감추면 가사도 사라질 수 있으므로 이를 해결책으로 확정하지 않는다.
2. 위 경로가 충족되지 않으면 같은 보표의 숨긴 가사 voice를 이용하는 입력 연결을 별도 평가한다. 기존 음표에 가사를 끼워 넣거나 드럼 리듬을 다시 쓰는 방식은 제외한다. 파트/성부 구조를 표시 편의로 재작성하지 않는 현행 규칙과 연결 방식의 충돌을 먼저 보고하며, 검토만으로 정본이나 렌더 복제본을 변경하지 않는다.
3. 표준 가사가 정상 출력되면 공통 크기 환산을 섹션·지시문·OSMD 가사에 적용한다. 마디 중앙 문구는 기존 의미를 유지하는 별도 표시 대상으로 남긴다. 이 항목까지 모두 OSMD 기본 가사로 대체할 수 있다고 주장하지 않는다.
4. 기본 가사를 표시하는 전체 보기에서는 같은 음절의 HTML 출력을 제거한다. PDF·연주 화면에서 사용하는 가사 데이터·배치 모듈은 실제 사용처가 있으므로 삭제하지 않는다. 마디 중앙 문구의 배율도 SVG와 같아야 한다.
5. 전체 보기 캐시와 가사 편집 후 갱신을 함께 설계한다. 현재 `engraveMusicXML`은 인쇄용 간격을 한 줄·두 줄·균등 악보 생성에 재사용하므로 인쇄용 가사만 켜도 연주 좌표에 영향을 줄 수 있다. 전체 보기 후보가 연주용 간격을 바꾸지 않도록 경로를 확인한다. 새 출력은 기존 가사 없는 캐시와 구별하되 원본·연습 정보·DB 스키마는 유지한다. 재생 프레임마다 조판하거나 전체 보기를 열 때마다 불필요하게 다시 조판하지 않는다.

기본 출력은 글자와 악보의 배율을 일치시키고 전체 보기의 HTML 가사 재배치를 줄일 후보다. 다만 파트 연결·마디 문구·캐시 갱신에 필요한 코드까지 비교하기 전에는 총 코드량이나 실행 부하가 줄었다고 판단하지 않는다.

## 검증 상태와 다음 구현의 완료 기준

이번에는 소스·공식 API·6패키지를 정적으로 읽었다. OSMD를 실행해 가사가 실제로 보이는지, 줄 간격·쪽 수·성능이 어떤지는 확인하지 않았다. 전환 가능성이 확인된 것과 전환이 검증된 것을 구분한다.

후속 구현·허용된 검증에서는 세 곡의 음절 1,085개와 갑자기의 마디 문구 7개를 빠짐·중복 없이 표시해야 한다. 드럼 음표와 시작 시각이 다른 가사, 연장, 긴 문구, 줄/쪽 경계, 가사 없는 줄을 포함한다. 섹션·지시문·가사 크기와 창 폭 변경 배율, 가사 편집·저장·재열기·기존 캐시 갱신, 연주 화면의 마디·박 좌표·PDF 표시 보존을 확인한다. 화면 검수는 릴리스 또는 별도 지시 범위에서 수행한다.

앱 코드·원본 악보·수록 패키지·저장 데이터·의존성·버전·빌드번호는 변경하지 않았다. 기존 청소 작업의 미커밋 문서는 보존한다. 문서·링크·앵커 검사 결과는 같은 날짜의 `history.md`에 남긴다.

## 후속 승인과 구현 — SVG 전체 보기

- 목표: 전체 보기의 음절 가사를 OSMD 기본 SVG 출력으로 전환하고 섹션·지시문과 같은 글자 크기·배율을 사용한다.
- 범위: 두 앱의 공통 전체 보기, 렌더러·글꼴 환산·파생 캐시와 관련 문서. 독립 가사 파트는 별도로 유지한다.
- 완료 조건: 독립 음절 위치·음가·연장과 마디 문구를 연결하고 HTML 음절 중복 표시를 제거한다. 전체 보기 조판이 연주용 마디 간격에 영향을 주지 않는다.
- 제외: 연주/PDF 가사 표시 전환, 정본·수록 패키지·저장 스키마·실제 저장 데이터·버전 변경, 화면 검사·테스트 실행·빌드·커밋·푸시·발행.
- 검증: 소스·저장 경계 대조와 lint·서식·타입·공통 구조·문서·링크·앵커 검사. 실제 기본 가사·줄 간격·배율·재열기는 릴리스 검수 대상으로 남긴다.

### 구현 내용

- `full-score-lyrics.ts`는 선택한 드럼 파트 뒤에 기존 독립 가사 파트를 유지한다. 정본의 성부·음가·backup·forward·연장 정보를 고치거나 가사를 드럼 음표에 붙이지 않는다. 가사 파트의 VexFlow 보표 출력만 제외하고 OSMD의 가사 조판·SVG 출력을 사용한다.
- 음절의 `LyricsHeight`와 마디 문구의 `GraphicalLabel`은 지시문과 같은 공통 크기 환산을 사용한다. 섹션 기본 10pt는 13⅓ SVG px다. 마디 문구는 박을 합성하지 않고 마디 중앙에 줄바꿈하며 native 하단 경계에 공간을 확보한다. Pretendard 로딩·내장은 기존 모듈을 재사용한다.
- 전체 보기는 필요한 때에만 전용 인쇄 pass를 실행하고 공통 캐시의 별도 정책 키로 재사용한다. 연주용 pass·간격·HTML 가사 처리는 유지한다. 전체 보기의 HTML 가사 행·리사이즈 관찰자는 제거했으며 줄 첫 마디 번호와 URL 해제는 유지한다.
- 제작기에서는 기존 `writeCanonical`을 Song 사본에 적용해 미저장 가사도 반영한다. 재생앱은 읽기 전용 정본을 사용한다. 정본·패키지·저장 데이터·스키마에 쓰는 코드를 추가하지 않았다.
- OSMD 2.3.0의 가사 줄 배치와 backend 생성/표현식 출력 훅을 인스턴스별로 연결한다. `GraphicalLabel`·`drawLabel`을 재사용하지만 전체 연결이 공개 API만으로 이루어진 것은 아니다. 엔진 갱신 때 이 경계를 확인해야 한다. 표준 가사의 시각·문구는 원본 `<lyric>`에서 읽으며, 현재 정본에 있는 텍스트 없는 `extend type="continue"`는 그대로 전달한다. 연장선의 실제 외형은 아직 실행 검증하지 않았다.

## 후속 오류 수정 — 원본 없는 보조 마디

- 목표: SVG 전체 보기에서 마지막 실제 마디 뒤에 같은 박자표와 오선이 덧붙는 오류를 제거한다.

### 같은 보표의 가사 성부에 대한 추가 질문

같은 part·staff에 다른 voice를 두고 그 음표에 lyric을 연결하는 것은 유효한 MusicXML 구성이다. [voice](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/voice/)는 파트 안의 여러 성부를 구분하고, [backup](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/backup/)은 성부별 독립 시간 진행을 연결하며, [lyric](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/lyric/)의 기본 위치는 below다. 독립 가사 리듬 때문에 별도 보표가 필수인 것은 아니다. 현재 별도 파트는 프로젝트의 저장 설계다. 정본 구조 전환은 가사 작성·읽기·편집과 기존 자료의 호환 계약도 함께 검토해야 하며, 이번 문법 확인만으로 정본이나 렌더 복제본의 성부를 합치지 않는다.
