# 정본 전수 감사 후속 교정 — 2026-11-12

[승인된 수정 순서](canonical-rule-audit-20261112.md#correction-priorities)와 [실행 계획](../../plans/canonical-corrections-20261112.md)에 따른 작업 기록이다. 교정·검증·사용자 판단·앱 수록을 구분한다.

## 확인된 수정

- 붉은 노을: 원본 PDF와 보존 좌표를 대조해 크레센도 시작을 48·96·110마디 2박, 종료를 49·97마디 4박으로 교정했다. 지시문 105·134마디의 음악적 적용 위치는 2박이다. 생성기의 입력 표와 독립 판독 기대값도 고쳤다. 112마디 2박부터 113마디 2.5박까지의 승인된 크레센도는 유지한다.
- 제작 공통 코드: 가사 검사를 64분음표 단위로 바꾸고 `grid64`로 보고한다. PDF 구조 판독의 네 번째 빔 범위와 `64th` type, 갑자기·붉은 노을의 출력 type을 보완했다. 곡별 깃발·쉼표 글리프 판독은 원본의 profile을 따르며 미확인 글리프를 임의 등록하지 않는다.
- 앱 공통 코드: 기존 웹앱 담당이 균등 좌표·진행선·가사 입력/길이·마디 경계·캐시를 반영했다. [앱 담당의 변경·검증 기록](grid64-app-implementation-20261112.md)을 직접 읽고 관련 코드를 확인했다. 정본·수록 패키지를 대신 수정한 것은 아니다.
- Rule의 적용 범위: 승인된 연습곡 작곡의 표제, 제작자가 반복을 펼친 연주본과 앱 자동 전개의 차이, 타격 없이 닫는 하이햇의 연결 사건을 명확히 했다. 기존 ADR-0007·0009·0012에 근거를 연결했다. 기존 연습곡 표제 13개·93마디 연주 순서·하이햇 닫기 32개는 보존한다.

## 사용자 승인과 적용

사용자는 후속 답변에서 “앞서 질문한 세 항목은 모두 원안대로 승인”했다. 적용 목록·직전 해시·확인 상태의 이전 근거는 `approval-applied.json`과 `lyric-evidence.json`에 보존한다.

1. Real Paradis의 근거가 충분하지 않은 30쌍 중 `confirmed=true`로 남은 22음절의 확인 상태를 해제했다. 60음절의 현재 위치·길이·문구와 과거 확인 근거는 보존했다. 이 처리는 원본 가사 위치의 확정 교정이 아니다.
2. 갑자기 재생 66–69마디를 원본과 같은 한 줄로 합쳤다. 원본 51·52·53·55마디에 대응하며, 두 번째 괄호로 넘어가며 54마디를 건너뛰는 곳이다. 생성기는 같은 원본 줄의 전방 건너뛰기에 불필요한 줄바꿈을 넣지 않는다. 93마디 순서·음표·가사와 원본 순서 79마디는 보존했다.
3. 최소 합성 자료로 64분음표 네 빔·깃발·쉼표 검사를 추가했다. 네 번째 빔 판독, profile에 정의된 깃발/쉼표, 모호한 빔·깃발 조합과 지원 범위 밖 다섯 빔의 오류 보고를 통과했다. 앱 담당의 가사 시작·길이·마디 끝·저장 환산 검사도 통과했다. 시험 DB는 만들지 않았다.

Loveholic의 추정 가사 4곳과 갑자기의 시간 없는 7문구도 새로 확정하거나 위치를 만들어 넣지 않는다. 상세 목록은 `data/production/canonical-corrections-20261112/lyric-evidence.json`에 둔다.

## 조판 도구에서 해결한 문제

- 새 OSMD의 섹션은 `.vf-stavesection`, 오선은 `.vf-stave`, 줄은 `.osmd-staffline` 아래에 있다. 과거의 직접 자식·`.staffline` 조회가 실제 표제를 찾지 못했다. 현재 native 구조를 사용하고 구형 출력 조회는 호환 범위로 남겼다.
- 마디 ID는 `osmd-m<0부터 시작하는 인덱스>-<보표>`다. `x`가 붙은 끝의 예고 박자·조표 조각은 실제 마디가 아니다. OSMD의 `GraphicalMeasure.d.ts` 계약과 실제 출력으로 확인해 마디 탐색에서 구분했다.
- native 오선 path는 소수 둘째 자리로 직렬화되지만 섹션 rect는 원래 좌표를 유지한다. 실제 차이 −0.004819 SVG 단위를 확인해 오선과 테두리의 일치 검사에만 최대 0.00501 허용치를 적용했다. 충돌·최소 여백 검사 허용치는 늘리지 않았다.
- 후보 하나마다 기존 API가 인쇄형과 연주용 세 보기를 모두 생성했다. 최종 재열기와 별개인 후보 탐색에 같은 공통 엔진의 인쇄형 단일 pass를 재사용하도록 앱 담당에게 요청했다. 조판 알고리즘·폰트·좌표를 제작 도구에 복제하지 않는다.
- R/L은 일반 지시문이 아니라 타격에 연결된 스티킹이다. native 조판이 이 words를 전용 기호로 변환하므로 일반 text 조회가 실패했다. 원래 R/L 1,168개와 적용 박을 보존하고 일반 표시 offset 탐색에서 제외한다.
- 갑자기 5마디의 원본 지시 높이가 XML에 없었다. native 기본 높이를 사용한 중간 후보는 빔 충돌 때문에 긴 가로 탐색 후 높이 분리로 넘어갔다. 원본 PDF의 문자 기준선 197.25950016pt·오선 첫 선 222.6494pt·간격 4.53545pt를 읽어 `default-y=55.980994`를 얻었다. 붉은 노을과 같은 원본 기준선 환산법이며 `ioi-source-word-height.json`에 근거를 남겼다. 이 높이를 먼저 기록한 후보로 재검수하며, 기본 높이로 만든 중간 결과는 최신본으로 쓰지 않는다.
- 실제 후보의 가사 글꼴 명시 1,085개가 공통 writer를 거치며 사라졌다. 기본 lyric-font를 소비하는 writer 보완으로 세 곡의 명시 속성을 보존했다. 기본 글꼴이 없는 두 기존 입력은 이전 출력 바이트도 유지한다. 위치·확인 상태 변경과는 별개의 저장 문제다.
- 여러 곡의 연주용 파생 SVG까지 한 요청에 묶어 보내다가 기존 40MB 수신 한도에서 HTTP 413을 받았다. XML·탐색 근거 7,104,879바이트를 먼저 보존했다. 파생 보기가 들어 있는 첫 페이지도 한도를 넘으므로 공통 페이지 전송에 Base64 분할과 순서·길이·gzip 무결성 검사를 추가했다. 수신기의 안전한 `artifactId` 하위 폴더, 한도·Origin 검사·기존 파일 덮어쓰기 금지는 유지한다. 통과한 offset 탐색은 저장된 XML과 근거에서 복구하고 전송 실패만으로 반복하지 않았다.
- Safari와 Node/JSDOM의 XML 직렬화는 선택적인 XML 선언 38바이트에서 달랐다. 그 외 XML 본문은 같다. 실제 브라우저 저장의 바이트 일치와 Node의 선언 제외 본문 일치·반복 저장 안정성을 구분한다.
- 승인 후 갑자기 재조판에서는 탐색 중 기억한 초기 글자 돌출값 `system.left=46.21875`와 완성 XML 재검수의 `50`이 달라 재사용 검사를 멈췄다. 실제 글자·오선·같은 줄 경계·여백은 모두 같았다. 판정에는 실제 `staffLeft`를 사용하고, 탐색 중의 임시 돌출값만 동등성 비교에서 제외했다. 차이 원문은 `final-render-artifacts/ioi-proof-comparison/`에 보존한다.
- Safari MCP는 조판·DOM 계측이 가능했지만 스크린샷이 검정이었다. `visibilityState=hidden` 상태에서 탭 전환·앱 활성화 후에도 같아 ego-browser Chromium으로 실제 SVG와 공통 연주 컴포넌트를 캡처했다. Safari 조판 계측과 Chromium 화면 검수를 구분하며 iPad·청취 검증으로 보고하지 않는다.
- 화면에서 균등 보기의 왼쪽 첫 음표 잉크 잘림과 스티킹의 세리프 글꼴을 발견했다. 후자는 XML의 Pretendard가 아니라 공통 `drum-notation.ts`의 `serif` 고정이 원인이다. 기존 웹앱 담당이 공통 crop·글꼴 경로를 보완했다. 64분음표 좌표·음악적 위치·세로 마스크를 유지하면서 좌우 잉크 여유를 확보했다. 실제 Real Paradis·갑자기·붉은 노을의 수정 후 화면과 집중 회귀 23개를 확인했다.

- 두 연습곡의 R/L 갱신 중 탐탐의 첫 조판과 재열기에서 줄기 끝 `211.25→211`의 차이를 발견했다. 비교 허용치를 넓히지 않고 중단했으며, 실패 원문은 `font-refresh-first-attempt.json`에 보존했다. 같은 입력을 이어서 두 번 조판했을 때에는 음표 관련 624노드의 전체 서명이 일치했다(`tom-reopen-warm-diagnostic.json`). 원인은 OSMD의 그리기 단계에서 VexFlow 줄기 폭이 기본 1.5px에서 승인된 1px로 늦게 바뀌는 순서였다. native 음표 생성 전 훅에 기존 `StemWidth × unitInPixels`를 적용한 48문자 패치로 보완했다. 첫 조판·반복·public 재열기 624노드가 일치했고 제작자의 새 Safari 조판도 통과했다. 워밍업 조판이나 SVG 좌표 보정은 추가하지 않았다. 앱 근거는 `.tmp/grid64-app-20261112/beam-fix/result.json`과 패치 안내에 둔다.

## 검증 결과

- 실제 기존 자료 검사: Python 공통 4개·가사 2개, 기존 TypeScript 공통 5개·가사/균등/정본 20개 통과.
- 갑자기 원본 PDF: 79마디·음표머리 838개·쉼표 11개, 판독 문제 0. 변경 전 전체 IR과 같다.
- 붉은 노을: 독립 지시/크레센도 기대값 검사가 이전 오류를 거부하고 교정 입력을 통과했다. 생성기 재생성도 137마디·550 quarter와 교정된 위치를 통과했다.
- 최종 여섯 정본의 XSD·유리수 시간축 검사 통과: 587마디·가사 1,085개·연음 21개. 가사 격자 이탈·동일 시작은0이며, 드럼 음표/음가·원본 연음·음원 연결을 보존했다. Real Paradis의 22확인 상태와 갑자기의 69마디 줄바꿈만 승인 목록에 따라 달라졌다.
- 공통 정본 writer/read 왕복, 브라우저 XML 바이트 일치, Node의 XML 선언 제외 본문 일치·반복 저장 안정성, 6패키지의 전체 자산·원음원·대체 악보 보존을 통과했다. `candidate-verification.json`, `package-verification.json`과 각 곡 `layout-report.json`에 정확한 후보 해시를 결합했다.
- 전체 SVG 6개와 연주용 인쇄 캐시 23쪽을 생성했다. 전곡 섹션·지시문 잉크/여백·같은 줄·XML 재열기를 검사했다. 붉은 노을은 16지시문, 갑자기는 5마디의 1지시문을 검수했으며 R/L은 전용 연결 경로를 유지했다. 승인 후 두 곡은 실제 지시문/오선/여백이 같은지 확인한 뒤 영향 없는 최소성 탐색 근거를 재사용했다.
- 실제 화면은 여섯 곡의 전체 SVG 제목·원제·BPM·가수/키트, 붉은 노을48·96·110–113·134 구간, 갑자기66–69 줄, 각 곡 주요 구간의 한 줄·두 줄·균등 보기를 확인했다. 붉은 노을134 지시문 겹침은 없다. 균등 보기 첫 잉크 잘림의 공통 보완을 확인했다. 두 연습곡 R/L 1,168개의 전체 좌표·크기·연결을 보존한 Pretendard 출력을 검사했고 대표 구간을 직접 보았다. 마지막 줄기 초기화의 출력 대조도 통과했다. `visual-review-final.json`에 최종 파일 해시·화면 근거와 대표 구간 검수의 한계를 기록했다.
- 승인된 최소 입력의 제작 측 검사 6개(기존 가사 2+새 경계 1+기하 3)와 앱 측 정밀도 13개가 통과했다. 앱 측 결과는 직접 코드·명령·로그를 확인했다. 실제 앱 DB 저장·청취·공개 배포 검증으로 확대하지 않는다.

- 마지막 캐시 정책은 `v47-stem-initialization`이다. 새 print-only 출력과 기존 캐시의 모든 음표 요소를 대조했다. Loveholic 1,929개·Real Paradis 2,477개·손 풀기 1,728개는 일치했다. 붉은 노을 934개·갑자기 669개 줄기 요소에는 이전 냉시작 보정이 남아 해당 두 곡만 출력을 갱신했다. 모든 차이 노드가 줄기이며, 갱신 뒤 print-only/public 음표 서명·전곡 조판·XML 바이트 일치를 통과했다. 지시문 잉크·오선·여백이 같은지 확인하고 최소 offset 탐색 근거를 재사용했다. 비교 원문과 실제 서명은 `final-render-artifacts/stem-policy-reuse-final/`에 보존한다. 기존 생성 정책 v45/v46과 v47 재검사·재생성을 구분한다.
- 이 대조의 첫 실행은 HTTP가 이미 풀어 준 gzip을 다시 풀려다 실패했다. 파일 문제로 판단하지 않고 응답의 `Content-Encoding: gzip`과 실제 SVG 바이트를 확인한 뒤 응답 Blob의 MIME을 그대로 사용했다. 첫 실패 자료는 남기며 정본·비교 기준은 바꾸지 않았다.

기존 드럼연습실 웹앱 개발 채팅 `01a0afc9-ca21-7371-9390-06eb07c017e9`에 최종 6곡의 정본·패키지·전체 SVG와 후보 해시에 결합한 검증 근거를 전달했다. `handoff-final-message.md`가 실제 전송 본문이며 `handoff-final-send-result.json`, 각 곡의 `handoff-final/delivery.json`과 `handoff-final-receipt.json`에 접수 근거를 남겼다.

## 보존과 근거

기존 정본은 `data/production/lyric-onsets-20261111/<곡 식별자>/score.musicxml`, 새 작업은 `data/production/canonical-corrections-20261112/`다. 시작 해시·Git 상태·원본 판독·실행 로그·새 후보를 함께 보존한다. 기존 정본·원음원·PDF를 보존한다. 수록 교체 전 6패키지는 `public-before/manifest.json`과 해시가 일치하는 사본으로 보존했다. 자동 커밋·push·배포는 수행하지 않는다.
