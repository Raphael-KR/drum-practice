# 갑자기: 같은 드럼 보표의 가사 성부 시험 — 2026-11-10

상태: **갑자기 시험본의 XSD·파일 재읽기·공통 OSMD 출력 확인 완료**. 운영 저장 계약의 일괄 전환은 아니다.

- 목표: 별도 가사 파트 대신 같은 드럼 파트·보표의 독립 성부에 가사를 저장해 OSMD 기본 출력과 재읽기 가능성을 확인한다.
- 범위: `public/scores/ioi-suddenly.drumscore`의 정본 XML을 복사한 갑자기 시험본 하나와 로컬 공통 렌더러다.
- 완료 조건: 드럼 음악·가사의 시작/길이·음절 ID·확인 상태·마디 문구를 보존하고, 한 보표 출력·저장 후 재읽기와 현행 앱 호환성 차이를 기록한다.
- 제외: 수록 패키지·제작 정본·브라우저 저장소 덮어쓰기, 다른 곡의 변환/렌더링, 운영 저장 코드 전환, 커밋·푸시·발행.
- 검증: 실제 갑자기 XML의 MusicXML 4.0 XSD·음악 시간축·메타정보 대조, 파일 재읽기, 현재 앱 reader/writer와 공통 OSMD 렌더러의 로컬 CLI 검사, 문서·링크·앵커 검사.

후속 결정: 사용자가 시험 성공 후 [같은 보표 가사 성부를 정본으로 채택](../../decisions/0029-shared-staff-lyric-voices.md)했다. 아래 저장 코드·호환성 차이는 **전환 전 시험 당시**의 결과다. 현행 구현과 새 검사 결과는 [전환 계획](../../plans/shared-staff-lyrics-20261110.md)을 따른다.

## 입력과 시험 경계

현재 [저장 계약](../../reference/score/musicxml.md#musicxml-canonical--저장-계약)은 `DrumPracticeLyrics` 파트와 음절별 voice를 사용한다. 사용자는 이번 실험에 한해 같은 보표 안의 가사 voice를 시험하도록 승인했다. [현행 출력 규칙](../../reference/score/rendering.md#svg-score-rules--전체-보기-가사)을 운영 코드에서 바꾸지는 않는다.

- 입력 패키지 SHA-256: `d3a64dcf9512cf849801acc9535f7f748ba0cd29f247d36611d7d438738c3323`.
- 실제 입력: 93마디, 드럼 음표/쉼표 1,047개, 음절 301개, 마디 문구 7개. 음절 구간의 중첩과 마디를 넘는 extend는 없다.
- 시험본·스크립트·측정 결과: `.tmp/suddenly-shared-staff-lyrics-20261110/`. 생성 입력과 결과는 Git에 넣지 않는다.
- Python 3.12.14·lxml 6.1.1의 기존 번들 환경과 로컬 MusicXML XSD를 사용한다. 렌더링은 기존 5173 서버·공통 모듈·ego-browser CLI에서 수행한다.

## 결과

같은 P1 파트·한 보표의 `voice=1`에 기존 드럼 악보를 그대로 두고, `voice=2`에 가사 음표와 필요한 쉼표를 시간순으로 배치했다. 가사가 없는 구간은 숨긴 쉼표로 채우고, 매 마디 드럼 성부의 실제 끝 시각에서 `backup`으로 돌아가 가사 성부를 기록했다. 갑자기의 실제 가사 음가는 divisions96으로 정확히 표현되므로 드럼의 divisions·duration을 바꾸지 않았다.

가사 음표는 `print-object="no"`, `print-lyric="yes"`, `dynamics="0"`으로 기록한다. 음표·쉼표는 보이지 않고 OSMD 기본 가사만 드럼 오선 아래에 표시한다. 별도 가사 보표를 삭제한 뒤 SVG에서 글자를 이동하는 처리는 추가하지 않았다. 기존 `HiddenVoicesKeepLayout`, `RenderLyricsOfHiddenVoices`, 공통 Pretendard·글자 크기·마디 문구 배치 모듈을 그대로 사용했다.

## 현재 저장 코드와의 차이

**XML 파일의 무손실 재읽기와 기존 앱의 저장 호환성을 구분한다.** 현행 앱의 저장 계약을 바꾸지 않은 상태에서 확인한 결과다.

1. 현행 `readCanonical`은 `drum-practice:score:v1`과 가사 전용 파트를 전제로 한다. 시험본에는 기존 형식으로 잘못 인식되지 않도록 별도 실험 필드 `drum-practice:shared-voice-trial:v1`을 사용했다. 기존 reader는 이를 “앱의 MusicXML 연결 정보가 없습니다”로 거부한다.
2. 현행 writer는 별도 `DrumPracticeLyrics`를 새로 만든다. 시험본을 기반으로 메모리에서만 실행하면 P1의 301음절과 새 파트의 301음절이 함께 남아 602음절이 된다. 이 결과는 저장소에 기록하지 않았다.
3. 기존 음절 ID는 음절마다 하나인 voice에 연결된다. 공통 가사 성부 하나에 여러 음절을 담으려면 voice를 음절 ID로 사용할 수 없다. 시험본은 표준 note의 고유 `id`와 음절 ID·확인 상태를 연결해 보존했다.

정식 전환에는 새 저장 형식의 reader/writer와 이전 형식 이관이 필요하다. 새 writer는 지정된 가사 성부의 음표·쉼표만 갱신하고 드럼 성부와 다른 메타정보를 유지해야 한다. 예전 별도 파트 형식은 구분해서 읽어야 하며, 두 구조를 중복 생성해서는 안 된다. `.drumscore`·전체 백업/복원·편집 후 저장·연주용 파생 가사도 같은 경로로 검증해야 한다.

이 시험에서는 **동시 음절과 마디를 넘는 연장 사례가 실제 갑자기에 없었다.** 해당 입력까지 검증됐다고 보지 않는다. 다른 곡 변환·운영 저장 이관·실제 오디오 재생·Safari/iOS 검수는 수행하지 않았다. 원래 섹션·지시문·박자·크레센도는 정본 그대로 유지했다.
