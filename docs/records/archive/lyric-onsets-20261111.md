## Real Paradis의 원인과 판단 근거

기존 기록의 ¼박 격자 반올림·토오쿠 뒤+¼박 이동과 `lyricArchive`의 `listening-anchors-2026-09-19-v5-before-quarter-grid`를 대조했다. 30쌍 모두 아카이브에서 서로 다른 시각에 순서대로 존재했다. 이후 `tooku-tail-plus-quarter-2026-09-19-before` 등 격자 아카이브에서는 같은 tick에 들어간 사례를 확인했다. 원음의 정확한 발음을 새로 측정한 근거가 아니라, 원래 순차였던 구절의 서로 다른 음절임을 확인하는 근거다. 기존 원본 드럼 PDF에 해당 음절별 보컬 음가가 있다는 근거는 확보하지 않았으며 아래 값을 원본 보컬의 정답이라고 주장하지 않는다.

24마디·30쌍의 앞 음절은 모두¼박 길이였다. 사용자 요청의 시작값 분리 교정으로 그¼박 구간을 두32분음표(각⅛박)로 나눴다. 앞 시작은 유지하고 뒤 시작만⅛박 이동했다. 앞 길이는⅛박으로, 뒤 길이는 원래 끝이 유지되도록⅛박 줄였다. 뒤 음절 시작은 항상 다음 서로 다른 시작보다 앞이며 마디를 넘기지 않는다. 초 단위 아카이브 차이를 새 시각으로 환산하지 않아 실연 그루브를 연습 격자에 넣지 않았다. 중복 아닌485개 시작, 전체 음절 ID/문구/순서/기존 confirmed, 드럼·박자·BPM·음원 연결은 그대로다. confirmed 보존은 새 청취 확정을 뜻하지 않는다.

## 실행·검증

Node22.22.2/JSDOM/Vite SSR에서 기존 writeCanonical/readCanonical을 사용했고 WebSocket/HMR·watch를 끈 뒤 종료했다. writer 소스 해시는 conversion.json에 결합하고 실행 중 일치를 확인했다. 새로운 가사 분배/writer를 앱에 추가하지 않았다. Python/lxml6.1.1에서6곡 모두 MusicXML4.0 XSD와 독립 유리수 대조를 통과했다. 가사 소유 블록을 제거한 전체 XML(별도 비교한 정본 메타데이터 필드 제외)은 c14n으로 동일하고 드럼 타임라인도 같다. 전체 Song의 비가사 필드는 동일하며 가사 ID/문구/순서/confirmed와 예상한 위치·길이를 비교했다. 공통 재읽기 후 전체 Song 왕복·반복 직렬화도 통과했다.

독립 검사에서는 첫 음표 segment의 길이를 마디 연장 전체 길이와 비교해 v2-l66에서3/8 대7/8 불일치가 발생했다. XML 오류가 아니라 text 없는 extend의 뒤쪽 음가를 아직 합산하지 않은 검사기 문제였다. 같은 성부/가사 행의 연장 구간을 전체 음가로 합치고 새 음절로 세지 않도록 수정했다. 초기 실패는 verification-initial-segment-diagnostic.json에 보존했다. 수정 후 모든 위치·전체 길이 대조가 통과했다.

공통 검사는 `tools/score-production/musicxml/common/lyric_onsets.py`와 `audit_lyric_onsets.py`다. 마디별 divisions·additive meter·backup/forward·voice별 chord·pickup과 전곡 누적 위치를 유리수로 처리한다. 현재 canonical part만 검사하고 보존 보컬 원문은 제외한다. text 없는 extend는 앞 음절의 전체 길이에 합산하고 시작 음절 수에는 넣지 않는다. 자동 위치 교정은 하지 않는다.

문서 갱신 중 .agents 스킬은 보호 경로여서 일반 쓰기가 거절됐다. 승인된 원칙의 절차 참조 한 줄만 별도 sandbox 검토를 거쳐 적용했다. 실패 전 반영된 문서와 미반영 문서를 구분해 나머지를 순차 적용했다. 앱·public·history.md 보호 해시는 교정 전후 동일함을 확인했다.

## 인계와 한계

Rule에는 현행 계약, 실행 절차에는 검사 명령·순서, ADR에는 이유와 대안을 분리했다. 구형 파일의 동시 시작 읽기/보존은 유지하고, 새 정본의 작성 적합성과 혼동하지 않는다. 전체 실제 화면·인접 글자 폭 충돌·오디오/보컬 음가 정확성·앱 저장/재열기는 이번 정적 검사에 포함하지 않는다.

앱 담당은 Real Paradis 새 XML `df172871a70445cc887addf9e850395f7eb0b0e3b00548a23a849c75450579a9`만 수록 XML/Song 파생값과 관련 캐시에 반영하면 된다. 나머지5곡은 해시가 동일해 교체가 불필요하다. 공개 배포·기존 사용자 DB 덮어쓰기·다른 곡 가사 이동을 승인한 작업이 아니다. history.md의 결과 통합은 앱 담당이 맡는다.

전체 manifest/검증: `data/production/lyric-onsets-20261111/manifest.json`, `verification.json`. 정확한 인계 본문과 도구 receipt는 `real-paradis/handoff/`에 보존한다.

최종 정적 검사: 새 공통 Python 두 파일 compile 성공. 공통 CLI는 교정 후6곡에서 exit0/PASS, 교정 전 Real Paradis에서 의도한 exit1/NEEDS_REVIEW를 반환했다. 문서 검사163개·로컬 링크4,658개·앵커3,406개와 git diff --check 통과. src/public/history.md 보호 해시는 최종 시점에도 동일하다.

기존 웹앱 개발 채팅에 전체6곡 경로/해시·30쌍 교정 판단·검증·미검증·실제 반영 필요 범위를 전송했다. 도구가 같은 threadId와 isError=false를 반환해 전송 접수를 확인했다. 실제 본문 SHA와 receipt는 위 handoff 폴더에 기록했으며 앱 수록 반영 완료와 구분한다.

## 개발 측 독립 확인과 로컬 수록 반영

제작 완료 후 개발 측에서 교정본6개를 직접 읽어 SHA256과 곡 전체 유리수 시작점을 대조했다. 시작 음절1,085개·중복0건을 확인했다. 이는 실제 화면의 글자 폭 충돌 검수가 아니다.

Real Paradis만 공통 `readCanonical`과 `createVerifiedPackage`로 수록본의 source/canonicalXML 및 Song 가사를 갱신하고, 디스크에 저장한 패키지도 공통 읽기·자산 비교로 다시 확인했다. 패키지 SHA256은 `f32d6b45cbeb92b84a6146064a7bfba391daf8f64108b65b807eb1f3c0b64570`에서 `c68d01ebdac7813da019fc1749d93ab9db8d4bb6bb745da889f8b3ed14f3bb4c`로 바뀌었다. 내장 XML은 제작 교정본 `df172871a70445cc887addf9e850395f7eb0b0e3b00548a23a849c75450579a9`와 바이트가 같다.

독립 ZIP 대조에서 바뀐 항목은 `score/source`와 `manifest.json`뿐이다. Song은 가사 위치·길이 및 이에 따른 재생 캐시만 달라졌고, 음절 ID/문구/순서/confirmed·곡 ID·나머지 메타정보·마디 연결점·설정은 유지했다. 음원·PDF·기존 파생 페이지 등 다른8개 자산과 나머지5곡 패키지는 바이트가 같다. 기존 페이지를 새 검수 결과로 표시하지 않으며, 두 앱은 새 XML에서 공통 조판을 수행한다. 공통 `scoreRenderKey`의 전후 값이 달라져 이전 XML의 파생 캐시는 재사용되지 않는다.

초기 통합 비교에서 메모리 객체의 `undefined` 속성과 JSON에 없는 속성을 다르게 판정했다. 파일 쓰기 전에 멈췄으며 JSON 저장 계약으로 비교 범위를 맞춘 뒤 왕복·보존 대조를 통과했다. 메타정보를 임의 삭제하거나 원문을 재작성한 문제가 아니다.

근거와 이전 패키지는 `.tmp/lyric-onset-correction-20261111/`에 보존했다. `independent-onsets.json`, `integration.json`, `package-verification.json`이 각각 독립 시작점 검사·공통 왕복·디스크 ZIP 대조 결과다. 원래 브라우저 보관함·공개 사이트는 변경하지 않았고 화면/청취·커밋·push·발행도 하지 않았다. 이번 결과는 로컬 수록본 반영까지다.


## 후속 정정 — 기존32분음표 그리드의 가사 적용

사용자는 “가사도 그 그리드에 맞추었어야지”, “64분은 내가 과거결정이 불확실해서 잘못 말한거다”라고 정정하고,4/4 한 마디32칸과 가사 앵커의 동일 조판 좌표가 앞선 결정임을 재확인했다. 따라서 위 기록/최초 전달의64분음표 표현은 당시 경위이며 현행 작성 기준이 아니다. 기존 [32분음표 결정](adr-0005-practice-layout-and-spacing-sources.md#균등-모드-최종-정정-고정-마디32분-격자-2026-10-04)을 가사 배치에도 적용한다. 이를 표시 규칙에만 한정하고 가사 작성에는 별도 기준이 필요한 것처럼 설명한 것은 제작 담당의 해석 오류였다.

현행6곡의1,085음절을⅛박 그리드로 다시 읽어 시작과 마디 연장 전체 길이를 검사했다. 그리드 이탈 시작0·길이0·시작점 중복0이며 실제 public6패키지 source/canonicalXML도 검사한 정본과 바이트 동일했다. Real Paradis의 이미 교정한30개 시작도32분음표 그리드에 있으므로 추가 악보 수정은 하지 않았다. 이 적합성 결과를 원본 보컬 음가의 정확성이나 일괄⅛박 이동이 기존 결정에 명시됐다는 증거로 확대하지 않는다.

Rule·ADR-0030·실행 계획·절차·공통 검사기의 현행 기준을32분음표로 바로잡았다. 원본에 명시된 연음/더 짧은 음가는 기존 원칙대로 반올림하지 않고 예외 근거를 별도 검토한다. 검사기는 이탈을 보고할 뿐 자동 이동하지 않는다. 가사 스킬은 이 Rule/절차/공통 검사기를 참조하므로 다른64분음표 규칙을 유지하지 않는다. 이번 실제 자료에는 그런 예외가 없어 그리드 이탈 분기의 실행 검증은 주장하지 않는다. 근거 `data/production/lyric-onsets-20261111/grid32-verification.json`.
