# 시간 비례 SVG의 줄 폭과 쉼표 중앙 배치

- 목표: 같은 마디 구성·박자 길이의 줄은 첫 줄과 폭을 맞추고, 온마디쉼표와 부분 2분쉼표를 각각 확정한 중심에 표시한다.
- 범위: 두 앱의 공통 MusicXML 조판·쉼표 표시·파생 캐시와 조판 Rule.
- 완료 조건: 시작 박자표 공간 때문에 생긴 줄 폭 차이를 제거하고, 온마디쉼표는 마디 중앙, 부분 2분쉼표는 사용자가 확정한 1.5박 기준으로 기호 중심을 맞춘다.
- 보존: 정본·음가·가사·박당 폭·원본 줄 구성. 짧은 줄의 오른쪽 여백은 기존 승인대로 유지한다. 커밋·push·발행하지 않는다.
- 검증: 관련 정적 검사와 기존 승인 범위의 실제 수록본 Safari 출력 확인을 구분해 기록한다. 합성 시험 데이터·시험 DB는 만들지 않는다.

## 원인과 수정

첫 줄의 native 박자표 시작 공간과 이후 줄의 공간이 달랐다. ‘갑자기’ 전체 보기에서 첫 줄의 시작 공간은 88.9784 SVG단위, 이후 줄은 48이었다. 같은 4/4 네 마디 줄의 폭이 각각 1,209.9784와 1,169로 달라졌다.

`ribbon-engraving.ts`의 기존 렌더 단위 native 정책에 시작 지시 공간 처리를 추가했다. 전체 보기·인쇄 조판의 각 줄은 첫 줄의 native 시작 공간 이상을 확보한다. 더 큰 박자표·지시 공간은 그대로 유지하고 리듬 폭·음표 크기는 늘리지 않는다. 연주용 마디에는 이 공간을 추가하지 않는다. 짧은 줄·변박 줄을 모두 같은 폭으로 늘리는 처리는 하지 않았다.

전체 보기의 쉼표 중앙 보완은 명시 높이가 있는 쉼표로 제한되어 있어, 시간 비례 배치로 마디 시작에 놓인 기본 온마디쉼표가 빠져 있었다. 기존 공통 기호 경계 계산의 그 제한과 중복 판별을 제거했다. 보이는 드럼 음표가 모두 마디 전체 길이의 쉼표인 경우 기호를 마디 중앙에 놓는다.

사용자는 부분 2분쉼표도 표시 위치를 조정하되, **1·2박을 쉬면 1.5박 위치에 기호 중심을 정렬**하도록 확정했다. `centerRestGlyphs`는 점 없는 `NoteType.HALF`를 구분하여 같은 `timePosition`으로 첫 박과 다음 박 시작점을 구하고, 공통 `restCenterShift`로 그 사이에 잉크 중심을 놓는다. 온마디쉼표는 마디 중앙 규칙을 우선하며 그 밖의 부분 쉼표는 이동하지 않는다. 숨긴 가사 음표·가사 위치·음악적 시작 시각은 이동하지 않는다.

공통 캐시 정책은 `drum-time-proportional-v56-system-insets-rests`, 쉼표 표시 버전은 `svg-geometry-sync-v19`로 갱신했다. 이번 작업 중 확인에 사용한 v55·v18 캐시도 재사용하지 않는다. 앱 버전은 0.11.5를 유지했고 최종 소스 빌드번호는 `6ee6cb6995a1`이다. 정본·수록 패키지·Song은 수정하지 않았다.

## 실제 출력 확인

환경: Node 26.13.0·pnpm 12.18.0, 기존 5173 개발 서버와 macOS Safari MCP. 기존 승인 범위에서 실제 수록 파일만 읽어 조판했다. 진단용 임시 DOM은 제거했으며 합성 입력·시험 DB는 생성하지 않았다. 앱에서 악보를 열 때 파생 렌더 캐시는 새 정책으로 생성된다.

- ‘갑자기’의 일반 4마디 줄은 모두 1,209.9784 SVG단위로 일치했다. 원래 33–35의 3마디 줄은 927.9784, 36–37의 2마디 줄은 645.9784로 남았다.
- 37~40마디 쉼표 잉크 중심과 마디 중심의 오차는 0.00001 SVG단위 이하였다.
- 20·41마디의 부분 2분쉼표 중심은 전체 SVG에서 1,030.9784, 연주 SVG에서 96이었다. 각각 공통 식의 `마디 시작 + prefix + L + 0.5×Q`와 일치한다. 4분·8분쉼표 좌표는 그대로였다.
- 2분쉼표 추가 조정 전후 전체/연주 조판 각각의 음표·가사 시간 앵커 1,161개, 가사 출력 308개의 문구·상자 좌표, 마디·줄 폭이 동일했다. 한 줄·두 줄은 이 연주 자산을 공유한다. 이번에 실제 재생·진행선 이동 검사를 반복하지 않았다.
- 줄 폭·온마디쉼표 수정 후 수록 6곡, 총 587마디를 인쇄 경로로 재조판했다. 모든 영역이 유한한 양의 크기와 페이지 안 경계를 만족하고 원본 XML의 줄 시작 목록과 일치했다. 부분 2분쉼표 수정 후에는 ‘갑자기’ 93마디·4페이지를 다시 확인해 같은 조건을 통과했다. 앞선 38마디 페이지 오류가 재발하지 않았다.
- 드럼연습실에서 실제 ‘갑자기’를 열어 전체 SVG의 첫 줄·후속 줄의 끝 정렬, 36~41마디의 짧은 줄·중앙 쉼표를 화면으로 확인했다. 최종 빌드의 전체 보기에서도 줄 끝 정렬과 20마디 2분쉼표의 이동을 확인했다. 제작기 GUI의 같은 조작을 중복 실행하지 않았으며 두 앱의 공통 조판 호출 경로를 확인했다.

근거는 로컬 `.tmp/system-width-rests-20261113/`의 `audit.js`, `before.json`, `after.json`, `print-audit.json`, `print-final-suddenly.json`, `half-before-with-lyrics.json`, `half-after.json`, `player-full-top.png`, `player-full-start.png`, `player-full-final.png`에 있다. 앞의 두 PNG는 2분쉼표 추가 조정 전 화면이다. `player-full-start.png`는 파일명과 달리 21~53마디가 보이는 화면이며 37~40마디의 온쉼표 확인에 사용했다. `player-full-final.png`는 최종 빌드의 첫 줄부터 28마디까지이며 20마디의 부분 2분쉼표를 포함한다.
