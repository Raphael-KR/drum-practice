# 갑자기 38마디의 페이지 영역 오류

- 목표: 악보제작기에서 실제 수록 ‘갑자기’를 오류 없이 열고 37·38마디를 확인한다.
- 범위: 두 앱이 공유하는 MusicXML 페이지 조판과 파생 캐시 정책.
- 완료 조건: 모든 마디 영역이 유효하고, 원본의 줄별 마디 구성과 연속 전체 보기를 유지한다.
- 제외: 정본·가사·음원 변경, 합성 입력·시험 DB 생성, 커밋·push·발행.
- 검증: 실제 수록 악보의 Safari 조판·화면 확인과 변경 코드·문서의 정적 검사를 구분해 기록한다.

## 원인과 수정

제작기 오류창에서 38마디의 상단이 `1947.046875`, 첫 SVG 하단이 `1853.5323486328125`여서 높이가 `-93.5145263671875`인 것을 확인했다. 실제 수록본을 페이지 조판 경로로 읽어도 같은 페이지에 38마디가 배치됐다.

이전 수정은 `RenderSingleHorizontalStaffline`을 연주용 timeline에서만 껐다. 악보를 불러올 때 먼저 만드는 A4 페이지 조판에는 여전히 이 옵션이 켜져 있었다. XML에 명시된 페이지 경계는 처리되지만, 그 전에 페이지 높이를 넘은 줄이 자동으로 다음 페이지로 넘어가지 않았다.

이 옵션은 페이지 높이 제한이 없는 연속 전체 보기에서만 사용한다. 페이지 조판과 마디별 연주 조판은 OSMD의 자동 페이지 나눔을 유지하며 XML의 명시적 줄·쪽 경계도 존중한다. 영역 값을 임의로 보정하거나 정본을 변경하지 않는다. 파생 캐시 정책을 `drum-time-proportional-v54-paged-systems`로 갱신한다.

6곡을 실제 조판하면서 Loveholic의 75–79마디와 붉은 노을의 1–5마디는 페이지 나눔 복원 후 기본 폭에 들어가지 않아 추가 줄바꿈이 생기는 것을 확인했다. 최초 조판의 native 마디 폭·페이지 여백을 XML의 원본 줄별로 합산하고, 필요한 경우 캔버스 폭만 한 번 확장한다. 시간축·음표·가사 크기는 바꾸지 않는다. 전체 연속 보기와 마디별 연주 조판은 이 폭 재계산의 대상이 아니다.

## 검증

실제 수록본 6곡을 Safari의 공통 `renderPrintedScore`로 읽었다. 총 587마디의 영역이 유한한 양수 크기이며 SVG 경계 안에 들어왔다. 모든 곡의 줄 시작 마디가 XML의 명시적 줄·쪽 시작과 일치했다.

| 갑자기               |      93 |              4 |      1500 |

| Loveholic            |     123 |              3 |      1592 |

- ‘갑자기’ 38마디는 파생 페이지 2의 상단 약 55.05, 높이 약 141.31 SVG단위로 유효해졌다. 원본 36–37의 2마디 줄과 38–41의 4마디 줄, 46마디의 명시적 쪽 시작을 유지했다. 위 페이지 수는 내부 인쇄 캐시이며 사용자에게 보이는 연속 전체 보기의 쪽 수가 아니다.
- 로컬 악보제작기의 실제 ‘편집 열기’와 재열기, 1줄·2줄 보기의 37·38마디를 확인했다. 93개 연주 마디의 SVG 좌표가 유효하고 새 콘솔 오류·경고가 없었다. 섹션 A는 38마디 위, 마디 문구는 오선 아래에 표시됐다.
- SVG 전체 보기는 1310.578×3776의 연속 SVG 한 장을 유지했다. 처음과 36–46마디를 화면에서 확인했다. 이 수정으로 전체 보기에 종이 페이지 구분을 다시 넣지 않았다.
- 증거: `.tmp/suddenly-pagination-20261113/`의 `before.json`, `print-audit.js`, `print-audit.json`, `editor-*.png`, `editor-final.json`, `editor-console.json`. 수록 6곡 검사는 실제 렌더 결과의 영역·줄 구성 대조이며, 6곡의 모든 편집·재생 기능을 화면으로 확인했다는 뜻은 아니다.
- 앱 버전은 0.11.5, 소스 빌드번호는 `464795b480a0`이다. 변경한 조판 코드 3파일의 ESLint와 앱 TypeScript 검사를 통과했다. 원본·제작 파일은 변경하지 않았고 실제 UI 열기에 따른 정상적인 보기 상태·파생 캐시만 사용할 수 있다. 합성 입력·시험 DB·전체 회귀·편집 저장 왕복·빌드·커밋·push·발행은 수행하지 않았다.
- 추가 정적 검사: 공통 재생·컴포넌트·소스 경계, 관련 6파일 Prettier, 문서 179개·로컬 링크 4,887개·앵커 링크 3,503개와 `git diff --check`를 통과했다. 로그는 증거 디렉터리의 `lint.log`, `typecheck.log`, `structure.log`, `format.log`, `docs.log`에 있다. 최종 2줄 화면의 실제 악보는 93마디이고 마지막 줄의 빈 셀 3개는 악보 마디 수에 포함하지 않는다.
