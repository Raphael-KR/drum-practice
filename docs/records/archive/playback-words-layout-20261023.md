## 원인과 적용 방식

실제 XML로 native calculateLabel의 입력/출력 X를 대조했다. 행 조판134마디에서 XML offset에 따른 중앙 앵커12.404084가 왼쪽 넘침 보정으로15.61775390625로 이동했다. 문구 폭30.177734375가 마디 폭32에 가깝고 섹션도 왼쪽에 있어 겹친다. grid도14.500912→15.61775390625로 바뀐다. 인쇄 경로와 달리 파생 폭에서 발생하는 native 라벨 경계 문제다.

공통 연습 조판에서 native 라벨과 실제 섹션 글꼴/테두리 폭을 사용한다. 최종 오선 경계·시스템 높이 계산과 SVG 그리기 전에 문구를 폭에 맞게 줄바꿈한다. 공간이 되면 원래 native 앵커를 유지하고, 단어를 읽을 폭이 없으면 X를 유지하며 위쪽 별도 높이로 충돌을 분리한다. 인쇄 경로는 적용하지 않는다. MusicXML·음악 시각·음표 기하·완성 SVG 노드는 수정하지 않는다. 출력이 달라지는 파생 캐시 정책을 v29로 갱신한다.
