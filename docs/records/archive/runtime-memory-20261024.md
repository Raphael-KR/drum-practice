# 렌더러 메모리 후속 조사 · 2026-10-24

문서 역할: **실행·검증 기록**. [앞선 실행 개선](runtime-performance-20261024.md)의 후속이다. RSS 816.7MiB 전체를 제거 가능한 앱 메모리로 보지 않고 확인한 중복 할당을 줄였다. 구현 당시의 범위와 결과를 보존하며, 후속 발행은 [0.8.15 기록](../releases.md#release-0-8-15-20261024)을 따른다.

## 작업 당시 계획

2026-10-27~28 문서 정리 때 `docs/plans/runtime-memory-20261024.md`의 계획 다섯 항목을 원문 그대로 이곳으로 옮겼다. 아래 제외 범위는 구현 당시의 범위이며 후속 릴리스 상태와 구분한다.

- 목표: 기존 렌더러 RSS 817MiB 관측의 보관 자원을 구분하고 불필요한 복사를 줄인다.
- 범위: 공통 재생 자원의 SVG·Blob·이미지·오디오 수명과 실제 붉은 노을 재생을 조사한다.
- 완료 조건: 확인된 중복을 제거하고 원본·저장 호환성·보기 전환·재생 표시를 보존한다.
- 제외: 원본 자료 삭제, 기능 축소, 버전 변경, 커밋·푸시·발행은 하지 않는다.
- 검증: 동일 로컬 자료의 단계별 RSS·힙·자원 계측, 관련 회귀 검사와 최종 전체 검증을 기록한다.

위 값은 동일 메모리의 서로 다른 표현/소유 범위를 포함하므로 합산해 RSS 내역표로 사용하지 않는다. 특히 Blob backing은 renderer 밖에 있을 수도 있다. vmmap은 Ego의 PartitionAlloc malloc zone 해석 실패를 알렸으며 VM tag를 SVG·폰트·이미지별 정확한 소유자로 분해하지 못했다. 과거 PID12255의817MiB를 현재 PID의 측정으로 소급 분류하지 않는다.

RSS는 코드 변경 없이도 시간이 지나며 크게 달라졌다. 첫 단계별 진단의 준비 직후 PID22275는737.9MiB였으나 뒤 재생 시347.3MiB였다. 진단 도구·GC·유휴 시간·공유 페이지 resident·브라우저 회수 시점의 영향을 받는다. 따라서 **817MiB→특정 값의 고정 상주량 감소는 이번에 입증하지 않았다.**

## 확인한 불필요한 할당과 수정

1. `displayPage`가 이미 디코딩된 SVG/PNG도 `arrayBuffer`로 읽고 새 Blob으로 복사했다. Blob은 불변이므로 같은 인스턴스를 반환한다. gzip 입력의 디코딩과 실패 동작은 유지하고 전역 비압축 캐시를 추가하지 않았다.
2. 공통 `preparePlaybackAssets`가 같은 페이지를 강조 추출·연습용 보정·안전 검사·viewBox/비율 계산에서 반복 파싱했다. 페이지당 하나의 소유 문서를 만들어 순서대로 재사용한다. 강조는 원래대로 연습 보정 전에 추출한다. 단독 `highlightPage`/`practicePage` 호출은 계속 별도 문서를 파싱해 원본 Blob을 보존한다.
3. 보기별 크기를 확인하려고 SVG를 따로 파싱하던 경로는 준비된 비율과 강조 페이지 높이를 재사용한다. 실제 오선 크기·6/4 마디 폭·강조 좌표를 유지한다.
4. 첫 페이지의 큰 메타데이터를 추출한 뒤 중간 SVG를 다시 직렬화/복사하지 않는다. 첫 문서 참조를 다음 페이지까지 보관하지 않고 로컬 디코딩 배열의 큰 원본을 연습용 사본으로 교체한다. 저장/입력 배열은 변경하지 않는다.
5. 안전 검사는 같은 문서를 빌려 사용한다. 정확히 인식한 내장 글꼴만 조사 대상에서 잠시 제외하고 즉시 복원한다. 임의 외부 href/src·CSS URL/import·script/foreignObject·event 속성 차단은 유지한다. 검사 실패 시 기존 자산 유지·새 URL 해제 계약도 유지한다.

## 반복 할당 계측

Ego의 원래 DOMParser/Blob 메서드에 위임하는 임시 wrapper로 실제 runtime 준비 호출만 집계했다. 작은 패키지 진단 페이지는 양쪽 같은 조건이며 최종 전체 앱 스타일에서도 호출 수가 일치했다. 신규 합성 악보나 시험 DB를 만들지 않았다.

| 자산 준비 관측               | 수정 전5041 |    최종2884 |
| ---------------------------- | ----------: | ----------: |
| DOMParser 호출               |         169 |          36 |
| 파서에 전달한 총 문자        | 445,813,742 | 145,007,316 |
| 명시적 Blob.arrayBuffer 호출 |         102 |           3 |

| 실제 디코딩 PCM              |  68,565,368 |  68,565,368 |

명시적 바이트 읽기 약276.2MiB를 없앴다. 이는 반복 할당/복사 총량이며 동시에 상주한 양이나 RSS 감소량이 아니다. 남은3회는 오디오·글꼴 준비 등에 필요하다. SVG 준비 자체는34장당34회 파싱하며 runtime의 BPM 등 다른 XML 파싱을 합쳐36회다.

중간 진단 페이지의 직후 RSS는1016.0→612.9MiB였으나 이때는 실제 앱 스타일이 없고 최종의 임시 참조 해제 보완 전이다. 최종 감소율로 사용하지 않는다. 전체 스타일 진단에서 stage1729×478px와 같은 crop 계산을 확인했다. baseline은 도구 timeout 후 늦게 완료된 상태를 확인하고 이어 측정해 유휴 시간이 달랐다. 재생 RSS294.8→565.3MiB, GC 후326.1→523.1MiB로 서로 시점이 맞지 않으므로 전후 성능 판정에서 제외한다. 실제 상주량의 고정 감소는 추가로 통제된 장기 측정이 필요하다.

## 기능·출력 확인

- 최종 이미지34장의 SHA256은 수정 전 진단의34장과 **모두 일치**한다. 출력/내장 글꼴을 줄이거나 좌표/원본 내용을 바꾼 개선이 아니다. 조판 캐시 정책v36과 입력·출력 형식을 유지했다.
- 실제 원곡 재생: Ego 위치206.992→212.008초, context2.948→7.952초. 이 Ego 환경의 rAF 제한은 기존 기록과 같아 프레임 평가는 Safari에서만 수행했다.
- Safari MCP의 실제 로컬 player·동일 자료에서 로드1.883초, stage1024×385px·전체 높이6691px를 확인했다. 실제 context running·위치211.940→216.944초,5초360프레임·최대 간격20ms를 기록했다. 정지와 한 줄→두 줄 전환·화면 캡처 확인을 마쳤다. 청취/iPad/Safari 충돌 완치 증거로 확대하지 않는다.
- 기존 실제 제작 패키지 회귀에서 SVG당1회 파싱·검사 문서와 출력 Blob의 일치·오선 배율·실제6/4·정본/패키지 왕복을 확인한다. 기존 불안전 SVG fixture는 독립 파싱과 공유 문서 경로 모두 거부하며, 후자에서 추가 파싱이 없는지 확인한다. 기존 PNG/압축 SVG 왕복 fixture로 불변 Blob 재사용과 손상 gzip 거부를 확인한다.
- 집중5파일29검사 통과. 전체 검증 결과는 아래 최종 검증 절에 기록한다.

## 도구 한계·종료

- Ego Page.captureScreenshot은 timeout이어서 화면 검수는 승인된 Safari MCP로 수행했다. HTML 변경으로 인한 진단 페이지 HMR 후 cleanup의 undefined 오류는 상태를 먼저 조회하고 이미 runtime이 사라진 탭만 닫아 처리했다. 다른 사용자 탭을 조작하지 않았다.
- Ego baseline mount의15초 evaluate timeout은 late effect를 경고했다. ready=true·runtime·URL34개를 재조회해 실제 완료를 확인한 뒤 이어갔고 중복 mount를 실행하지 않았다. 해당 RSS는 비교 근거에서 분리했다.
- TaskSpace12 종료 전 보기 왕복에도 URL34개를 유지하고 dispose 후0개·34개 revoke를 확인했다. finish(keep:[])를 한 번 실행했고 PID23237 종료를 확인한다. Safari 임시 runtime과 resume wrapper도 해제하고 직접 만든 탭만 닫았다.5173 서버는 유지했다. Ego 업데이트는 실행하지 않았다.
- Git 제외 근거는 `.tmp/runtime-memory-20261024/`의 before/after-comparable·before/after-styled·inventory·asset-hashes·view-cycles·closure JSON, vmmap-before/after, Safari 화면, 집중/전체 검사 로그다. 임시 진단 모듈을 제품 코드나 상시 profiler로 넣지 않았다.
