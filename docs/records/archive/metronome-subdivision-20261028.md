## 구현 결과와 근거

- `src/model/metronome.ts`가 모드 순환·직접 선택·음표 위치·잘못된 분할 값 보정을 공통으로 담당한다. 기존 1500Hz/1000Hz 음색과 볼륨·25ms 예약 루프를 재사용한다.
- 자연 반복의 누적 음가, 배속 변경·끄기 후 다시 켜기의 순서를 유지한다. 전환 시 아직 시작하지 않은 일반 클릭만 취소하고 음악·카운트오프를 유지한다. 끄기에서는 일반 클릭 노드를 만들지 않는다.
- 두 앱 상단의 SVG 버튼과 설정 > 재생 > 카운트오프 아래 3분할 알약을 같은 변경 함수에 연결했다. 8분은 앰버 배경과 갈색 아이콘·글자·포커스를 공유하며 우측 설명 요소를 만들지 않았다.
- 구형 필드 누락은 경고 없이 4분으로 읽고, 명시적으로 잘못된 `clickDivision`만 사본에서 4로 보정한다. 기존 저장곡·패키지·라이브러리 백업·연습 JSON과 제작기 draft/revision 경계에 적용했다. 원본을 읽는 것만으로 덮어쓰지 않으며 작업별 안내와 제한된 진단을 한 번 제공한다.
- 실제 화면 검사에서 일반 hover 규칙이 Warm 색상을 덮는 우선순위와 설정 행의 자동 축소로 `끄기`가 줄바꿈되는 문제를 수정했다. 메트로놈의 Space/Enter는 native button 클릭으로 처리하고 전역 재생 단축키에 함께 전달하지 않도록 했다.
- 승인된 계획에 포함된 `playback`, `ux`, 파일 형식 Rule과 UI 카탈로그·생성 문서를 갱신했다. 새 패키지·음원 파일·DB 스키마·별도 타이머를 추가하지 않았다.

### 도구 문제와 미확인 범위

- Safari MCP가 만든 탭은 `document.visibilityState=hidden`이고 rAF가 1초 안에 실행되지 않아 로딩이 멈췄다. 탭 전환 요청으로도 풀리지 않아 프로젝트 지침에 따라 Ego Lite로 대체했다. 이번 성공을 Safari 성공으로 기록하지 않는다.
- Ego의 가상 공간이 실제 창에서 열리지 않은 상태에서는 스크린샷이 시간 초과했다. 같은 검증용 공간을 native UI에서 연 뒤 캡처했다. 일부 선택자 클릭이 버튼 밖으로 전달되는 도구 문제는 현재 사각형 확인 후 CDP 입력/키보드로 대체했다. 앱 준비 전 조작은 `body[data-ready=true]`를 기다린 뒤 재검사한다.
- 초기 개발 화면에서 `ResizeObserver loop completed with undelivered notifications`가 관측됐다. 메트로놈 예약 오류와 구분하며 아래 기능 검사의 결과를 대체하지 않는다.
- 지정 iPad mini (A17 Pro) 시뮬레이터가 현재 available 목록에 없었다. 새 기기·런타임 설치는 하지 않았으며 iPad 터치·Safari 응답형 검수는 미확인이다.
- 사람의 실제 청취·출력 음질/싱크, Safari의 4/4·6/8/박 분석 음원 실재생은 확인하지 못했다. 자동 시간/예약 검증과 Ego의 4/4 실제 재생을 해당 결과로 확대하지 않는다. 릴리스 전에 지정 Safari/iPad 환경과 실제 청취를 확인한다.

## 승인된 계획과 완료 기준

다음 요구와 설계는 구현 전 승인한 기준을 보존한 것이다. ‘계획·제안’ 표현과 마지막 계획 단계의 확인 범위는 당시 기록이며, 현재 구현·검증 상태는 위 결과를 따른다.

## 확정한 사용자 동작

| 현재 모드 | 4/4 한 마디의 소리 | 픽토그램 제안 | 상단 버튼 색상 | 상단을 짧게 누른 뒤 |
| --- | --- | --- | --- | --- |
| 4분 | `띳 똑 똑 똑` — 마디 첫박만 높은 음 | 기존 메트로놈 + 4분음표 표시 | 기존 앱 강조색 | 8분 |
| 8분 | `띳 똑 띳 똑 띳 똑 띳 똑` — 8분 간격으로 두 음을 번갈아 사용 | 기존 메트로놈 + 연결된 8분음표 표시 | 따뜻한 앰버 배경·짙은 갈색 아이콘 | 끄기 |
| 끄기 | 일반 메트로놈 무음 | 기존 메트로놈 + 사선 표시 | 기존 흰 배경 | 4분 |

- 새 곡의 기본값은 기존과 같이 켜짐이며 **4분 모드**로 시작한다. 음악·메트로놈 음량 기본값은 유지한다.
- 정지 중 전환은 설정만 바꾸고 재생을 시작하지 않는다. 재생 중에는 음원을 멈추거나 위치를 되돌리지 않고 다음 유효한 클릭부터 적용한다. 끄기는 즉시 일반 클릭을 음소거한다.
- 길게 누르고 있는 동안에는 기존 공통 도움말만 표시한다. 손을 떼어도 모드가 바뀌지 않는다. 도움말 화면에서도 실제 상태 전환은 차단한다.
- 카운트오프는 별도 설정과 기존 스틱 소리를 유지한다. 8분 모드로 바꿔도 일반 카운트오프를 8번으로 늘리지 않으며, 메트로놈 끄기로 카운트오프를 끄지 않는다.

### 설정 > 재생의 직접 선택

사용자 추가 요청에 따라 **카운트오프 바로 아래**에 다음 행을 배치한다.

```text
카운트오프  [기존 스위치]
메트로놈    ( 4분 | 8분 | 끄기 )
```

- 표시 이름은 **메트로놈**, 선택지는 왼쪽부터 **4분 · 8분 · 끄기**다. 하나만 선택되는 3분할 알약형 버튼이며, 누른 항목의 모드를 직접 선택한다. 선택된 항목을 다시 눌러도 해제하거나 클릭 예약을 다시 만들지 않는다.
- 설정에 있는 다른 알약형 버튼의 `segmented-control`·`settings-choice-buttons` CSS를 재사용한다. 높이·모서리·경계·선택 표시·포커스·반응형 규칙을 복제하지 않는다. 선택된 8분에는 상단과 같은 Warm 색상 변수를 적용한다.
- **우측 설명은 넣지 않는다.** 설명 문구나 빈 설명 요소·설명용 공간을 추가하지 않고, 기존 설정의 제목·조작 정렬과 간격을 따른다. 길게 누르는 공통 도움말과 접근 가능한 이름은 유지한다.
- 상단에서 전환하면 설정의 선택 항목이 즉시 바뀌고, 설정에서 선택하면 상단 픽토그램·색상과 실제 클릭이 함께 바뀐다. 창을 다시 열어도 현재 상태를 표시한다.
- 두 진입점은 하나의 모드 변경 함수와 같은 곡별 설정을 사용한다. 상단은 다음 모드를 계산해 전달하고, 설정은 선택한 모드를 직접 전달한다. 재생기 갱신·화면 동기화·저장은 같은 경로에서 한 번만 수행한다.
- 카운트오프와 같은 설정 구역에 놓이지만 메트로놈을 별도 전역 선호값으로 중복 저장하지 않는다. 카운트오프의 독립 설정·동작을 유지한다.

## 음표 간격과 소리 순서

### 박자표와 음표 단위를 구분

현재 [beatEvents](../../../src/model/model.ts)는 마디의 `beats`와 `denominator`에 따른 박 시각을 반환한다. 따라서 현재 코드가 모든 곡에서 4분 간격인 것은 아니다. 사용자에게 이 차이를 설명했고, **모드 이름대로 4분·8분 간격으로 통일**하기로 결정했다. 분모가 4가 아닌 곡의 기존 메트로놈 간격 변경은 이번 계획에 포함한다.

| 박자표 | 한 마디의 길이(4분음표 기준) | 4분 모드 | 8분 모드 |
| --- | --- | --- | --- |
| 4/4 | 4 | 4번 | 8번 |
| 3/4 | 3 | 3번 | 6번 |
| 6/8 | 3 | 3번 | 6번 |
| 2/2 | 4 | 4번 | 8번 |

예를 들어 120 BPM의 4/4 한 마디에서 4분 클릭은 `0, 0.5, 1.0, 1.5초`, 8분 클릭은 `0, 0.25, 0.5, …, 1.75초`다. BPM 숫자나 음원 속도를 두 배로 바꾸는 방식은 사용하지 않는다.

### 공통 시간 계산

1. 연주 전 구간을 제외하고 각 마디의 음가를 `beats × 4 / denominator`개의 4분음표 길이로 환산한다.
2. 곡의 음악적 시작점을 기준으로 위치를 계산하되, 재생 중에는 **자연 반복을 포함해 계속 증가하는 누적 음가 위치**를 유지한다. 4분 모드는 1, 8분 모드는 0.5 간격의 클릭 위치를 선택한다. 마디·자연 반복 경계에서 간격을 다시 시작하지 않는다.
3. 선택한 위치를 해당 마디의 박 위치로 환산하고 기존 `beatTime()`을 사용한다. 분석된 `beatTimes`가 있는 원곡은 실제 인접 박 사이에서 보간하고, 연습 BPM은 기존 출력 시간 변환을 적용한다. 음원 전체 평균 BPM으로 실제 박 시각을 덮어쓰지 않는다.
4. 자연 반복에서는 음원·악보 위치만 구간 처음으로 돌아가고, 클릭의 누적 음가와 다음 소리 순서는 이어간다. 누적 위치를 이번 반복의 원래 악보 위치로 환산한 뒤 `beatTime()`과 기존 출력 시간 변환으로 소리 시각을 계산한다.
5. 클릭 범위는 시작 포함·끝 제외로 유지한다. 마디·반복 경계의 클릭을 중복 예약하지 않는다.

4분 모드는 클릭 위치와 마디 첫박이 일치하면 기존 높은 음을 사용하고, 나머지는 낮은 음을 사용한다. 음원 분석에서 1마디 시작이 미확정인 경우에는 기존처럼 마디 첫박 강조를 만들지 않는다.

8분 모드는 연속 재생의 누적 8분음표 위치 순번에 따라 **높은 음 → 낮은 음**을 반복한다. 높은 음의 크기·음색은 모든 위치에서 같다. 첫박이라는 이유로 음량을 높이거나 소리를 추가하지 않고, 마디·자연 반복 경계에서도 교대 순서를 초기화하지 않는다. 실제 소리 발생 횟수 대신 예정된 음악적 위치를 사용하므로 일시적인 예약 지연이나 끄기 상태 때문에 순서가 밀리지 않는다.

홀수 박자·변박에서도 선택 음표의 간격을 지킨다. 예를 들어 3/8에서는 4분 모드가 두 마디에 걸쳐 3번 울리고, 8분 모드의 소리는 `띳 똑 띳 | 똑 띳 똑`으로 이어진다. 4분 격자와 일치하지 않는 마디 시작에 첫박 표시용 클릭을 추가하지 않는다. 분모 16의 홀수 박자도 같은 누적 음가 기준으로 검증한다.

### 자연 반복과 사용자 조작의 기준

| 상황 | 클릭 위치·소리 순서 처리 |
| --- | --- |
| 다음 마디 진행·구간 자연 반복 | 누적 음가와 8분 교대 순서를 유지한다. 반복 경계에서 첫 소리를 강제로 추가하거나 `띳`으로 초기화하지 않는다. |
| 모드 전환·끄기 후 다시 켜기 | 재생 중 누적 음가를 유지한다. 다음 유효한 4분/8분 위치부터 적용하며, 끄기 동안에도 위치 계산은 이어진다. |
| 재생 중 배속 변경·연속 재생의 내부 cycle 재생성 | 같은 음악적 위치와 다음 소리 순서를 새 출력 시간에 연결한다. 내부 재생기 재시작을 사용자의 재시작으로 취급하지 않는다. |
| 사용자가 재생 시작·재시작·탐색·마커/구간 이동을 실행 | 최종 이동 위치의 원래 악보 음가를 기준으로 클릭 위치와 순서를 새로 맞춘다. 중간 박으로 이동하면 다음 유효한 음표 위치부터 울린다. 카운트오프 적용 여부는 기존 이동 동작의 정책을 따른다. |

정지 중 이동은 소리를 내지 않고 다음 재생의 기준 위치만 정한다. 모드 변경 버튼을 누른 순간을 새 박으로 삼거나 지난 클릭을 몰아서 내지 않는다.

예를 들어 120 BPM에서 3/8 한 마디의 길이는 0.75초다. 이 마디를 자연 반복할 때 4분 클릭은 연주 시작 기준 `0, 0.5, 1.0, 1.5, …초`를 유지한다. 반복 시작인 0.75초에 클릭을 추가하지 않는다. 8분 클릭은 `띳 똑 띳 | 똑 띳 똑`으로 이어진다. 원곡의 실제 템포가 변하는 경우에는 같은 음가 간격을 실제 박 시각에 매핑하므로 초 단위 간격은 변할 수 있다.

## 기존 코드를 재사용하는 설계

| 책임 | 구현 대상과 계획 |

| 모드와 클릭 위치 | 신규 예정 `src/model/metronome.ts`에 모드 판정·순환·분할 값 정규화와 클릭 이벤트 계산을 둔다. 기존 `beatTime()`을 재사용하며 UI나 Web Audio에 의존하지 않는 함수로 만든다. 재생기는 cycle 사이의 누적 음가를 전달하며, 그때마다 다른 소리 계산 함수를 만들지 않는다. |
| 소리와 예약 | [audio-core.ts](../../../src/modules/audio/audio-core.ts)의 `Player.pulse()`를 그대로 사용한다. 현재 높은 음 1500Hz·낮은 음 1000Hz, 음량 곡선·출력 제한기·볼륨 경로를 공유한다. |
| 공통 버튼 | [playback-forms.ts](../../../src/modules/playback/playback-forms.ts)·[playback-shell.ts](../../../src/modules/playback/playback-shell.ts)에서 상단용 버튼과 카운트오프 아래 선택 행을 생성한다. | 설정 선택 스타일 | [공통 알약형 CSS](../../../src/modules/playback/styles/06-responsive.css)의 `segmented-control`·`settings-choice-buttons`를 재사용한다. 기존 선택·hover 배경과 전경·테두리·포커스 색상을 필요한 역할별 변수로 연결하고, 메트로놈 8분 선택 상태에만 공통 Warm 팔레트를 적용한다. 변수 미지정 시 기존 색상·외형을 유지한다. |
| 표시·도움말 | [icon-svg.ts](../../../src/shared/ui/icon-svg.ts), 공통 재생 CSS, [UI 카탈로그](../../../src/shared/ui/ui-catalog.json)와 i18n 문구를 사용한다. 도움말의 기존 `켜기/끄기` 안내도 3단계로 수정한다. |
| 저장·가져오기 | [practice-library.ts](../../../src/platform/storage/practice-library.ts)의 새 가져오기 기본값에 4분 모드를 포함하고, 기존 곡·백업 복원은 저장된 값을 보존한다. |

`beatEvents()`는 박자 맞추기 미리듣기와 기존 박 분석 검증에서도 사용하므로 일괄적으로 4분·8분 계산으로 바꾸지 않는다. 일반 재생기의 클릭 이벤트만 새 함수로 연결한다. 같은 소리를 내는 함수나 별도 AudioContext·반복 타이머·음원 분석 과정을 추가하지 않는다.

### 재생 중 전환과 성능 보존

- 현재 `Player`는 한 재생 cycle마다 클릭 목록을 만들고 25ms 간격의 예약 루프에서는 다음 이벤트만 읽는다. 이 구조를 유지하며 매 tick·화면 프레임마다 목록을 다시 계산하지 않는다.
- cycle에는 소스 구간과 별도로 시작 시점의 누적 음가를 연결한다. 다음 자연 반복 cycle은 앞 cycle이 끝난 누적 위치에서 시작한다. 곡 위치가 같아도 반복마다 클릭 위치·음색이 다를 수 있으므로, 원본 구간의 이벤트 목록을 그대로 되감지 않는다. 누적 정보는 현재 재생 세션의 상태이며 곡 설정에 별도 저장하지 않는다.
- 모드가 바뀔 때만 현재·미리 준비한 다음 cycle의 **일반 클릭** 목록을 갱신한다. 음악 소스, cycle의 음악 시작 시각, 재생 위치, 반복 범위, 카운트오프 예약은 유지한다.
- 이미 약 150ms 앞까지 예약한 일반 클릭은 음악·카운트오프와 구분해 관리한다. 아직 시작하지 않은 이전 모드의 클릭만 취소하고 새 간격으로 예약하여 겹침을 막는다. 이미 울린 클릭을 다시 내지 않는다.
- 끄기에서는 일반 클릭의 새 Oscillator 생성을 생략한다. 카운트오프는 독립적으로 유지한다. 다시 켤 때는 계속 진행된 누적 음가를 기준으로 시작한다.
- 종료·곡 교체·화면 해제 시 새 이벤트 목록과 클릭 소스 참조도 정리한다. 모드 전환을 반복해도 타이머·노드가 누적되지 않는 것을 확인한다.

## 픽토그램과 도움말 제안

- 기존 메트로놈 윤곽을 공통으로 두고, **4분음표 / 연결된 8분음표 / 사선**으로 현재 상태를 구별한다. 작은 표시가 실제 크기에서 읽히는지는 구현 후 검수한다.
- 운영체제 글꼴의 음표 문자를 그대로 넣지 않고 기존 공통 SVG 방식으로 그린다. 외부 아이콘 패키지나 래스터 이미지를 추가하지 않는다.
- 현재 버튼 위치·크기·간격·반응형 터치 영역을 유지한다. 4분은 기존 앱 강조색(플레이어 블루·제작기 오렌지), 끄기는 기존 흰 배경을 사용한다.
- 사용자 추가 요청에 따라 **8분 모드는 두 앱 공통의 Warm 톤**으로 구분한다. 따뜻한 앰버(금빛 주황) 배경에 짙은 갈색 픽토그램을 제안하며, 제작기의 4분 오렌지와도 색조·밝기가 구별되도록 한다. 공통 CSS 색상 변수로 관리하고 hover·포커스에서도 8분 색상 구분을 유지한다. 실제 색상값과 대비는 구현 후 두 앱에서 검수한다. 색상뿐 아니라 음표 모양으로도 상태를 구별한다.
- 상단용은 2상태 checkbox 대신 `button type="button"`으로 바꾼다. Tab으로 접근하고 Enter/Space·터치로 한 단계씩 전환한다. 접근성 이름과 도움말에는 현재 모드와 다음 동작을 제공한다. 세 상태를 checkbox의 중간 체크 상태로 표현하지 않는다.
- 명칭은 항상 **메트로놈**으로 유지한다. 도움말 예: `현재: 8분음표. 두 소리를 번갈아 들려줍니다. 짧게 누를 때마다 4분 → 8분 → 끄기로 바뀝니다.`
- 공통 길게 누르기·선택 방지·포커스 표시를 유지한다. 기존 설정 > 재생에 위 선택 행을 추가하며, 별도 팝업이나 상단 버튼은 추가하지 않는다.

### Warm 상태색의 공통 CSS 적용

- 기존 알약형 CSS의 hover 배경은 파란 계열로 고정되어 있다. 선택색만 교체하면 마우스를 올렸을 때 Warm 표시가 사라지므로 선택·hover·누름·포커스 상태를 함께 다룬다.
- 배경·전경(글자/아이콘)·테두리와 필요한 상태별 색상을 공통 CSS 변수로 받도록 한다. `--segment-accent` 등 기존 변수는 재사용하고, 새 변수의 기본값은 현재 색상으로 둔다. 모양·크기·그림자 구조·전환 효과는 기존 규칙을 재사용한다.
- 상단 8분 버튼과 **선택된** 8분 알약에 같은 의미의 Warm 팔레트를 연결한다. 4분·끄기 및 선택되지 않은 8분 버튼에는 기존 선택/비선택 색상 규칙을 적용한다. 앱 전체 강조색이나 알약 그룹 전체 색상을 Warm 톤으로 덮어쓰지 않는다.
- 두 앱에서 기본·hover·누름·키보드 포커스 상태를 확인한다. Warm 배경 위의 글자·아이콘·포커스 표시를 구별할 수 있어야 하며, 기존 보기·악보 형식·제목 순서 알약의 색상과 동작은 유지되어야 한다.

## 저장 호환성과 변경하지 않는 동작

- 기존 파일의 `click: true`이고 `clickDivision`이 없으면 4분 모드, `click: false`이면 끄기로 읽는다. 필드 누락은 정상적인 구형 파일이므로 보정 경고를 내지 않는다. 숫자 4·8은 그대로 사용하며, 그 밖의 분할 값은 **해당 필드만 4로 보정**한다. 이를 이유로 곡이나 백업 전체의 열기를 거부하지 않는다.
- 모드는 곡별 기존 `settings` 저장 경로를 사용한다. 별도의 전역 설정이나 IndexedDB 저장소를 추가하지 않는다. 기존 Song 버전과 원본 음원·악보·박 시각은 유지한다.
- 저장 상태는 `click`과 `clickDivision`에서 도출한다. 별도의 `mode` 값을 중복 저장하지 않는다. 끄기에서 다음 조작은 이전 선택과 관계없이 4분으로 간다.
- 새 악보·음원 가져오기는 4분 켜짐으로 초기화하고, 이미 저장한 곡과 명시적 사용자 설정 복원은 8분 선택도 보존한다. `.drumscore`, 제작기 저장, 연습 JSON 왕복에서 필드 보존을 확인한다.
- 구버전 앱이 새 8분 필드를 무시하면 기존 켜짐 메트로놈으로 동작할 수 있다. 구버전에서 8분 지원이나 재저장 시 새 필드 보존을 보장하지 않는다.
- 박자 맞추기 창의 미리듣기는 [기존 계약](../../reference/product/audio-practice.md#audio-practice--박자-맞추기-전용-메트로놈)을 유지한다. 상단과 스타일·음색을 공유하되 미리듣기의 독립적인 켜기/끄기·첫박 확인·카운트오프 동작과 저장 설정 경계는 유지한다. 상단 버튼의 3단계 상태가 이 창으로 새어 들어가지 않도록 별도 회귀를 둔다.

### 잘못된 분할 값의 제한적 보정

- 공통 정규화 함수를 `.drumscore`·기존 저장곡·연습 JSON 읽기 경계에서 최종 `validateSong()` 전에 적용한다. 형식이 정상인 설정 객체의 `clickDivision`만 다루며, 나머지 설정과 악보·음원의 유효성 검사는 그대로 유지한다.
- 보정은 읽은 데이터의 작업 사본에 적용한다. `click: false`는 그대로 끄기이며, 음량·BPM·박 시각·마커·반복 구간·원본 파일은 바꾸지 않는다. 읽기 보정만을 이유로 원본 파일이나 기존 저장 레코드를 자동으로 덮어쓰지 않는다. 이후 기존 저장 동작에는 보정된 값 4가 반영된다.
- 사용자에게는 기존 알림 경로로 `메트로놈 분할 설정을 4분으로 보정했습니다.`를 알린다. 여러 곡을 한 번에 복원할 때는 해당 작업의 보정 결과를 묶어서 한 번 안내한다. 새 확인 팝업이나 설정 행의 우측 설명은 추가하지 않는다.
- 진단에는 보정 대상 식별자·필드명·허용값·실제 잘못된 값과 타입·적용값을 필요한 범위로 남긴다. 비밀정보·불필요한 개인정보·전체 곡 데이터는 출력하지 않는다. 보정 여부는 결과로 반환하고 재검증·화면 갱신마다 같은 경고를 반복하지 않는다.
- 손상된 필수 데이터나 다른 필드 오류까지 정상으로 처리하는 보정으로 확대하지 않는다. 기존 `click` 값도 정규화 대상에 추가하지 않는다. 분할 값 보정 후에도 다른 검증 오류가 있으면 그 오류는 기존 경로로 보고한다.

## 구현 순서와 단계별 완료 조건

1. **상태·시간 계산**: 기존 박 이벤트와 분리된 공통 모드·음표 위치 계산을 추가한다. 4/4·3/4·6/8·2/2·홀수 박자·변박, 실제 박 시각, 자연 반복의 누적 음가 유지와 사용자 탐색의 재정렬, 구간 끝 제외 계산을 확인한다.
2. **재생기 연결**: 기존 두 음색과 예약 루프를 재사용한다. 정지/재생/카운트오프/반복 중 전환에서 음악의 정지·재시작, 중복 클릭, 카운트오프 변화가 없어야 한다. 자연 반복·배속 변경·끄기 후 다시 켜기에서도 누적 클릭 흐름을 유지한다.
3. **공통 UI·저장 연결**: 두 앱의 상단 버튼·설정 선택 행·아이콘·도움말·키보드와 저장을 연결한다. 상단 순환과 설정 직접 선택을 같은 변경 함수로 연결하고 양쪽 표시를 동기화한다. 공통 알약형 CSS의 상태색 변수를 연결하고 잘못된 분할 값만 보정하는 공통 읽기 경로를 추가한다. 다른 설정과 미리듣기 2상태 조작을 보존한다.
4. **정본·회귀 검증**: [재생 Rule](../../reference/product/playback.md)과 필요한 [UX](../../reference/product/ux.md)·[음원](../../reference/product/audio-practice.md)·[파일 형식](../../reference/score/file-formats.md) 문서를 실제 구현과 맞춘다. UI 카탈로그가 바뀌면 생성 문서도 갱신한다. 아래 검사 결과와 미확인을 `history.md`에 기록한다.

기존 `tests/{unit,integration,local-media}` 검사 구조를 사용한다. 음표 위치·전환은 portable 검사에, 실제 패키지와 Player·화면 회귀는 기존 해당 검사에 추가한다. `beatEvents`의 기존 분석·미리듣기 검사를 삭제하거나 새 메트로놈 출력에 억지로 맞추지 않는다. 새 합성 시험자료·시험 DB가 필요한 항목은 구현 당시 적용 지침과 사용자 허가 범위를 먼저 확인한다.

구현 후 lint·서식·세 타입·i18n·구조·문서·관련 회귀·두 앱 빌드를 확인한다. 로컬 Safari에서 4/4·6/8과 실제 박 분석 음원, 1줄/2줄 화면의 전환·청취를 확인하고 iPad 터치 검수는 [기기 검수 절차](../../how-to/verify-ipad.md)를 따른다. 자동 예약 검사를 실제 청취·실기기 검증으로 대신 보고하지 않는다.

## 이번 계획 작업의 확인 범위

코드와 현행 문서의 연결 관계를 읽어 계획을 작성했다. 음색 재사용, 공통 버튼, 저장 기본값, 미리듣기와 카운트오프의 분리 지점을 확인했으며 기능을 구현하거나 재생·청취하지 않았다. 문서 검사의 실제 결과는 `history.md`에 기록한다.
