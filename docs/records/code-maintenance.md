## 공통 재생 폼과 설정 코드 정리 — 2026-11-09

- 목표: 기존 동작을 유지하면서 공통 재생 코드의 불필요한 전달 단계와 역할 혼재를 줄인다.
- 범위: `playback-forms.ts`의 빈 함수·전달 함수와 사용하지 않는 버튼 ID, 설정 선택·상태 동기화 함수의 위치, 두 앱의 호출부와 기존 검사 참조를 정리한다.
- 완료 조건: 동일한 HTML·설정 함수 본문·이벤트 순서를 유지하며 두 앱이 같은 공통 모듈을 사용한다. 옮긴 함수와 바꾸지 않은 파일을 변경 전 자료에 대조한다.
- 제외: 저장 형식·악보·CSS·새 사용자 기능 변경, 테스트 실행·빌드·화면 검수, 버전 인상·커밋·푸시·발행. 앞선 문서 변경은 보존한다.
- 검증: 함수 본문·호출부 정적 대조, `pnpm run check`, `git diff --check`. 실행 기록은 `.tmp/code-cleanup-20261109/`에 둔다.

### 확인한 정리 대상

- `loopFieldsHTML()`은 빈 문자열만 반환한다. 반복 구간의 실제 콘텐츠는 기존 `loopExtra` 슬롯으로 들어오므로 빈 함수가 필요하지 않다.
- `playbackTransportRightHTML()`은 `progressFieldHTML()`에 진행 위치 ID만 넘긴다. 함께 전달하던 `mark`·`sound` ID는 렌더링과 이벤트 연결에서 사용하지 않는다. 마킹 기능과 음량 설정 자체는 유지한다.
- `playback-forms.ts`가 HTML 생성 외에 설정 카드 선택·스크롤 및 메트로놈·선택 버튼 동기화를 담당한다. 카드 선택은 기존 `playback-settings-layout.ts`, 상태 동기화는 기존 `playback-settings.ts`로 옮긴다. 함수 본문과 실행 순서를 변경하지 않는다.

### 실행 결과

- 설정 함수 3개의 선언·본문이 이동 전과 같은지 AST로 대조했다. 앱 소스 10개도 import·타입을 제외한 문장을 비교해, 명시한 빈 함수/전달 함수 치환과 미사용 ID 제거 외의 실행 문장 변경이 없음을 확인했다. 정적 대조는 앱 실행 성공의 증거로 대신하지 않는다.
- `playback-forms.ts`는 331줄에서 177줄로 줄었다. 새 기능 모듈이나 의존성을 추가하지 않고 기존 설정 모듈로 책임을 나눴다.
- 기존 테스트 2개의 호출부를 새 함수 경로와 인자에 맞췄다. 기존 기대값을 유지했으며 테스트를 실행하거나 새 시험 데이터를 만들지는 않았다.
