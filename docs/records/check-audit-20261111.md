### 유지한 검사와 구체적 이유

- **브라우저 저장 호환성:** 폐기 SQL은 활성 실행 경로가 없지만, 구형 IndexedDB 이관·bytes-v1/Blob·snapshot·백업/복원·v1 가사 읽기에는 현재 소비자가 있다. 같은 `legacy`·`retired` 이름만으로 제거하지 않았다. 삭제 동작이 복구 저장소를 되살리지 않는 검사도 실제 삭제 계약을 확인하므로 유지한다.
- **의미가 있는 부정 검증:** XSS·외부 URL 차단, 사라져야 하는 로딩/도움말/임시 복사 요소, 구형 파트의 v2 전환, 선택·재생 종료 상태, HTML 내보내기 금지와 API 404는 현재 입력·출력 계약을 확인하므로 유지한다.
- **독립된 검사 층:** 저장 codec과 실제 DB/패키지 왕복, 소스 의존 경계와 완성 player 번들 경계, 음표/가사 의미와 실제 조판 좌표, 로컬 결과와 원격 CI/공개 응답은 서로 대체하지 않는다.
- **같은 이름의 다른 가사 교정:** m32·m39·m48에는 분할·앵커·아카이브와 적용 전제 차이가 있다. 일반화한 batch 표에 넣거나 삭제하지 않았다.
- **Worker로 로드되는 오디오 모듈:** import 그래프에서 처음 분리되어 보인 beat tracking·stretch 모듈은 `new URL(..., import.meta.url)` Worker 진입점으로 사용된다. 해당 단위 검사는 유지한다.
- **Python·곡별 제작 검사:** 원본 PDF의 독립 기대값·MusicXML 의미/규격·MIDI·인계 파일/해시와 Apple 보조 도구의 시간/모호성 경계를 검증한다. 과거 실측 재현은 명시적 opt-in이며 일상 CI/릴리스에 추가하지 않는다.
- **릴리스 단계:** PR과 병합된 main, 앱 번들·Sites 패키징·공개 응답은 입력/산출물이 다르다. 동일 입력의 통과 결과를 재사용하는 기존 규칙과 각 단계의 고유 검사는 유지한다. iOS 실기기·시뮬레이터는 사용자 별도 요청 범위다.

종료 판단은 위 범위의 현재 소스와 확인한 후보를 기준으로 한다. 앞으로의 코드 변경에서 불필요한 검사가 다시 생기지 않는다는 보증은 아니다.

- 검증: 기존 메모리 fixture·jsdom·fake-indexeddb·프로젝트 `.tmp`의 임시 사본만 사용한다. 실제 악보 자료와 글꼴은 기존 파일을 읽고, 네트워크·오디오·화면 측정은 mock으로 대체한다.

### 실행 결과와 수정

Node 26.13.0·pnpm 12.18.0·Vitest 5.1.0에서 지정한 15경로를 `pnpm exec vitest run`으로 실행했다. 직전 `check`가 준비한 생성 파일이 존재하고 관련 입력이 바뀌지 않았음을 확인해 사용했다.

- 최초 실행: **15파일, 230개 중 229개 통과·1개 실패**, Vitest 보고 전체 시간 10.86초.
- 실패 원인: 옮긴 폰 가로 설정 테스트가 일반 설정 메뉴를 `화면 → 재생 → 정보 → 악보`로 잘못 기대했다. 실제 공통 `settingsPanel`은 정보 카드를 마지막에 삽입하므로 기존 순서는 `화면 → 재생 → 악보 → 정보`다. 앱 복원 오류가 아니며 테스트의 기대값 두 곳만 바로잡았다.
- 추가 정리: `player-recovery-removal.test.ts` 끝에서 결과를 확인하지 않고 DB를 다시 열고 닫던 호출 1개를 제거했다. 현행 DB 재열기와 두 저장소의 결과는 `retired-score.test.ts`가 이미 검증한다. 구형 v2에서의 archive 삭제·현행 버전 전환·실제 악보/편집 이력/초안 보존 assertion은 유지했다.
- 수정 파일 재실행: `playback-runtime` 9개와 `player-recovery-removal` 1개가 각각 통과했다. 나머지 13파일은 테스트·앱·의존성 입력이 그대로여서 최초 통과 결과를 재사용했다.
- 최종 결과: **15파일의 230개 모두 통과, 실패·skip·todo 0개**다. 한 번에 모두 재실행한 결과로 표현하지 않는다. 실행 로그와 JSON은 `.tmp/check-audit-20261111-repeat/focused-regression/`의 `initial`, `runtime-recheck`, `recovery-recheck` 파일과 `result.json`에 보관한다. SVG 차단 사례의 `Unsafe score SVG` 출력은 예상한 거부 결과이며 실행 오류가 아니다.

비용이 가장 큰 두 파일은 `ui`와 `playback-screen`이었다. 최초 실행에서 Vitest가 보고한 파일별 시간은 각각 약 9.53초·6.73초다. 병렬 실행 결과이므로 합산하지 않으며 앱 로딩·스크롤 성능 측정치로 사용하지 않는다. 기존 삭제된 510ms 대기 외에 이번 실행에서 제거할 근거가 있는 추가 대기나 검사 파일은 확인하지 못했다.

jsdom과 모의 오디오/치수로 실행한 회귀검사다. 실제 Safari 화면 배치·청취·스크롤 성능, iOS 실기기·시뮬레이터, 전체 테스트·빌드·배포의 성공을 의미하지 않는다. 추가 사용자 결정이 필요한 사항은 없다.

수정한 두 테스트 파일의 ESLint·Prettier와 앱/테스트 타입 검사를 통과했다. 문서·링크·앵커와 `git diff --check`도 통과했다. 이번 후속 작업의 변경은 두 테스트와 이 기록·`history.md`뿐이다. 시작 해시와 대조해 `src` 255파일(생성 파일 2개 포함), 읽은 악보 입력, 이전 history 원문과 HEAD/index 보존을 확인했다. 근거는 같은 실행 디렉터리의 `lint.log`·`format.log`·`types.log`·`docs.log`·`preservation.json`에 둔다.
