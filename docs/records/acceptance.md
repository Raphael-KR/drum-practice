# 제품 수용 상태

문서 역할: **사실·연구 기록**. 원문 날짜·입력·환경·결과·실패·미확인은 각 절의 당시 상태다. 이번 통합에서 과거 검증을 재실행하지 않았으며, 기록의 “현재”는 원래 작성 시점이다. [기록 안내](README.md)와 [현행 정본](../RULES-INDEX.md)을 구분한다.

<a id="acceptance--검증-현황"></a>

## 검증 현황

최신 자동 검사·공개 반영은 [Sites 발행 기록](../how-to/release.md#sites-publication--sites-발행-절차)을 따른다. 아래는 실기기 사용자 확인 이력이며 최신 코드 전체의 검증 상태를 대신하지 않는다.

최신 사용자 확인: 공통 0.7.12, 2026-10-15. 자동 검사·브라우저 관측·사용자 실기기 확인·발행 확인을 구분한다.


원문 출처: `docs/operations/acceptance.md`. 원래 날짜·상태·실행 경로는 위 원문 기준이다.

### 0.7.12 — 붉은 노을 iPad 실기기 사용자 확인

- 확인일: 2026-10-15. 공개 v0.7.12에서 사용자가 iPad 실기기로 붉은 노을을 확인했다.
- 사용자 보고: “아이패드에서 붉은 노을 확인했어. 악보도 잘 나오고 박자도 잘 맞네.”
- 결과: 붉은 노을 악보 표시 정상, 음원과 박자 일치에 대한 사용자 청취 확인 완료.
- 릴리스: 구현 `12580ec`, 소스 빌드 `115dee39d643`, Sites 버전69. 수록본은 `app-01`이며 [앱 반영 기록](songs/red-sunset.md#red-sunset-app-integration--붉은-노을-앱-반영)을 따른다.
- 범위: 해당 곡의 iPad 실기기 표시·청취 확인이다. 재생 모드·확인 마디 범위는 별도로 지정되지 않았으므로 두 모드 전곡 검사나 자유 엔딩134–137의 개별 타격 시각 확정으로 확대하지 않는다. 기존 자동 검사·브라우저 계측과 별도 근거로 기록한다.

### 0.7.11 — iPad 실기기 사용자 확인

- 2026-10-15 공개 발행 후 사용자가 iPad 실기기에서 확인했다.
- 사용자 보고: “아이패드에서 확인했어. 하단 버튼 크기 좋아졌네. 잘 된다.”
- 확인 결과: 악보 재생 화면의 하단 바로가기·구간 버튼 크기 개선이 실기기에서도 정상임을 사용자 확인으로 기록한다.
- 범위: 이번 하단 버튼판 개선에 대한 확인이다. 다른 기능의 전체 회귀나 기기별 성능 검증으로 확대하지 않는다. 에이전트의 데스크톱 Safari 검증과 별도 근거다.
- 릴리스: 구현 `cc8b677`, 소스 빌드 `9e84b3a09483`, Sites 버전68. [발행 기록](../how-to/release.md#sites-publication--sites-발행-절차)을 따른다.

<a id="acceptance--남은-확인-범위"></a>

### 남은 확인 범위

- 실제 iPhone/iPad에서 새 음원 파일 선택·긴 곡 분석·변환 대기·저장소 유지·앱 전환 후 복귀.
- 내장/외장 출력 장치의 실제 메트로놈 지연, 카운트 음량, 고정 BPM 변환 음질.
- 다른 라이브 음원의 전체 박 추적과 연주 시작 후보 정확도. 추정 실패 시 수동 보정 흐름 포함.
- 한 줄/두 줄 보기에서 사용자가 실제 연주하면서 느끼는 가독성과 탐색·구간 조작.

이 항목은 이번 문서 정리로 새로 실패한 문제가 아니라 검증 범위의 경계다. 이미 확인한 개별 기기·곡 결과는 해당 기록을 우선하고, 과거의 포괄적인 미검증 문구로 되돌리지 않는다. 1.0 최종 수용 완료를 선언하지 않는다.

<a id="acceptance--과거-검사-취급"></a>

### 과거 검사 취급

이전 QA·조사 문서 보관본은 사용자 요청으로 삭제했다. 현재 남은 근거로 확인할 수 없는 결과를 재검증 완료로 간주하지 않는다. 서로 다른 검사의 시간·테스트 수를 합쳐 새 결과로 보고하지 않는다.

<a id="acceptance--실험-자료-정리-중-실행-결과"></a>

### 실험 자료 정리 중 실행 결과

2026-10-13 17:48 KST에 시작한 `npm run test:drum -- --maxWorkers=4`는 114파일·636테스트 통과(20.25초). 이후 빌드 출력 디렉터리 생성 순서 및 제작 helper 경로·오류 안내를 수정했다. 이 후속 수정에 대한 재시험과 빌드는 실행하지 않았다. 새 전역 시험 사전 허가 지침을 적용하며, 정리 중 생성된 로그도 삭제한다.
