# 120 → 80 BPM 오추정 보정 결과 (2026-10-13)

현재 분석기를 유지하면서 강한 점4분음표 간격(3:2 비율)을 실제 4분음표로 오인하는 후보 선택을 보정했다. 곡 이름·파일 해시 조건은 사용하지 않는다.

## 원인과 변경

- 기존 후보 선택은 단일 간격의 자기상관 × 템포 prior를 사용했다. 이후 소수점 보정에서만 1~4배 간격을 합산했으므로 처음 선택한 80BPM을 벗어나지 못했다.
- 해당 녹음의 32kHz 진단: 0.75초(80BPM) 상관 약 0.369, 0.5초(120BPM) 약 0.236. 그러나 120BPM의 4박인 2초 상관은 약 0.567로 강했고, 80BPM의 4박인 3초 상관은 약 0.138이었다.
- 기존 후보보다 1.5배 빠른 근처의 국소 최대값을 추가로 확인한다. 원래 점수가 기존의 70% 이상이고, 1~4박 누적 근거가 20% 이상 강할 때만 교체한다. 3:2 후보 외의 기존 선택·정밀 보정·첫 박 추정은 유지한다.
- 느린 2/3배 후보까지 대칭으로 적용하는 초안은 합성 90BPM을 60으로 바꾸는 회귀가 있어 폐기했다. 단순히 네 간격을 모든 후보 점수에 더하는 방식도 다른 곡을 바꿔 채택하지 않았다.
- 강세만 있고 보조 박 근거가 부족한 리듬은 자동으로 1.5배 올리지 않는다. 진짜 60/80/90BPM과 기존 40~240BPM 단순 클릭 회귀를 유지한다.
- 분석기/캐시 계약을 v3로 분리해 v1·v2의 이전 추정 결과를 새 가져오기에서 재사용하지 않는다. 기존 서버 행과 이미 저장된 사용자 곡·수동 보정은 수정하지 않는다.

## 동일 16곡 전후 비교

Apple M4 Pro / Ego Chromium 152, 실제 앱의 32kHz 디코딩·스테레오 RMS 합성·첫 90초. 이전/수정 함수를 같은 브라우저와 같은 버퍼에서 각 3회 교대 실행했다. 별도 워밍업 후, 테스트/빌드가 끝난 상태에서 시간을 다시 측정했다. 파일 읽기·디코딩은 제외, 채널 합성과 분석을 포함한다. 이전 44.1kHz 라이브러리 비교 시간과 직접 비교하지 않는다.

- 곡별 중앙값의 중앙값: 이전 14.55ms → 수정 14.20ms. 차이는 측정 변동 범위로 해석하며 속도가 개선됐다고 주장하지 않는다.
- 혼자가 아닌 나: 80.0 → 120.0BPM. 나머지 15곡의 BPM 동일. 16곡 모두 첫 박 추정값 동일, 각 3회 BPM 동일. 음원 SHA-256 16개 모두 이전 기록과 일치.
- 이전 비교와 같은 기준 9곡에서 ±2% 일치 7/9 → 8/9. 붉은 노을은 137.9 그대로이며 인쇄 악보 134와 해당 녹음의 차이는 미확정이다. 기준 없는 7곡은 정답 판정을 하지 않는다.
- 박 위치 알고리즘은 변경하지 않았으므로 첫 박/마디 첫 박의 정확도를 개선했다고 주장하지 않는다. 모든 3:2 음악적 모호성을 해결한 것은 아니다.

## 검증 및 적용 상태

- 집중 5파일/35테스트 통과. 120BPM 3+3+2 강세와 약한 quarter pulse 재현, 느린 반복으로의 오변경 방지, 진짜 느린 템포 보존, 근거가 없는 패턴의 무조건 가속 방지 검사 포함.
- 전체 드럼 앱 107파일/585테스트 통과. 이후 캐시 회귀 보강 최종 2파일/9테스트 통과.
- i18n/타입 검사, editor/player 분리 빌드 및 앱 경계 통과. 기존 큰 청크 경고는 남아 있다.
- 독립 브라우저 확인 96회 + 별도 시간 측정 96회, 모두 같은 전후 BPM. 앱 기본 분석 경로와 같은 source를 격리한 시험이며 16곡을 사용자 목록에 중복 저장하지 않았다.
- 구현은 로컬 소스에 반영. 앱 버전은 유지하고 소스 빌드번호 갱신. 커밋·푸시·공개 발행 미수행. 실제 iOS/iPadOS 시간은 미측정.
- STT·AFM은 리듬 주기 진단에 필요하지 않아 사용하지 않았다.
