## 2. 해결할 문제

기존 연습 영상에는 현재 악보와 다음 악보가 두 줄로, 가사는 별도의 하단 영역에 표시된다.

1. 연주 중 첫 줄에 시선이 머물러 둘째 줄을 미리 읽기 어렵다.
2. 가사가 악보와 떨어져 있어 위치 확인에 활용하기 어렵다.
3. 줄 끝에서 시선이 왼쪽으로 돌아갈 때 다음 내용을 충분히 예상하지 못한다.
4. 둘째 줄을 읽으려는 순간 그 줄이 위로 이동하여 위치를 다시 찾아야 한다.
5. 영상만으로는 연습 구간과 이름 있는 마커를 편리하게 관리하기 어렵다.

제품의 핵심은 기능 수보다 **악보의 연속성, 다음 마디의 가시성, 음악과의 동기화**다.

## 3. 확정된 사용자 요구와 초안 제안

### 확정된 요구

- 입력은 원본 PDF 악보, 음원, 가사다. MusicXML은 필수가 아니다.
- 일본어 가사는 번역문보다 한글 발음으로 보면서 음악의 위치를 찾는 데 사용한다.
- 가사는 별도 패널이 아니라 해당 시점의 악보 바로 아래에 있어야 한다.
- 템포 표시, 메트로놈, 구간 반복, 마커가 필요하다.
- 재생 속도는 1% 단위로 조절할 수 있어야 한다.
- 현재 줄을 읽다가 화면이 갑자기 교체되는 혼란을 줄여야 한다.
- 첫 검증곡은 「風と丘のバラード」이며 기준 템포는 94 BPM이다.

### 이번 초안의 권장안 — 사용성 검증 후 확정

- 기본 화면은 고정 재생선과 한 줄 가로 스크롤이다.
- 재생선은 화면 왼쪽에서 약 1/3 지점에 놓는다.
- 가독성을 유지하면서 오른쪽에 다음 2~3마디가 보이도록 배율을 조절한다.
- 원본 3쪽 배치는 원본 보기에서 유지한다. 연습 보기에서는 마디를 연속 배치한다.
- 모든 파일은 기본적으로 기기 안에서 처리·보관한다. 자동 분석에 별도 서버가 필요한 경우 처리 위치와 전송 범위를 별도 결정한다.
- 첫 구현은 현재 곡으로 동작을 검증하고, 이어서 다른 곡 입력과 정렬 보정 흐름을 완성한다.

## 4. 핵심 사용 흐름

### 곡 준비

1. PDF와 음원 파일을 선택하고, 가사를 붙여 넣는다.
2. 곡 제목·기준 BPM·기본 박자를 확인한다.
3. 앱이 악보의 줄과 마디 영역, 음원의 첫 박과 템포를 추정한다.
4. 사용자가 원본 악보와 음악을 보며 잘못된 마디선·박 위치·변박을 보정한다.
5. 가사 구절을 음악 시간에 연결하고, 필요한 부분은 음절 단위로 보정한다.
6. 준비된 곡을 저장하고 연습 화면으로 이동한다.

자동 추정이 실패해도 수동 정렬로 준비를 완료할 수 있어야 한다. 모든 PDF와 노래가 자동으로 정확히 인식된다고 가정하지 않는다.

### 매일 연습

1. 저장된 곡을 열고 마커 또는 마디 번호로 이동한다.
2. 속도와 클릭 볼륨을 조절한다.
3. 시작·끝 마디를 선택해 반복 범위를 만들고 이름을 붙인다.
4. 카운트인 후 연습한다.
5. 익숙해지면 1%씩 속도를 올린다.
6. 종료 후 다시 열면 곡의 설정·마커·반복 구간을 복원한다.

### 연습 화면 세부 원칙

- 악보와 가사가 화면의 주 영역을 차지한다. 큰 제목이나 별도 가사 패널로 공간을 소모하지 않는다.
- 박 표시와 마디 번호는 재생선 근처에 배치한다.
- 현재 위치 강조가 음표를 가리지 않도록 한다.
- 하단에는 재생, 속도, 반복, 마커, 클릭의 주요 조작을 둔다.
- 설정을 펼쳐도 현재 위치를 잃지 않아야 한다.
- 정렬 편집과 연습 모드를 구분해 연주 중 실수로 악보 위치가 바뀌지 않게 한다.
- 초기 시제품에서 같은 후렴 20~30초를 가로 스크롤과 두 줄 고정·교대 갱신 방식으로 비교한다. 최종 기본 방식은 사용자의 실제 연주 결과로 확정한다.

## 6. PDF 기반 구현 원칙

PDF는 악보의 시각 자료로 사용한다. 첫 버전에서 음표를 전부 의미 데이터로 변환하지 않는다.

```text
PDF → 페이지·줄·마디 영역 → 연주 순서에 따른 마디 배치
음원 → 첫 박·템포·마디/박 시간표 ─┐
가사 → 구절/음절 시간표 ────────┼→ 공통 재생 시간 → 악보·가사·클릭
반복 구간·마커 ────────────────┘
```

- 마디 영역만 알면 마디 단위 이동·반복이 가능하다.
- 음표 간 인쇄 간격은 시간 간격과 항상 비례하지 않는다. 정밀한 재생선과 가사 배치에는 마디 내부의 박 위치 기준점이 추가로 필요하다.
- 빈 마디, 반복 마디 기호, 다마디 쉼표는 하나의 그림이 여러 재생 마디를 나타낼 수 있다.
- 원본 PDF에 작은 글씨를 억지로 넣는 대신, 웹 연습 화면에서는 별도의 가사 높이를 확보한다.
- MusicXML 가져오기는 후속 확장 후보이며 PDF 입력의 전제 조건이 아니다.

## 8. 재생 엔진과 기술 검증 항목

프레임워크와 라이브러리는 아직 확정하지 않았다. 기술 선택 전에 다음을 작은 시제품으로 검증한다.

1. iPad에서 음정 유지 속도 변경과 1% 조절이 안정적으로 동작하는가.
2. 오디오 재생 시간을 기준으로 악보·가사·클릭을 동기화할 수 있는가.
3. 탐색·속도 변경·반복 시 예약된 이전 클릭이 남아 이중으로 울리지 않는가.
4. 반복 경계에서 불필요한 대기나 중복 박 없이 이어지는가.
5. 작은 PDF 마디를 확대해도 선명하고, 메모리 사용이 과도하지 않은가.
6. iPad 파일 선택·저장·새로고침·화면 회전에서 복원이 가능한가.
7. 자동 음원·가사 분석을 기기에서 처리할지, 별도 준비 도구로 처리할지 결정한다. 서버 처리는 기본 가정에 넣지 않는다.

초안 성능 목표는 표시와 음악의 오차 100ms 이내, 클릭과 검증된 박 기준의 오차 30ms 이내다. 실제 기기 측정 후 기준을 확정한다. 자동 가사 인식의 정확도와 재생 엔진의 동기화 정확도는 별도로 평가한다.

백그라운드 전환·오디오 중단 시 조용히 어긋난 채 계속 재생하지 않는다. 일시정지 또는 재동기화 후 상태를 알리는 동작을 검증해 결정한다. 무선 오디오 출력 지연도 별도로 확인한다.

임시 폴더는 영구 보관소가 아니다. 구현 착수 시 파일 존재와 원본 대응을 확인하고 필요한 자료를 프로젝트 안에 보존한다. 현재 PRD 작성 단계에서는 원본 미디어를 복사하지 않았다.

기존 자료는 출발점으로 사용한다. 음절 위치 일부는 추정이며 필인 구간의 가로 좌표도 검수가 필요하다. 기존 영상·PDF가 곧 완전한 정렬 정답은 아니다. 기준 BPM은 94이며, 분석값과 표시값의 미세한 차이는 동기화 자료에 보존한다. 84마디 5/4 이후의 위치를 별도로 확인한다.

## 10. 단계별 구현 범위와 통과 조건

| 단계 | 범위 | 통과 조건 |
|---|---|---|
| 1. 화면 시제품 | 현재 곡 후렴 일부, 가사 통합, 두 가지 화면 전환 비교 | 사용자가 다음 마디를 미리 읽고 위치를 잃지 않는 표시 방식을 선택한다. |
| 2. 현재 곡 연습 | 전체 곡, 속도, 클릭, 카운트인, 반복, 마커, 저장 | 처음부터 끝까지 및 변박 전후에서 동기화가 유지되고 연습 설정이 복원된다. |
| 3. 다른 곡 준비 | 파일 입력, 마디 영역 지정, 음악·가사 정렬 보정 | 별도 코드 수정 없이 두 번째 곡을 준비하고 연습할 수 있다. |
| 4. 자동화 개선 | 마디·박·가사 자동 추정과 확인 흐름 개선 | 수동 보정 경로를 유지하면서 곡 준비 작업을 줄인다. 완전 자동 성공을 완료 조건으로 삼지 않는다. |

첫 대상곡만 동작하면 ‘현재 곡 시제품’으로 보고한다. 다른 곡을 사용자가 준비할 수 있기 전에는 범용 업로드 앱이 완성되었다고 표현하지 않는다.
