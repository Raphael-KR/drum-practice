# MusicXML 정본 전환

- 목표: 악보·메타정보·가사 리듬 성부 및 음원 연결점을 MusicXML에 보존한다.
- 범위: 로컬 웹앱의 저장/복원/HTML/가사 편집과 보컬 MusicXML 가져오기. 기존 사용자 교정 보존.
- 완료 조건: 저장 후 MusicXML에서 마디·박 가사를 복원하고 음원 연결 변경에도 악보 위치가 불변. 자유 초 편집 제거.
- 제외: 없는 보컬 음높이 추정, PDF의 무검증 자동 채보, 렌더러 즉시 교체.
- 검증: MusicXML 왕복/가사 위치/메타정보/연결점 보존 회귀 검사, 실제 앱 및 빌드. 렌더러 비교는 기존 렌더러를 유지한 채 근거를 기록한다.

MusicXML 원문은 렌더러로 재생성하지 않고 직접 보존·수정한다. 화면의 Song은 파생 편집 모델이다. 가사 초 단위 값은 재생용 캐시다. 가사 정본은 독립 파트의 음절 시작과 음가다. 기존 PDF만 있는 곡은 채보하지 않은 드럼 음표를 만들지 않으며 가사 성부부터 보존하고 원본 PDF를 유지한다. 변환된 MusicXML이 있는 곡은 그 악보를 기반으로 한다.

## 현재 가사 제작 기준

2026-10-03 사용자 확정: 악보가 표준이다. 가사 위치·음가는 원본 악보를 기준으로 저장하며, 가수의 실제 가창 차이를 반영하지 않는다. 실제 가창 시각·길이의 측정·기록은 요구하지 않는다. `time/end/grid`는 악보 위치와 음원 연결에서 계산한 재생 캐시이며 실제 발음의 전사 값이 아니다. 별도 `DrumPracticeLyrics`는 기존 저장 구조로 유지한다. 아래 과거 이전·검증 기록은 당시 사실이며 현재의 추가 가창 검증 과제가 아니다. 자세한 기준은 [변환 정책](MUSICXML-CONVERSION-POLICY.md#가사-기준--악보-우선)을 따른다.

## 저장 계약

- `RecordData.canonicalXML`이 정본이다. 악보 원문을 유지하며 `DrumPracticeLyrics` 파트만 앱이 다시 쓴다. 제목·제작자 변경도 여기에 쓴다. `Song`의 메타정보·가사·재생 시각은 화면/오디오용 파생 모델이고, 열 때 XML에서 다시 복원한다.
- 가사 위치: `measureId + quarterOffset + durationQuarters`. 단위는 사분음표 길이이며 박자표 분모에 따라 화면의 ‘박’으로 변환한다. 기본 편집은 ¼박이고, 보컬 악보의 세부 음가는 그대로 보존한다. XML은 divisions/duration, 독립된 unpitched 음표와 lyric으로 기록한다. 음높이는 추정하지 않는다. 동시 음절은 서로 다른 voice로, 마디를 넘는 길이는 extend로 보존한다.
- 초 단위 자유 가사 편집과 끝 시각 입력을 제거했다. `time/end/grid`는 재생·기존 표시 코드의 캐시다. 이력의 이전 초 단위 데이터는 복구 근거로만 남긴다. 초기 이전 때 기존 시작 격자를 유지하고 끝 길이는 음악적 단위로 변환한다.
- 원제는 work-title, 표시 제목은 movement-title 및 `drum-practice:display-title`, 제작자는 artist/composer/lyricist로 저장한다. 원래의 다른 메타정보/파트는 유지한다.
- **최신 사용자 결정(2026-10-06): 앞으로 제작하는 모든 드럼 연습 악보의 가수란(`artist`)에는 선택하여 사용하는 드럼킷 이름을 반드시 기록한다.** 예: `SoCal 드럼킷`, `Portland 드럼킷`. 개별 세 곡만의 예외가 아닌 공통 제작 규칙이다. 드럼킷은 [선택 기준](GARAGEBAND-DRUM-KITS.md)에 따라 정하고 SoCal로 고정하지 않는다.
- 연습 악보의 키트 이름은 MusicXML `identification/creator type="artist"`와 파생 `Song.artist`에 동일하게 저장한다. 패키지를 만들면 내장 정본 XML과 Song의 값도 동일해야 한다. 제작·교정·재제작·저장 후 재읽기에서 누락이나 불일치를 확인한다. 이 메타정보 규칙이 요청하지 않은 음원 제작을 추가하는 것은 아니다.
- 일반 곡 악보의 `artist`는 실제 가수·아티스트를 유지한다. 세션 연주자·강사·참고 영상 채널은 가수로 입력하지 않는다. 참고 자료의 출처는 제작 문서에 보존한다.
- 결정 이력: 처음에는 가수 없는 연습악보를 비우기로 했으나, 탐탐 무빙16/28마디와 시작전 손플기에 드럼킷을 표기한 뒤 모든 드럼 연습 악보로 일반화했다. 이전 빈칸/개별 곡 한정 지침은 현재 제작 기준이 아니다. 기존 작품의 키트는 탐탐 무빙16마디/시작전 손플기=SoCal, 탐탐 무빙28마디=Portland이며 ID는 유지한다.
- `drum-practice:score:v1` miscellaneous-field에 마디의 안정 ID, 라벨·박자표와 음원 시작/끝 연결점, 음원 SHA-256, 음절 ID·확인 상태를 둔다. 현 앱의 인쇄 순서 재생에 맞춰 occurrence=1이다. 반복 기호의 자동 펼치기는 기존과 같이 지원하지 않는다. 임의 중간 박 앵커 UI는 이번 범위가 아니며 기존 마디 시작/끝 연결로 보간한다.
- **연습 박 기준 — 사용자 결정(2026-10-13): 선택한 연습 속도에 따른 일정한 메트로놈 박을 기준으로 한다.** 실연의 개별 타격이 앞서거나 늦는 그루브를 박별 시간표에 반영해 연습 격자를 흔들지 않는다. 악보에 기보된 리듬·음가·박자 변경은 보존한다. Loveholic은 기존 첫 박0.193초와 일정한136.232 BPM 기반 음원 연결 시간표를 유지하고 추가 마디·박별 실연 추종 분석/교정을 수행하지 않는다. 악보 BPM136 유지·원곡 측정값 별도 표시·원곡 배속1.0 결정도 유지한다.
- 악보 템포와 음원 측정값은 분리한다. Loveholic의 사용자 결정(2026-10-13)은 표준 tempo와 Song.bpm=136 유지, 별도 원곡 추정값136.232·첫 박0.193 저장이다. `drum-practice:recording-tempo:v1` miscellaneous-field에는 `version`, `scoreBpm`, `bpmEstimate`, `firstBeatEstimateSeconds`, `audioSHA256`, `method`, `status`를 JSON으로 둔다. 앱은 원곡 추정값을 표시하되 ‘원곡’ 재생은 배속1.0으로 한다. 이 필드가 있다는 이유로 표준 악보 템포나 기존 마디 시각을 덮어쓰지 않는다. 측정값은 해당 음원 해시와 결합된 추정치이며 일반 MusicXML 앱의 필수 기능이 아닌 이 프로젝트의 메타정보다.
- XML 음원 해시가 있으면 열 때 실제 음원과 대조한다. 렌더러를 통과해 정본을 다시 만들지 않으므로 앱 전용 확장 필드가 사라지지 않는다.
- IndexedDB, ZIP의 `canonical.musicxml`(미디어 제외 백업에도 포함), 단일 HTML이 정본을 보존한다. 파일·안내 → MusicXML 저장에서 직접 내보낸다. 다시 가져오면 가사·메타정보·연결점을 읽는다.
- MusicXML에 실제 드럼 악보가 있으면 마디 수/박자표를 바꾸는 편집은 원본 악보에서 수행하도록 막는다. 영역과 음원 연결은 앱에서 수정 가능하다. PDF만 있는 곡에서는 PDF를 유지하며 가사 XML부터 생성한다. 이 XML을 드럼 음표까지 채보된 악보라고 표시하지 않는다.

## 보컬 악보 입력

### 악보의 박별 음원 연결 (2026-10-15)

- 사용자가 붉은 노을의 남은 재생 문제 수정·수록을 승인했다. `drum-practice:score:v1`의 마디에 선택적인 `beatTimes`를 저장하고 `Song.measures`로 복원한다. 배열 길이는 기보 박 수, 첫 값은 `start`, 이후 값은 엄격한 증가이며 모두 `end`보다 작아야 한다. 음가·박자표·가사 위치는 바꾸지 않는다.
- 배열이 없으면 기존 시작/끝 균등 보간을 유지한다. 기존 악보에 자동 추정 박을 주입하지 않는다. 위 Loveholic 일정 연결 정책은 유지한다.
- 원곡은 원본 1배속과 저장된 박 시각을 사용한다. 연습 모드는 박자표 분모를 반영한 사분음표 위치로 음원을 정규화하여 고정 BPM을 사용한다. 원곡의 현재 BPM은 완료된 최근 박 간격에서 계산한다.
- 시작/끝 연결점을 편집하면 내부 박 시각도 같은 비율로 이동한다. 명시적 전체 템포 재배치 및 XML 표준 템포 적용은 박별 배열을 제거하고 균등 연결로 바꾼다. 정본에 배열이 없으면 파생 캐시의 배열도 제거한다.
- 붉은 노을의 `drum-practice:recording-grid:v1`은 제작 추정의 근거만 보존한다. 런타임은 이 필드를 임의 적용하지 않는다. 해당 곡의 엔딩 추정과 실기기 청취 미확인은 [앱 반영 기록](RED-SUNSET-APP-INTEGRATION.md)에 구분한다.

가사 편집 → 보컬 MusicXML 가져오기 → 파트 선택. 마디 수와 각 박자표를 검사하고, 전주/반복 순서는 사용자에게 맞추도록 안내한다. 가사가 있는 음표의 리듬을 읽어 독립 가사 파트에 기록하며 원래의 보컬 파트도 `DrumPracticeVocalSource`로 보존한다. 가사 교체 전 확인하고 이전 가사는 이력에 보관한다. PDF 보컬 악보의 자동 채보, 음절별 노래 청취 검증은 이번 입력 기능과 구분한다.

## 렌더러 결정

OpenSheetMusicDisplay를 유지한다. 악보 로드 때 렌더링하고 재생 중에는 기존 표시를 갱신하는 구조는 유지한다. 변환 작업에서 전달한 ‘SVG 렌더링 후 재사용’은 후속 표시 최적화 방향이며 이번 정본 전환에서 캔버스/PNG 렌더링을 SVG로 교체하지 않았다. Verovio의 확장 필드 왕복 소실 조사 결과를 고려해 렌더러 출력으로 XML을 재생성하지 않는다. 두 렌더러의 동일 iPad 성능 비교·채택 변경은 수행하지 않았다.

## 검증

- 31개 테스트 파일, 114개 검사 통과(최종 실행 기록 history.md). 정본 재읽기, 파생 캐시 무시, 동시 음절/마디를 넘는 길이, 보컬 셋잇단음표, 음원 연결 이동, XML 재가져오기, 저장/HTML/유형 전환 보존, 해시 불일치 거절을 검사했다.
- 원곡 515개 시작 위치 이전 변경 0개. 길이는 기존 재생용 끝 시각을 음악적 길이로 변환한 값이며 실제 발음 길이를 새로 청취해 검증한 결과가 아니다.
- 가사 전용 XML 및 실제 UI에서 보컬 파트를 추가한 전체 XML 모두 로컬 W3C MusicXML 4.0 XSD PASS. 외부 프로그램을 거친 앱 확장 필드 보존을 보장하는 결과는 아니다.
- localhost QA 곡에서 보컬 가져오기, 마디/박 변경 후 저장, XML 재읽기 확인. iPad mini(A17 Pro) iOS27 Safari에서 HTML의 가사 편집 화면 확인: `docs/experiments/canonical/ipad-lyrics.png`.
